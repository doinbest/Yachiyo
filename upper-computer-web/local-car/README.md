# 八千代·巡航 · 本地小车控制台

适配当前 STM32 USART1 文本控制台。网页、CMD 和调试脚本通过本地 Python 服务共享一个串口连接。本地服务是唯一连接方式。

## 启动与连接

需要 Python 3 和 pyserial；缺少时执行 `python -m pip install pyserial`。Windows 双击本目录 `start.cmd`，或运行：

```powershell
python serve.py
```

用桌面 Chrome/Edge 访问 `http://127.0.0.1:8765/`，不要直接双击 HTML。服务仅监听回环地址，无需 npm、云部署或网络字体。更新程序后退出旧服务再启动。

- 启动服务不会自动连接串口，连接、刷新和重连不会启动运动。
- 网页共享模式先在“串口”列表中选择设备，再点击连接；没有默认 COM 号。列表显示端口号及设备名称（如 CH340），默认通信格式仍为 115200 / 8N1。
- CH340 换 USB 接口后点击“刷新串口”，重新选择当前端口。刷新仅枚举设备，不打开串口、不发送指令；只有一个端口时也不自动选中。页面不持久保存端口选择。
- CMD 输入 `ports` 查看列表，输入 `connect COM7` 连接指定端口（COM7 仅为示例）。仅当启动时明确传入 `--serial-port COM7`，才允许省略端口输入 `connect`；网页始终自行选择。
- 工程工具配置中的串口与网页默认值独立。占用时先释放其他串口助手。

## 终端工作台布局（2026-09-21）

桌面采用左侧连接与导航、中央常驻终端、右侧任务操作，六页共用固定分栏比例，切换地图页不会改变连接区或终端宽度。默认打开“系统与标定”；导航依次为系统与标定、底盘、地图与遥测、二维码、视觉任务、机械臂与夹爪。右侧单独滚动，终端输入框和底部停车区始终保留；窄屏改为上下分区。默认深色，可切换浅色。本版不展示人物背景，浏览器中已有的背景偏好不删除。

点击发送操作时，终端顶部立即显示原始命令与“待发送”，日志记录请求；串口实际写出后才增加 TX，并显示“已写出 · 待设备确认”。写出不代表动作完成，失败或拒绝发送不会增加 TX。顶部最近操作不受日志筛选影响。共享服务停车单独显示“请求停车”，以底部停车状态和实际 TX/RX 为准。

主界面只保留常用操作：读取位置、夹爪 PWM/释放、单轮调试及旧速度测试等不再单独铺设控件，协议能力仍保留，可在手动终端输入。回零与参数、四轮状态、准备跑图及高级运动默认折叠。底盘反馈对象固定为四轮，不再提供单轮或协议单位选择菜单。离线地图的播放按钮独立可见，路线表和模拟参数按需展开。

## 六个工作页

| 页面 | 操作 |
|---|---|
| 系统与标定 | 信息、帮助、IMU 状态、原生标定、5 秒重新验证、Z 轴清零、角度输出及主控重启 |
| 底盘 | 整车平移/转向、四轮反馈快照、准备跑图与四段路线；高级区保留指定航向和地图位移，故障恢复单独折叠 |
| 地图与遥测 | 离线 16 段模拟、在线指令推算与反馈估计 |
| 二维码 | 支持检查、最新缓存读取、新码跟随、四组三位数字及接收统计 |
| 视觉任务 | 物料搜索与对准、相机识别、Base/X 独立对准、标定 |
| 机械臂与夹爪 | Base/Z/X/全部轴的使能、停止、状态；单轴相对角度；夹爪；折叠区内回零、零点和参数 |

表单展示实际命令；一次执行发送一次，不自动重发普通运动命令。`pos` 为电机轴相对角度，网页单次限制 ±360°；固件另有机械行程和脉冲配置检查。`material auto` 包含识别、搜索和对准，`ALIGNED` 只表示对准完成。

二维码页的 `qr read` 读取缓存，不触发扫码器，也不消费主循环任务码；跟随通过显式 `qr stream on/off` 控制，新码通知最多 5 Hz。没有新码不等于扫码器离线。

## 准备跑图与实车路线

在底盘页展开“准备跑图 · 实车四段路线”。本车采用已确认的 Emm42 默认配置：3200 控制脉冲/电机轴圈、65536 位置反馈单位/电机轴圈、Receive 应答，仅修改 ID。准备流程直接采用这些协议参数，不再要求选择应答模式或勾选实测位置单位。旧配置文件中的 profile/units 不覆盖本车预设。

“本车配置”只需保存四轮安装方向确认，取消勾选后也可保存以撤销资格。准备时只应用到 MCU RAM，不修改驱动器或 Flash。现场仍须确认小车实际摆放位置与朝向。协议数值已知不代表实车距离已验收。

“准备跑图”依次检查任务空闲、应用位置单位并检查固件默认 Receive、开启四轮反馈并检查静止状态、检查 IMU 资格；已有上电验证资格时直接复用，必要时执行 5 秒静止验证。操作者确认车体中心在右下起点 `(2250,150)`、车头朝上、整车静止后，程序设置 `(2250,150,90°)` 原点并开启新遥测会话，收到有效起点反馈后完成准备。

准备期间共享服务限制其他来源修改状态，查询、取消和停止仍可用。准备完成不启动运动。

| 实车操作 | 命令 |
|---|---|
| 开始第 1 段 | `chassis route start` |
| 手动下一段 | `chassis route next` |
| 取消路线 | `chassis route cancel` |
| 查询路线 | `chassis route status` |

固件四段依次到 `(2100,300)`、`(2100,1200)`、`(2100,2100)`、`(1200,2100)`，每段反馈确认停止后等待人工继续。到点是编码器反馈估计进入容差，不代表完成扫码、视觉精对准或抓取。`chassis move` 是独立的地图相对位移测试，合位移大于 0 且不超过 300 mm。

`chassis run vx vy 0 hold_ms` 自动保持起步 HWT101 航向，需要本次验证通过且数据新鲜，不需要地图原点；非零角速度执行给定转向。显式 `chassis heading` 的目标为模块角度，仍需要地图锚点。起停各 0.5 秒，界面保持时间 0.1～59 秒。

## 停车与解除锁定

CMD 按 Ctrl+C 或网页“立即停止底盘”会取消准备、清空待发普通命令、锁定新的运动请求并优先请求底盘停车。CMD 窗口继续运行；`quit` 先执行停车流程、最多等待 6 秒后退出。

状态依次区分请求已发出、MCU 受理、电机总线停车发送完成、四轮反馈确认停止；没有新鲜有效反馈时不能显示已确认停车。查看结果后明确解除锁定，任务不会自动恢复。

`stop all`、视觉停止、底盘停止各有范围；统一停车属于软件措施，不是硬件急停。关闭网页、强制关窗口或无线失联无法保证停车。本地服务的主动断开有停车流程。

## 地图与遥测

### 离线模拟

默认 16 段展示两批物料路线，可编辑起步、匀速、减速、停留和车体速度，最多 50 段。单段运行从地图当前位姿开始，整条运行从设置的初始位姿开始；路线编辑当前不持久化，刷新恢复默认。

离线播放只作用于浏览器，**不会上传路线或发送实车运动命令**。1/4/10 倍速只改变观看速度；离开页面、隐藏浏览器或停顿超过 250 ms 会暂停。模型采用半余弦起停、最大 20 ms 中点积分，并可量化整数 RPM。

场地为 2400×2400 mm，原点在左下；车体名义外框 300×300 mm，碰到边界、工作区或转盘时终止模拟。默认几何 L=210、W=240、D=80 mm、G=1，包含估计和假设，只用于模拟；不涵盖展开机械臂、随机障碍、驱动器动态和实车定位误差。

默认理想路线运动 154 秒、含占位停留 170 秒，不包含实际取放和视觉耗时。整数 RPM 模式末段可能触发边界保护，需要末端精定位；路线结束与整车返回原启停区合格分别判断。

### 在线遥测

手动选择指令推算或反馈估计并开启遥测，发送 `chassis stream on <非零会话编号>`；关闭发送 `chassis stream off`。准备跑图也会显式建立遥测会话。

`@CHASSIS` JSON 必须先收到同会话 config，再接受 state。在线几何来自 MCU 配置，不使用离线假设。指令推算不等于测量；反馈估计使用 MCU 位姿、轮位置与航向有效性，不以目标 RPM 代替原始反馈。

当前状态周期 2000 ms，首次等待配置最多 8 秒，配置后超时为周期三倍；旧 config 缺少周期字段时按 200 ms 计算。样本相对 MCU 时间的 600 ms 新鲜度要求保持不变。超时清除当前状态，重启订阅需要手动操作；时间跳变、会话或轨迹序号变化会断开轨迹。

## 日志与排障

- 公共终端支持模块与 TX/RX/系统筛选、跟随、清空和导出，最多保留 500 条；清空日志不清二维码或地图状态。
- 设备回复中的 `accepted` 只表示请求受理；到位与停止必须读取对应反馈。
- 最多 24 条常用指令，点击即发送；主题和常用指令保存在浏览器。
- 服务原始收发记录在项目 `.embeddedskills/logs/serial/`，用于排查丢字、串口写出及反馈。
- 服务不可用时检查 CMD；串口占用时释放其他程序；准备超时时看回显、ERR、四轮反馈和 IMU 状态，不自动重复运动。
- `bus_locked=1` 是总线隔离；`chassis reset-confirmed` 只能在驱动器已经实际复位后使用，它不会复位驱动器。

### 2026-09-22 固件通信更新

新固件使用 USART1 循环 RX DMA、普通 TX DMA，地图周期仍至少 2 秒；网页兼容 v1 及紧凑 v2 状态。地图压缩保留反馈时间戳、位置、航向及停止判断，不能替代实物定位验收。

需要排查串口时，在中间终端手动输入 `console status` 查看缓冲与错误统计，输入 `chassis snapshot` 获取详细底盘状态；两者在停车锁定时仍允许查询。连续 IMU/视觉调试各只保留最新待发样本、每路最多每 500 ms 开始一次发送；终端不是所有传感器采样的完整录波文件。命令回复与停车回复优先，但仍可能等待正在发送的一帧结束。

更新固件后刷新本地页面。若 Python 服务正在运行，关闭并重新启动 `start.cmd`，使新诊断命令的只读分类生效。串口仍由用户选择，未连接不会自动发送指令。协议数组与统计定义见[当前协议](../../docs/上位机协议.md)。

### Z 轴清零与主控重启（2026-09-22）

“系统与标定”新增 **Z 轴角度清零**（`imu zero`）：保持静止，把当前模块 Z 轴角度设为零。终端先显示受理，再显示归零前后样本。它不会消除漂移，也不做零偏标定；跑图前重新验证 IMU、设置地图起点。

先人工确认整车静止（机械臂收到 ACK 不代表到位）。在左侧连接区点击“重启设备”（`system reset`），确认后发送。软件任务或标定忙时拒绝；空闲时先发送受理回复再软件复位，停车请求可取消尚未执行的重启。此操作会重新初始化 STM32，不会给驱动器或 IMU 断电；不是停车按钮。收到启动信息后网页清除旧状态，订阅需手动重新开启。本地服务停车锁定时须先解除锁定。

软件验证及实物待验项目见[开发记录](../../docs/开发记录/2026-09-22远程重启与Z轴归零.md)。

左侧“连接串口 / 断开 / 重启设备”集中管理设备连接与重启；设备信息仍在系统页查询。已移除各页重复的常用指令区及表单“加入常用”按钮；表单保留复制和执行，手动终端仍可输入指令。旧浏览器收藏数据不再读取，其他偏好保持原样。

### 上电自动准备 IMU（2026-09-22）

固件默认 Receive，无需控制台设置应答模式。上电后保持整车静止，固件等到 IMU 新鲜数据后归零并自动验证 5 秒；看到 `result=PASS verified=1 control_ready=1` 后可进行航向控制。失败只报告一次，可在系统页点击“重新验证 5 秒”；不自动执行原生标定。总等待还包含初始化、归零及无线传输时间。地图起点、轮向确认和反馈检查仍由准备跑图完成。

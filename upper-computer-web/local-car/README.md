# 八千代·巡航 · 本地小车控制台

适配当前 `template/App/arm_console.c` 的 USART1 文本控制台。不依赖上层 React/Vinext 工程。默认由本地 Python 服务独占串口，CMD、网页和调试脚本共用连接与接收数据；Web Serial 保留为独立备用方式。

## 启动

Windows 双击 `start.cmd`，需要 Python 3 和 pyserial（缺少时执行 `python -m pip install pyserial`）；或在此目录执行：

```powershell
python serve.py
```

用桌面 Chrome 或 Edge 访问 http://127.0.0.1:8765/ 。如果默认浏览器不是 Chrome/Edge，请手动复制地址。

仅监听 `127.0.0.1`，无需云部署、npm 安装或网络字体。升级后先退出旧服务，再运行新入口，避免旧进程继续提供旧接口。不要直接双击 HTML。

CMD 中按 **Ctrl+C 请求底盘停车，窗口继续运行**；输入 `quit` 先执行停车流程再退出。强制关闭窗口或无线失联无法保证停车。它是软件停车措施，不是硬件急停。

## 使用

1. 默认使用本地服务，已确认本车为 COM23、115200 / 8N1、DL-20 无线链路。
2. 点击连接。若提示串口占用，先释放串口助手或 Web Serial 的 COM23 连接。连接、刷新和重连均不启动运动。
3. 在工作台顶部选择机械臂与夹爪、底盘、视觉任务、二维码、地图与遥测或系统与标定。使能、失能和状态等直接操作；运动表单显示实际命令。调试参数默认收起。也可在公共终端手动输入命令。
4. 「加入常用」保存当前操作及参数；常用按钮点击即发送。移除常用按钮不向设备发送数据。
5. 公共终端支持当前模块/全部模块/通用回复及 TX/RX/系统筛选、跟随、收起、清空和导出；最多保留最近 500 条。向上翻阅暂停跟随。导出包含所有分类；清空日志不清二维码、轨迹或设备状态。
6. 「背景设置」允许选择不超过 2 MB 的 PNG/JPEG/WebP，调整强度；支持浅色和深色。背景、主题、常用指令保存在当前浏览器；共享服务的原始收发记录另存于项目 `.embeddedskills/logs/serial/`。

### 首次配置与准备跑图

在底盘页展开「本车配置」，按实际驱动配置选择 `receive` 或 `none`，实测一圈反馈变化确为当前固件支持的 65536 协议单位后勾选确认，并确认四轮方向已经检查，然后保存。若实测值不同，不勾选该项，应先核对驱动协议。未确认项保持空白；保存的是电脑配置，不会修改驱动器持久参数。

以后点击「准备跑图」，程序先检查任务空闲，应用保存的 MCU 参数并回读，再检查反馈和静止状态。IMU 资格不足时验证 10 秒。将车放在右下起点、车头朝上后，点击起点确认；程序建立 `(2250,150,90°)` 原点并开启遥测，收到有效起点反馈后才完成准备。准备完成不会自动启动路线。

Ctrl+C 或网页统一停车会取消准备并锁住新的运动命令；检查结果后需明确解除停车锁定，才能继续操作。停止结果区分请求已发送、停车发送完成和轮子反馈确认停止。没有新鲜反馈时保留“停止未确认”。

原生 USB CDC 由香橙派 `orange_pi/change.py` 使用 B2 颜色视觉协议；USART1 才是本页文本控制台。旧 `sys.ping#`、`PING/INFO` 网页入口和 B3 圆环编号不适用，圆环编号快捷项已移除。

## 指令边界与反馈

- 每条命令发送一次，追加 `\r\n`。固件最多 63 字节、6 个字段；页面拒绝内嵌换行和非 ASCII 输入。
- 常用动作覆盖机械臂、夹爪、底盘、视觉和系统帮助；故意不提供无参数的 `chassis backward` 快捷项，定距后退必须输入距离。
- `pos` 是电机轴相对角度。参数面板限每次 ±360°；当前固件的 Z 轴本身没有同样的固定角度上限。机械行程和当前配置仍由固件检查。
- 配置速度 1～3000 RPM、加速度参数 1～255、脉冲限制 0～3200；只有单独 Z 轴允许限制为 0。
- `accepted` 只表示接受请求，不能视为到位；只有收到明确 `OK state ... reached=1` 时显示所查询轴报告到位。
- 右侧展示最近一条设备反馈，不把异步日志猜测关联到某次按钮点击。自动任务的 `OK` 不表示整套动作完成。
- 四个停止按钮保留各自真实范围，没有把 `stop all` 标成整车急停。停止被固件拒绝时查看 `ERR`；关闭页面、断开串口都不等于停车。
- 不自动重发运动指令，不自动循环发送，不自动运行组合动作。

## 二维地图（#map）

### 离线路线表（每段起步—运行—停车）

地图上方每行是一段有限动作：停车状态、车体前向 vx / 左向 vy（mm/s）、逆时针 ω（rad/s），以及起步、匀速运行、减速停车、停留时间（秒）。合速度上限 100 mm/s、角速度上限 0.15 rad/s；每段运动最多 60 秒，停留最多 60 秒。起停时间须大于零，默认各 0.5 秒。

- **运行整条路线**：从设置中的初始位姿开始；**运行此段**：从地图当前位姿开始，只运行选中行。
- **暂停 / 继续**：冻结和恢复模拟时间。离开地图页、隐藏浏览器或页面停顿超过 250 ms 也会暂停，不补跑后台时间。修改参数会结束本次模拟，需重新运行。
- **添加 / 删除 / ↑ / ↓**：编辑动作与顺序，最多 50 段。当前版本参数只在此页面有效，刷新恢复示例；尚未保存或导出路线。
- **1 / 4 / 10 倍速**：只改变观看速度，不改变路线参数、计算时长或积分步长。
- 地图标记模拟停车点和段号，列表记录停车时刻、X/Y 和朝向。不会吸附到预设工位；整数 RPM 模式逐步量化整个起停过程，保留偏差。
- 离线模拟按300×300 mm车体外框检查场地边界、图中淡黄区/工作台和转盘，干涉前保留上一有效位置并提示出错段。未包括展开机械臂、随机黑色障碍物或实车误差。

默认16段从 `(2250,150,90°)` 出发，保持车头朝上；用麦轮横移和倒退连接工位。

| 5 | (1200,350) | 第一批粗加工：按码全部放好3件，再按规定顺序重新抓回车载仓 |
| 6–7 | (1200,1200) → (350,1200) | 第一批暂存区按码平放 |
| 8–9 | (1200,1200) → (1200,2100) | 第二批取料入车载仓 |

| 13–16 | (1200,1200) → (2100,1200) → (2100,300) → (2250,150) | 返回原右下启停区 |

依据本地《附件2-1命题与运行》第7–8页，每批携带三件，跨区运输放在车载仓。上述取放仅为任务说明，不模拟机械臂或实际抓取成功。

直线100 mm/s，首尾斜移两分量各50 mm/s；起停各0.5秒，每段默认停留1秒，可编辑。理想模型行驶154秒、含占位停留170秒，回到原初始位姿。实际取放、加工、视觉对位时间未计入，不能用此时长判断三分钟完赛。积分不吸附端点。

整数RPM模型默认在第16段返回时触发外框边界保护，显示“返回阶段需末端精定位”。路线结束与返回合格分开：完整路线结束且整个300×300 mm外框进入原启停区才显示返回合格；单段结束不代表整条路线或搬运完成。完成/出错后切换页面或数据来源保留结果，只有运行中才进入暂停。

重复工位的邻近停车编号合并显示（如4/9）；各次实际停车位姿和外框保留，完整列表逐条列出。

按300×300 mm外框：扫码点车侧到二维码板名义间距150 mm，原料停车点车头到转盘名义间距70 mm，粗加工与暂存停车点车侧间距各50 mm；镜头实际位置/工作距离须另行测量。地图实线为最大初始外框，虚线为轮心。依据本地《附件2-1命题与运行》第2页：启动投影不超过300×300 mm、高度不超过400 mm；出发后允许展开，因此此固定外框不代表展开后的机械臂。

`route-model.mjs` 使用现有运动学、半余弦起停和最大 20 ms 中点积分；没有模拟 UART5 下发间隔、驱动器动态或定位误差。所有路线操作仅作用于浏览器。

本轮两批路线的软件与浏览器验证结果见 [开发记录](../../docs/开发记录/2026-09-12两批搬运离线路线.md)。本轮不修改固件。

- 从「地图与遥测」进入，无需另开串口页。离线模拟可直接使用；启动/暂停/复位仅操作浏览器，不发送底盘运动命令。
- 车体前向 vx、左向 vy 单位 mm/s，逆时针角速度 ω 单位 rad/s。初始 X/Y 用 mm，θ 输入为度，内部用弧度。20 ms 固定小步中点积分，按真实经过时间补步，单次停顿超过 250 ms 或页面隐藏自动暂停。
- 模型分「理想运动学」「整数 RPM 命令近似」。两者均先按 100 RPM 上限整组同比缩放，后者再量化整数 RPM；不修改实车电机设置。几何默认 L=210、W=240、D=80 mm、G=1；轴距/轮距为估计，轮径/减速比为假设。编辑仅影响离线模型。
- 2400 mm 正方形场地原点在左下，整块灰底；四个 450 mm 浅黄块左下坐标组合为 X/Y=550、1400。左/下工作区分别是 x=0..150、y=910..1490 和 x=910..1490、y=0..150。右下/右上蓝区 300 mm；二维码在 (2400,1200)，区段 1100..1300；原料区中心 (1200,2470)，直径 300。虚线物料位置仅为示例。
- 车轮按 FL/RL/RR/FR = 1/2/3/4，轮心坐标 (+105,+120)、(-105,+120)、(-105,-120)、(+105,-120)。虚线轮心框与300×300 mm模拟外框分别显示；外框只用于离线名义尺寸检查，不能代表展开后的实车。
- 在线选择「指令推算」或「反馈估计」，然后手动「开启遥测」。发送 `chassis stream on <非零随机uint32>`，关闭发送 `chassis stream off`。连接和切换页面不会自动订阅或发送其他命令。状态流最短周期为 2 秒，发送积压时延后生成快照；接收行支持约 2 KB，发送命令仍限 63 字节。
- `@CHASSIS` JSON 先收到同会话 config，才接受 state。v=1 是协议版本；rev 记录几何配置版本。在线几何只使用该 config；重复/乱序 MCU 时间丢弃、间隔或 trace_seq 变化断开轨迹。首次等待配置最多 8 秒；收到配置后按 telemetry_period_ms 的三倍判断断流（新固件为 6 秒，旧固件未带该字段时仍为 600 ms），超时清除当前状态，重新开始需手动开启新会话。反馈样本相对 MCU 时间的 600 ms 有效性限制保持不变。不得把陈旧数据当实时测量。
- `simulated`、`command_estimate`、`feedback_estimate` 分开；反馈估计使用 MCU 给出的有效位姿、四轮位置有效性/采样时间和航向有效性。原始反馈 RPM 的电机方向符号与右轮逻辑目标不同，表格明确标为原始反馈，不以目标代替。位置原值每圈单位显示固件确认配置，0 表示待用户确认（本地手册规定 65536）。
- 地图不包含实车运动按钮。运动接口继续在 USART1 控制台中逐项使用，依设备回复确认实际结果。

`map-model.mjs` 是纯计算/遥测状态模型；`map-view.mjs` 绘制地图及绑定控件；`tests/map.test.mjs` 核对矩阵、圆弧解析解、量化、时间补步、会话及失效边界。浏览器/内存测试不代表实物反馈链路已经验证。

交叉语言合同测试：在项目根目录运行 `python tests/chassis_map_contract_test.py`，编译实际 C 模型和遥测输出，再将 JSON 传入网页模块验证公式、整组限幅、1273/4500 脉冲基线、配置优先和反馈有效性。产物及日志保存在 `.embeddedskills/tests/`。


## 新版操作分层

- 机械臂先选择 Base/Z/X/全部轴。全部轴仅允许支持它的查询和控制，不生成单轴相对运动。夹爪打开、夹取直接操作。
- 视觉分任务执行、相机调试、标定与分步测试。物料搜索与对准只发 `material auto`，其内部包含识别和搜索；`ALIGNED` 只表示对准完成。
- 新底盘入口为 `chassis run` 与 `chassis heading`。速度 mm/s、角速度 rad/s；界面保持时间 0.1～59 秒转换为整数毫秒，起停各 0.5 秒。航向必须明确填写 HWT101 模块目标角度，与人工地图初始位姿分开。
- 旧位置/持续速度/单轮/hold 测试归入调试。旧 `chassis hold` 使用整数秒 1～10，没有新版起停规划。驱动应答模式、位置单位和复位确认必须人工操作。
- `stop all` 在视觉/物料任务忙时优先取消该任务，否则停止全部机械臂轴；运行中的新底盘运动测试也会请求停止。它不是硬件急停，也不能保证一次同时取消所有机构动作。
- `#arm/#chassis/#vision/#qr/#map/#system` 共用串口与日志；旧根地址及 `#console` 进入机械臂页。换页、主题切换均不发送指令。保留 `sky-atelier-v1` 的主题、背景及 `{label,wire}` 收藏；无法识别的收藏标为手动，命令不改写。

## 二维码（需本轮固件）

1. 连接 USART1 后进入二维码页，点击“检查支持”。仅查询 `qr status`，旧固件不支持时提示升级。
2. 点击读取最新缓存，发送 `qr read`。没有新码显示“—”；重复查询不消耗主循环的任务码消息。
3. 需要新码通知时显式开启跟随，发送 `qr stream on`；关闭发送 `qr stream off`。这是上报开关，不启动扫码器。重连后需要重新检查支持、手动开启跟随。
4. UART4 接收四组三位数字，用 `+` 分隔，以 CR 或 CRLF 结束。页面显示原码、四组、序号、年龄和统计；没有新码不等于扫码器离线。
5. `received` 是收到的字节数，`accepted/rejected` 是接受/拒绝的完整帧，`uart_errors` 是 UART 错误。重复有效码也产生新序号。事件最多 5 Hz，拥塞保留最新事件并独立计数；不会覆盖地图遥测。

发送调度保持完整帧，下一次选择为命令回复、二维码事件、地图遥测。命令发送成功、驱动受理与实际停止分别理解。所有验证均需上板实测；本轮软件不会自动连接、烧录或发送运动命令。


## 纵向布局调整（2026-09-12）

## 实车前四段测试（real-route-1）

底盘页新增独立面板，使用现有 USART1 连接。它与地图的离线 16 段路线编辑器分别工作；编辑、播放离线路线不会改变或发送实车路线。

| 按钮 / 操作 | 实际命令 | 边界 |
|---|---|---|
| 开始第 1 段 | `chassis route start` | 从固件已确认的初始位姿开始当前段 |
| 手动下一段 | `chassis route next` | 当前段反馈确认停止后，由操作者显式点击 |
| 取消路线 | `chassis route cancel` | 请求取消；实际停止看 `stop_confirmed` 和现场情况 |
| 查询实车路线 | `chassis route status` | 连接后可查询，无须先订阅；回复进入收发记录 |
| 单段相对位移测试 | `chassis move <dx_mm> <dy_mm>` | 地图相对位移，+X 右、+Y 上，合位移大于 0 且不超过 300 mm |

建议先用 100～300 mm 单段位移测试验证方向、位置反馈和停车。两个分量都必须填写，斜向按合位移限幅。参数不是车体前向/左向，也不是绝对目标。初始位姿为 `(2250,150,90°)`，前四个目标为 `(2100,300)`、`(2100,1200)`、`(2100,2100)`、`(1200,2100)`；航向保持 90°，固件反馈定距速度为 50 mm/s。需先完成驱动反馈配置、IMU 验证和地图锚点设置。

MCU 自主完成**当前一段**的运动与停车，网页不定时下发速度，也不自动进入下一段。连接、重连、刷新、切换页面或数据来源不会发送运动指令或自动订阅。每次按钮点击只发送对应一条命令；页面不提前认定请求受理、到点或停止。旧固件不支持的 `ERR` 原样保留在日志。

地图选择在线数据来源后，手动开启现有遥测，才显示本会话中的实车当前段。`@CHASSIS` v1 的 state 可以附带可选 `route`：

```json
{"state":"waiting","reason":"reached","segment":1,"action_id":12,"target":[2100,300,90],"error":[1,-2,0.2],"feedback_valid":true,"stop_confirmed":true}
```

`state` 支持 idle/running/stopping/waiting/done/error/cancelled，`segment` 为 0～4（0 为未进入路线，活动段从 1 开始），`action_id` 为 uint32。`target` 单位依次为地图 X/Y mm、航向度，`error` 为 X/Y mm、航向度。两项有效标志必须为布尔值。在线地图用红色十字标记当前目标；实车面板同步显示状态。缺失或不兼容的 route 不影响旧版位姿遥测，但不会显示实车到点信息。反馈无效时隐藏误差数值，停止条件独立使用 MCU 上报的 `stop_confirmed`。

会话不匹配、配置未收到、超过配置指定周期三倍的接收超时和断线不会产生实车路线显示；断流后需手动重新订阅。文本 `OK chassis route ...` 留在日志中，不用于推断地图目标或到点。离线地图不绘制实车目标，在线地图不混用离线的停车标记。

单独执行 `chassis move` 时，路线复位到 idle、段号为 0；实时诊断改用 state 帧中可选的顶层 `distance` 对象：

```json
{"active":true,"state":"running","reason":"none","action_id":9,"target":[2250,250,90],"error":[0,100,0.1],"feedback_valid":true,"stop_confirmed":false}
```

`distance` 仅在固件处于定距模式时上报，状态支持 idle/running/stopping/done/error；目标、误差、动作编号及有效标志与 route 使用相同单位和校验。路线段号大于 0 时优先显示 route；仅段号为 0 且 distance 有效时，面板显示单段位移诊断，在线地图标出单段目标。缺字段、无效数据、断线或超时均不沿用旧目标，也不拿指令推算结果补齐。单段任务的文字查询使用底盘页“读取任务状态”（`chassis task`），查询回复保留在日志；实时地图仍需手动开启遥测。

这里的到点是编码器反馈估计进入容差，可能受轮滑和标定误差影响；它不表示视觉精对准、扫码成功、抓取完成或比赛整套搬运完成。网页测试使用内存状态，不向硬件发送命令。

完整固件实现、实际软件验证结果和逐步上板操作见[实车前四段反馈路线](../../docs/开发记录/2026-09-12实车前四段反馈路线.md)。硬件方向、反馈单位和航向修正尚需作者架空核对。

## 无线地图遥测发送调整（2026-09-12）

USART1 每次最多发送 32 字节，完成后间隔 30 ms；整个 JSON 发完后才选择下一条回复或事件，避免拼接破坏格式。下一次选择优先命令回复，其次二维码事件，最后地图遥测。关闭遥测会取消尚未发送的状态，正在发送的 JSON 会完整结束。长状态发送期间查询回复会等待，地图显示的是最近一帧快照。参数为 COM23 / DL-20 实测排障后的试调初值，更新固件与网页后仍需验证无线接收。详见 [修改与测试记录](../../docs/开发记录/2026-09-12无线地图遥测限速发送.md)。

## 准备跑图（bridge-1）

入口位于 **底盘页最上方 → 准备跑图**。连接串口后点击一次，全程保持静止。网页依次暂停遥测、读取任务和配置、选择并开启四轮反馈、检查静止反馈、读取 IMU 资格；未取得资格时执行 `imu verify 10`，约 11.5 秒后自动查询结果。已有有效资格则跳过验证。

检查通过后点击 **确认已在起点，继续准备**：仅当车体中心确在右下 `(2250,150)`、车头朝上且静止时确认。程序发送地图原点设置，再开启新的遥测会话并切换到在线反馈来源；收到有效起点反馈后显示“准备完成”。之后仍由用户点击 **开始第 1 段 → 手动下一段**。准备按钮不会启动路线、电机或标定写入。

准备期间其他命令入口被拦截，停止按钮可用并终止准备；取消、断线、超时、设备拒绝均不会继续自动设原点。已发出的 10 秒只读验证可以自行结束。刷新和重连不自动恢复准备。遥测失效或起点状态变化时，旧“准备完成”提示撤销。

应答模式与每圈位置单位从本机已人工保存的“本车配置”应用到 MCU RAM，再查询核对。准备期间，共享服务阻止其他 CMD/网页提交运动；查询和取消、停止保持可用。10 秒仅是短时静止检查，漂移及数据有效性阈值保持不变；原生零偏标定仍为 20 秒获取 + 30 秒验证，`imu verify 120` 长验证保留。

更新后重新启动 `start.cmd`，访问 `http://127.0.0.1:8765/?v=bridge-1#chassis`，并烧录本轮固件。旧固件不支持 token 停车和独立停止查询，不能用旧固件验收 Ctrl+C 停车确认。

本轮详见 [COM23 共用控制台与软件停车记录](../../docs/开发记录/2026-09-12COM23共用控制台与软件停车.md)。

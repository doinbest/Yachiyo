# 雷达通信协议

## PD12 雷达盘舵机

TD-8125MG使用独立`lidarservo`命令，经主车USART1控制台处理，不属于雷达UART数据流；网页入口在“机械臂与夹爪”。PD12 / TIM4_CH1，84 MHz输入时钟、PSC=83、ARR=19999，CCR1数值对应微秒。

| 命令 | 行为 |
|---|---|
| `lidarservo out` | 输出2450 μs，转出至实测扫描位置 |
| `lidarservo in` | 输出1450 μs，收回至实测车内位置 |
| `lidarservo pulse <500..5000>` | 手动设置整数微秒脉宽 |
| `lidarservo status` | 只读已设置的输出状态 |

2450/1450由用户2026-10-12实车确认；固件常量为`LIDAR_SERVO_SCAN_PULSE_US`/`LIDAR_SERVO_STOW_PULSE_US`，位于`Hardware/lidar_servo.h`。后续出发前采图采用转出2450、机构稳定后扫描、采集完成收回1450的顺序；本次没有自动扫描、自动收回或自动出发调用。

成功返回`OK lidarservo enabled=<0|1> pulse_us=<0|500..5000>`，只证明软件已设置输出，不证明机构到位。`enabled=0 pulse_us=0`表示上电后尚未设置脉宽，不是实物失能反馈。原`off`命令/接口已删除，发送返回格式错误并保留当前输出。

非法整数/越界返回`ERR lidarservo range pulse_us=500..5000`，格式错误返回`ERR lidarservo format: out | in | pulse <500..5000> | status`，均保留原输出。PWM未初始化成功返回`ERR lidarservo unavailable`。取放、路线/底盘运动、IMU标定、雷达扫描或待重启时，转出/收回/新脉宽返回`ERR lidarservo task_busy; status allowed`，结束相应任务后显式重试。状态查询在普通忙状态和总线锁定下放行。

`out/in/pulse`均为普通机构运动命令，不占用优先停车队列，也不解除停车锁定。上电输出为零，网页进入、刷新、重连不自动发送脉宽。手动5000上限仍保留，但用户实测超过2800不响应；比赛位置使用已验证的1450/2450。详见[转出与收回操作](../../Code/upper-computer-web/local-car/docs/地图与雷达.md#雷达盘转出与收回)。

网页操作见[地图与雷达](../../Code/upper-computer-web/local-car/docs/地图与雷达.md)，实物条件见[硬件与运行基线](../硬件与运行基线.md)。正式车载地图与 `f1_host` 诊断地图分别维护配置和任务；读图、规划、网页预演均不启动底盘或机械臂。

LDS50C 接 F407 USART2 PA2/PA3，921600/8N1；共享控制台为 USART1 115200/8N1、64 字节 DMA 分块。控制命令是以 CRLF 结束的空格分隔 ASCII。进入页面、刷新、切页、重连和保存本机设置不发送雷达或运动命令。

## 安装、网格与稳定点

正式地图适用性由完整地图与其扫描配置有效性决定；采集时的`origin`保留为快照身份与历史定位版本，不能拿它与当前底盘`localization.generation`比较来判地图失效。地图/路径/稳定点仍按同一采集身份配对。首次设置或重设底盘原点、反馈暂失后恢复不改变已有地图的冻结场地坐标；实际路线启动继续由底盘核验当前原点、位置、速度与反馈新鲜度。采集期间仅定位版本变化不终止扫描，实际底盘运动仍中止静态采集。旧错误码`map_origin_or_parameters_changed`保留兼容，现表示地图缺失、扫描配置已失效或规划未对应当前地图；不能据此要求重新设置底盘原点。

当前默认是情况2：名义雷达 `(2280,314)` mm，零角180°。有效投影使用定点标定，矩阵按行排列，平移保留小数：

```text
M_q16 = [65809,680,-407,66623]
t_q16 = [149407997,20569846]
zero_tenths = 1800
```

情况1使用 `(230,230)`、零角90°、单位矩阵。情况2不是网页坐标旋转后的情况1。正式g4选择右下固定180°，选择右上固定270°；右上独立使用可调 `upper_lidar_x_mm,upper_lidar_y_mm`，2026-10-12用户确认采用 `(2050,2250)`，源码默认与之相符，单位矩阵保持，不镜像情况2矩阵，也不从右下坐标推导右上。该雷达安装坐标与右上车辆名义起点 `(2250,2250)` 分开；车辆起点不随雷达坐标编辑变化。实际用于扫描的有效 Q16 几何写入结果元数据；编辑下方名义坐标保留原点小数，不重复平移，上方直接由独立XY生成Q16平移。网页只把 Q16 除以65536用于显示，不重新标定。

两轴网格边界均为 `[150,550,1000,1400,1850,2250]` mm。新图 `g:4` / `grid_version:4` 使用 `150≤X<2250、150≤Y<2250`，内部边界均归右/上格。物理场地仍为0～2400 mm；外侧150 mm不参与扫描判障。历史 `g:3` 保留旧逆T归格语义（X边界归左，Y归上），`g:2` 保留0～2400网格；客户端按快照版本绘制，不能套用当前默认。

正常单次扫描收集15个有效完整圈再发布。持续建图先填满15圈，随后每提交一个新完整圈，用最近15圈发布新图。坏帧、DMA覆盖、缺角或单位变化只回滚正在采集的不完整圈，已提交的有效圈保留；重采次数是诊断，不按累计次数退出。静态采集仍使用当前固件的10秒完成窗口；持续模式没有此总时长限制。

稳定算法标识 `algorithm:1` 表示容量256候选、10 mm分箱、30 mm邻域、至少3个不同有效圈投票。每个候选每圈最多一票；同圈密集回波不重复增加票数。发布点带确定的毫米 X/Y，格计数按发布稳定点逐个归格，阈值针对稳定点数。原始/筛选/场外点数为 `uint32`，来自整个15圈窗口；不能把最后一圈诊断云当作15圈原始数据重建。候选数、替换和丢弃计数单独报告，容量替换不使结果伪装为完整原始云。

地图/路线重算与重新采集分开：仅修改阈值、手工障碍或路线可从完成稳定点重算；修改安装几何、筛选或网格后，下一结果重新积累15圈。普通停止和取消保留有效配置及上次完整地图；原点或模型变化只影响对应结果的适用性，不删除历史结果。

正式车载工位锚点、station/visit、车辆与IMU方向保留。诊断 `f1_host` 默认任务仍为 `1-5-4-2-3-4-2-3-1`；情况2的任务1为R1C5，首尾为该格中心 `(2050,350)`，其他任务按原F103格中心。情况2任务保护掩码为 `0x00404414`，情况1为 `0x00404405`；固定障碍掩码均为 `0x00050140`。诊断任务与主车ID8或独立F103转盘无执行关系。

| `radar live start upper\|lower` / `radar live preview upper\|lower` | 原120分区持续预览，保留原语义，不建图 |
| `radar live status` / `radar live stop` | 读取/停止持续模式 |
| `radar stop` | 显式停止，保留上次完成地图与发送冻结结果 |
| `radar start status` | 最近起点结果与冲突证据 |
| `radar start upper\|lower` | 选择最近完成自动采集的候选；不重新扫描 |
| `radar get` | 开始读取当前RAM参数 |
| `radar set <key> <value>` | 修改当前RAM参数，不运动 |
| `radar plan` | 从完成地图重新规划 |
| `radar result <plan>` | 冻结并连续发送同身份地图、路径、稳定点和结束标记 |

正常扫描、诊断扫描与持续模式互斥。回复 `OK radar <reason>` / `ERR radar <reason>` 表示受理结果，不表示雷达或车辆已完成动作。右上目前是规划参考，实车导航仍沿现有下方参考执行限制。

正式参数读回21页，前19页保持顺序：`lidar_x_mm,lidar_y_mm,zero_deg,distance_min_mm,distance_max_mm,angle_min_tenths,angle_max_tenths,threshold,energy_min,energy_max,situation,grid_version,zero_tenths,m00_q16,m01_q16,m10_q16,m11_q16,tx_q16,ty_q16`；page19、20追加 `upper_lidar_x_mm,upper_lidar_y_mm`，支持 `radar set <key> <mm>`，范围0～2400，按0.1mm读回。下方坐标仍用原XY键；Q16键以有符号整数传输。旧g3仍读回10页，网页按设备报告的页数收齐。参数只在RAM中，重启恢复源码默认；本机坐标保存不自动写回设备。

### 正式数据帧与冻结

单行 `@RADAR <JSON>\r\n` 连同前缀和CRLF不超过256字节。原公共身份为 `session,origin,scan,map,plan`。新 `g:4` 地图/路径页使用等价紧凑身份 `i:[session,origin,scan,map,plan]`，客户端先归一后校验；旧完整身份字段仍可读取。

`result` 或首次结果页读取冻结地图、有效几何、地图统计、计划和稳定点。后续滚动发布只更新后台最新结果，不改变正在发送的身份或点字节。旧身份在ACK前仍能补页；新的显式result或读取最新编号可建立新冻结结果。map/path只在同身份完整后成对替换，稳定点独立拼齐及核验CRC；晚到预览不能替换地图。停止后可显式读回最后完成结果。

| kind | 内容 |
|---|---|
| `status` | state/reason/elapsed/applicable/points_valid，正常目标可带 `c:[done,15]` |
| `progress` | 紧凑身份i、live_active、mapping、`window:[first,last,count]`、c；区分持续采集进度与上次发布地图 |
| `diag` | 3页：接收字节/包/坏包/覆盖；alarm/last_alarm/unit；tx_done/tx_errors/uart_errors/rx_ready/last_tx |
| `start` | 最近完成scan的id、auto、selected、reason，及qr/raw/conflicts两起点数组 |
| `map` | page0含g/mask/pose/coverage/age_ms/applicable；新图后续包含有效geometry、situation、algorithm、start_id、window、stats、stable、grid；counts页带offset，拼齐恰为25格 |
| `path` | page0含start/valid/failed_leg，points为 `[x_mm,y_mm,station,visit]`；station0为中转点 |
| `stable` | id=冻结scan，offset/total及10字节点的Base64 data，整点流crc32 |
| `result_end` | 冻结公共身份，mp/pp/sp为地图/路线/稳定点实际页数；旧结果sp=0 |
| `points` / `cloud` | 显式原始诊断云，angle/distance/energy；不是稳定点，不代替15圈窗口 |
| `params` | rev/key/value，修订号和所有页必须一致 |
| `nav` | 现有state/reason/index/total/station/visit/stopped |

新map元数据格式：`geometry:[m00_q16,m01_q16,m10_q16,m11_q16,tx_q16,ty_q16,zero_tenths]`，`window:[first,last,count]`，`stats:[raw,filtered,outside]`，`stable:[stable_count,candidate_count,replaced,dropped]`，`grid:[六条X边界,六条Y边界]`。这些值属于已冻结地图，不能用当前草稿或新采集窗口替换。正常稳定结果algorithm=1；诊断单圈为algorithm=0，不广告15圈稳定点。

map/path每页 `crc32` 覆盖去掉末尾crc32字段后的原始JSON ASCII字节，不含 `@RADAR ` 和CRLF，包含身份和分页。浮点字面值可能含 `.0`，不得先JSON.parse再stringify计算CRC。算法为IEEE反射CRC-32（0xEDB88320、初值/末异或0xFFFFFFFF）。坏页只补坏页/缺页，兼容旧无CRC页。稳定点CRC覆盖完整解包点字节流，与map/path单页CRC范围不同。

稳定点每点10字节、小端：`angle_tenths u16, distance_mm u16, x_mm u16, y_mm u16, votes u8, flags u8`；当前flags bit0=确认稳定。分页数量依据实际身份长度计算，允许超过32页，不能使用32位位图截断缺页列表。设备正式result流仍按100 ms非阻塞页节奏发送；停车/普通回复优先，不增加全局串口等待。

## `f1_host` 诊断服务

| 命令 | 行为 |
|---|---|
| `radar host status [fast]` | 状态；fast启用紧凑结果及已有结果同步 |
| `radar host start` | 只请求雷达旋转 |
| `radar host scan 15 [fast]` | 明确正常单次15圈；旧 `scan [fast]` 仍识别且目标15圈；显式替换主机持续模式 |
| `radar host live start [fast]` / `radar host live stop` | 持续最近15圈建图/停止；同时保留120分区预览 |
| `radar host stop` | 停止主机扫描/持续模式，取消后续自动发送 |
| `radar host draft reset` / `radar host set <key> <value>` | 建立/编辑RAM草稿 |
| `radar host apply <revision>` | 原子应用；阈值/路线重算完成稳定结果，证据参数改变则重新积累15圈 |
| `radar host get active\|draft` | 分页读取活动配置/草稿 |
| `radar host result <plan>` | 兼容文本map/path连续回传 |
| `radar host bundle <plan> all\|0,2,4` | 只重传紧凑缺页，不采集、不重算 |
| `radar host fetch <kind>:<id> <page>` | config/map/path/preview/cloud/stable显式读回或补页 |
| `radar host ack <plan>` | 同身份完整结果确认，释放发送冻结结果 |

草稿键保留 `angle_min/angle_max`（0.1°）、`distance_min/distance_max`（mm）、`energy_min/energy_max`、`radar_x/radar_y`、`x1..x4/y1..y4`、`threshold/manual_mask`；新增situation（1或2）、grid_version及上述六个Q16系数、zero_tenths。切换情况更新安装、起点和对应保护格，保留其他筛选、网格和路线草稿。`planning_mode`为mission/point，mission为连字符任务列表，start/goal为 `row,column,cell|radar|goal`。固定掩码和对应情况的保护掩码只读。

活动配置和草稿只在F407 RAM中；保存本机配置只写浏览器本地存储。主机服务只负责旋转、采集、建图与路径显示，不提供车辆执行入口。

### 紧凑布局2

```text
@RADAR {"v":2,"profile":"f1_host","k":"r","i":[session,config,scan,map,plan],"l":0,"p":0,"n":7,"t":488,"d":"...","c":"12345678"}\r\n
@RADAR {"v":2,"profile":"f1_host","k":"e","i":[session,config,scan,map,plan],"l":0,"n":7,"c":"12345678"}\r\n
```

l=0单次、l=1持续。p从0起，n总页数，t完整二进制长度；每页最多72字节，字节偏移为 `72*p`。33路点为488字节/7页，193路点为2088字节/29页。CRC字段c覆盖删除c后的完整原始紧凑JSON。先组装全部字节再解码，map/path同一接收事件发布；稳定XY以独立host_stable分页读取，不混入preview。

| 字节偏移 | 布局2，小端 |
|---|---|
| 0 | layout u8=2 |
| 1/5/9 | raw/filtered/outside u32 |
| 13/17/21 | scanned/manual/effective mask u32 |
| 25/26/27 | path_valid/failed_from/failed_to u8 |
| 28 | waypoint_count u16 |
| 30～79 | 25格稳定点counts，各u16 |
| 80/82/83/84/85/86 | stable_count u16、window_count u8、situation u8、grid_version u8、algorithm u8、candidate_count u16 |
| 88/92 | candidate_replacements/candidate_dropped u32 |
| 96/100 | window_first/window_last u32 |
| 104～119 | M四个s32 Q16，行优先 |
| 120～127 | t两个s32 Q16 |
| 128 | zero_tenths u16 |
| 130～141 / 142～153 | X/Y边界各六个s16 |
| 154/156 | 冻结名义radar_x/radar_y u16 |
| 158起 | 每路点10字节：X/Y/下一段距离各u16，row/column/direction/turn各u8 |

旧layout1 reader保留：74字节头、统计u16、25格counts及原10字节路点。旧layout1常见84字节页，新layout2按72字节页；客户端根据layout和总字节数处理，不能套用新头偏移读取旧结果。

结果冻结至ACK。期间采集继续发布后台最新窗口，补页仍读同一冻结身份，不发送积压中间窗口。客户端缺页用逗号列表批量恢复；结束标记丢失也可根据已有分页信息恢复。有效推进延长等待，不因整个下载耗时超过10秒终止；恢复失败保留上次完整快照。每4次不同结果确认后允许一次完整预览，预览永不代替地图或消除地图传输错误。

### 主机文本页与稳定分页

v1文本页为 `@RADAR {"v":1,"profile":"f1_host",...}`，包含session/config/scan/map/plan、page/pages/offset/total，整行≤256字节。

- host_status：a/l、ss/ls、cloud/preview、reason。无线结果广告绑定冻结结果；当前配置尚未完成时map/plan=0。
- host_config：36条记录。前27条保留source,width,height,x1..x4,y1..y4,radar_x,radar_y,angle_min,angle_max,distance_min,distance_max,energy_min,energy_max,threshold,fixed,manual,protected,planning,mission,start,goal；追加situation,grid_version,zero_tenths,m00_q16,m01_q16,m10_q16,m11_q16,tx_q16,ty_q16。source为active/draft/capture。ACK前 `fetch config:<冻结config> <page>` 返回capture配置及冻结身份；活动草稿不覆盖历史图配置。
- host_map：统计 `s,raw,filtered,outside`（u32），掩码 `m,scanned,manual,effective`，路径结果 `p,valid,failed_from,failed_to`，25条 `c,index,count`；以分号合并完整记录，offset是记录序号，不写死页数。
- host_path：`w,x,y,distance,row,column,direction,turn`；无路点为 `n,valid,failed_from,failed_to`。
- host_result_end：mp/pp为同身份文本地图/路线页数。
- host_stable：scan为稳定结果身份，offset/total，Base64 data为上述10字节点，crc32覆盖完整解包流，允许超过32页。
- host_preview：独立非零live_id，不是scan；4字节点angle_tenths/distance_mm。停止再开始不复用编号。
- host_cloud：5字节点angle_tenths/distance_mm/energy；显式诊断缓存，不是15圈原始数据。

host_map/path页CRC覆盖去掉crc32后的原始JSON；host_stable/preview/cloud CRC覆盖完整解包字节流。预览和稳定点发送前复制到冻结缓存，数据生产继续更新也不改旧页。正式/主机共用唯一256×10字节CPU CCM稳定点发送副本，显式切换采集模式移交所有权；CCM不参与DMA。

## 单圈原始诊断、预览与通信查询

诊断 `raw` 独立id，公共session/origin/scan/map来自该诊断，plan=0。前5页：(0)state/complete/truncated/total/crc32；(1)pose/unit/start/auto/points；(2)filter/point_total；(3)window/circle/cloud_truncated；(4)received/losses/bad/restarts/cloud_valid。之后按offset/total/hex传16KB滚动字节窗口。circle为同一RX游标基准的 `[start,end)`，complete只在有效圈全部受窗口覆盖且无缺段时为true。下载完成与采集完整分开，停止/失败可导出明确标注的部分诊断，不附带旧圈数据。

filter顺序是距离下/上限、原始角下/上限、阈值、能量下/上限。raw CRC为上述IEEE CRC-32，覆盖完整下载窗口；工具 `python Code/tools/radar_capture_unpack.py <诊断JSON>` 可验证并导出原始字节与元数据。旧逐圈evidence只作显式历史诊断，不作为新15圈稳定算法的逐圈完整原始点云。

原持续预览每圈120个3°分区，各保存最近有效回波及真实角度，空区间距离0；覆盖360°，只用于显示。live_state包含s/id/active/state/reason/q/pose/age_ms/points；live包含s/id/q/o/n=120/d，每片24个4字节点，每圈5片。按s/id/q拼装，冻结当前圈发送后取最新完成圈，中间旧圈跳过；这些帧不触发正式地图替换。新稳定地图仍采用自己的有效Q16几何。

`radar probe`仅发送6字节ASCII `LUUIDH`，不配置单位、滤波、转速或波特率，不启动扫描；`radar probe status`只读。查询与扫描共用非阻塞命令队列；查询中扫描返回query_in_progress。USART2发送完成后最多等2秒，身份字符串必须来自本次发送后，且MCU发送完成才为confirmed/sn_reply。回显、旧回复、测量包或报警不能证明往返。支持分包，最多24字符，50 ms文本间隔收束。

probe三页为状态/发送完成、接收统计、sn及前24字节hex；状态包括transmitting/waiting/confirmed/unconfirmed/error/cancelled。未确认原因包括alarm_only/reply_unknown/no_reply；发送异常为tx_busy/tx_error/tx_timeout。报警值保留传感器小端原值；示例 `CE CE CE CE 00 01` 为256（0x0100），不交换字节。累计计数只作诊断，恢复后查看增量和有效测量，不要求累计报警归零。

人工停车响应、真实机械边界和驱动故障处理保留。串口受理或MCU DMA发送完成都不能代替硬件完成确认；用户2026-10-12确认香橙派当前程序无需在STM32烧录后重开，不再将重开程序作为视觉实测前置步骤。本地源码、远端部署及实车验证分别报告。

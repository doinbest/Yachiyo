## Base电流与驱动只读诊断

`bus read <id 1..8> current|voltage|error|home|driver` 单次读取实际驱动数据；Base为ID5。示例：`bus read 5 current` 返回相电流mA；`voltage`返回供电mV；`error`返回有符号位置误差及Emm角度；`home`返回保存的回零模式、方向、RPM、超时及碰撞阈值；`driver`返回闭环电流上限、开环工作电流、输出限制原始值、堵转保护及驱动到位窗口。

这些命令不改参数、不运动、不执行HOME/ZERO，不解除停车锁定。任务空闲后读取，运行中返回tasks_busy；复用单ID只读诊断隔离，停车可中断，完成后释放隔离。当前主车使用Emm驱动布局：误差65536单位/圈，配置回复33字节；X固件布局不在此入口的支持范围。供电/电流为读取当时样本，不是回零过程峰值；普通位置配置`config base`不代表驱动保存的回零速度、电流上限。

读取需烧录含此入口的新固件，网页系统与标定页的“电机只读诊断”可选Base及项目；服务端更新后需重新启动服务并刷新页面。停止锁定期间两端均允许这些查询；完成确认仍以回零专用状态为准。

## 现行静态对准与码垛

短时定位速度资格或三轴反馈缺失/失鲜时，有限目标及实测历史保留但暂停使用；同一定位代次、原点、单位、目标和观察姿态下，反馈恢复且共同时间包围样本齐全后，按实际累计位移续调，不要求先有新图像。不可用期间仍走原宽限减速及停车期限，不扩大600 ms反馈新鲜度、不补算指令位移；定位重建导致代次变化、参考/姿态变化、真实驱动异常、换目标或停止仍撤销目标，停车后不凭旧目标自动续走。有限目标层的保留不取消整个取放任务原有反馈准入：反馈字段必须有效并满足feedback_ms（默认2000 ms）。仅超过有限目标600 ms年龄门槛、但仍满足任务准入时可暂停后续调；字段valid=false或超过任务期限仍沿原feedback_stale停车。定位feedback_valid从有效变无效会递增代次并重建里程基线，旧目标仍撤销；独立速度资格失效不一定改变代次。

静态漏检时，有合格高位视觉/实测时间基线则继续有限剩余调整；否则沿原趋势减速，默认loss_grace_ms=250 ms。接近窗口、重获新误差方向变化或宽限耗尽仍停车，不是单次漏检一律停车。停车期间同请求的有效新帧已经恢复时，撤销待重识别并保留原数据流，避免重复B2/0A清掉视觉跟踪。新鲜性优先用实际接收时刻，恢复仍需停车确认及恢复起点后的3次新观测；旧缓存、错误目标或暂停前报文不能推进。再次持续缺有效数据仍沿原窗口重发，不重置恢复期限。新增vision_gap_expired、vision_pause_near_window、vision_pause_direction_change与vision_stream_retained原因；不改变原控制和停车条件。

### 自动三轴回零与诊断
上电/复位等待1秒后，Z/X碰撞回零与ID8车仓就近回零先并行执行。Z/X的HOME按应答依次发出，不等待Z运动完成才启动X；随后逐轴验证回零结束、稳定位置及正常使能。Z/X均验证成功后先打开夹爪（2450 µs），保留Base启动前原有等待，并等待ID8完成回零建立参考后，才使能并启动Base单圈就近回零（mode=0）。Base承载整套机械臂，最后执行；直接发送0x9A/00使用已保存的单圈机械零点，不执行自动方向参数准备。驱动重置后先在正确车仓姿态设置并保存机械零点；切换回零模式不能替代设零。就近HOME返回0x12表示已在零点，仅接受本条命令结果，随后仍按原HOME退出、新鲜位置与使能/停稳反馈验证；E2/EE仍报错。ID8仍由独立总线所有者推进，全部机构完成后才安排IMU静止5秒验证。`grab rehome`同样先并行Z/X、验证后开爪再启动Base，不重放已完成的上电ID8回零，也不新增其参考依赖；单轴手动命令保留，HOME受理不会自动建立三轴参考。不修改驱动器保存的回零电流、方向、模式或电机ID。

回零中的`grab status`增加`home_started/home_verified`位图，bit0/1/2分别为Z/X/Base；Z/X已验证、ID8仍在回零时为`home_wait_turntable`，此时位图为3/3，Base尚未启动。上电ID8未建立参考报告`home_turntable_failed`，不启动Base。停止先中断已启动但尚未验证完成的回零，再逐轴读取退出状态，同时取消未启动的Base与ID8待办并中断ID8回零；一轴退出未确认不阻止其他轴收到中断。60秒运动窗口从各轴HOME请求受理时计时，Base不消耗前序回零等待时间；停车5秒窗口保留，中断回零标志不等于实车停稳。

每轴先读取回零标志，过温、过流或编码器/校准未就绪则停止；本次 HOME 发送前的 bit3 表示上一次回零失败，允许新 HOME 重试，不把它判成本次失败。HOME 受理后的 bit3 对 X/Z 或严格模式 Base 仍按本次回零失败停止；Base 默认允许下述降级验证。随后发送使能并读取实际电机状态，不能以 ENABLE ACK 代替使能确认。使能状态在 1500 ms 内仍不成立时为 `home_enable_failed`，不开始该轴 HOME。

HOME 完成后仍读取回零状态、位置和电机状态，要求连续两轮使能正常且位置稳定；X/Z 保留 ±182 反馈单位的零点窗口，Base 使用驱动保存的机械原点对应的实际多圈坐标，不清零。若仅使能位短暂为 0，先按 100 ms 查询节奏复查 600 ms（两轮完整的回零/位置/状态查询）；其间使能自行恢复则继续原流程。超过宽限且确认 HOME 成功、位置稳定、无过流/过温/回零失败/堵转保护，输出 `OK grab home_enable_recovery axis=... home_flags=... motor_flags=... raw=...`，仅补发一次 ENABLE，不重发 HOME。补发后 1500 ms 内重新核验两轮位置和使能；持续未使能报告 `home_enable_failed`，位置相对恢复前变化超过本轴稳定窗口（X/Z 为 182 反馈单位，Base 为 5°）报告 `home_position_changed`。驱动真实故障、总线错误和人工停止均不会触发补使能。

除下述 Base 单独回零失败可降级外，这些失败沿现有停止和回零中止流程处理，不建立失败轴参考。排除驱动/通信问题后，可用 `grab rehome` 重新验证；普通人工停止后不会自动续跑。诊断报告增加 `enable_recovery=0/1`，表示本轴是否已提交恢复使能。

回零请求未被总线接收且返回 `HAL_BUSY` 时，固件保持当前轴，按原有 100 ms 轮询节奏重试；已受理的 HOME 不重发，原有每轴 60 s 超时不变。总线因通信错误或超时锁定后，比赛沿既有保留进度的恢复流程处理；非比赛场景由固件停止任务、排空事务后自动恢复通信，恢复内可重试的通信错误间隔2秒重试。人工停止取消待办，同一旧故障不再次触发。自动恢复通信不重启已中断的HOME或宣告参考有效；停止及回零中止的优先发送仍保留。

请求提交硬失败时先输出 `ERR grab home_request axis=... action=... result=... bus_locked=... bus_reason=... uart_error=... fault_ms=...`，随后状态报告 `reason=home_bus_fault`（总线锁定）或 `home_request_failed`（其他提交错误）。驱动回零标志异常仍为 `home_driver_fault`，与提交错误分开。

已受理事务异步失败时，在原有 `ERR grab home ...` 和停车流程前增加以下诊断；不改变原有 `home_feedback_failed`、停车、中止、超时或降级条件：

- `ERR grab home_transaction`：`axis/step/action/result` 是失败发生时的轴、回零步骤和任务命令；`phase` 区分普通事务 `none`、显式手动Base方向回零的 `params_read`（0x22读参数）、`params_write`（0x4C仅RAM写入）、`params_verify`（0x22读回核对）、`trigger`（0x9A发送HOME）。`func` 为本次子命令功能码，`mode` 仅在HOME动作时有意义。
- `sent/ack` 保留原任务命令的发送/应答语义：Base准备参数期间均为0，不能把参数配置应答当成HOME已发送。`wire_sent/reply/bus_result/tx_ms/uart_error` 是当前子事务的实际发送完成、匹配应答、总线结果、发送完成时刻及其错误；无总线事件时 `bus_result=none`，发送时刻仅在 `wire_sent=1` 时有效。这里的 `uart_error` 不是历史首故障，也不包括已成功重启RX的软告警，后者仍看 `WARN bus rx_restarted`。
- `code_valid=1` 才可将 `code` 解释为驱动命令返回码；参数写入的E2/EE不再丢失。读取状态返回的普通标志不是命令码；`code_valid=0` 时不能用 `code=0x00` 推断驱动成功或某个特定故障。
- `ERR grab home_reply axis=... step=... len=... hex=...`：保存本次匹配应答，冒号分隔十六进制；未收到应答为 `len=0 hex=none`。缓存最多18字节（覆盖当前机械臂最长参数应答），`len` 为实际长度；超长时仅输出前18字节，不把零填充当作收到的数据。
- 读回不一致再输出 `ERR grab home_verify axis=... offset=... expected=... actual=...`，`offset` 从参数块首字节0起，报告首个差异。此时没有驱动拒绝码也可能失败，应结合原始18字节与该差异判断。

网页终端为上述三种行提供中文说明，导出的原始协议不变。原有 `home_flags/motor_flags` 仍是最近有效缓存，不代表失败那次事务收到了这些标志，也不能单凭它们锁定本次原因。手动 `home base dir` 的结果事件也携带同一子事务证据；自动流程和 `grab rehome` 输出上述完整诊断。

三轴回零流程已启动、尚未全部验证时，`missing=home_pending` 表示“回零未完成，参考尚未验证”，不能解释为用户漏设 `x_ppm`。X验证成功后恢复命令脉冲尺度约31.746脉冲/mm及回零边界；旧车仓伸出参数恢复将随参数退役删除。三轴完成后才按真实配置输出missing=none或具体缺项；网页中文摘要不参与协议解析。

## 机械臂通信错误

2026-10-03 启动接收修复：UART5 在本次上电首次发送尝试前、没有活动事务时遇到单独的 FE 帧错误，会清理接收残片并重启接收，按现行2 ms应答交接与队列调度继续提交请求。接收重启成功才算恢复；失败锁定并报告 `rx_restart_failed`。运行中的NE/FE/ORE短时接收错误，在未锁定且不处于专用探测/恢复过程时，仅清理接收残片并重启RX DMA，保留当前TX、原应答期限和真实应答校验，不重发HOME或运动。报告WARN bus rx_restarted；应答缺失仍按原超时处理。DMA错误、接收溢出及接收重启失败沿故障路径处理。此行为不重发已发送的电机运动命令，也不修改驱动配置。

`info` 在发生过启动恢复时追加 `[MOTOR BUS STARTUP] recovered_fe=<次数> last_ms=<最近一次故障时刻> rx_restarted=1`，表示历史启动接收恢复记录，不是当前实时健康保证。原 `[MOTOR BUS] locked/reason` 仍表示隔离状态与首次隔离原因。当前 `owner=9` 且 `addr=0 func=0 active=0` 表示没有历史发送事务，9 是 owner 枚举的结束标记；单电机通信测试 owner 为8，ID8转盘实际 owner 为7。旧固件未加入测试前的结束标记为8。

### 当前机械臂方向
`config <axis> <rpm> <acc> <limit_pulses>` 的acc对X/Z允许0..255，对Base及all入口仍为1..255；默认Base20、X/Z0。该配置用于固定X/Z任务、手动位置、Base、视觉连续纠偏及标定。固定X/Z直接发送场景速度与所配置档位；0档直接按目标速度运行，不追加MCU余弦规划。阶段速度由x_speed、x_transfer_speed、z_speed、z_pick_speed等决定；grab accel和grab track accel仍是视觉MCU加速度（mm/s²），与驱动档位独立。

`grab get/set` 的名称、默认值、范围和启动/回零载入时机由 `Code/template/App/grab_parameters.def` 定义，网页数值元数据由 `python Code/tools/sync_grab_parameters.py` 生成。`z_speed` 和 `z_pick_speed` 范围均为大于 0、至 333.333 mm/s，`grab track pick` 显式速度也使用此范围；运动前仍按当前 `z_ppm` 检查 1～3000 RPM。网页默认 Z 下限同步为 −110 mm、Base 偏转范围同步为 ±360°。默认值载入时机、未知场景高度留空及 RAM 保存规则保留。

- X：`pos x` 正值向外，负值向内；正值协议方向 CCW（1）。
- Z：当前安装实测 CCW 向下，已将正值协议方向改为 CW（0），使 `pos z` 正值向上、负值向下。设备是否具备此方向以当前固件和读回为准；`info` 输出 `arm positive_dir base=1 z=0 x=1 (0=CW 1=CCW)` 可核对。
- `home z collision` 的方向独立采用驱动器 `O_Dir`；当前安装要向上回零，应将其设为 CW。STM32 方向宏不修改驱动器已存储的回零参数。
- Z 普通运动上电默认等效于 `config z 2250 0 0`：普通位置默认速度2250 RPM、Emm加速度档位0（直接按目标速度运行）、单次脉冲数无限制（不代表机械行程保护）。控制台临时`config`只在RAM，STM32复位后恢复默认值。固定Z任务同样读取该档位；回零速度仍由驱动器`O_Vel`决定。

现有 `enable/disable/state` 命令不变。单轴错误增加总线隔离状态：

- `ERR motor tx bus_locked=0/1`：请求未能提交到电机发送层。
- `ERR motor communication axis=base bus_locked=0/1`：异步传输失败，没有有效电机返回码。
- `ERR ack_timeout axis=base state_unknown bus_locked=0/1`：未在期限内收到合法应答，不能据此判断电机没有执行命令。

`bus_locked=1` 表示共享 UART5 总线处于故障隔离，后续普通电机请求会被拒绝；不是网页按钮失效，也不是驱动实际复位的证明。参见[UART5 循环 DMA 修复记录](../开发记录/2026-09-12UART5循环DMA与单次失能故障修复.md)。

2026-09-27 起，启动及 `info` 增加 `BUILD motorbus_diag=1 date=... time=...`。上述通信错误后以及 `info` 中输出首次锁定记录：

```text
[MOTOR BUS] locked=1 reason=uart_error fault_ms=12345 owner=2 addr=7 func=0x3A active=0 wait=0 uart_error=0x00000004
```

此行为格式示例，不是实车采样。`fault_ms` 为 MCU 启动后的故障时刻；`owner` 为 0=停车、1=底盘、2=机械臂、3=旧驱动接口、4=四轮反馈、5=尚无事务。`active/wait` 为故障记录时是否存在事务/等待应答；空闲 UART 错误时，`addr/func` 仅标记最后下发的事务，不能据此归责该电机。`drain_timeout` 则标记被取消且尚未收完应答的查询。

| reason | 含义 |
|---|---|
| `none` | 当前没有保留的隔离记录，其他故障字段不用于判断 |
| `uart_error` | UART5 HAL 错误回调；错误码在重新启动接收前保存 |
| `rx_overflow` | UART5 软件接收环形缓冲溢出 |
| `reply_timeout` | 已发送，等待驱动器应答超时 |
| `tx_timeout` | 未在期限内收到发送完成回调 |
| `cancelled_reply` | 取消了等待应答的普通事务，保留迟到应答隔离 |
| `drain_timeout` | 被取消的反馈查询未在期限内收完应答 |

`uart_error` 为位掩码：PE=0x01、NE=0x02、FE=0x04、ORE=0x08、DMA=0x10，可组合。首次记录不会被后续失败覆盖；正常查询不会清除记录或解锁。`info` 只读取 RAM，即使总线锁定也可以查看。详见[首次锁定诊断记录](../开发记录/2026-09-27-UART5首次锁定诊断.md)。

### Base 回零降级继续

`grab get base_home_degrade` 读取策略；`grab set base_home_degrade 1` 为默认比赛模式，`0` 为严格模式。该项为 MCU RAM 配置，普通停止保留，复位恢复源码默认 1。网页“参数调试 → 运动与标定”提供同名参数，显式应用并读回才生效。

仅在本次 Base HOME 已受理、编码器及校准就绪且只有回零失败 bit3 时降级。要求 HOME 已退出、无过温/过流，读取新鲜位置及电机状态，使能正常、无瞬时堵转/堵转保护，再读取实际 0x35 转速。连续两轮位置稳定且实际转速为 0 RPM，才把当前多圈位置作为近似后向车仓参考，继续上电 IMU 验证或手动 Base 回零后的姿态准备。Base 两次位置差窗口为 5°，并不表示距离保存机械零点不超过 5°；X/Z 的窗口仍为 182 反馈单位。降级且短暂失能时，恢复 ENABLE 前也须读取实际零速，之后仍核验新鲜反馈。

输出 `OK grab home_degraded axis=base failed_home_flags=0x0B rear_deg=... reference=approximate motion=quiet`，完成原因为 `home_complete_degraded`；状态字段 `base_home_degraded=1` 持续到该参考失效或正常回零重新建立，后续准备、抓放及普通停止仍可见。`home_verified` 位图表示流程已验证通过，Base 可能为降级参考，必须结合此字段，不等于三轴均精准回零。近似参考的误差会带入 Base 作业 +117.5° 和返回车仓，不写驱动机械零点、不清多圈位置、不改变 ID8 仓位或底盘航向。

严格模式退出或降级验证超时后，如果本次 Base 回零失败且 X/Z 已验证，可在“视觉任务 → 回零与通信恢复”点击“确认 Base 近似参考并继续”，或发送 `grab home accept`。人工需确认当前方向接近车仓；命令仅重新读取 Base 反馈，不重发 HOME/X/Z 动作，仍要求上述停稳与正常驱动状态。接受后不自动恢复此前已取消的姿态准备，需再次点击准备；上电流程会继续安排 IMU 验证。中断可能清除驱动失败位，显式接受仍标记为近似参考，保留原始失败标志。无本次失败记录、X/Z 未验证、机构正忙或总线锁定时拒绝。人工停止取消待办，不迟到续跑。

过温/过流、编码器或校准未就绪、堵转保护、读回失败仍沿原故障停车路径。HOME 持续运行、实际转速非零、位置持续变化不会建立参考；短时波动恢复后继续验证，60 秒原有上限保留。

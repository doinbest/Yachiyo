# 协同对准发散修正 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** 修正当前视觉对准的响应不匹配，并在持续偏离时请求停车；让上位机清楚显示实际模式、控制指令和设备参数。

**Architecture:** 保留现有 B2 接收、加权矩阵求解、X 边界分配及停车证据链。在 GrabTask 的对准阶段增加运动结果检查，重新安排紧凑状态字段；网页复用现有命令与参数读回机制。响应矩阵按同一观察姿态的实际测量修正。

**Tech Stack:** STM32F407VGT6、STM32 HAL、C、Keil MDK、Python 串口桥接、原生 JavaScript 网页、GCC 主机回归。

**Spec:** 本次对话中用户要求“列出完整的修改方案，如果有需要修改 CubeMX 的要求，先提出完整步骤让我修改，你再修改代码”。本文的设计依据和全局约束作为实施基线。

## 设计依据

- 本轮原始 B2 坐标 CY 从 236 降至 14；按准心 (334,338)，DY 从 102 增至 324 px。接收序号持续增加。
- 2026-10-02 17:04 的实际启动命令是 `grab start pick 3`。16:55 另有 `grab start align 3`，也出现偏离，并记录到 `vf=9.876, vl=-17.391`。这些是速度指令，不能当作实际测速。
- 本轮 X 反馈约 -0.009 mm、目标 0 mm。现有求解器已在回缩边界撤除不可行的 X 回缩分量，再由底盘分配纠偏；没有证据要求重写边界求解。
- 当前 J 为 `[2,0,0] / [0,2,2]`，列是前向、左向、X 伸出，行是 DX、DY。2 px/mm 是联调初值。纵向实际响应与模型不一致是重点假设，尚不能直接认定 j11 应反号。
- 之前留档的蓝色收敛趋势主要来自水平修正，纵向误差约 -2～0 px，不覆盖本轮大纵向偏差。早先实测及用户反馈仍保留其原有范围。
- 网页当前 align/pick 命令定义和按钮入口对应正确。需要增强操作辨识，不能将本轮 pick 指令归因于已证实的网页映射错误。
- 完整 `grab status` 已有 X、vf/vl、model；自动报告超过 319 字节时改用紧凑格式，省略这些字段。网页用紧凑快照覆盖完整快照，造成持续诊断缺项。

原始缓存和离线复算分别在 `.embeddedskills/logs/blue-align-diagnosis-20261002-cache.json`、`blue-align-diagnosis-20261002-solver.csv`。CSV 是当前源码默认模型的限幅目标复算，不是本轮实测速度。

## CubeMX 结论

**本方案不需要修改 CubeMX，也不需要重新生成代码。**

`Code/template/template.ioc` 已配置 USB CDC，以及 UART5 的 DMA 收发和中断；主循环已有相机接收处理及 GrabTask 控制。新增判定使用现有主循环、接收序号、HAL 时间和反馈，不增加外设、中断或计时器。

本次不修改 `.ioc`、引脚、时钟、DMA、NVIC、USB 描述符和 CubeMX 生成区。用户暂时无需进行 CubeMX 操作。若后续调查出现确有必要的外设改动，先另列设置步骤、生成范围及 USER CODE 保留检查，交由用户修改后再接续代码。

## Global Constraints

- 本方案按物料和转盘静止的对准场景设计；相机安装、图像朝向、Base 观察方向改变时需要重新核对响应。运动目标持续跟随不在本次范围。
- 保持香橙派实际程序及 B2 协议；本地 `Code/orange_pi/change.py` 不作为实机已更新的依据。B2 不能单独证明目标身份或原图采集时刻。
- 保留准心 (334,338)，除非观察姿态与实际抓取落点测量证明需要调整。不得移动准心来掩盖发散。
- 保留 X 行程 0～100 mm、X 速度上限 5 mm/s、现有 Z 速度及抓放参数；不因本轮 X 在零位而自动改预伸位置。
- `travel_mm=0` 保持现行用户选择；不恢复此前已关闭的行程门槛，不恢复全阶段 timeout 或额外人工确认开关。
- 保留合法漏检停车、250 ms 减速容忍、停稳后 1500 ms 恢复等待和两次恢复上限。新鲜视觉发散使用独立停车原因，不能当作漏检恢复自动续跑。
- 停车请求、发送完成与反馈确认分别报告；缺少反馈时不得宣称停止。
- 默认串口由用户选择，操作前核对实际连接；本方案不自动连接、自动发送预设或选择 COM 号。
- 保留用户已有改动。只更新本方案涉及的控制、网页、测试和现行文档，不清理历史日志，不自动提交整个工作区。

## Review Focus

1. 纵向模型与实际响应相反，但 B2 仍持续 Valid=1 时，应在目标离开画面前请求停车；触发时间仍须实测。
2. 单帧抖动、某一轴暂增但整体误差下降，以及正常控制响应延迟，不应被误判为持续发散。
3. 重复接收序号、无效/过期帧和恢复过程不能积累旧增长证据；同一个快照不能冒充多个样本。
4. X 在两个边界附近时，撤除不可行 X 分量后，底盘仍应按正确模型纠偏；不能误报为机构越界。
5. 网页实际发送 pick、紧凑报告缺字段或参数仅写出时，不能分别显示为 align、当前完整数据或设备已确认。

## Task 2 持续发散时请求停车

**Interfaces:** 消费 `vision_read(now)` 的新鲜有效观察、现有运动受理结果及 `fault(const char *reason)`。沿既有 GRAB_STOPPING 和停稳反馈进入 error，不新增自动重试状态。

拟采用以下联调初值，它们是本方案建议，不是已通过实车验收的参数：

- 误差使用 `E=hypot(DX,DY)`，单位 px；建立本轮对准的最佳误差 `E_best`。
- 在受理非零纠偏运动后，对新的有效 B2 观察进行判断。`E > E_best + max(20 px, 0.25 × E_best)` 视为明显偏离。
- 明显偏离连续保持至少 1000 ms，且期间至少 5 次不同接收序号的有效观察，触发 `alignment_diverging`。
- 单帧增长不触发；回到阈值内清除连续增长证据；进入容差窗口、漏检/过期、停车、重新开始或恢复新一轮对准时清除监测窗口。grace、恢复停车及取放阶段不累计。
- 保留触发时的误差、最佳误差、增长时长及观测数供完整状态查询；与用于下一轮的内部窗口分别处理，避免停车清理抹掉诊断证据。

- [ ] 新增反号模拟响应的失败用例：持续有效视觉下误差扩大，旧代码继续纠偏，新行为应请求停车并保持不抓取。
- [ ] 在接受新观察后、下一次运动下发前接入增长判断；align 和 pick 的共有对准阶段均适用。
- [ ] 触发 `fault("alignment_diverging")` 后不再发送新的对准运动，不自动反转 J，不自动恢复。复用停车反馈判定，触发时保持 `stop_confirmed=0`。
- [ ] 增加正常收敛、短噪声、响应延迟、整体误差下降但单轴暂增、重复序号、漏检恢复及 X 两端边界回归。
- [ ] 验证缺少停车反馈时保持 stopping，取得四轮及机构新鲜停车证据后才报告确认；align 成功进入 hold，pick 成功保持现有取放流程。
- [ ] 核对上述阈值在离线噪声/延迟场景中的表现；需要调整时更新本方案和测试，不将初值写成实测结果。日志式输入仅是离线构造，不伪称为完整相机逐帧采集。

## Task 4 实车核对方向并修正矩阵

**前置条件:** Task 1～3 软件验证和构建通过；另行确认实际下载器和串口，用户明确允许本次烧录及短移。固件受理和反馈确认分别记录，不默认沿用历史连接参数。

- [ ] 固定同一观察姿态：Base 回零观察方向、Z=0、相机安装/图像朝向不变、单个蓝色目标及转盘静止。先静止采样，检查明显坐标簇跳变或漏检；无法确定同一目标时不据此标定。
- [ ] 先查横移这一关键项：用现有限时低速命令执行正、反方向短移，建议起步 5 mm/s、300～500 ms 保持，包含原有起停过渡；每段分别确认停止。该建议仍需按实物可用空间确定，不能用速度×时间冒充实际位移。
- [ ] 同时观察车体物理方向和 CY 响应。如果车体实际运动与命令方向不一致，先处理底盘方向配置；如果物理方向正确，则按测量更新视觉响应，不能用 J 掩盖车轮映射问题。
- [ ] 通过新鲜四轮反馈按现有 Emm 65536 协议单位换算实际前向/左向位移，X 用既有机构位置反馈；比较移动前后多个有效坐标的稳定值，不拿单帧差值作精确标定。
- [ ] 用前后、左右及有空间时的 X 伸出/缩回短移独立计算矩阵列。正反响应重复核对后再采用；X 无法安全进行测量时保持初始项并明确未测，不凭底盘结果翻转 j12。

| 运动列 | 水平响应项 | 垂直响应项 |
|---|---|---|
| 前向 f | `j00=ΔDX/Δf` | `j10=ΔDY/Δf` |
| 左向 l | `j01=ΔDX/Δl` | `j11=ΔDY/Δl` |
| X 伸出 x | `j02=ΔDX/Δx` | `j12=ΔDY/Δx` |

DX=CX−334，DY=338−CY，因此 ΔDY=−ΔCY。单位均为 px/mm。显著交叉响应应写入 j01/j10 等项，不继续强行设零。

- [ ] 先用现有 RAM 设置和读回确认验证可信矩阵；对照低速闭环效果。实测支持的系数再写入 `visual_defaults_restore()` 并同步网页初值。
- [ ] 记录 model=custom 只表示参数被设置，不代表标定通过；未测项仍注明初值。新编译默认在启动及 Base 成功回零后的既有恢复位置载入，不增加 Flash 持久化框架或每次启动的人工确认门槛。

## 执行顺序与回退

顺序为诊断输出 → 发散停车 → 低速与网页入口 → 软件测试/构建 → 用户授权的烧录和短移测量 → RAM 验证模型 → 固化可信系数 → 软件与实车复验。

代码实施前保留当前相关文件和固件产物的可追溯快照，不覆盖现有用户改动。RAM 修改记录每个键的修改前值及读回值；异常时停止后恢复这些值，不自动续跑。固件回退使用留存的带地址 HEX/ELF，在用户明确授权和下载参数确认后进行。方向参数不能在运行中自动试错翻转。

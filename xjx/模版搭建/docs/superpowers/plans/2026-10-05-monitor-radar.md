# 实车监控全场雷达与无运动预览实施计划

> 执行方式：本轮原生执行；按测试、实现、上板验证顺序完成。

**Goal:** 在实车监控中显示全场雷达障碍和同圈规划，并在准备跑图中预览绕障的 C 路线，不驱动电机。

**Architecture:** 正式雷达继续使用 radar_map.c / radar_console.c，网格外边界扩展到 0、2400，内部 550、1000、1400、1850 不变。备用 F1 雷达页使用独立原有网格，不改其协议与功能。监控复用正式扫描与下载流程，本机路线预览使用相同 C 核心。

**Tech Stack:** STM32 HAL C、Keil、原生 JavaScript、Python 本地桥、CMSIS-DAP、COM14 115200/8N1。

**Spec:** 本轮用户确认：全场参与判障、保留已有特殊区域处理、备用页不改、仅预览不实际驱动步进电机。

## 约束与验证重点

- 不改 USART 波特率、无线节奏、备份雷达页及其他控制台业务。
- 保留固定障碍和二维码/原料台的既有豁免，不额外泛化工位保护。
- 场内外边缘、历史结果、地图/路线编号不同步、不可达路线、预览无运动命令均有测试。
- 烧录复位必须阻止启动自动回零，使用调试断点跳过本次启动调用，不改变正常固件启动约定。

## 实施步骤

- [x] 网格测试：正式 0～2400、备用仍 150～2250，运行失败测试后修改 C 默认网格及网页正式网格。
- [x] 监控测试：同圈地图/路线发布，扫描、停止和读回入口，历史状态不伪装实时。
- [x] 实车监控布局：全场网格、固定/扫描障碍、规划/反馈/指令线分色；准备跑图增加本机 C 绕障检查和播放，零运动 TX。
- [x] 运行相关 C、网页和服务回归，Keil 构建。
- [x] DAPLink 验证、阻止本次启动回零、COM14 静止扫描，记录地图/路线/预览结果和实际限制。
- [x] 更新使用说明和开发记录，交付。

实施补充：判障范围扩展，车辆中转通道坐标不变；旧历史按原网格显示。实测两圈均有17个规划坐标点，其中一圈暂存转向300×300外框触及R2C1，界面如实区分格路可达与净空失败；本轮不实施实际运动。页面扫描实测还发现多个控制台重叠读页，已验证page_pending后匹配页继续完成，不增加固定等待。

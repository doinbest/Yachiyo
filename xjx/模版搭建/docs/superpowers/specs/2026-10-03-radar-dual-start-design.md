# LDS50C 双起点识别：需求整理与设计依据

日期：2026-10-03。状态：分析与设计，尚未实施。

## 1. 要解决的问题

车辆可能从场地右上方或右下方出发。用户确认两个起点都以车头朝二维码台的方向直行，二维码装置为竖立二维码板及底座。希望利用 LDS50C 看到的物料台、二维码装置几何轮廓判断起点，再使用正确的地图坐标运行既有路线。

本次功能是“静止扫描识别起点，并建立相应地图参考”，同时解决双起点的路线入口和返航。它不承担二维码内容识别，也不扩展为完整两批物料赛事调度。

## 2. 源码核查结论

### F1 参考工程

`Code/reference/Radar_2026-10-01/Radar/` 没有实现双起点识别。

| 文件 | 现有实现 | 对移植的意义 |
|---|---|---|
| `Core/Inc/navigation_config.h` | 雷达位置固定为 `(230,230)` | 初始位置由配置给定，不由雷达识别 |
| `Core/Src/nav_math.c` | 极坐标直接叠加上述固定位置 | 没有搜索车辆起点或初始姿态 |
| `Core/Src/navigation_config.c` | 网格、工位和访问顺序为固定常量 | 可参考任务序列，不能直接解决两个起点 |
| `Core/Src/path_planner.c` | 路线起终点使用固定雷达位置 | 需要另行支持所选车辆起点 |
| `Core/Src/scan_mapper.c` | 扫描点累计为网格占用 | 未提取圆盘、板面或底座特征 |

`Code/reference/2026-09-26/` 中的 `Lds50cHost` 是 C# 上位机参考，不是另一套 F1 固件；核查到的代码也没有自动双起点分类。现有移植分析记录中的历史状态不能代替当前 F4 源码。

### 当前 F4

当前 F4 已具备 USART2 DMA 接收、完整一圈极坐标缓存、5×5 占用图、C 路径规划及网页分页显示；没有双起点识别。

| 文件 | 当前限制 | 本功能需要改变的范围 |

| `App/radar_scan.c` | 采集一圈时直接用给定雷达世界坐标投影并发布地图 | 新增仅采集局部点云的识别入口；确定起点后重投影同一圈 |

当前扫码 `(2100,1200)`、原料 `(1200,2100)` 等坐标是车辆停靠目标，不能作为二维码板、物料台的实物中心。建图只累计 `[150,2250)` 活动区点，但完整极坐标缓存保留区外点；特征识别必须读取完整点云。

## 3. 资料事实与尚需实测的信息

### 赛事资料

依据项目内《附件2-1-第九届中国大学生工创大赛智能+工程创新赛道命题与运行》，印刷第3页图1、第4页表2/图2、第6页任务编码：

- 场地为 `2400×2400 mm`，右侧有两个 `300×300 mm` 启停区。
- 图中启停区1位于右上，启停区2位于右下。
- 原料台顶面直径 `300 mm`、总高度 `80～100 mm`；底部支撑与顶面轮廓不同。
- 原料台与二维码板在规定范围内随机摆放。图中原料区横向和二维码纵向有 `1100～1300 mm` 标注，不能固定到单个中心坐标。
- 二维码板为 A4 横放、垂直安装；二维码位于板中间，尺寸 `80×80 mm`。底座尺寸与离地高度没有在这些页中完整给出。
- 随机黑色障碍柱为 `φ50×100 mm`。
- 场地底色、车道和蓝色起点是平面图案，不能当作雷达可探测的墙壁。

沿用当前“左下原点、X向右、Y向上、yaw从+X逆时针”的地图，两个区域的名义中心如下：

| 起点 | 名义车辆中心 | 朝二维码台的名义航向 |
|---|---|---|
| 启停区1 / 右上 | `(2250,2250) mm` | 沿右侧车道向下，约 `270°` |
| 启停区2 / 右下 | `(2250,150) mm` | 沿右侧车道向上，约 `90°` |

表中的角度是根据场地图和“向二维码台直行”建立的名义姿态，不代表车辆实际摆放角度恰好相同。若实际车头直接指向板中心而不平行车道，使用标定后的出发航向。起点区域中心也不是已完成的车辆中心测量。

### 用户提供的 LDS50C 说明书

依据《LDS_50C_2__3 360度TOF激光扫描测距雷达使用说明书》，印刷第4页图4-2/图4-3、第5页表5-1、第7页坐标系定义：

- 雷达角零线位于设备正前方，角度顺时针增加。沿用当前 `世界角=雷达零线世界角-扫描角` 的转换。
- 距离分辨率 `10 mm`；表列测距精度为 `±30 mm`，附带20 m以内、10%～70%反射条件和90%可信度说明。不得把协议的 mm 单位当作1 mm精度。
- 激光垂直角偏差范围 `±0.3°`。扫描距离越远，扫描高度也可能相对近处变化；还需考虑装车倾斜。
- 说明书给出的外形高度 `51 mm` 和光学窗口尺寸属于设备结构，不是装车后的离地扫描高度。
- 说明书支持当前使用的 `921600` 波特率；本功能不改变 USART2、DMA、引脚和通信配置。

说明书原文件位于用户本次附件路径，公开副本省略个人微信附件的绝对路径。

实施前的实物资料项是扫描平面离地高度、雷达安装偏移/朝向，以及该高度下物料台和二维码装置的实际可见轮廓。用户已经确认的车头方向和二维码装置形式不再重复确认。这些缺项不阻碍软件方案设计，但决定特征模板和实物验收结果。

## 4. 采用的方案

### 局部点云先识别，确定起点后建图

数据链为：

`静止完整圈 → 局部点云分组 → 物料台/二维码装置特征 → 两起点布局匹配 → 起点结果 → 注册车辆参考 → 同圈投影建图 → 按所选起点规划 → 显式启动路线`。

1. 复用现有单个 `4096` 点缓存。识别前不依赖车辆已经选择了哪个起点，不先生成一张按下方起点投影的新图。
2. 在雷达局部坐标中按相邻角度、距离间断分组，处理 `0°/360°` 接缝；排除无效距离，使用完整角范围和实际可见区，避免建图角度筛选误剪掉识别目标。
3. 物料台以实测轮廓为模型：扫到圆盘边缘时拟合局部圆弧；扫到底部支撑时使用支撑轮廓。部分圆弧的点均值不能直接当圆心。板面可见时提取线段，底座可见时使用底座模板。尺寸匹配采用含测距误差的范围，不要求精确300 mm。
4. 将候选特征分别放入右上和右下起点假设，检查形状、相对方位、距离及允许摆放区域。以物料台为主要区分证据，二维码装置作交叉验证；对遮挡证据降低权重，不因少一个板面就必然失败。QR距离在两个起点可能相近，禁止只用其距离分类。
5. 输出起点、实际参与匹配的目标、两个假设得分/差值和结果原因。不把分数包装为未经标定的正确率百分比。几何证据无法区分时返回“待判定”，继续当前扫描窗口内的采集；不随机选择起点。

识别是两个离散起点的分类。可移动的物料台和二维码装置不能单独证明车辆的精确绝对位姿。第一版按经标定的起点摆放姿态建立参考，并标明“起点名义参考”；不把分类结果描述为毫米级雷达定位。精确初始位姿修正需要实测固定参照或经过验证的额外几何约束。

### 车体安装参数与参考连续性

新增安装参数：`lidar_forward_mm`、`lidar_left_mm`、`lidar_yaw_offset_deg`。雷达世界位置由车辆中心和航向计算：

`P_lidar = P_car + R(yaw_car) × [forward,left]`，`zero_deg = yaw_car + yaw_offset`。

当前预设雷达 `(2170,230,180°)` 相对于下方车辆 `(2250,150,90°)`，数学上可换算为前向 `80 mm`、左向 `80 mm`、角偏移 `90°`。它们只是现有预设的等价表达，不能作为实测安装值。原 `lidar_x_mm/lidar_y_mm/zero_deg` 继续作为既有手动扫描的世界坐标参数；自动模式分别展示安装参数和本次算出的只读世界坐标。

成功识别后复用 `ChassisLocalization_Origin` 和现有 IMU 航向锚点，不修改 IMU/轮向，不重新触发一轮归零或静止验证。原点成功注册后等待现有反馈更新，再允许路线执行。若航向暂不可用，保留识别结果并等待现有数据恢复；原有验证明确失败时显示其原因，不自动重试标定。

旧完整地图在扫描失败、停止、暂未识别时保留为历史。成功注册的新原点、新地图和新计划使用一致的 generation/scan/map 标识；不能在原点注册失败后发布看似适用的新地图。当前 `ChassisMotion_AnchorSet` 在读取航向前作废旧锚点，实施时需要调整该调用顺序，避免一次失败的注册破坏原有效参考。

### 路线与工位

雷达规划路线的首点和末点使用选定起点，执行门槛检查该起点及其参考代次。该路线默认保持所选出发航向平移，不因为 A* 路径转角而自动旋转车头；麦轮平移与车头方向分开。原16段固定路线保留当前下方起点和90°行为。

扫码、原料工位交接继续按 `station/visit`；工位编号1仍表示起点，与“启停区1/2”的分类编号分开。上方出发的二维码读取方向和原料观察姿态需要实物验证。第一版不把探测到的盘心/板心直接填为车辆停靠点；若后续需要随随机位置调整停靠，另用已标定的停车偏移推导。

### 控制台

地图雷达区域新增“扫描并识别起点”按钮、起点结果和目标轮廓图层。结果显示“启停区1 / 启停区2 / 待判定”及当前/历史来源；详细得分保留诊断区。识别在F4本机完成，网页优先读取少量结果和特征，不等待低带宽无线链路传完整4096点。参数调试“雷达与路线”增加安装关系、两起点名义姿态及可见轮廓标定分组，沿用现有一键读回与写后比较。

导航、读参数、切换页面均不触发扫描或运动。识别入口只扫描与建立参考，路线执行仍由现有显式开始按钮触发。网页离线回放调用同一 C 识别和规划核心，不新增 JS 判定算法。

## 5. 边界与验收原则

- 只规划修改 F4 与本地控制台；不修改香橙派程序、B2 协议或二维码读取硬件协议。
- 保留官方 Emm_V5、W25Q128 驱动及诊断；不改 IOC、引脚、时钟、EIDE 配置，不运行 EIDE。
- 参数仍仅作用于 STM32 RAM；不增加 Flash 保存、启动加载或浏览器自动写参数。
- 短暂坏帧、单位变化和 DMA 覆盖只重采当前未完整圈，沿用10秒扫描窗口；不增加固定恢复次数耗尽规则。
- 在同一扫描窗口内追加完整圈，只累计小型特征证据，不复制完整点云；保存结果后旧点云仍按现有单缓存语义更新。
- 停止及时取消剩余采集/识别，不清已有效参数、其他业务参考或旧完整地图。结果待判定不触发电机搜索运动。
- 不烧录、不复位、不向实车发指令。软件验证与后续双起点实物验收分别记录。

完整修改步骤见[实施计划](../plans/2026-10-03-radar-dual-start-localization.md)。

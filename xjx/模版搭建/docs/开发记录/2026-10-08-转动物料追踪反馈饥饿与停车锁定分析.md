# 转动物料追踪：反馈饥饿与停车锁定分析

状态：完成串口复测与代码复现；生产代码未修改、未重新烧录。用户要求本轮分析，为后续修改提供依据。

后续状态：用户已授权修复；实现及验证见[动态追踪公平查询与停车回读修复](2026-10-08-动态追踪公平查询与停车回读修复.md)。以下保留分析阶段事实。

## 实机结果

用户确认物料台正在转动。本轮通过本地控制台共享 COM38 / 115200 链路操作，未修改物料台 F103 程序或转速。项目当前 F103 入口为 `Turntable_DirectInit/Process`，按键启动分度、停留后循环；源码名义速度不能代替当前实物转速测量。

第一次 `grab track start 3` 返回 `bus_unavailable`。DAP 不暂停、不复位 CPU 的只读快照确认：底盘 `BusStatus.stage=STOPPED`、`error=CANCELLED`、`locked=1`，已发送四轮速度为零，机械臂空闲。共享 MotorBus 的锁定值却为零。也就是说，故障停车后的底盘锁与共享总线锁是两个独立状态；只看 `bus status locked=0` 不足以说明追踪入口可启动。执行现有 `bus recover` 后收到 `arm_ready=1 chassis_ready=1 wheels_stopped=1`，未重建料台参考或充值预算。

恢复后启动确实受理，蓝色目标重现时能输出运动并持续接收坐标。两次实测先后触发 `feedback_stale`，其中后一段产生 132 个有效视觉样本、275 次控制更新，实际批次中位数 22 ms、p95 25 ms、最大 43 ms。控制求解最大 2 ms；这次失败不能归因于控制求解卡住或完全收不到目标。

故障后的停车还出现 `stop_unconfirmed`；共享总线锁定后机械轴反馈不再更新。最后执行 `stop all` 和 `bus recover`，收到完整 `arm_ready=1 chassis_ready=1 wheels_stopped=1`，没有恢复运动。GrabTask 保留上一段 `error/stop_unconfirmed` 历史结果，不能把这个旧结果当作恢复检查失败。

## 已复现的代码缺陷

`GrabTask.c:track_io` 的顺序为：X 到期位置读取 → X 最新运动/停保持 → X 位置读取 → 低频 X 状态及 Z/Base 状态/位置读取。前面的每个成功分支均直接返回。

当目标每 20 ms 更新、X 请求经排队后约 20～25 ms 才完成时，返回处理点总有更新后的 X 目标，或到期的 X 位置读取。慢项始终没有机会，虽然 X 的数据非常新，其他必要反馈却持续变旧。`track_feedback` 又要求三轴位置/状态全部在 `feedback_ms` 内（默认 2000 ms），并检查四轮位置年龄不超过 600 ms及速度/状态年龄不超过 `feedback_ms`。任一项失败都直接报同一 `feedback_stale`。

本轮独立主机探针直接调用生产 `track_io`，每 20 ms 改变控制序号、X 目标与速度，在 5 秒窗口模拟完成事务：

| 模拟事务完成时间 | X 最大位置年龄 | 慢项最大年龄 | 慢项回复数 |
| --- | --- | --- | --- |
| 15 ms | 75 ms | 739 ms | 36 |
| 20 ms | 80 ms | 5000 ms | 0 |
| 25 ms | 75 ms | 5000 ms | 0 |
| 80 ms | 160 ms | 5000 ms | 0 |

这是确定存在且可以重复的查询饥饿缺陷。上一轮慢项回归采用固定 X 输出，没有持续增加控制序号/改变目标，因此能通过，未覆盖真实动态追踪的竞争条件。表中的完成时间包含模拟排队/事务周期，不是声称驱动 ACK 本身耗时 20 ms；实机驱动 ACK 多为 0～2 ms，队列等待最高约 23 ms。

## 证据边界

控制台 `feedback_age` 仅表示 X 位置年龄，不能代表 Z/Base、X 状态或四轮的年龄。日志中 X 年龄 7～37 ms 与 `feedback_stale` 并不矛盾。

DAP 的有效快照看到仅观察/视觉暂停时慢项能正常刷新、短时运动后慢项年龄上升，但覆盖故障时刻的采样因 CMSIS-DAP USB 命令不匹配、读内存失败而提前结束。未取得触发瞬间的完整三轴/四轮年龄，因此暂不指定实机最后是哪一项先超时；不能把主机模拟当作这个具体电机的实机证明。

## 后续修改方向

1. 修正共用追踪 IO 调度，让 X 最新目标/位置更新与慢项查询有明确的轮转机会；保留最新目标覆盖语义及四轮原子批次，不用无限排队或放宽超时掩盖饥饿。
2. 故障触发时保存具体电机、反馈类型与年龄，区分主动未查询、驱动未回复和一次短暂延迟；之后的停车回复不覆盖故障证据。
3. 同步核查故障停车中取消在途运动后的隔离/只读反馈通路，以及底盘锁和共享总线锁的显示与恢复关系。保留人工停车与实际故障处理，不直接取消应答模式或全部保护。
4. 加入持续改变目标、包含排队时间的回归；同时验证静止、视觉丢失后恢复、正常停止及故障恢复后重新启动。P001（手动 Base 转动使参考/矩阵失效）仍暂缓。

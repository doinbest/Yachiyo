# 蓝色协同对准模拟与停止修正

## 目标与范围

用户要求修改此前测试暴露的问题，并模拟执行仅视觉协同对准指令，发现类似软件问题后继续修复。保留全部已有工作区改动；本轮修改源码、测试、网页标签及现行文档，未访问硬件、发送设备指令、烧录或复位。

## 已复现并修复的问题

1. **重复停止使停稳证据不断重置。** 旧 `GrabTask_Stop()` 每次进入都重新执行 `stop_begin()`，清空停止发送标志、四轮/机械轴静止累计。主机回归先复现：每50 ms重复一次停止，100次处理仍无法达到idle/stop_confirmed。修正为停止已进行时保留进度；故障停车转人工取消仍更新原因，首次停止及必要反馈要求保持。新回归确认重复停止可完成且不新增运动请求。
2. **周期精简状态漏报目标颜色。** 完整状态超过319字节时改用精简行，原格式没有color。现在精简行也保留color=3，可与完整状态及相机请求核对。
3. **启动缺少明确的简短受理回报。** `grab start align` 受理后先报告 `OK grab start align accepted color=3 protocol=B2`，再输出阶段状态。accepted仍不是到位或停稳确认。
4. **运行固件难以在运动前核对。** `info` 增加 `GRAB protocol=B2 align_color=3 pick_color=1`，与实际识别请求共享颜色定义；不依赖可能未重新编译的旧对象文件日期。网页快照将3显示为“蓝色 · 3”。

## 指令模拟

新增 `tests/grab_command_sim_test.c`，调用生产 `GrabTask_Command`、生产状态机和生产 `console_tx.c` 分块发送队列。复用已有测试的时钟/机械端点，构建虚拟像素响应模型；串口字节解析由已有 `arm_console_host_test` / `console_rx_test` 回归覆盖。这里没有运行真实电机、摄像头或无线模块。

| 场景 | 结果 |
|---|---|
| 蓝色目标初始误差40/30像素 | 在合成J=[1,0,0;0,1,1]、2像素整数容差条件下，12.4秒进入settle，13秒进入hold；连续模型误差约2.48/2.07，整数报告2/2；全过程无夹取、无Base转向，随后取消并确认停止 |
| 发送接口连续4秒返回HAL_BUSY，随后重复停止 | 停止确认不依赖控制台回包送达；恢复发送后可排空状态队列，无回复丢失；不重新发运动 |
| 蓝色目标短暂漏检 | 先停稳，恢复3次新有效坐标后继续一次对准；仍只发过一次识别请求；人工停止成功 |
| 启动/停止指令延迟48秒后同批处理 | 状态机处理两条指令后，在产生目标运动之前取消；底盘速度、轴位置、相机启动、夹取请求均为0 |

此外，既有状态机回归继续覆盖错误颜色拒绝、蓝色/红色模式切换、失效坐标、USB断开、反馈过期、行程超限、恢复次数和静止门槛。所列13秒是特定合成模型的模拟时间，不能作为实车预计耗时或标定结论。

# 控制台全页审查与冗余分析（2026-10-14）

## 范围与结论

用户要求审查当前控制台：比赛任务主体已较清晰，重点检查下方冗余，并覆盖其他页面。本轮仅分析，未执行界面重构或固件修改。

审查基于当前工作区源码及已有未提交差异，在本地服务中查看了七个主页面、六个视觉子页和三个地图子页。浏览器查看视口为1280×720。已有共享串口处于连接状态，本轮只切换页面和滚动，没有点击设备查询、运动、停车、标定、参数应用、连接或断开按钮。离线检查使用虚拟节点及模拟发送函数。

总体问题是：正式比赛、单项测试、手动控制和诊断的展示层级没有统一；部分共享区无条件出现在不需要它的页面；较早的说明与新流程并存。比赛页主体可保留，先修正操作含义和参数一致性，再整理重复显示。

## 按影响排序的发现

### R01 / P1：雷达安装方向换算仍以右下车头90°为基准

- 位置：`Code/upper-computer-web/local-car/radar-installation.mjs:76`，`parameter-page.mjs:86`及`:92`。
- 参数页显示“右下名义车头为地图90°”，`radarZeroFromRelative()`使用`90 + angle`，读回反解使用`zero - 90`。该结果会填写可应用的`zero_deg`草稿，并沿参数页写入设备RAM。
- 当前确认基线为右下车头180°、雷达0°向左180°；右上雷达0°向下270°。选择“车头0°”却生成90°，读回180°则解释为“车左+90°”，相差90°。这会误导安装方向设置，不能只当作说明文字问题。
- 离线实测：`radarZeroFromRelative(0) === 90`；`radarInstallationFromZero(180)`返回`left / +90°`。
- 建议：普通参数入口沿已确认的右下/右上固定方向展示，任意安装方向放在明确的独立诊断层；如保留相对车头换算，统一采用所选起点的当前航向基准。保留历史F1参考坐标转换，不把历史转换和当前车辆航向混用。

### R02 / P2：比赛页“停止并退出”实际为暂停语义

- 位置：`app.mjs:353`，`mission-panel.mjs:53`；固件对应`GrabRoute.c:78`及`:264`。
- 所有视觉子页共享顶部“读取抓取任务状态 / 停止并退出”，第二个按钮发送`grab stop`。正式比赛中该命令经`GrabRoute_Stop()`进入保留进度的`ContestMission_Stop()`；真正终止本轮的是`grab mission stop`，调用`ContestMission_Cancel()`。
- 比赛页同时出现“停止并退出”“暂停比赛”“停止比赛”，前两者却都保留比赛进度，容易让操作者误以为已经结束本轮。
- 建议：比赛页使用已有的比赛控制栏，隐藏通用测试工具栏；单项页面按各自含义保留停止入口。底部人工停车响应继续保留，并明确作用范围。

### R03 / P2：机械臂页的车载放料回复被归入视觉页

- 位置：`app.mjs:181`、`:418`，`protocol.mjs:196`。
- 机械臂页提供`grab place car`、`grab pose rear`及`grab stop`；`moduleForWire()`将这些命令及对应`OK/ERR grab`回复归入`vision`。通用“当前模块反馈”读取`status.get(active)`，机械臂页的`active`为`arm`。
- 因而机械臂页发起这些操作后，本页反馈卡可能仍显示上一条机械臂反馈或“尚无本模块回复”；实际抓取状态被送到另一个页面，用户需要看终端或切页才能知道结果。
- 离线核对：`grab place car`、`OK grab place car accepted`和`ERR grab place car rejected`均归属`vision`。
- 建议：跨页入口就地显示它实际所属任务的反馈，或将该自动放料入口集中到物料取放页并保留清晰跳转。协议模块归属可保留，不能只为显示而改通信语义。

### R04 / P2：比赛路线速度脱离共用本机设置

- 位置：`app.mjs:453`，`mission-panel.mjs:39`。
- 共用速度绑定仍查找旧的`grab-mission-speed`，新比赛页创建的路线速度输入没有这个ID，且直接预填200。参数页“下次路线启动速度”、地图实车启动速度等会同步，比赛页不在其中。
- 离线实测：共用设置350，再更新420，比赛输入始终200。用户从参数页调整“下次路线启动速度”后开始比赛，实际比赛命令仍可能使用200。
- 建议：如果继续以“共用下次路线速度”提供设置，应接入现有绑定和保存；若比赛速度有意独立，则明确标注并独立保存。两种设计均只影响下一次明确开始，不改变在途比赛的采用值。

### R05 / P2：比赛读回状态没有更新时间

- 位置：`mission-panel.mjs:83`及`:85`。
- `live`只在接收和连接变化时更新；“设备最近读回”没有时间戳或年龄。连接仍在但长时间没有比赛回复时，旧的阶段、停车原因及可继续状态仍按最近读回显示。
- 离线实测：模拟接收`paused`，时间推进一小时并刷新控制，仍显示“设备最近读回”。通用抓取区另按5秒区分历史，两个区域的展示依据不同。
- 建议：显示最后报告时间或“多久前更新”，保留历史进度；缺新回复时给出读取状态入口，不据此清空任务、参数或库存，也不新增无依据的自动终止。

### R06 / P2：多处现行文字仍描述旧实物条件

- `parameter-page.mjs:8`：仍写“二、三仓待标定”，与已确认的0°/+90°/+180°及默认值同步事实不符。应区分已确认几何和设备RAM未读回。
- `app.mjs:391`：机械臂页仍写“Base通常用就近回零”，当前自动回零及快捷方向规则为负相对方向的单圈方向回零。显式就近测试可以保留，默认操作指引应采用当前方案。
- `app.mjs:418`：按钮“转向、伸出并放料”，同一表单说明及当前规则却要求X保持收回。应改为实际动作名称。
- `protocol.mjs:102`：`grab rehome`说明仍写“并行启动Z/X/Base”，与X/Z完成验证、开爪后启动Base的现行初始化顺序不符。
- `parameter-page.mjs:8`：Z场景说明仍写“车载退出再分度”，未反映已实现的外侧姿态下提前ID8分度，建议保留核心坐标定义，把详细动作时序放到对应操作说明。

### R07 / P3：比赛页下方重复了比赛与抓取状态

- 位置：`app.mjs:355`、`:375`，`mission-panel.mjs:60`。
- 比赛页本身已有本轮实际码/采用码、批次、件、仓位、目标环和原因；通用抓取区又重复`grabRouteSnapshot`的比赛标题、计数、任务码及路线原因，再显示抓取子任务信息。
- 子任务的X/Z/Base位置、DX/DY及缺项对排查有用，重复比赛摘要则增加滚动和阅读成本。
- 建议：比赛页常显一份比赛进度，将子任务细节合入“本件动作详情”折叠；回零和深入诊断通过系统页或折叠入口访问。普通单项测试继续保留自己的状态反馈。

### R08 / P3：普通任务页常驻终端与操作区同宽

- 位置：`styles.css:43`、`:54`、`:62`。
- 1280×720实看时终端宽约494像素，任务工作区宽约493像素；比赛页首屏只看到部分设置，开始按钮和进度在下方。系统页首屏几乎被视觉标定占满，启动状态和恢复需要滚动。
- 地图已有底部日志折叠，参数页已有全宽布局，是可复用的现有做法。
- 建议：任务操作默认占主要宽度，终端默认作为可展开的底部区域或侧栏；保留最近命令、关键错误与完整日志导出。展开日志由用户选择，不改变记录和收发行为。

### R09 / P3：物料取放页合并后仍有三个相同查询入口

- 位置：`app.mjs:275`、`:353`，`grab-track.mjs:156`、`:198`、`:277`。
- 顶部、原料追踪区、车仓取出区各有`grab status`按钮；显示则分为追踪状态、取出提示和页底通用反馈。同一个状态查询出现三次，操作后还可能要滚到另一个区域看结果。
- 原料区常显夹取条件、入仓距离、追踪方式、读写参数、导出本段和六行诊断；已有“追踪记录与诊断”折叠，但“导出本段”仍在主操作排。
- 建议：每个当前操作区就近展示主要状态，将共用查询集中一处；颜色、仓位、开始、继续和停止优先展示，细调条件及记录操作放入已有折叠。保留固定夹取、静态夹取和只追踪测试，不按按钮数量简单删功能。

### R10 / P3：部分子页仍继承无关的共享恢复与查询区

- 位置：`app.mjs:353`、`:355`、`:488`，`stack-panel.mjs:67`。
- “仅识别”已隐藏抓取状态，却仍显示`grab status`、`grab stop`及“回零与通信恢复”；本页真正的停止入口是`camera stop`。
- 码垛页顶部和末尾各有一个同名`grab stop`。编号环主流程已覆盖高位/下降选择，A/B通信对照属于专用复现工具，当前已折叠，不需要因命令相近删除。
- 建议：共享工具栏按当前子页匹配；只识别页面集中相机状态和停止，码垛保留一处明确测试停止。不同用途的测试以名称和层级区分。

# 底盘同步与二维地图对齐 — 2026-09-12

按作者批准的 A–E 计划实现首版独立底盘软件。依据为《底盘参数与二维地图控制设计基线》、本地 Emm 协议资料、当前 HAL 工程及已移入的 GongXun2025 参考源码。保留 USB B2、视觉动作策略和主循环结构；未连接电机、烧录或更改驱动器持久参数。

## 1. 数据如何流动

```text
chassis run / heading（有限时长）
    → chassis_motion：20 ms、半余弦、航向资格/锚点
    → mecanum_chassis：冻结四轮、100 ms、snF=1 × 4 + 同步广播
    → motor_bus：唯一 UART5 DMA 收发、10 ms 间隔、所属模块事件
    → 原始速度/位置缓存 → chassis_observer：低速估计
    → chassis_telemetry + console_tx：显式开启的 5 Hz USART1 JSON
    → local-car/#map：离线模拟 / 指令推算 / 反馈估计
```

| 文件 | 本次职责 |
| --- | --- |
| `template/App/chassis_config.h` | 210 mm 轴距、240 mm 轮距、暂定 80 mm 轮径、暂定 1:1；版本 `geom-20260912-v1` |
| `chassis_model.c/h` | 前向/左向/逆时针，FL/RL/RR/FR，统一限幅、整数量化、地图转换及中点积分 |
| `chassis_motion.c/h` | 有限任务、起停过渡、原 PID 航向模式、互斥、异常停车 |
| `template/Hardware/motor_bus.c/h` | DMA 持久缓冲、流式收帧、单待应答事务、总线预约、优先停车 |
| `mecanum_chassis.c/h` | 同步速度/旧位置/单轮入口统一收发，反馈缓存与异步状态 |
| `mechanical_arm.c/h`、`Emm_V5.c/h` | 保留动作与封装，改为事件按所属模块分发；无 UART5 旁路发送 |
| `chassis_observer.c/h` | 实际下发目标的指令推算、两组位置增量与 HWT101 航向估计 |
| `chassis_telemetry.c/h`、`console_tx.c/h` | 新命令、版本化 JSON、回复优先/旧遥测丢弃、非阻塞 USART1 TX |
| `upper-computer-web/local-car/` | 原控制台内新增地图，同一串口连接和日志，无地图实车运动按钮 |

Keil/EIDE 仅登记新增源文件。`main.c` 在 HWT101 处理后运行运动任务；新任务运行时暂停 OLED 与比赛屏内容刷新，USART1 不再等待发送结束。首次编译调用图显示已知最大调用深度 1068 B，超过原 1024 B 栈，因此启动文件栈调整为 4096 B，并把遥测大快照留在静态区。未改 CubeMX `.ioc` 或 HAL 源码。

## 2. 参数与状态的含义

- 车体 `vx` 前方为正、`vy` 左方为正、`omega` 逆时针为正。地图原点左下，X 向右、Y 向上，车头向右为航向零。
- 地址 1/2/3/4 = 左前/左后/右后/右前；前进方向 0/0/1/1，仍待架空确认。
- 命令脉冲暂定 3200/圈；物理编码器分辨率未知；Emm `0x36` 按有符号的 32 位幅值保存到 `int64_t`，每圈协议单位另行确认。65536 不代表编码器精度，也不是位置命令的 3200 脉冲。
- 新任务合速度 ≤100 mm/s、角速度 ≤0.15 rad/s、四轮整组限幅 100 RPM；驱动速度仍是整数 RPM。新模式 `acc=0`，旧位置测试加速度独立。
- `true`/`request accepted` 表示 RAM 请求接受。发送完成、驱动应答和物理停止是不同事件。无应答配置不能证明驱动接受，更不能证明实车停止。
- `done + timed_complete` 仅说明有限时间任务结束及停车发送流程结束，不表示到达地图目标点。部分同步缓存取消或通信故障会锁住恢复；即使停车已发出，也不假定缓存清除。

## 3. 控制台使用顺序

所有命令经 USART1/Zigbee，以回车结束。实际 COM 口由作者选择；原生 USB CDC 继续服务香橙派 B2。

先核对实际 Emm 驱动型号、整数 RPM 缩放、应答配置与方向，再用下面对应命令记录**本次 MCU 运行内的确认**。这些命令不会写驱动器参数或 Flash。

```text
chassis profile receive
# 四台驱动确认为收到命令立即回复一次时使用；若确认无应答，则 profile none。
# 未确认保持默认 UNKNOWN，不启动底盘运动。

chassis feedback 1
chassis feedback on
# 只轮询地址1：0x35 速度、0x36 实时位置、0x3A 状态。
chassis feedback
# 只读缓存，显示原始RPM/位置/状态位；valid和rx_ms依次对应速度、位置、状态。

chassis feedback off
chassis units 65536
# 架空完成一圈测量并核对协议后才记录；units 0 撤销确认。

chassis feedback 0
chassis feedback on
# 0表示四轮轮询；选择会先关闭轮询，on须明确发出。
```

新测试均是有限时长，参数单位与旧 `chassis velocity` 不同：

```text
chassis run 30 0 0 2000
chassis run 0 30 0 2000
chassis run 0 0 0.1 2000
```

上面分别是直行、左移、逆时针旋转；保持 2000 ms，加上默认起步/停车各 500 ms，共 3000 ms。仅在前一项审查通过后逐项上板。API 可分别指定 `transition_ms/hold_ms/stop_ms`，控制台首版固定 500 ms 起停；总任务上限 60 s。

航向保持先沿用现有静止标定/验证，再设置地图锚点：

```text
imu verify
chassis origin 2100 300 90
chassis heading 30 0 0 2000
chassis task
chassis stop
```

`origin` 将**当前合格的 HWT101 角度**对应到地图位姿，XY 是人工初值，不是传感器测到的位置。`heading` 第四个参数是现有 HWT101/MCU 模块角度（度，含配置正方向），不是地图角度：示例中的 0 只有在实际希望保持模块 0° 时才填写。地图与 MCU 不重复计算 PID。

`chassis stop` 立即取消任务并请求异步停车；`chassis task` 查询任务原因及总线阶段。出现 `locked` 后，先检查错误与驱动状态，完成实际驱动器复位和静止确认，再执行 `chassis reset-confirmed`。该命令只解除 MCU 隔离，不会替你复位电机。

## 4. 同步、反馈与异常处理

四轮快照发送期间预约总线，普通机械臂/反馈请求不能插入。每条命令间隔至少 10 ms；有应答时等待各自正确地址/功能码/长度/末尾 `0x6B`。最后广播才触发同步。新目标覆盖下一组，不修改正在发送的一组。

Emm 帧没有可回传的任务序号。超时或取消待应答事务后采用保守隔离，不让相同地址/功能的迟到应答误完成新任务；实际复位确认后才能恢复。CRC 不适用于此协议，`0x6B` 是当前手册指定的校验/结束值。

反馈轮询以约 200 ms/四轮整轮为目标；它只能使用同步事务之外的空隙。应答时间或连续运动会拉长实际周期，保留每轮 MCU 接收时间并显示过期，不能宣称固定 200 ms 全部读完。时间戳取 MCU 收到字节的时刻，不是驱动器采样时刻。

反馈估计须连续两组四轮位置、确认每圈单位、有效航向锚点。单轮年龄上限 600 ms，组内接收跨度上限 250 ms；每轮分别用自身时间差换算。失效后重新建立基准，不积分断档距离。异步轮询配合当前 HWT101 航向仅适合低速观察，还不是 XY 位置闭环。

指令推算使用最后已发送同步快照，并按发送时间分割速度变化；位置控制期间不把零 RPM 冒充有效估计。指令推算本身不含打滑、负载、驱动内部加速等实物效果。

## 5. 地图与遥测

双击 `upper-computer-web/local-car/start.cmd`，用 Chrome/Edge 打开本地页面后进入「二维地图」。离线可调整轮径、轮距、初始位姿和速度；两种模型都整组限幅，再由命令近似模式量化整数 RPM。转向使用 20 ms 小步长中点积分，页面隐藏/长暂停会停住模拟。

地图保留赛题 2400×2400 mm 灰色区域、四块 450 mm 浅黄色区域及局部白色工位区。轮心矩形仅说明结构，不作为整车外廓或碰撞判据。

连接不会运动或自动开遥测。地图的「开启遥测」发送 `chassis stream on <非零随机uint32>`；关闭发送 `chassis stream off`。协议为 `@CHASSIS ` + JSON + CRLF，v=1，先 config 再 state，状态 5 Hz。主控重启默认关闭；重新订阅使用新会话，不拼接之前轨迹。修改人工原点增加 `trace_seq`，页面断开轨迹段。

config 包含几何版本、确认状态、轮序、方向和已确认位置单位；state 包含 MCU 时间、任务、目标、原始轮反馈及有效性/时间、HWT101 地图航向、两个估计来源和总线状态。右轮原始电机方向符号与逻辑目标不同，页面明确标注。在线参数只取 MCU，手动调参只影响离线模拟。

USART1 回复优先于待发遥测；一条正在发送的完整 JSON 不被回复拆开。待发遥测只保留最新一条，并统计丢弃数量。缓冲区复制后保持到完成回调，不引用格式化函数的临时栈。

# STM32F407VGT6 工训赛事搬运小车

本项目包含搬运小车 STM32 固件、香橙派视觉代码、串口屏配置、本地网页控制台及独立物料台转盘固件。主车主控为 STM32F407VGT6（LQFP100，1 MB Flash），主要使用 STM32 HAL 裸机主循环；独立物料台转盘使用 STM32F103C8T6，车载 ID 8 转盘由主车 UART5 控制。

现有功能包括机械臂与夹爪、麦轮底盘、HWT101 航向验证与保持、B2 颜色搜索/对准、二维码任务码、串口屏、OLED、地图遥测和实车15目标路线。路线默认200 mm/s，长段转向后前进或后退，工位恢复观察姿态。视觉对准和路线到点不等于完整搬运任务完成；软件回归不替代实物验收。

2026-10-09 后续退役独立Base/X对准 `ArmVision`：统一使用 `grab align color|ring`，旧 `vision` 命令仅回复退役提示，PE2不再从OLED概览启动旧对准。保留旧物料搜索 `MaterialVision`，其参考/标定入口改为 `material ref`、`material calib <颜色>`；`grab` 流程不依赖这些入口。详见[退役记录](../2026-10-09-退役ArmVision独立对准.md)。

网页“地图与遥测 → 雷达建图”当前通过 F407 USART1 / DL-20 的115200共享链路工作，LDS50C由USART2以921600接收。单次与持续扫描均由F407按F1的 `(230,230)` 坐标、阈值1和任务保护格完成判障与规划，网页优先读取冻结障碍/路线，再显示120分区预览，不自动上传整圈点云；RAM配置读回、可调网格、黑白主题及本机保存保留。使用与接线见[控制台手册](原控制台手册.md)，本次验证见[持续建图修复记录](../2026-10-05-F1雷达持续建图与无线结果同步修复.md)。

“实车监控”“离线对照”和其他控制台页面不变；主机建图与实车建图/运动入口独立。第一阶段雷达直连代码保留作诊断及历史参考，已不是当前雷达页的数据源。本次软件验证未打开串口、发送设备指令或烧录，不代表实物障碍与无线链路已验收。

单件取放采用 ID 8 车载三仓转盘：外部夹取后入仓、从车载仓取出后向粗加工区或暂存第一/第二层竖直释放，再返回保存的外侧观察姿态。三仓与电机 1∶1 直连；第一仓定义为人工参考零位，第二/第三仓角度需要标定，车载X默认100 mm。上电库存为待核对，须人工确认；软件完成结果不等于真实夹持验收。`align` 保持只对准，`pick` 采用相同的视觉对准和漏检恢复流程；两批调度现由 `grab mission` 负责，Z上下搜二维码待后续。参数调试页使用五个展开标签、蓝色深色背景和一键读回，参数仍只存 STM32 RAM。当前接口见[上位机协议](原上位机协议.md)。

控制台需要 Python 3、pyserial；缺少时执行 `python -m pip install pyserial`。服务启动后用桌面 Chrome/Edge 打开 `http://127.0.0.1:8765/`。无需 npm 安装、旧 React 页面或云部署。启动不会自动连接串口。

网页“雷达建图”当前复用主车 USART1 / DL-20 的 115200 / 8N1 共享连接，由用户手动选择实际 COM 口。LDS50C 原始测量经 USART2（921600）进入 F407；正常单次扫描只回传障碍掩码、25格点数和规划路线，不自动上传完整点云。第一阶段独立 USB-UART 直连模块保留供诊断，不再接入当前雷达页；实车监控/离线对照不变。操作与同圈重算见[雷达页说明](原控制台手册.md)，本次纠偏见[结果回传记录](../2026-10-04-F1雷达结果回传纠偏.md)。

上电后保持整车静止：固件默认 Emm42 Receive 应答，自动等待 IMU 新鲜数据并执行 5 秒验证；通过后才取得航向控制资格。失败时在系统页重新验证，地图起点仍需准备跑图确认。见[本次变更记录](../2026-09-22默认Receive与上电IMU验证.md)。

已通过验证的 IMU 在运行中短暂通信异常或数据超时后暂停使用，恢复通信并连续收到两帧新鲜数据后自动恢复可用状态，不再因累计错误永久锁死。恢复不归零、不改地图参考、不自动重启已停止的任务；验证失败或取消仍需重新验证。见[恢复修复记录](../2026-10-07-IMU短暂异常后有效状态恢复.md)。

## 硬件与通信

| 接口 | 引脚 | 当前用途 |
|---|---|---|
| USART1 | PA9/PA10 | 无线文本控制台，ASCII/CRLF |
| USART2 | PA2/PA3 | LDS50C，921600/8N1，循环RX DMA |
| PC USB-UART | 独立转换器 | 第一阶段网页雷达直连，3.3 V UART、TX/RX交叉并共地；雷达电源单独按手册供给 |
| USART3 | PD8/PD9 | 串口屏 |
| UART4 | PC10/PC11 | 二维码 |
| UART5 | PC12/PD2 | 步进电机共享总线 |
| USB CDC | PA11/PA12 | 香橙派 B2 视觉 |
| I2C1 | PB6/PB7 | OLED |
| I2C2 | PB10/PB11 | HWT101 Z 轴角度，SDA=PB11 |
| TIM1_CH1 | PE9 | 270°夹爪舵机控制信号，50 Hz PWM |

CAN1/CAN2 当前停用，工程配置保留；将来启用时重新确认节点与速率。SWD 调试器型号和参数以实际连接为准。

板载 PE4/PE5 可在 OLED 页面间翻页。进入 `4/4 Servo Test` 后保持 Off，PE2 选择松开 500 µs，PE3 选择抓紧 700 µs；PE5 开启/关闭输出，PE4 退出并清零输出。USART1 `grip open`、`grip catch` 与网页“打开”“夹取”使用相同的两个实测脉宽；`grip idle` 也取松开位置。上电与仅进入页面不会驱动舵机；信号消失后是否保持力由舵机型号及供电决定。700 µs 为用户确认的完全抓紧位置，不继续增加脉宽顶住机构。

USART1 控制台、香橙派 USB B2 和 UART5 电机协议各自独立，不能混用。旧 `sys.ping#`、香橙派 CRC 帧和 B3 圆环编号实现已退出活动工程。

## 工程结构与构建

- `Code/template/Core`：主程序、外设初始化和中断入口。
- `Code/template/Hardware`：电机、Camera、二维码、HWT101、显示、按键及 Flash 驱动。
- `Code/template/App`：机械臂、底盘运动/定位/路线、视觉任务、控制台与显示业务。
- `System` 职责保留为无业务含义的公共功能，当前未使用的延时模块已删除；`Drivers` / `Middlewares`：第三方代码。
- `Code/tests`：固件主机回归；控制台测试在 `Code/upper-computer-web/local-car/tests`。

主要构建环境为 Keil MDK-ARM，备用工程在 `Code/template/MDK-ARM/eide`，配置名同为 `template`。CubeMX 工程为 `Code/template/template.ioc`；只有修改外设配置时才重新生成，生成前检查 USER CODE 和差异。

2026-10-02 精简只更新 Keil 清单；EIDE 按用户要求暂不维护，仍有已删除模块的旧路径及原有 SPI 缺项，未验证可用。张大头 Emm 与 W25Q128 驱动完整保留，详见[固件精简记录](../2026-10-02-STM32主车固件精简.md)。

控制台的 `grab set` 和 `config <axis> ...` 修改 RAM 参数，受理后供后续控制使用；STM32 复位/重新上电恢复已烧录固件默认值。网页保存的路线速度只在浏览器本地保存，修改网页预填值不会改写固件默认值。当前没有这些参数的 Flash 保存与上电加载功能；保留 Flash 驱动不等于调参已经掉电保存。

在工程根目录运行软件回归：

```powershell
python Code/tests/run_firmware_tests.py
node --test Code/upper-computer-web/local-car/tests/*.test.mjs
python -m unittest discover -s Code/upper-computer-web/local-car/tests -p 'test*.py'
python Code/tests/radar_wire_contract_test.py
```

固件主机测试需要 Python 和 PATH 中的 GCC；网页测试需要 Node.js。上述测试使用主机模拟，不打开实车串口。日志集中保存到 `.embeddedskills/`，其中仅提交 `config.json`；Keil/EIDE 也会在各工程内生成被 Git 忽略的编译输出。

转盘回归独立运行 `python Code/物料台转盘/turntable/tests/run_tests.py`；HMI 使用屏幕编辑软件编译。当前 F407 的默认构建和下载参数不用于转盘。

## 电机总线恢复入口（2026-09-27）

误操作或通信锁定后，可在本地控制台“系统与标定”或“视觉任务 → 回零与通信恢复”点击“恢复电机总线”（`bus recover`），用 `bus status` 查询结果。恢复先停止任务、逐台检查全部七台驱动器，成功后不自动续跑；底盘同步缓存仍不确定时保留底盘运动限制。详见 [电机总线恢复与手动操作检查](../2026-09-27-电机总线恢复与手动操作检查.md)。

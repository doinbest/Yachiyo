# 实车前四段反馈路线 — 2026-09-12

## 本轮结果与边界

按作者批准方案实现反馈距离控制与手动逐段路线。软件交付完成，尚未连接、烧录或进行实物验证。不能把模拟或主机测试结果当作四轮方向、实际单位和地面精度的确认。

前四个地图目标：`(2100,300)` → `(2100,1200)` → `(2100,2100)` → `(1200,2100)`；人工初始位姿`(2250,150,90°)`。车头保持地图上方，第一段是麦轮斜移，不是转动45°。不执行扫码、取料、机械臂动作或后续12段。

## 代码结构

- 新增`chassis_localization.c/h`：统一原点、两类估计、完整反馈组序号、有效性和代次。关闭遥测不停止定位。原点/单位修改和反馈断档使旧距离任务失去资格，恢复通信不会自动续跑。
- 扩展`chassis_motion.c/h`：保留原定时接口，新增`ChassisMotion_MoveTo(x,y,map_yaw_deg,max_speed,timeout)`。地图误差经过比例、速度/加速度限制、地图到车体转换，复用航向PID和四轮统一限幅。地图角度先转换到现有模块目标角度，不能把90°直接当作HWT原始目标。
- 新增`chassis_route.c/h`：固定四站，关联运动action_id，每站完成后保留任务占用并等待人工next；不逐站重置估计。取消后不能中途续跑。
- 主循环顺序：HWT采集/标定 → 刷新航向 → 定位 → 运动 → 路线 → 电机处理 → 遥测。显示刷新在运动和路线等待期间暂停；查询仍可处理。
- 机械臂、视觉、标定、夹爪和旧底盘启动入口加入占用检查；读取状态、位置、配置和停止仍可用。路线等待也禁止其他运动插入。
- Keil/EIDE只登记新增源文件。未修改CubeMX引脚/外设参数或HAL源码。

默认参数：50 mm/s、平移Kp=1.0 s^-1、加速度100 mm/s²、角速度限0.15 rad/s、位置容差10 mm、航向容差2°、单段超时60秒。配置集中在`chassis_config.h`，属于初始调试值。

### 正常停车与故障停车

进入容差后，先发送同步零速快照，等待本组和正在进行的反馈事务完整结束，再发四轮停止。正常停车不通过取消半组同步指令/未回包查询来制造缓存隔离；超时、取消和故障仍使用立即抢停。

停车确认必须满足：停止发送流程完成、至少三组新的有效反馈覆盖不少于500 ms、每轮速度绝对值≤1 RPM、相邻位置增量换算≤2 mm、位置和航向仍在容差内。重复缓存不能累计确认次数。3秒内无法确认，报`stop_unconfirmed`；到站成功为`feedback_arrived`并置`stop_confirmed=1`，不表示视觉工位对准完成。

### 反馈轮询修正

原轮序查询在100 ms同步速度发送间隙里可能使四轮位置时间跨度超过250 ms。改为四轮速度一组、四轮位置一组、四轮状态一组。定位只对完整新位置组检查250 ms跨度，部分替换组不冒充同一组；每轮600 ms新鲜度仍逐圈检查。

实际C总线/定位联测采用模拟UART发送完成和应答：0 ms应答延迟时最大组间隔300 ms、组跨度89 ms；8 ms应答延迟时380 ms/97 ms。旧查询顺序会使相同测试失败。这是软件时序测试，实物延迟仍需测量，不能据此保证固定反馈频率。

## 操作接口

| 命令 | 行为 |
|---|---|
| `chassis move dx dy` | 地图相对位移mm，长度>0且≤300；保持启动时航向，速度上限50 |
| `chassis task` | 原任务/总线状态；距离任务另输出地图目标、位置与航向误差、反馈有效性及停止确认 |
| `chassis route start` | 要求本次显式原点匹配(2250,150,90°)，当前反馈位置在起点容差内；不自动设置原点 |
| `chassis route next` | 只在上一段反馈确认到站且等待人工继续时接受 |
| `chassis route status` | 当前段、目标误差、反馈、原因、停止确认 |
| `chassis route cancel` | 取消路线并请求停止，取消后不得自动续跑 |
| `chassis stop` | 同时取消路线资格；旧停车入口兼容保留 |

运动中的反馈关闭/选轮、配置/原点修改会被拒绝。轮子反馈显示移动时，新的距离任务也拒绝启动。

网页底盘页新增独立实车区域，离线16段模拟保留。`@CHASSIS v1`新增可选`route`、`distance`、`localization`状态字段；旧字段保持。地图显示订阅会话内的新反馈目标和误差，失效后不保留假目标。浏览器不按动画推进电机，切页/刷新/重连不会自动开始下一段。已启动的有限单段由MCU执行；断开浏览器本身不是实物急停。

## 上板测试步骤

### A. 先架空核对底层

1. 由作者烧录编译产物，先架空车轮，核对地址1/2/3/4对应左前/左后/右后/右前及前进极性。确认实际Emm驱动与应答设置。
2. 仅在确认四台驱动收到命令立即回复时选择`chassis profile receive`；确认无回复时选`chassis profile none`。程序不代写驱动器配置。
3. 用`chassis feedback 1`、`chassis feedback on`读取单轮缓存，观察速度、位置、状态及时间；随后依次检查四轮。完成一圈测量，实际协议位置增量确为65536后才输入`chassis units 65536`。不符合则停止本轮落地测试，先核对驱动协议。
4. 执行`chassis feedback 0`、`chassis feedback on`，检查四轮反馈有效。选轮会关闭轮询，所以on须在选轮后执行。核对有效轮径和传动比；当前80 mm/1:1仍为假设。
5. 使用已有有限时长小速度测试逐项确认直行、横移、转向符号，以及停车发送与反馈效果。出现locked时先查故障与实际驱动状态，不用reset-confirmed掩盖未处理的问题。

### B. 空旷地面单段测试

底层与航向修正方向确认后，放到空旷地面，确保至少300 mm周围行驶空间；保持静止执行`imu verify`并等待PASS。然后给当前位置一个测试用地图原点：

```text
chassis origin 1200 1200 90
```

等待四轮反馈建立，执行`chassis task`或开启地图反馈遥测查看有效性。先测一条：

```text
chassis move 0 100
chassis task
```

这是地图向上100 mm，在当前90°车头约定下是前进。观察直到`reason=feedback_arrived`且`stop_confirmed=1`。尺量实际距离和偏航，并与地图估计比较；失败时保存完整状态，不能直接进入路线。

通过后分别测试`chassis move -100 0`（地图向左）、`chassis move -100 100`（左上斜移）。每次单独发送，上一段停止并测量后再发下一条；不要一次粘贴整组运动命令。需要停止时用`chassis stop`。

### C. 实物地图前四段

1. 将车实际放在右下启停区，车头朝上。上一次任务必须结束；若路线仍占用，先取消并等待停车流程结束。
2. 静止时显式设置`chassis origin 2250 150 90`，等待反馈有效；这一步是人工对齐，不是自动定位。
3. 执行`chassis route start`。只运行第一段左上斜移。
4. 查询`chassis route status`。看到`state=waiting`、`stop_confirmed=1`后，检查实际位置、车头与剩余间距，确认无误再输入`chassis route next`。
5. 以相同方式通过扫码点、提前转向点、转盘前停车点。最后`state=done`仅表示前四段反馈路线完成。
6. 记录每站尺量X/Y误差、航向、四轮反馈更新时间；中途不重置原点掩盖累计误差。若取消，先人工回到起点并重新建原点，不续跑剩余段。

转盘前还有70 mm名义间距，但实际车体外廓、镜头位置、安装误差和侧滑需要实测。通过上述空车测试后，再单独实施视觉末端对位。

# IMU原生标定审查

日期：2026-10-15。范围为当前HWT101 I2C驱动、原生零偏标定状态机、控制台及网页入口、底盘角度资格与定位调用链。检查了已有工作区差异并保留；本轮未修改固件或网页实现，未发送实车命令、复位、烧录或部署。

## 标定流程核对

当前 `imu cal start` 实际执行：解锁 `0x69=0xB588` → `WORKMODE 0x48=1` → 静止20秒 → 重新解锁并写 `0x48=0` → 回读模式和零偏 → 解锁并写 `CALIYAW 0x76=0` → 从后续新样本起验证30秒 → 通过后解锁并写 `SAVE 0x00=0` → 回读模式和零偏。寄存器步骤至少间隔100 ms，总时间略长于50秒。

I2C发送寄存器地址和低字节在前的两个数据字节，不发送UART帧头；与[维特官方SDK的I2C分支](https://github.com/WITMOTION/WitStandardModbus_WT901C485/blob/main/ESP32/ESP32_sdk/mian/wit_c_sdk.c)一致。[厂家HWT101CT FAQ](https://witmotion-sensor.com/products/hwt101ct-485-military-grade-z-axis-inclinometer-mems-tilt-sensor-built-in-highly-integrated-crystal-gyroscope-rotation-angle-attitude-sensor-kalman-filter-algorithm-automatic-data-storage-multi-cascade-support)支持 `0x48=1`、20秒、`0x48=0` 流程；本车版本适用性仍以已有用户协议及实际寄存器读回为依据，不把其他接口或型号的说明当作实车兼容验收。

验证使用角度展开及线性拟合，阈值仍为漂移绝对值≤0.01°/s、残差RMS≤0.1°、最大采样间隔300 ms。STM32不扣除拟合漂移，不加载外部Flash旧偏置。验证PASS、保存请求、读回成功及实物断电保持分别解释；`persistent=UNTESTED`不代表已完成断电验收。取消和异常恢复最多尝试三次正常模式写入及回读，保存失败不授予控制资格。标定全过程的整车静止仍由用户保证；软件任务空闲不能证明车体无外力或振动。

## 代码发现

确认一项P1集成问题，登记为[P002](../待解决问题.md#p002--imu短暂异常导致地图锚点及原点丢失)：标定模块运行期短暂失联能恢复资格，但 `heading_read` 在资格暂不可用时清除地图锚点，定位模块随后清除原点。资格恢复后不会恢复地图定位。问题属于既有底盘调用链，当前未提交改动没有引入该路径；标定状态机自身的两帧资格恢复测试不能覆盖此问题。

复现使用真实 `chassis_motion.c`、`chassis_localization.c`、`chassis_observer.c`、`chassis_model.c`，借用现有硬件fixture注入资格失效与恢复。建立原点后各标志为1；失效后全部为0；恢复后仅heading为1，anchor/origin/feedback仍为0。证据保存在 `.embeddedskills/tests/imu-native-review-20261015/anchor-loss.c` 和 `anchor-loss.log`。

原生20秒流程、I2C字节序、正常模式恢复及验证后保存流程未发现新的可确认代码缺陷。该结论限定为源码和主机验证，不代替模块实际标定效果或断电保持验收。

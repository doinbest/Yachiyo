# 扫码段并行衔接

用户反馈上一轮连续性已有改善，但开局斜移后仍停车等待Base到扫码姿态，要求Base转动同时底盘直行，并检查其余同类等待。本轮按最新要求替代此前“Base+35°确认到位再直行”的串行约定，角度、底盘路线及速度参数不变。

## 检查与修改

| 位置 | 原交接条件 | 本轮行为 |
|---|---|---|
| 右下开局入口转向后 | Base转35°任务全部完成才直行 | X收回、Z提起且本次新鲜静止反馈有效后，Base转35°与直行重叠 |
| 右上开局 | 等扫码姿态全部完成再启动路线 | 仍完成起点/四轮/IMU及可选雷达准备，再凭新鲜X/Z资格并行出发 |
| 扫码后离开 | Base完全返回行驶参考才继续路线 | 提Z收X确认后，Base回转与下一段平移重叠 |
| 路线待提交阶段 | 仅work_dock允许姿态并行，其他平移统一等GrabTask结束 | 统一按真实姿态资格判断平移；转向仍等待完整姿态，busy保留目标重试 |
| 转向完成、下一平移尚未发出时暂停 | 继续重发已完成转向，又等Base全部完成 | QR姿态受理或work_turn完成后保存下一直行/dock目标，继续重取资格后直接补平移 |
| 跨路段普通中转点 | 当前路段结束无条件等Base全部完成 | 保留该点原到位/停稳，再按下一实际阶段判断；平移可继续，转向仍等待 |

`GrabTask_PoseClearanceReady()`现包含QR姿态准备，仍仅适用于`GRAB_ROUTE_POSE`，核验本次开始/继续后的X/Z静止证据、位置、Base状态和新鲜反馈。实际扫码升降、夹取、释放等任务不会通过该资格。路线在扫码工位交接以及下一次车体转向前，仍等Base完成；暂停和恢复使用原绝对目标，不重复启动35°相对动作。

检查了正式调度的准备、行驶、二维码请求/展示/离开、工位换位、入仓后离站及路线待提交路径：路线自动停留参数已为0；现存停车主要是运动到位/停稳确认或机构前置条件。工位内换位与离站沿用上一轮的重叠及双方汇合。保留取盘前1秒、夹爪释放等待、视觉稳定和车体转角边界。旧单项`GrabRoute`扫码等待属于独立入口，不借正式比赛优化改变其行为。

## 验证

- 生产GrabTask：QR姿态新鲜资格、X伸出/Z偏低/反馈过期/驱动故障拒绝、暂停后重取资格、最终35°绝对目标。
- 生产路线：右下Base延迟、双方不同完成次序、串口事务busy、并行暂停续接不重复QR准备、右上出发资格、扫码交接等待与车体转向边界。
- 生产比赛调度：扫码离开及右上准备在资格成立后启动路线，原起点核验仍执行；原工位汇合和暂停用例继续运行。

# 追踪实时长日志与发送／反馈诊断

## 本轮目标与范围

用户确认增加电脑实时日志，解决128条MCU环形记录约6.4秒、早期运动过程被覆盖的问题，并继续定位上一段“计算请求非零，编码器变化为零”的现象。本轮不调整追踪估计器、J、速度／加速度／延迟参数，不修改香橙派、不改变静态align/pick、雷达、路线、回零或驱动默认配置。

上一段只能证明末尾窗口有38.31/5.78/13.49 mm/s的计算请求、实际位置差分为0，不能证明这些请求实际以对应RPM发到电机，也不能归因于通信断连或供电。新日志补充发送链路证据，不宣称该运动问题已经修复。

## 实现

- 独立`grab track log start [50..1000 ms] / stop / status`，默认关闭，默认周期50 ms。只有观察／追踪产生计算记录才有实时行，不自动启动机构、视觉、参考或任务。
- `TRACK live`独立会话id及候选记录序号，19项控制数据加34项IO整数，整行IEEE CRC32。请求速度、四轮完成同步后RPM、速度反馈、原始位置、各反馈年龄、X受理/发送目标和总线状态分别保存；Receive确认不冒充实际运动。
- X的DMA完成时刻通过motor_bus事件传到MechanicalArm事件；事务结束再发布，但时间不取ACK接收时刻。实际驱动动作不变。
- 实时发送复用console_tx空闲的DMA帧缓冲，没有额外大队列，忙时跳过诊断，未开始行让位于正常／停车回复，已开始整行不拼接。候选序号使跳过或无线丢失可见，不为日志添加固定等待。
- 原128条冻结环形缓存不扩展，仍导出19项原核心数据；不将当前IO塞到旧时间记录。详细IO保留一个当期快照，长期记录由电脑磁盘承担。
- 网页追踪卡新增实时记录操作和最新IO显示，不自动订阅／重建参考，日志关闭不等于运动停车。重连后查询订阅可接受后续数据，不冒充从第0条完整采集。
- 本地桥接原有无缓冲原始RX文件持续落盘；报告工具支持原始bin、JSONL RX事件与旧工具JSON，区分实时和冻结来源、缺号／坏CRC、启动过渡／稳定段、发送RPM与反馈年龄。

## 使用

1. 新固件烧录后按现有流程恢复有效机构状态；本轮尚未执行烧录或恢复动作。
2. 本地控制台连接实际COM14、115200/8N1，视觉任务页点击“开启实时记录”。可以先仅观察；物料移动期间连续留存，不必停车后才导出全部数据。
3. 开始与停止追踪仍用原来的明确运动操作。先停止追踪并取得反馈确认，再关闭记录；保留最终整行传输的时间。
4. 电脑文件在`.embeddedskills/logs/serial/<连接时间>-rx.bin`和同名`.jsonl`；保存时长不受6.4秒限制。分析：`python Code/tools/tracking_report.py <文件> --source live --kind physical`。
5. 默认50 ms为请求节奏，不保证DL-20无损20 Hz；链路占用高可显式`grab track log start 100`。报告必须保留缺条，不能补造之前未上传的详细IO或将图像估计速度当独立的转盘实际转速。

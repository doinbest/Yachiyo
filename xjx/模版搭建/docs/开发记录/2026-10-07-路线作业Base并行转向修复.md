# 路线作业Base并行转向修复

状态：下述BaseRoutePosition为当时的局部修复，已由同日“机械臂统一位置接口与过度互锁检查”替代；当前正式任务统一调用PositionEx。

现场蓝色首件路线已到物料台附近，但preparing_work一直不完成，Base诊断target=nan、commanded=0，最终route_timeout。用户要求停止后state=idle、cancelled、stop_confirmed=1；本轮要求修改、重新烧录，完成后再重新打开香橙派，不自动运行实车。

根因：GrabTask_PoseStart允许在已验证后向收回姿态中与底盘转向并行，但底层MechanicalArm_PositionEx无条件拒绝ChassisRoute_IsBusy或ChassisMotion_IsBusy时的位置请求。原grab_pose_test将这些条件固定为false，未覆盖实际冲突。加入底盘忙且模拟底层拒绝普通位置指令的测试后，旧代码停在route_pose/preparing_work，run_to断言失败。

修复：添加任务专用MechanicalArm_BaseRoutePosition，只请求Base绝对位置；仍经过MOTOR_BUS_ARM普通队列、轮批次原子性与匹配Receive应答，不直接绕开总线。普通Position/PositionEx、HOME/ZERO及X/Z限制保持。GrabTask仅在work姿态路径调用新入口；先核验X收回、Z达到车载抬起高度，再转Base。已验证后向姿态即使底盘转向先完成，也直接转Base，避免退回X/Z位置准备而再次被路线忙拦住。静止且高度不足的初次作业仍先抬Z、收X；底盘运动时姿态不满足则明确travel_pose_changed。

验证：任务测试覆盖底盘仍运动，以及底盘已完成但路线仍运行两种时序，均只增加一次Base位置动作，没有X/Z、夹爪或回零动作。真实mechanical_arm.c/motor_bus.c测试在路线忙或距离动作忙时普通PositionEx仍拒绝，新Base入口排队等待轮批次释放后发送ID5绝对800脉冲，并收到匹配FD ACK。完整回归、Keil和烧录结果随后补充；主机模拟不等于实车90度验收。

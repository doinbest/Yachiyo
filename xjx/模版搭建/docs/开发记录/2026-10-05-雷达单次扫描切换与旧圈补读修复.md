# 雷达单次扫描切换与旧圈补读修复

日期：2026-10-05。范围：`#map/radar` 单次扫描及主机雷达模式切换。延续用户已确认的 COM14 / 115200 和 DAPLink 下载权限。

## 根因

实物日志事件 5534 发送 `radar host scan`，5551 收到 `scan_accepted` 后，5552 仍发送旧圈 `radar host fetch path:416 1`；5563 返回 `ERR radar host snapshot_or_page`。新扫描已经取消固件旧发送缓存，网页却仍在旧结果补读流程中。

同时发现重复 `radar host result 416/440` 和重复补页：上轮留作交付的验证浏览器标签与用户原页面同时消费状态、自动读图。本轮已关闭该验证标签，不再留下额外串口写入方。

回归复现还发现：

- 新扫描指令正在写出时，迟到的旧“完成”状态会重新启动旧结果读取。
- 单次扫描由另一客户端启动时，当前客户端没有取消旧圈补页。
- 已完成地图后重新开启持续扫描，底层沿用旧 `READY`，固件可能过早冻结历史结果。
- 新扫描可能与尚未完成的雷达写入重叠，取消后的旧读取异常也会覆盖新操作状态。
- 持续采集时单次按钮仍可点击，但原固件直接拒绝主机持续模式中的单圈请求。

## 修改

1. 网页 `RadarHostClient` 保存新扫描前的结果身份，等待新的完整圈；旧身份完成状态不触发自动读取。新采集开始时取消旧结果等待，不删除已完成历史快照。
2. 雷达普通写入依次执行，并在实际发送前核对操作版本；取消后的旧补页/ACK 不再写出。雷达停止命令绕过普通等待，未增加停止响应门槛。
3. 已取消读取的迟到异步异常不再覆盖新操作；当前有效操作的真实错误仍显示。
4. F407 `RadarHost_Scan` 只结束主机持续模式，再启动单圈；不结束实车拥有的雷达工作。`RadarScan_HostLiveStart` 明确进入准备状态，第一完整圈出来前不宣称新结果已完成。
5. 采圈和新扫描请求等待期间暂时禁用单次按钮；结果下载期间允许开始下一圈，停止按钮不受该条件影响。更新雷达模块浏览器缓存版本。

保持 F1 判障与规划、雷达 `(230,230)`、阈值 1、保护格、其他控制台界面、USART1 115200、DL-20 配置和已取消的 30 ms 固定等待不变。未修改 IOC、EIDE、采集超时或实车导航动作。

## 使用与限制

用户原网页需要 `Ctrl+F5` 更新模块后再解除停止锁定。建议仅保留一个雷达控制台读图页面；本轮不新增跨网页通用锁定框架。

无线连续发送仍有实际丢页，本轮单次结果遇到流或结束标记丢失时走原有超时补页，耗时约 12～16 秒，切换测试约 18 秒；这不是判障或路径算法耗时，本轮未宣称解决无线吞吐/延迟。保留坏页恢复能力，不恢复固定 30 ms 等待。

本轮通过的是生产客户端串口操作和网页按钮状态回归，不替代赛场障碍摆放、雷达方向或实车路线执行验收。

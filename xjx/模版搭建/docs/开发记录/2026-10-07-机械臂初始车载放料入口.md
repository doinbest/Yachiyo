# 机械臂初始车载放料入口

用户要求将机械臂控制台中的“转到仓位”改为机械臂 Base 从回零处转向车载口、X 伸出、Z 放下，并明确下降后自动松开夹爪。已核对原固定位置入仓包含这段动作，但开始时还会执行外侧夹取，没有直接放料入口。因此复用 GrabTask 现有轴反馈、转向、车载伸出、下降及松爪动作，新增 `grab place car`。

动作以已验证后向 Base 多圈锚点为基准，先 Z 提到 `z_car_lift`、X 收回，再转到车载取放方向（默认相对后向锚点逆时针90°），X 到 `x_car`（默认100 mm），Z 到 `z_place` 后松爪，结束停留在放料姿态。不会重复回零、不采集视觉、不转动 ID 8，也不改库存；用户应先将目标空仓对准取放口。这里用于初始机构检查；自动物料任务继续沿用原有分仓及库存流程。

控制台替换原仓位选择表单，新增停止放料和复用已有“收回朝后”入口。`turntable index` 及参数页仓位分度保留，截图中的 `slot_unset` 仍表示对应仓位角度未配置。

参数缺项只检查当前动作需要的轴尺度/行程、车载 X/Z、转向和反馈参数，不要求原料夹取高度、视觉模型或转盘角度。软件专项验证从非零多圈后向锚点转到正确车载方向、X100 mm、到 Z 放料高度后松爪、无外侧夹取/视觉/转盘分度、库存不变以及末端停留。

验证结果：完整固件主机回归通过，网页435项通过，Keil构建0错误0警告。未烧录、发送硬件命令或进行实车动作验证。

## 实车 Base 转向等待问题

用户反馈 `grab place car` 转动 Base 后没有继续，并授权使用当前共享串口 COM14/115200 读取及复现。通过本地服务共享连接发送一次任务，没有重新打开或抢占串口。复现仍停在 turn；长状态无线回传出现缺字，未取得完整的取消前目标/状态位。取消后位置约 −89.4～−89.5°，读取 state base 为 0x83；这些取消后的数据不能独立证明取消前驱动到位位状态。已发停止请求，抓取返回 cancelled、stop_confirmed=1，保留上位机停止锁；未重新执行运动。

源码 Base 完成原本同时要求现有1°角度容差、命令后的新鲜位置/状态、稳定时间和驱动位置到位位。主机测试复现“实际到目标且静止、驱动使能但没有位置到位位”会永久停在 turn。现将 Base 完成按既有1°容差、新鲜命令后反馈、静止稳定、使能且无驱动故障判断，不再重复要求驱动更细的到位门槛。未放宽位置容差、反馈年龄或停稳时间；X/Z继续要求驱动到位位。主机覆盖正常放料、未到角度、运动、过期反馈和故障，不将模型通过描述为本次实车已修复。

# 正式雷达首段显示与执行统一

日期：2026-10-05。范围：正式实车监控对应的 `RadarPlan`；备用F1雷达建图页不改。

## 原因与修改

此前设备路线首段只发布起点 `(2250,150)` 与扫码点 `(2100,1200)`，网页按实际路点连线，显示长斜线。实际C运动profile早已拆成短斜移到 `(2100,300)`、再沿X=2100直行到扫码位，导致显示与执行几何不一致。

现在规划核心明确发布：

`(2250,150,1,0) → (2100,300,0,0) → (2100,1200,5,1)`

最后两个字段为station/visit。接驳点是通行点，不触发扫码交接；二维码仍为5/1，后续工位顺序不变。上方起点仅用于规划，其对应首段接驳点为 `(2100,2100)`。

首段按这两条实际线段与完整占用矩形检查，不再按已弃用的长斜线判障；任一线段受阻则使用原有格路绕行，不强制穿障碍。执行profile接受显式接驳点时不会再次插点，固定15目标路线的旧直接首腿拆分兼容保留。此前R2C1/R5C1两障碍回归场景由15点变为16点，多出的点是既有实际接驳，不是新增绕行。

网页仍直接绘制设备路点，不单独改线、平滑或编写另一套规划。生产 `chassis_route_profile.c`、判障算法、无线节奏、IOC、EIDE、IMU/底盘方向及自动回零流程均未修改。旧历史快照保留，重新扫描后得到新路线。

# Base 等其他机构完成后再回零

## 需求与依据

用户报告 Base 经常在上电就近回零时读回 `home_flags=0x0B`，手动回零后普通电机状态为 `0x81`；观察认为已基本到达保存原点，并补充 Base 承载整套机械臂、负载较大。现有信息不能确定故障根因。用户要求其余机构先一起回零，完成后再回零 Base，以减少同时运动影响并先收回 X、升起 Z。

## 实现

- 上电等待1秒，Z/X碰撞回零与ID8车仓就近回零并行；Z/X按应答发出HOME，再验证两轴回零、稳定位置与使能。ID8由原独立所有者执行。
- Z/X均验证完成后等待ID8结束并建立参考，再执行Base的原使能确认、就近HOME与连续稳定反馈验证。等待时状态为 `home_wait_turntable`，`home_started=3 home_verified=3`；ID8失败不启动Base。
- `grab rehome`先并行Z/X，再Base，不重放已完成的ID8上电回零，也不新增ID8参考要求。手动单轴回零、手动Base后的局部参考验证保持原流程。
- Base的使能准备计时在前序等待结束后开始，运动窗口从Base HOME请求成功受理时计时。停止取消未启动Base，已启动Base沿原HOME中断链退出；取消后不会迟到启动。
- 同步固件启动说明、网页中文摘要及现行操作资料；保留旧固件启动说明的中文解析。

不改驱动器保存的电流、回零速度、方向、原点与模式，不把顺序调整视为已经确定或消除驱动回零失败根因。

## 验证

新增状态机回归首先在旧实现失败：X/Z仍回零时Base已启动。调整后专项回归通过，覆盖任一线性轴仍运行、回零位置未通过、ID8延迟/失败、等待停车、Base阶段停车/失败及前序等待不消耗Base运动窗口。网页新增回归首先复现新启动说明被显示成四机构并行，调整后通过。

独立审查发现Base前置准备时间会占用60秒运动窗口，已在HOME成功受理时校正计时基准。补充回归制造4秒BUSY准备延迟，验证HOME后59.9秒仍运行、超过60秒才超时退出；修复前失败、修复后通过。同步修正硬件基线中ID8的并行描述。

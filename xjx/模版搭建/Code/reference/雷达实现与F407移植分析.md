# 雷达参考实现与 STM32F407 移植分析

日期：2026-10-02。依据两份本地源码及当前 `Code/template/`，本轮没有修改活动固件、IOC、工程清单或控制台。用户说明已在 F1 验证雷达；本文的软件边界以实际源码为准，未进行本次硬件复验。

## 1. 两份资料的职责

`Radar_2026-10-01/Radar` 是 STM32F1 HAL 工程：USART2 接雷达，USART3 输出导航报告，上电启动一次扫描，完成后停止雷达，生成路径并保持结果。没有车轮执行器接口。

`2026-09-26/a/Lds50cHost` 是 Windows C#/.NET 上位机：Core 库负责解析、整圈组装、过滤、地图、路径和配置编码；应用层负责串口生命周期、单圈/连续扫描与网页界面。它既能直连雷达，又设计了给 STM32 下载配置和路径的协议。其余三个目录未发现另一套 F1 雷达源码。

## 2. F1 的数据流

`main → Navigation_Init/Start → LdsReceiver → LdsParser → ScanMapper → GridMap → PathPlanner → NavigationResult → NavigationReport`。

### 串口与启动

- USART2 为 PA2 TX / PA3 RX，921600、8N1，无流控。
- F1 使用 DMA1 Channel6，循环接收 256 字节。关闭 HT/TC 中断，主循环用 NDTR 推算写位置并逐字节读取。
- 开始时先发 `LSTOPH`，随后发 `LMDMMH`、`LOCONH`、`LFFF1H`、`LSSS1H`、`LSTARH`。指令都是六字节 ASCII，无换行；请求毫米、能量、去拖点、设备滤波，再启动。
- 原发送函数使用阻塞 HAL_UART_Transmit（超时 100ms），每条之后 HAL_Delay(20ms)。六条指令仅间隔等待就约 120ms。发送成功只证明 UART 发送完成，未逐条验证雷达已经应用。
- 启动末尾清空解析状态和事件队列，从当前 DMA 写位置开始读，排除启动前残留数据；也可能丢弃此前已经返回的状态帧。

### 帧解析

纯 C `lds_parser.c` 不依赖 HAL，允许任意分片输入，按小端解析：

| 类型 | 帧结构 | 校验/角度 |
|---|---|---|
| 普通包 | CE FA、N、起始角、N 个能量+距离、校验 | 长度 8+3N；相邻包起始角决定跨度 |
| 固定分辨率包 | CF FA、N、起始角、扇区角、点、校验 | 长度 10+3N；点间隔为扇区角/(N-1) |
| 状态 | ST、flags、三个保留字节、ED | 8 字节，记录单位、能量、去拖点、滤波 |

测量校验为点数、起始角、可选扇区角以及各点能量/距离的累加低 16 位。F1 每包最多 256 点，事件队列容量 2。统计字节、有效包、坏长度、坏校验和原始字节样本。

### 完整一圈与建图

- 首次起始角下降：丢弃前面的不完整圈，从这里开始累计；第二次下降：结束完整一圈。
- 普通包暂存到下一个包到来，再按跨度/N 插值。最后一个普通包先结算，再关闭这一圈。
- 原回绕判断是任何 `previous > current`，并未要求跨过 360° 附近。
- 角度为 0.1°；距离字段按 mm 使用。默认筛选 0～360°、100～40000mm、能量 0～255。
- Q15 正弦表做极坐标转换：X=230+d·sin(a)，Y=230+d·cos(a)。0°指向地图+Y，角度顺时针增加。
- 只累计格子点数，没有保存整圈点云。X/Y 边界均为 150、550、1000、1400、1850、2250mm，形成 25 格；统计区域为 [150,2250)，不能理解为整块 2400mm 场地都参加建图。
- F1 默认任一格出现 1 个有效点就设障碍；四个固定禁区为 R2C2/R2C4/R4C2/R4C4；五个任务点所在格受保护，不会被扫描设为障碍。

### 规划与输出

任务顺序是 1→5→4→2→3→4→2→3→1。每一段在 5×5 地图上做四邻域 A*，代价和启发值使用格中心的毫米曼哈顿距离，拼接时保留必要回退、去掉相邻任务段的重复连接点。最多 193 个路点。

输出包括障碍掩码、25 格点数、每个路点坐标、下一段距离、方向、转向与诊断。第一和最后一个点用雷达坐标 (230,230)，其他点用格中心。初末段的真实坐标连线可能不是纯水平/垂直，但方向仍来自格邻接关系，执行时应使用真实坐标，不能只按方向枚举和距离运动。

扫描超时为 10 秒；完成后停止雷达、同步规划、进入 PATH_READY。原 Navigation_Start 只接受 IDLE，完成/失败后需重新初始化或补充显式重新开始接口。报告通过 USART3 阻塞发送，整份终态报告一次输出。

## 3. 上位机与 F1 的区别

上位机先组装完整原始一圈，之后可以重新筛选、显示、导出 CSV；连续扫描每圈替换结果。F1 边扫描边累计格子，改筛选后必须重新扫描。

上位机支持报警帧 CE CE CE CE + code，点数上限 4096；F1 没有独立报警解析，上限 256。上位机用状态处理厘米/毫米切换，单位改变时丢弃半圈；F1 虽然解析状态，但 Navigation_Poll 没有将状态事件用于测量归一化或门槛验证。

源码默认障碍阈值：上位机为 3，F1 为 1。外边界上限：上位机允许恰好 2250mm，F1 使用半开区间排除。两端直接比较结果时要先统一这些规则。

上位机自定义 A5 5A + CRC16 协议用于暂存/应用/保存/读回配置及下发路径；F1 当前没有对应接收实现，只有 USART3 文本结果报告。因此“上位机有下载按钮”不等于这一份 F1 已支持下载。协议文档中只自动发启动/停止的描述也落后于 RadarCoordinator.cs 的五条启动配置，以代码为准。

## 4. 对照当前 F407 工程

| 项目 | 现状与移植判断 |
|---|---|
| 雷达串口 | 已预留 USART2 PA2/PA3，当前 115200，只有 GPIO/UART 初始化，没有 RX DMA 配置和 USART2 IRQ 接入 |
| DMA | F1 Channel6 不能搬来；需按 F407 映射配置，避免已用 UART5 RX Stream0、TX Stream7、USART3 TX Stream3 |
| 调试输出 | USART3 PD8/PD9 已是串口屏；不能移植原 NavigationDebugUart 对 huart3 的输出。应接入 USART1 ConsoleTx |
| 主循环 | 已有视觉、机械臂、电机、IMU、底盘和显示；必须控制雷达处理耗时，不能直接引入 HAL_Delay 和大段阻塞报告 |
| 运动执行 | 有 ChassisLocalization、ChassisMotion_MoveTo 和底盘路线模块，可作为将来执行入口；参考工程自身不含执行器 |
| 地图航向 | 当前底盘 yaw 从地图+X逆时针计 rad；雷达角度从其前方顺时针计，必须显式转换并加入安装位置/角度 |
| 工程维护 | 驱动放 Hardware，建图/规划/任务放 App，纯公共数学按实际复用放 System；同时维护 Keil/EIDE 清单 |

## 5. 必须调整的实现点

1. **接收容量与溢出识别。** 921600/8N1 的理论上限为 92160 字节/秒，256 字节约 2.78ms 写满；500000 时约 5.12ms。原读写位置相同无法区分“无新数据”和“已覆盖整轮”，队列满时退出会进一步增加覆盖风险。F407 应用循环 DMA，依据实测主循环最长间隔选容量（如 2～4KB 起步），结合半满/全满事件记录进度；仅 IDLE 不足以保障连续流。明确统计丢字节并丢弃受污染圈，不能仅增大缓存而宣称解决。
2. **启动和停止改为非阻塞状态机。** 用 tick 控制命令间隔，发送失败/状态异常独立报告，雷达不会拖住停车和电机任务。
3. **状态真正参与数据有效性。** 校验毫米、能量等配置；支持报警和串口错误恢复。状态未知与实际厘米要区分，不能默认 unknown 就表示厘米。
4. **圈完整性规则。** 防止角度异常下降被视为完整一圈，坏校验/覆盖要使扫描结果失效或标记质量，增加包数/角覆盖等证据；空地图不应只凭两次下降就当成可靠无障碍结论。
5. **坐标与车辆尺寸。** 安装偏移经车体 yaw 旋转后再平移至地图；测量方向由雷达安装方向减去顺时针扫描角换算。先明确车体前向、地图轴和安装角，不能把现有 IMU 值直接加到雷达角度。规划还需核对车体外廓、夹爪突出范围和通道宽度；原算法只检查格子，未做实际车体净空验证。
6. **扫描与路线独立。** 雷达扫描/规划结果先供查看，显式启动后才接入已有底盘任务互斥、超时和停车路径；不改写实车 16 段固定路线，也不让网页地图模拟自动运动。

## 6. 建议的移植顺序

### 第一步：只接收和诊断

移植 lds_parser、启动指令、结果事件和接收驱动，增加 F4 串口/DMA 适配。用 USART1 ASCII 命令管理扫描和状态，输出字节/包/校验/报警/单位统计。此阶段不调用电机。

验证：纯 C 解析回归；噪声、任意切片、最大包、坏长度、坏校验、报警、单位切换；F407 编译；实机检查串口流与主循环耗时/溢出。

### 第二步：静止单圈建图和规划

保留参考的普通/固定包插值和 5×5 A*，统一阈值与边界，增加明确扫描起点和安装变换。先在已确认位置静止扫描，输出地图、路径和失败段。

验证：同一批原始数据分别送 C# 与 C 实现，比较完整圈、各格点数/掩码和路线；随后用实物障碍位置核对结果。

### 第三步：显式低速路径执行

增加单独的路径执行状态机，逐路点调用 ChassisMotion_MoveTo，按真实坐标选择平移/航向策略。麦轮可以保持航向横移，原来的“转向”枚举不必逐个变成车体旋转。复用既有反馈和停车证据；启动前检查地图原点、方向确认、IMU资格、轮反馈和任务冲突。

验证：主机测试取消、失败、超时和任务互斥；上板先单段再多段，不把编译或模拟成功当成实车到位。

### 第四步：按需求扩展

如果希望边走边扫描，需要动态雷达位姿、数据时间和运动畸变处理，另行设计；当前原实现不是 SLAM。网页点云或地图可后续接现有本地控制台。不要为了复用旧上位机下载功能，把其二进制协议塞进现有 USART1 ASCII 控制台或恢复外部 Flash 方案。

## 7. 后续实施前需要的实物信息

雷达确切型号/版本及当前实际波特率（参考 F1 源码为 921600，不等同于当前硬件确认）、供电和 UART 电平/接线、车体安装偏移和朝向；目标是起点静止规划后运行，还是运动期间持续感知。软件分层和源码复用分析不依赖这些答案，本轮无需烧录或发送命令。

# LDS-50C 全局设备会话协调设计

## 目标

在保留现有“单次扫描”和新增“持续扫描”界面的前提下，让所有浏览器页面共享同一个可靠的雷达设备会话。浏览器刷新、同时打开多个页面或旧页面销毁时，都不能争抢串口、拆分数据流或误停另一个页面刚启动的扫描。

## 用户可见行为

- “持续扫描”启动后，雷达持续旋转；每完成一圈就更新点云、障碍格和规划路径。
- “停止持续扫描”发送 `LSTOPH`，保留最后一圈结果。
- 持续扫描期间，所有页面都显示相同的运行状态，并禁用冲突操作。
- 主动点击“停止持续扫描”停止当前全局会话。
- 页面销毁时，只能停止由该页面启动且仍然是当前会话的持续扫描；不能停止后来由其他页面启动的新会话。
- 单次扫描进行期间，其他页面尝试断开串口时得到明确的“设备操作正在进行”错误，不会强制关闭数据流。
- 断开串口时若持续扫描正在运行，先请求停止并等待停止流程结束，再关闭串口。在 `LSTOPH` 写入失败时仍关闭串口，但界面必须报告失败，不能显示“停止成功”。

## 核心模型

`RadarCoordinator` 是雷达串口操作的唯一仲裁者，统一管理：

- 连接与断开；
- 单次扫描；
- 持续扫描；
- 手动雷达命令；
- 当前持续扫描会话身份与失败状态。

协调器使用两个互补的同步边界：

1. 生命周期锁：串行化“开始操作、连接、断开”等状态转换，防止断开与新扫描在检查和执行之间插入。
2. 设备操作门：保证任意时刻只有一个串口数据消费者或雷达命令操作占用设备。

## 持续扫描会话租约

每次成功启动持续扫描都会返回一个不可伪造的会话租约，其中包含单调递增的会话编号。协调器保存当前会话编号。

- 显式停止按钮可停止当前全局持续扫描。
- 页面销毁使用“条件停止”：仅当它保存的租约仍与当前会话编号一致时才停止。
- 会话自然失败、被其他页面停止或被断开流程终止后，旧租约立即失效。
- 新会话拥有新编号，因此旧页面不能误停新会话。

## 操作流程

### 连接

获取生命周期锁，确认没有活动设备操作，再打开指定串口。完成后释放设备门和生命周期锁。

### 单次扫描

在生命周期锁内尝试获取设备门；若已占用则立即报错，不排队。获得设备门后释放生命周期锁，执行启动、整圈接收和停止，最后释放设备门。

### 持续扫描

在生命周期锁内确认没有当前持续会话并获取设备门，创建租约和取消源，然后启动后台逐圈解析。每个完整圈调用现有 `ApplicationState.SetRawScan`，自动重新筛选、分类障碍和规划路径。会话结束后保存失败信息、使租约失效并释放设备门。

### 停止持续扫描

显式停止或匹配租约的条件停止会取消后台会话并等待其 `finally` 写入 `LSTOPH`。停止写入失败作为操作失败向调用者和所有页面公开。

### 断开

断开流程独占生命周期锁：

1. 若有持续扫描，则取消并等待其停止流程；
2. 获取设备门，防止新操作插入；
3. 关闭串口；
4. 释放设备门和生命周期锁；
5. 若停止命令失败，在串口已关闭的事实基础上向界面报告该失败。

若活动操作是单次扫描而非持续扫描，断开立即拒绝，由用户等待单次扫描结束或超时。

## 界面职责

`RadarControlPanel` 不再直接打开、关闭或写入串口，只调用协调器。组件保存自己成功启动时获得的持续扫描租约，并订阅协调器的全局状态事件。组件销毁时使用租约执行条件停止。

串口下拉框仍通过只读枚举获取端口名称。波特率选择和 `921600` 的实际设备配置不改变本设计。

## 错误处理

- 竞争操作立即返回明确错误，不静默等待。
- 正常取消持续扫描不作为错误。
- 数据流结束、串口读写失败和停止命令失败写入运行日志，并通过协调器状态通知所有页面。
- 最后一圈成功扫描始终保留；停止或断开失败不能清空地图。
- 断开后的界面状态必须以“串口已关闭”为事实，同时附带停止失败原因。

## 测试

在现有假串口上增加以下回归测试：

- 持续接收至少两圈并逐圈更新，停止后写入 `LSTOPH`；
- 持续扫描占用期间拒绝单次扫描；
- `LSTOPH` 写入失败向调用者报告；
- A 页面租约失效后，不能停止 B 页面后来启动的会话；
- 单次扫描占用期间断开被拒绝且串口保持打开；
- 持续扫描与断开串行化，断开完成后串口关闭且没有新会话插入；
- 页面条件停止只作用于匹配的当前租约。

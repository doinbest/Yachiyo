# 八千代·巡航本地控制台

静止电机总线诊断可在终端显式发送`bus mode-test receive off 2`，轮询可选off/on、交接可选2/3/5 ms。只对四轮RAM应答模式切换、读回、观察1秒并恢复，不发送运动或驱动Flash保存；已有新鲜四轮静止反馈且任务空闲才受理。`bus mode-test status`只读缓存，`bus mode-test stop`优先取消并尝试恢复模式，不代替整车停车；恢复失败查看restored=0及具体原因。切换不是只读命令，仍受epoch和停止锁定约束。桥接分类更新需要重新启动本地服务加载；刷新网页、连接及重连不自动执行该诊断。详见[固件诊断记录](../../../docs/开发记录/2026-10-17-静止应答模式切换诊断入口.md)。

正式linear比赛支持倍率K（默认1，范围0.1～5）：先按基准路线总限速与路段基准限速取较小值，再将最终平移速度、起步加速度及停车减速度各乘K一次。基准总限速默认1000，实际总限速=基准总限速×K；基准及实际总限速均须10～5000 mm/s，超范围明确拒绝。包含扫码、工位贴近/换环/退出、右上连续换向及第二批连续路径的平移限速与加减速；转向上限、视觉纠偏、机械臂、等待、几何及到点/停稳判据独立。K随本轮受理锁定，暂停/继续/总线恢复保留；独立动作使用原默认。cosine兼容入口仅接受K=1，不能与余弦K200混用。新命令可在末尾追加scale=<K>，省略为1；设备报告route_base_speed、route_scale及实际route_speed，网页草稿预览与设备读回分开，编辑/刷新/重连不发送。

比赛任务默认开启视觉航向矫正；其余初值为实际扫码、右下起点、雷达关闭、高位Z=0、路线1000 mm/s、转向100°/s、linear。色环矫正独立最高10°/s；黑线仍需独立标定。刷新网页后新默认用于下一次显式开始，不自动发车或改变暂停比赛。完整默认参数表见[视觉任务手册](docs/视觉任务.md#比赛任务卡片默认配置)。

“视觉任务 → 物料取放 → 固定夹取与静态对准 → 仅协同对准”提供静态收敛增益λ输入及显式读取、应用并核对，范围0.001～10、默认草稿2.5 s⁻¹；设备值单独显示，挂载、编辑、刷新与重连不发送。该参数由静态颜色/编号环/工位对准共用，动态追踪λ独立。正常静态纠偏按新有效帧更新的固件状态见[开发记录](../../../docs/开发记录/2026-10-16-静态对准新帧调度与增益入口.md)，操作见[视觉任务](docs/视觉任务.md#静态协同对准的λ)。

linear单段测试支持独立起步加速度与停车减速度，各10～5000 mm/s²；网页初值500/300，参数受理后锁定，只覆盖本次独立动作。旧指令只给一个加速度时仍同时用于加、减速；固件省略参数、普通MoveTo及比赛路线保留300/300。制动包络用停车减速度，速度矢量减少当前平移动量时用减速度、增加时用起步加速度；前进与后退一致。普通linear直线到点进入位置/航向窗口后，先让平移参考按减速度降至零，再请求同步零速及真实停车确认；人工停止、取消和故障仍立即请求停车，原地转向和连续路径主体沿用独立控制。cosine参数及航向默认P0.02/D0不变。

底盘控制计算目标周期为1 ms；直线平移曲线更新周期默认1 ms，独立单段测试可在上位机填写1～100 ms整数。曲线周期只决定平移速度参考（含位置收敛、制动包络及加减速限制）的更新时间，中间复用最近参考；坐标系转换、按新鲜IMU更新的航向纠偏、四轮分配和到点/停车检查仍按控制循环执行。1 ms与1 ms时同频；例如曲线5 ms时，中间控制循环复用平移参考。参数受理后锁定，仅覆盖本次独立测试，后续普通任务恢复默认1 ms；原地转向、连续路径仍用各自控制。控制周期是主循环调度目标，不保证硬实时1 ms、IMU每1 ms出新样本或串口四轮批次每1 ms生效；同值去重、最新待发目标替换、同步批次及反馈组调度保留，不补发历史积压。

视觉航向独立测试可选择色环或暂存区前方黑线；比赛第二批暂存码垛自动使用黑线，设备状态回传采用来源。色环0D和黑线0E分开匹配；正式比赛色环按已验证反号1∶1执行IMU闭环校正，黑线未标定仍仅观测，详见[视觉任务](docs/视觉任务.md)。

界面默认使用粉色主题（深粉背景、浅粉高亮），可切换黑色背景；原蓝色主题偏好自动采用粉色。物料颜色及地图数据图例保留实际含义。
本地Python串口服务与浏览器操作台，共享F407 USART1无线链路；网页提供任务操作、参数读回、地图和诊断。串口命令与完成语义见[协议索引](../../../docs/上位机协议.md)。

## 启动与连接

系统与标定页新增“电机只读诊断”，默认选择ID5 Base；可读实际相电流、供电电压、位置误差、驱动回零参数及电流上限。也可手动发送 `bus read 5 current|voltage|error|home|driver`，其中竖线表示任选一项。需新固件、重启更新后的本地服务并刷新网页；任务空闲时读取，停车锁定期间允许，读取不修改驱动参数。

1. 安装Python 3和pyserial；缺少时执行 `python -m pip install pyserial`。
2. 双击本目录 `start.cmd` 或上一级 `启动控制台.lnk`，也可在本目录运行 `python serve.py`。
3. 用Chrome/Edge访问 `http://127.0.0.1:8765/`，刷新串口列表，人工选择实际设备并连接，默认115200/8N1。

服务只监听回环地址，无需npm安装或云部署；不要直接双击HTML。启动不自动连串口，页面切换、刷新和重连不发送运动或雷达启动命令。快捷方式移动项目后须调整路径。退出服务前停止任务并确认反馈，再断开串口；服务终端输入 `quit`。

## 操作入口

底部“解除停止锁定并恢复底盘”显式点击后按需完成总线恢复，兼容普通恢复完成和本次比赛保留恢复的paused/bus_recovered回复；比赛路径确认停稳、非自动续跑并重读底盘状态后，再开启四轮反馈并等待新鲜静止数据；保留有效原点和IMU验证，不自动运动。固件准入仅向真正paused且当前停车证明有效的比赛放行精确反馈0/on，缓存查询保持只读，新停止撤销准备资格。失败显示具体原因并可重试。网页刷新后加载显示；本轮固件准入需后续编译下载才在设备生效，未编译烧录。比赛成功后仍保持暂停，由用户显式继续。详见[停车与恢复](docs/连接与恢复.md#停车与恢复)。

独立IMU异常进入`imu_recovery_wait`时，比赛卡区分停车待确认与已停稳但定位待恢复，保留本轮进度并禁用继续；恢复为`paused/imu_recovered`后才可点击“继续当前阶段”，页面不会自动发车。新比赛准备暂停不接管旧done路线。源码、网页及待实车状态见[五项修复记录](../../../docs/开发记录/2026-10-16-比赛恢复与IMU资格五项修复.md)。

“底盘单段运动测试”点击开始直接提交运动，不重复准备；状态区显示设备最近回报与年龄，“查询状态”只读状态，反馈或参考缺失时再点“准备/恢复测试状态”。显式准备复用有效参考，仅补缺失项，完成不自动发车；运行后自动读取结果；卡片内“停止测试”共用真实停车链路。linear分别填写本次起步加速度和停车减速度，网页初值500/300、各10～5000 mm/s²；cosine增加K值输入，默认200、范围10～2000整数，过渡时间K×2 ms；两种模式均可填写航向P、D，各0～1，默认P0.02/D0。测试结果显示设备实际采用的加速度/K和P、D，不读取当前表单草稿；这些参数只覆盖本次独立测试，不改比赛路线默认值。结果同时显示设备采用的减速度，未回报时不猜测。本项需要更新配套STM32固件并刷新网页，本地服务沿用现有长命令接口。尚未实车验收。详见[单段测试](docs/地图与雷达.md#单独测试当前路线加速度)。

比赛转向速度的网页输入范围为5～500°/s，默认100；底盘“平移与转向测试”和“持续速度控制”允许输入±500°/s。此为上位机输入上限：当前固件比赛/定时转向仍限制100°/s，持续速度控制仍限制360°/s，超限命令会被设备拒绝。更新后刷新网页即可加载；视觉航向单次试转保留原低速范围。

“机械臂与夹爪 → 夹爪舵机”提供打开2450 μs、夹取1920 μs两个默认按钮，另有500～2500 μs自定义输入，点击“应用脉宽”才改变当前开口。输入、刷新、切页与重连不动作；测试值不覆盖自动任务默认。网页换算后使用现有`grip duty`指令；自动默认2450 μs需对应新固件。

车仓取料曾实测使用2120 μs，见[10月14日记录](../../../docs/开发记录/2026-10-14-统一DXDY与物料台一次横移.md)；当前车仓下降前使用2120 μs防碰开口，普通自动打开和自定义输入预填2450 μs。自动流程在Base回仓转向时设置2120 μs并开始car_pick_wait_ms（默认100 ms），下降前核对ID8/Base到位及等待时间；已闭爪续接不重新开爪。手动自定义输出不改变自动默认。

“机械臂与夹爪”提供PD12 / TD-8125MG雷达盘控制：实测转出扫描2450 μs、收回车内1450 μs两个按钮，保留手动脉宽输入和查询；旧五档快捷值与停止PWM已删除。需新固件、重启本地服务并刷新网页。详见[转出与收回](docs/地图与雷达.md#雷达盘转出与收回)。

## 开发与验证

`app.mjs`组织界面，`protocol.mjs`定义命令，`parameter-schema.mjs`及相关模块管理参数；`serve.py`/`serial_bridge.py`管理共享服务及串口队列。雷达主流程在实车监控：采集15有效完整圈，或持续更新最近15圈；下方默认情况2安装，保留车体与工位坐标。稳定XY、安装/仿射/窗口均按设备冻结结果显示和导出，雷达建图页通过F407主机接口提供原始最后圈、preview120及完整诊断对照。停止采集、取消下载与取消路线是独立操作；本机保存不发设备，重连不续采。两页均连接当前正式F407固件、共用F407 C算法；f1_host为历史协议名称，前期F1源码保存在reference中。保留的直连雷达模块只供独立诊断。

抓取参数默认值/范围由[grab_parameters.def](../../template/App/grab_parameters.def)维护，仓库根运行 `python Code/tools/sync_grab_parameters.py`生成网页元数据。不要手写第二套默认值。

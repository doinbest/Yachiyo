# 视觉、取放与赛事操作

X/Z固定目标动作使用当前轴配置的驱动加速度档位，默认X20、Z255；场景速度和有限绝对终点保持，MCU不再周期重发余弦调速。视觉连续纠偏、渐进下降、回零、Base和ID8沿用各自控制。到位、停稳、机械限位和驱动故障检查保留；Z先抬到0再收X，取仓避让X30 mm并行规则不变。比赛卡片可选底盘linear300或cosine K200，受理后锁定；设备采用模式以读回为准。

当前要求见[比赛与取放约定](../../../../docs/比赛与取放约定.md)，硬件基线及源码/设备状态分别核对；历史开发记录保留各次事实。

2026-10-13比赛动作衔接已优化，继续使用现有“开始本轮比赛 / 暂停比赛 / 继续当前阶段 / 停止比赛”，无需网页额外写入参数。每批末件入仓后直接转入行驶准备，不再返回观察再收回；进站、工位换位与离站时，确认Z提起和X收回后，Base剩余转动可与底盘平移重叠，双方完成后才开始下一项作业。共线同向的纯途经点可连续通过，转角、扫码及工位仍按原边界执行；当前固定地图没有可合并的共线纯途经段，该项用于含此类点的规划路线。三种并行暂停/续接及两批取放已通过主机模拟，实车仍需验收，见[实施记录](../../../../docs/开发记录/2026-10-13-比赛动作连续衔接.md)。

共享串口连接方式见[控制台入口](../README.md)。切换页面和标签不发送命令；“仅识别”不运动，点击对准/追踪/取放才进入对应任务。完整字段与错误原因见[机械臂协议](../../../../docs/协议/机械臂与取放.md)及[B2/追踪协议](../../../../docs/协议/视觉B2与动态追踪.md)。

2026-10-12统一比赛功能已按[流程设计](../../../../docs/superpowers/specs/2026-10-12-统一比赛任务流程设计.md)集成。正式入口在“比赛任务”，单项联调入口继续保留。车仓入/出均保持X收回，旧参数已删除；需烧录新固件后生效。软件验证与实车验收分开，见[实施记录](../../../../docs/开发记录/2026-10-12-统一比赛任务实现与验证.md)。

夹爪舵机重装后方向与最早结构相反，2026-10-12再次确认当前值：`grip open` 为2500 µs（12.5%），`grip catch` 为1920 µs（9.6%）；手动对应 `grip duty 12.5` / `grip duty 9.6`。网页按钮显示脉宽，手动占空比预填9.6%。自动取放调用同一预设。旧结构松开500 µs、抓紧700 µs仅保留作历史对照，详见[硬件基线](../../../../docs/硬件与运行基线.md)。

## 参数与准备

正式比赛加工进站为(1200,380)到点转至180°后视觉接管，删除固定125 mm贴近；同次工位作业保存首次成功对准的实际底盘XY及环号，后续按环距150 mm保留位置偏移换环，每件仍重新视觉确认，加工取回顺序不变。中心到暂存区在中心停车，按较小转角选0°倒车或180°前进至(425,1200)，停车转90°作业朝向，保留最后75 mm低速接近。暂停/恢复保留工位锚点，再次进站重建；无需网页写入新参数，预览共用固件C核心。

静态对准靠近准心（DX/DY均在各自容差2倍内）时，短时漏检会停车等待新帧并保留识别数据流，不每次重发识别；有效坐标持续缺失达到loss_grace_ms（默认250 ms）才在停稳后重获。恢复需停稳后的3次新鲜有效坐标，再重新满足正常对准稳定条件。人工暂停/继续仍保留原流程，动态追踪使用其独立宽限机制。

参数页先读回设备值，再显式应用改动；浏览器预填和本机保存不等于MCU值。抓取默认值/范围统一见[grab_parameters.def](../../../template/App/grab_parameters.def)，轴config的acc为Emm档位，grab/track accel为MCU mm/s²。参数只存RAM，复位恢复源码默认，普通停止保留。未知加工/暂存高度留空并显示具体缺项，不自动代填。

Base回零位置就是夹爪朝向车仓；作业准备为回零锚点+130°，返回车仓默认base_car_offset为−130°。ID8仓位角度0°/+90°/+180°独立于Base。任务姿态准备仍先核验Z抬起和X收回再转Base。任务到位容差2°，2～5°残差低速重发原绝对目标，不进行FD模式2相对补偿。上电先并行启动Z/X碰撞回零与ID8车仓就近回零；Z/X验证完成且ID8建立回零参考后，再启动Base就近回零，全部完成后才进行IMU验证。需重建三轴参考时执行 `grab rehome`，同样先Z/X、后Base，不会重放已完成的上电ID8回零；手动单轴回零与 `turntable home` 保留。ID8回零对应仓1，仓2/3相对仓1为+90°/+180°（2026-10-13结构调整后），已由用户确认；当前固件默认已同步为0°/+90°/+180°，运行RAM值仍用get读回；库存按实物核对。

“机械臂与夹爪”轴控制区提供“设置机械零点”（`origin <axis>`）、“就近回零”（`home <axis> near`）和“碰撞回零”（`home <axis> collision`），均作用于当前选中的 Base、Z、X 或全部轴。设零将当前单圈机械位置保存到驱动器，不移动电机，也不同于当前位置计数清零；回零使用驱动器已有参数。Base 通常用就近回零，X、Z 通常用碰撞回零；选择全部轴时，同一方式依次用于三个轴。单轴手动回零受理不表示运动完成。只有 Base 就近回零后的参考待验证时，可直接点击“准备抓取姿态”：固件确认本轴回零完成、稳定位置及使能反馈，建立后向锚点后继续准备，不重发 HOME，也不重新回零 X/Z。X/Z 原点或全部参考需要重建时仍用 `grab rehome`。

准备过程中只想停下，点击“停止准备”（`grab stop`），等待 `stop_confirmed=1` 后可以直接再点“准备抓取姿态”。普通停止保留后向锚点和配置；重新准备用本次新鲜停稳位置判断，已经抬起的 Z、已经收回的 X 和已到目标角度的 Base 不重复运动。Base 转到一半停止时，重新准备只补剩余角度。已处于目标姿态时仅读取并确认，返回 `work_ready`。在局部回零验证期间停止会取消后续准备，不自动续跑；Base 单独回零失败时可按下节降级确认继续；其他故障或已被中断时，排除问题后仅重新执行 Base 就近回零，再点准备。

Base共用作业转角按当前要求统一为130°，用于视觉姿态、抓取准备及持料作业。使用时需与既有工位车体朝向及路线转向衔接，Base机构转角不替代地图车体yaw。当前按钮发送 `grab pose work`，源码已统一按后向锚点加130°准备，任务共用准备同步更新。作业到车仓默认偏转−130°，车仓朝向就是Base回零锚点；ID8的仓位角度独立管理；需烧录新固件后生效。

Base 回零默认允许降级继续（`base_home_degrade=1`）：驱动仅报回零失败时，确认 HOME 已结束、新鲜位置稳定、使能正常、无保护故障且实际转速连续两轮为 0，再接受当前位置为近似车仓参考并继续。任务状态持续显示“Base 使用降级参考”；这不代表精准回到驱动保存零点，后续 +130° 准备及回仓会带入参考偏差。过温、过流、堵转保护和反馈失败仍停车。严格验证可在“参数调试 → 运动与标定”将该参数设为 0 并读回，复位恢复默认 1。

严格模式失败或降级验证超时后，人工确认夹爪已接近车仓方向，可展开本页“回零与通信恢复”，点击“确认 Base 近似参考并继续”（`grab home accept`）。仅本次 Base 失败且 X/Z 已验证时受理，仍重新核验停稳，不重发 HOME 或重复 X/Z；不会自动重启已取消的准备。若准备已中断，验证完成后再次点击“准备抓取姿态”。

## 静态颜色与编号环

颜色用 `grab align color <1..6> [z_mm] [stay]`，编号环用 `grab align ring <1..3> [z_mm] [stay]`。旧grab ring align/start align保留兼容，旧vision入口退役。所有入口直接使用视觉B2的DX/DY，包含真实零值；编号环和物料的准心由视觉端各自管理，STM32不重算。旧ref_u/ref_v参数及网页输入已删除。

编号环页选择环号与对准高度，启动后从朝后姿态收X、转Base，到位才识别，不预伸50 mm。识别后先横向接近，随新坐标逐步下降；靠画面边缘暂缓下降，重新进入中央区域继续。达到目标高度、像素窗口并停稳后，“对准后抬高”只抬Z至最高等待装料；“保持低位”用stay保持高度并显示偏差，不继续运动纠偏。

对准后可人工装料、闭爪，再使用独立放置高度执行 `grab ring place <z_mm>`，只下降/松爪/提起，不取仓或改库存。手动环放置默认−140 mm来自用户实物验证；固件仍按当前Z配置核验。用顶部停止并退出结束识别和任务，等待停车确认。

## 手动码垛

1. 选择下层颜色，点击“码垛视觉对准”：`grab stack align <颜色>`。香橙派已包含码垛补偿，STM32直接按DX/DY归零对准、停稳后等待装料，不再追加39/−1偏移。漏检恢复使用同一偏差来源。
2. 人工装入上层物料，`grip catch`闭爪。
3. 用 `grab stack lower <z_mm>`调整绝对高度，可以向上移动或覆盖未完成目标，下降不松爪。
4. 用 `grab stack release`独立松爪，保持高度；`grab stack lift`另行提起。

高度尺滚轮每格1 mm，停滚1秒才发送最后高度；停止/断线/切页/故障/重启取消待发，不重放。STM32不再计算码垛补偿，目标点由视觉端管理。本测试不取仓、驱动ID8或改库存。

## 原料追踪夹取与入仓

2026-10-13起，车仓选仓共用逻辑改为：1号仓执行ID8单圈就近回零，2/3号仓继续最短方向定位。仓1等待`OK turntable home complete ref=1`及停稳反馈后才进入Base回仓；已有库存不会因这次回零被清空。入仓、取出及比赛流程同步采用，网页按钮和命令用法不变；需编译烧录新固件后生效。

“视觉任务 → 物料取放”统一承载原料追踪夹取与入仓、单独追踪、车仓取出、固定夹取和加工取回。已移除独立“动态追踪”标签；原追踪链接自动进入物料取放。原料区共用一套颜色、夹取条件、目标仓位和状态；主按钮为“追踪夹取并入仓”。单独跟随/只夹取收在“单独追踪与夹取”，三种模式参数收在“独立追踪参数”，实时记录、导出及诊断收在“追踪记录与诊断”。固定夹取与旧静态测试折叠保留；STM32命令、取放任务和库存语义不变。

1. 完成回零后直接选择1/2/3号目标料盘；明确选盘并启动入仓即表示该盘可用，不需要额外确认空仓，软件UNKNOWN或旧OCCUPIED记录不阻止指定仓入仓。仓位固件默认1/2/3为0°/+90°/+180°。自动选仓仍只选择软件记录为空的仓，普通停止保留参考和库存。
2. 点击“准备抓取姿态”。Base到后向参考+130°后自动打开夹爪2500 µs；准备中同一红色按钮显示“停止准备”。
3. 选择颜色、目标仓、追踪方式（默认纯视觉＋反馈减速）。设定夹取高度、夹取后上升距离、入仓下降距离。默认Z夹取−50 mm、上升50 mm到0、从0下降60 mm到−60；下降速度保持111.11111111 mm/s，夹取窗口±100 px、视觉保持至少10 ms。上升目标=夹取Z+上升距离，入仓目标=上升目标−下降距离，不是机械零点到料盘的距离。
4. 点击“追踪夹取并入仓”。网页显式写入并逐项读回夹取条件及高度/速度参数，全部一致才发送一次`grab track pickstore <颜色> <仓0..3> <模式>`；仓0自动选择最低编号已确认空仓。STM32观察并追踪，双轴±50 px开始下降，Z到位且满足闭爪窗口/保持后停车，新鲜坐标及机构停稳确认后闭爪。10 ms是最小保持时间，实际要等下一帧，仍需停车确认及闭爪等待，不代表10 ms内夹住。
5. 完整入仓链为提起、收X、ID8分度并确认到位、Base转到已验证车仓参考、下降松爪，等待`release_ms`（默认300 ms）后记录库存，再提起收X并返回本轮保存的Base/X/Z观察位置。全程车仓X保持收回，旧伸X参数和动作已删除。Base回仓不重新发HOME；ID8的相对仓位角不作为Base角度。最终`result=stored`才表示完整结束；用户明确此入仓动作尚未实车测试。

“只追踪夹取（不入仓）”仍返回`picked`并保持物料。之后可选仓点击“将已夹取物料入仓 / 继续入仓”，发送`grab track store <仓0..3>`，不会再次下降夹取。入仓中点击“停止追踪 / 入仓”请求全部相关机构停车，夹爪保持当前输出；未释放时保持物料，放料已开始但尚未完成的仓位标为待核对。等待停稳、排除故障后，仍持料或释放尚未记账时选择原仓位显式继续，仓0也可续接原仓；本次颜色、转移/放料高度与返回姿态保留，修改草稿不覆盖已在进行的搬运。松爪之后续接只补库存记录及返回，不重复闭爪或再投料。已完成释放等待和库存记账、仅剩返回动作时，停止后可以直接选择其他颜色/仓位开始下一件；固件先补齐提起、收X、Base到准备方向，再进入新追踪，不再要求先完成上一件的Z/X观察位置返回。新准备期间再次停止会取消待启动任务。无有效夹持上下文、续接仓位不符、车仓参考缺失或自动选仓没有空仓时拒绝，并在任务状态说明原因。夹持与库存是软件记录，没有新增物料传感器。

刷新、切页和重连保持被动，不写参数、不启动或自动继续任务；烧录后固件使用新默认，网页输入仍是草稿，点击启动时会按草稿显式应用并核对。只更新网页不会改变现有MCU RAM。

## 车仓取出并保持

“视觉任务 → 物料取放”独立卡片“车仓取出并保持”：选择1～3号料盘及下降/等量上升距离，默认40 mm。Z从`z_max`下降夹取；夹取前X保持收回，等待car_pick_wait_ms（默认300 ms）。夹取1/2号盘后，Z上升同时X从收回位置向外伸30 mm，两轴到位后保持X避让位置转Base至参考+130°；3号盘夹取后仅升Z、X保持收回。完成后保持闭爪，不调用会开爪的`grab pose work`，不向外部工位释放。当前正式任务按1/2/3号盘依次取出，分别对应第一/第二/第三件。

固件在Base位于外侧且静止时，让ID8分度与提起、收X并行；否则先完成机构避让再分度。X/Z和ID8均确认到位，再让Base回已验证车仓参考，X保持在收回位置`x_min`。车仓分度和Base到位后设置2120 μs取料开口并等待car_pick_wait_ms（默认300 ms），才下降、闭爪；按原`close_ms`等待后提起，并按盘号执行上述X避让，两轴到位才将该仓库存置空并转Base到+130°，返回`operation=car_pick result=picked`。这是按用户所选料盘执行的手动动作，不要求登记库存或物料颜色；即使软件库存为UNKNOWN或EMPTY也能启动。仍需有效后向/车仓参考。夹取后以及已闭爪续接均不自动打开夹爪。

2026-10-13取料开口实测为2120 μs，夹取仍1920 μs、默认手动打开仍2500 μs。暂停/续接已闭爪阶段保持夹爪；初始化、原料准备和最终放置释放不随本次改动改变。对应版本已有后续烧录记录，设备当前版本和实车效果另行核对。

按钮发送一次`grab take <仓1..3> work <下降mm>`，无需网页定时拼接动作；终端省略距离时发送`grab take <仓> work`，读取固件参数`car_pick_drop_mm`（默认40 mm，RAM参数）。car_pick_wait_ms等待（默认300 ms）为固件非阻塞阶段，停车仍可立即请求。手动work流程已不需要旧车仓伸X参数；本次用户进一步确认入仓也保持X收回，统一计划将全局删除旧参数及其其它引用。输入距离必须大于0且不超过150 mm，实际目标还要满足当前Z行程。软件已知仓内颜色时保留记录，否则状态color=0表示未指定，页面显示“无需指定颜色”，不默认记作红色；不启动颜色识别。

使用卡片的“停止车仓取出”请求停车，“读取取出任务状态”查看原因和确认结果。停止保留夹爪输出及本次仓位/颜色/高度；等停稳后选原料盘再次点击启动即可续接。尚未闭爪时重建取放准备并重新等待car_pick_wait_ms（默认300 ms）；已闭爪时从提起续接，不再次闭爪，不重新分度取另一件。夹取开始但提起尚未确认时，仓位标待核对；同一任务续接后再确认置空。已进行任务的距离不会被新的输入草稿覆盖。原“车载取出并释放”的粗加工/暂存场景流程保留。

## 动态追踪与夹取

入口已并入“物料取放”。展开“单独追踪与夹取”可选择预测、纯视觉、反馈减速或只夹取不入仓；共用上方颜色和夹取条件。“预测追踪”即原“一键持续追踪”，协议不变。

物料视觉默认准心为(372,345)。原预测、纯视觉、反馈减速三种追踪均直接采用B2有符号DX、DY，零值就是到准心，不回退到CX/CY减旧参考。后续结构变化可修改香橙派启动参数`--center-x/--center-y`；CX/CY仅保留为诊断坐标，全部视觉控制不再用MCU静态参考重算目标。需要匹配的本地固件与视觉版本；本地源码修改不代表远端已部署。

遇到“姿态准备请求被拒绝；请读取抓取任务状态”时，在“视觉任务 → 动态追踪”点击“准备抓取姿态”旁的“读取抓取任务状态”。该按钮只查询 `grab status`。点击“查看抓取任务状态反馈 →”可跳到本页下方的“抓取任务状态”，先看阶段和“原因”，缺少参数会直接列出；“参考状态”在“完整反馈与诊断”中。页面顶部也提供同名查询按钮，其他视觉任务页可使用。

“读取追踪状态”查询动态追踪反馈；准备期间原快捷查询显示为“读取准备状态”。明确名为“读取抓取任务状态”的按钮始终查询抓取任务，不启动准备、回零或重试。收到拒绝提示本身不会自动查询或重复执行动作，应以查询返回的具体原因处理。

1. 香橙派B2程序运行，点击“准备抓取姿态”（grab pose work），等待work_ready。
2. 选择颜色，“一键持续追踪”（grab track begin）先等待本轮停稳反馈及新鲜视觉，缺少参考才建立；首次预算允许0～50 mm，已有参考/已耗预算不充值。
3. “只追踪夹取（不入仓）”（grab track pick）在新鲜DX、DY均进入±50 px时开始下降，底盘/X继续追踪。新坐标移出该窗口时仅暂停Z，重回窗口续降；短漏检沿原250 ms宽限处理，持续漏检停住底盘/X/Z等待恢复。闭爪窗口独立使用track_pick_tol_px（默认±100 px），新鲜坐标在窗口内连续保持track_pick_hold_ms（默认10 ms）且Z反馈到位后开始停车确认，停稳后再次核验新鲜坐标再闭爪、提起。保持计时可在下降期间累计，只由新测量推进；超窗、无效坐标或超过当前模式漏检宽限会重计，重复帧不能完成保持。保留实际到位/停车反馈，不预测整段下降漂移。高度/下降速度读取共享z_grab/z_pick_speed；完成picked保持物料，不自动入仓或改库存。

“动态追踪与物料夹取”卡片可修改“夹取误差窗口”（1～100 px）及“夹取连续保持时间”（0～10000整数毫秒，0为不等待）。使用“读取夹取条件”查看设备值，“应用夹取条件并核对”只写参数；点击“只追踪夹取（不入仓）”先写入并读回核对两项，再发送一次启动命令。设备拒绝、读回不符、停止或断线不会继续启动；刷新、切页和重连不自动写入或启动。参数存于设备RAM，普通停止保留，设备重新上电恢复默认值；窗口不改变水平追踪纠偏tol_px，保持时间也不改变停车稳定时间stable_ms或闭爪等待close_ms。
4. 短漏检按现行250 ms宽限减速/预测，持续缺失停车等待。行程窗口不足时停稳后继续观察，新有效目标回到可追范围可在原预算内自动续追。人工停止结束本轮，不自动重启。

仅观察与reference/start仍保留独立串口入口。X行程/50 mm预算是当前几何与机械条件，不是自动测距。实际发送节奏由Receive应答与反馈轮转决定，20 ms预测或300 ms摘要不能当每台电机的发包周期；状态页查看触发反馈年龄和真实计时。

### 停转过调对照验证

原“一键持续追踪”和“只追踪夹取（不入仓）”继续使用预测算法。新增两个按钮只跟随，不下降、不操作夹爪：

| 按钮 | 命令 | 用途 |
|---|---|---|
| 纯视觉追踪 | `grab track visual <颜色> [首次余量]` | 新鲜坐标直接纠偏，去掉物料速度/加速度拟合、外推和前馈；执行方式与原追踪共用 |
| 纯视觉＋反馈减速 | `grab track feedback <颜色> [首次余量]` | 在纯视觉基础上，以实际反馈速度和底盘/X独立加减速参数安排减速 |

每次比较先点击停止，等“实际反馈已确认”，再切换入口。已有参考和剩余接近预算继续沿用，首次余量输入不会给旧参考充值。普通停止、网页刷新和重连保留设备RAM参数；不自动恢复运动。验证模式先取得本轮停稳反馈和两次不同时间的新坐标，再开始跟随，不等待240 ms拟合窗口。

参数区选择原预测/纯视觉/反馈减速，再显式“读取全部”或“应用并核对”，三套参数独立保存。2026-10-12纯视觉和反馈减速默认调整为底盘160、X60 mm/s、lambda2.0、X前瞻60 ms；原预测组保持底盘160、X60 mm/s、lambda2.5、X前瞻120 ms。本次恢复追随速度上限，提高纠偏需求，保留较短X前瞻；提前减速算法未在本轮调整，过调仍需实车比较。共同初值仍为联合加速度300 mm/s²、X权重2.333333、窗口±5 px、最大领先12 mm、控制间隔20 ms、额外批次限频0、漏检宽限250 ms。反馈模式另有`body_accel=300`、`x_accel=120` mm/s²，分别用于底盘合速度与X的加减速；这些是软件联调初值，不是实测机械能力。底盘驱动档位仍20，X仍读取`config x`，不自动设0。

使用本轮预设：先停止并等待实际反馈确认；使用更新后的网页，展开“独立追踪参数”，选择“纯视觉追踪”，点击“填入追踪预设”再“应用并核对”；对“纯视觉＋反馈减速”组重复操作。点击“读取全部”，确认各字段下方“最近读回”为底盘160、X60、lambda2、horizon_ms60；输入框是草稿，不能代替设备读回。填入预设、选择模式、刷新网页均不发送参数；需要显式应用才能修改当前设备RAM。普通停止和切换模式保留已有参数，原预测组不跟随重置。新版固件初始化会使用各组新默认，但本地编译不代表已经烧录。

验证模式不使用`fit_ms/latency_ms`；`horizon_ms`仍用于将X速度变成有限领先的位置指令，不预测物料轨迹。无新坐标时按最近有效帧间隔加一个控制周期保持最近速度，下限两个控制周期、上限原宽限；尚未测得帧间隔时沿用原宽限。超过保持时间开始平滑减速，明确无效坐标立即开始平滑减速。超过原宽限进入停车等待，恢复后在原预算内继续。重复快照不重复求旧误差的纠偏。

记录里的`mode=predict|visual|feedback`绑定每条实时/冻结行的CRC，导出时保留参数所属`profile`。对照记录同方向、相近速度的移动→停转过程，分别评价运动跟随偏差、停转后的最大偏差、反复次数和收敛时间；软件模型通过不代表实车过调已改善。

整段调参记录按以下步骤使用：

1. 点击“开启实时记录”。网页先读回13项设备追踪参数，再开启逐帧像素订阅，不启动运动。每个合法B2回复都记录目标编号、有效/漏检、当前目标匹配、中心CX/CY、MCU接收时间和序号；不按10 Hz抽样，不重复传包头、偏差和其他可推导字段。“保留速度诊断”默认勾选，默认1000 ms（5 Hz），可选50/100/500/1000 ms；间隔只影响速度诊断，可取消勾选只记录像素。参数读回失败会显示“参数读回不完整”及原因，仍尝试开启记录以保留诊断；不会把草稿或未读回参数填作设备实值。
2. 启动观察/追踪，期间本地服务把实际收到的原始字节持续落盘，不限128条或500条。保持服务、串口和设备在线；浏览器刷新不清磁盘文件，也不自动重开订阅。
3. 停止追踪并确认实际反馈停稳，再“关闭实时记录”。关闭记录不停车。
4. 展开“整段记录与完整 TXT 导出”，点击“读取磁盘记录”，选择服务记录和追踪段。页面显示校验通过条数、候选数、缺帧、损坏行、数据跨度、有效/漏检回复、接收均频、设备放弃入队数、速度诊断数和参数项数；未收到开始/结束标记的段不会称为完整。
5. “导出整段追踪 TXT”保存该订阅开始到结束的全部接收文本，并附开始前最近设备参数读回；损坏行和未结束的尾部原样保留。“导出完整接收 TXT”保存选中文件的全部RX字节；“导出完整收发 TXT”附实际时间、TX/RX/系统事件。历史文件在服务重启后仍可读取。导出期间继续接收时，以点击时的文件边界为准，结束后可再次导出。

原始数据在 `.embeddedskills/logs/serial/`；清空终端只清网页缓存。“导出本段”仍是最近128条冻结窗口，不是整段历史。分析用 `python Code/tools/tracking_report.py <整段追踪TXT或rx.bin> --source live --kind physical`，实际转速/方向人工记录，不能把模拟标为实车。

逐帧记录在Camera逐个解析合法B2回复时生成，粘包中的中间帧也保留；Valid=0作为漏检记录，m=0表示不匹配当前控制请求。收到的是MCU接收时间，不能当摄像头曝光时间。源码中视觉链路是USB CDC，115200串口用于电脑回传。像素采用现有回复FIFO顺序发送，积压时统计dropped，停车仍优先；无线链路损坏用序号/CRC发现。不会宣称未经实测的无损50～60 Hz，也不能从128条缓存补造历史。当前固件需更新后才能使用逐帧订阅；只更新网页不能让旧固件支持PIX。直接`grab track log start`仍保留默认50 ms的旧速度诊断入口。

- 单件物料入仓/车载取出/加工取回分别使用页面对应步骤；align只对准，普通pick按同一静态控制流程夹取。`grab place car`是独立车载放料，不自动驱动ID8或改库存；同样保持X收回。

- 正式两批使用下方统一入口；旧省略来源的 `grab mission 200` 不再受理，避免无声使用旧任务码。

### 统一比赛入口

已启动的进站作业姿态持续等待work_ready，不依赖底盘之后是否切入move位置修正阶段；姿态启动仍限于原work_turn/work_dock边界。底盘已到工位且确认停稳、该次姿态完成后才交接抓取；暂停继续保留已经启动的姿态，不重复创建准备任务；恢复时仍按原流程重新核验姿态，不用旧任务完成状态放行。

正式比赛保持车头90°到二维码点扫码，不再固定掉头180°；扫码后Base恢复行驶参考，底盘保持90°向上到右上接驳点，再保持90°向左平移到物料台中间(1200,2100)，到点停稳后原地顺时针转90°至0°；第二批从中心进站保留连续转向。右下标准开局同样连续移动中转到90°，不在旧(2100,300)中途停车。独立二维码测试入口仍保留原转向。

比赛内可恢复的电机通信异常会进入“通信异常停车 → 总线恢复 → 恢复后停稳验证”；当前任务码、批次、件号、已完成库存和夹持/释放阶段保留。自动恢复成功后续跑；失败进入“总线恢复待处理”，在比赛卡片点击“恢复电机总线”重试，验证后点击“继续当前阶段”。也可直接点击“继续当前阶段”，明确请求重新恢复并续跑。恢复中点击“暂停比赛”撤销自动续跑，恢复后停在暂停；“停止比赛”终止本轮并取消恢复，不能再续接。系统页的手动bus recover在有活动比赛时也保留进度，非比赛场景保留原语义。新状态依赖对应固件，已有后续烧录证据；当前设备版本及实车结果另行核对。

1. 完成机构回零和IMU验证，选择右下(2250,150)、车头朝左，或右上(2250,2250)、车头朝下，按所选起点放车并清空实际三个料盘。点击开始本轮比赛即声明这些准备已完成，无需额外确认、逐仓登记或另点准备跑图。
2. 分别选择执行码来源、起点、雷达开关和工位对准高度；采用实际扫码，或输入固定任务码。固定码示例 `156+123+516+231`；两批颜色集合一致，每组三件颜色与环号不能重复。
3. 点击“开始本轮比赛”。STM32先准备后向机构姿态，自动选择四轮反馈并开启轮询，检查新鲜速度/位置/状态、停稳、使能及无驱动保护，验证IMU航向。原点与反馈符合所选起点则复用，否则按本轮起点建立定位；等待新定位反馈后出发。缺反馈、未停稳或暂缺IMU时显示具体原因并等待恢复，不立即报路线启动故障。开始新比赛受理后初始化本轮库存，普通暂停/继续不重设定位或库存；开启雷达时先由STM32展开、扫描规划、收回稳定，关闭时走固定路线。随后前往二维码工位实际扫码，必要时Z上下搜码；串口屏仅显示实际结果。网页分别显示实际扫码和本轮采用码，迟到的扫码不覆盖执行码。
4. 固件连续执行每批原料三件反馈追踪入仓。粗加工必须先空爪对准目标编号环、稳定停稳并保存实际X/Z，然后在外侧姿态下并行执行抬Z收X与车仓分度，汇合到位后Base回仓，等待car_pick_wait_ms（默认300 ms）下降40 mm夹取；提起时1/2号盘同步伸X30 mm避让，3号盘无需伸出。两轴到位再持料转回130°，恢复保存的X位置并确认到位，Z直接一次连续下降至加工台放置高度（默认−140 mm）松爪并提起，不在−100 mm对准高度中途停下。全部放完后重新视觉对准取回，第一批暂存、第二批按同色位置码垛，再回所选起点。无需网页逐件拼接命令。
5. “暂停比赛”发送`grab mission pause`，保存当前码、批次、件、仓、夹持和释放阶段，停车确认后才显示暂停。“继续当前阶段”恢复，已夹/已松动作不重放；续接先等待路线定位就绪，再恢复抓取子任务。顶部“停止并退出”、`grab stop`在正式比赛中仍按暂停处理。
6. “停止比赛”发送`grab mission stop`，撤销本轮及子任务的续接。停车确认后显示“本轮已结束”，不能继续原阶段，之后可开始新比赛。夹爪输出、有效配置、参考和已完成库存保留；在途取放仍沿用现有待核对规则。`cancelling`表示正在结束，`cancel_wait`表示结束推进但未确认停车，不能启动新比赛；处理通信/驱动故障后再次点击停止比赛重试。

正式比赛第一层暂存先空爪对准目标编号环，确认新鲜视觉、稳定及停车后保存本件实际X/Z、工位、环号和绝对释放目标；保持底盘位置与朝向，抬Z收X并回仓取料，保留1/2号盘伸X30 mm避让。持料转回作业方向后恢复保存X并确认到位，Z连续直达保存的z_proc_place目标松爪，不再请求色环视觉。默认高位Z=0，显式低位使用z_temp_align；暂停继续保留本件快照和已夹/已释放阶段。第二层码垛先空爪识别第一层已放好的同色物料，协同对准并核验新鲜视觉及停稳后保存实际X/Z、目标颜色和z_stack_place绝对释放目标；再抬Z收X、回仓取出第二批物料（1/2号盘仍并行伸X30 mm避让），持料转回作业方向、恢复保存X，确认机构到位后下降至保存高度释放。取仓后至释放不再请求视觉，不因持料遮挡而重对准；暂停/通信恢复保留本件快照及已夹/已释放阶段，终止作废快照。独立持料测试入口保持原语义。

工位高度均为绝对Z坐标，负值向下。`z_rough_align`、`z_temp_align`仅用于显式低位对照，默认−100 mm；默认高位对准为Z=0。`z_proc_place`默认−140 mm，加工释放、加工取回和第一层暂存共用；`z_stack_place`默认−110 mm，用于第二层码垛释放。相较上一版，两种放置目标均向下增加10 mm，Z下限仍为−150 mm。加工取回后抬至`z_car_lift`（默认0 mm）。车仓入仓仍使用抬升目标减`track_store_drop_mm`，默认下降40 mm；取出默认40 mm等量升降，等待`car_pick_wait_ms`（默认300 ms）。设备实际参数须读回核对。

加工区空爪对环时，收到有效视觉、开始水平纠偏后，Z按完整`z_rough_align`目标连续下降，边降边对准，不再每5 mm分段。Z到位、视觉稳定和停车条件全部满足后才保存实际位置并去车仓取料。

加工取回受理后先把空爪最大张开至2500 µs，避免夹指遮挡目标；默认在绝对Z=0使用物料DX/DY对准；仅显式低位对照时先降至`z_rough_align`（默认−100 mm）。稳定停稳后固定X和底盘位置，停止视觉请求，继续下降至`z_proc_place`（默认−140 mm），Z到位后直接闭爪。最终固定下降期间及到位后不再用像素误差复核，不因像素变化或视觉缺失退回对准；下降中暂停后继续原下降。对准阶段窗口仍为`dx_tol/dy_tol`默认各±1 px、至少3个新帧且持续200 ms，以设备读回为准；原料动态夹取±100 px保持独立。

加工放置的车仓取出、加工区前两件取回入仓，以及暂存/码垛的共用车仓取出流程：Base经新鲜反馈确认在外侧130°且静止后，ID8与抬Z、收X并行分度。两边都到位才让Base回仓；ID8提前到位的反馈若过期，只补读验证。暂停会停止这次分度，继续仍使用本件仓位；已经闭爪的物料不会因此重新开爪。夹爪位于车仓上方时仍先抬升避让，再允许分度。

加工区第三件取回入仓单独避让：受理时保存仓3配置角、仓3+90°避让角及z_car_lift绝对高度。Base在外侧且Z已提起时，ID8从仓2直接正向180°到避让位置（默认270°），不在中途仓3停下或确认；避让到位后才开始对准/下降。夹取后必须等Z抬升到位，再反向90°回仓3（默认180°），可与收X及Base回仓并行；X收回、Base和ID8均到位后才下降入仓。暂停/通信恢复沿用保存的绝对目标，已到避让位置且机构处于低位时只补读验证，不重新旋转；释放后才记库存。此例外不作用于原料、加工区前两件、暂存或码垛；同一加工取回接口指定仓3的单项测试也采用该避让。

独立暂存持料测试低位持料放置若最终下降后新坐标出窗，仍保持夹爪状态、提回对应对准高度重新纠偏；单次缺帧等待新坐标。第二层直接消费香橙派已补偿的DX/DY，STM32不追加偏移。

停车未确认会显示 `stop_wait`，不当成已停稳。处理驱动/通信故障后执行“回零与通信恢复”中的总线恢复；完成后明确点击继续，重新核验停车再续接。若按过全局停车，还需解除服务端停车锁；解除本身不会续跑。

统一比赛已有软件集成及[10月14日验证与下载证据](../../../../docs/开发记录/2026-10-14-统一DXDY与物料台一次横移.md)，其后版本见[编号环记录](../../../../docs/开发记录/2026-10-14-编号环对准高度与抬升选择.md)。后续源码、实际烧录版本及实车验收分别判断；自动入仓、持料放置及完整两批仍按对应步骤验收。

## 视觉响应标定

2. 选择颜色1～6，点击“启动视觉响应标定”（`grab calib <1..6>`），只发送一次启动。保持Base/Z/夹爪状态；底盘以20 mm/s前行1秒、返回1秒，X以8 RPM相对移动5°并返回，使用现有停稳和反馈流程。

旧MaterialVision、后退搜索及全部material命令已删除，旧命令只返回退役提示；静态对准、编号环、码垛、动态追踪和独立相机识别保留。只读grab route/mission/calib status可在运行或停止锁定时查询。历史实测及部署证据见[开发记录](../../../../docs/开发记录/README.md)。


## 两起点二维码控制测试

二维码页“起点到二维码控制测试”默认选择右下，可切换右上；切换只改变本页操作入口和路线说明，不发送指令。机械臂先等待上电三轴回零成功，或执行 `grab rehome` 重建参考；本测试保持Base朝向和X位置，只在扫码需要时升降Z。右下车放在 `(2250,150)`、车头朝左−180°；依次点击“重新验证5秒”（等待通过）、“设置右下起点”，再启动。右上仍为 `(2250,2250,-90°)`、车头朝下，并提供相应“设置右上起点”按钮。固件采用已确认的65536反馈单位/圈，启动任务自动选择并开启四轮反馈，等待新鲜速度和位置后行驶。进入页面、改输入、连接与刷新均不启动运动。

默认底盘50 mm/s。右下保持车头朝左斜移到 `(2100,300)`，原地顺时针90°转至朝上，再直行到 `(2100,1200)`；右上经 `(2100,2100)` 到同一二维码接近点，行驶时保持朝下。两种路线均在接近点原地转180°，右下转后车头朝下−90°，右上转后车头朝上90°；沿用IMU航向和四轮反馈确认转向及停稳后才进入Z扫码。测试到扫码结束，不进入原料抓取。二维码板实际Y位置在1100～1300 mm范围变化，可在展开的扫码参数中设置并主动读取确认。扫码模块一直接收；默认转向并停车后等1000 ms，尚未取得本轮真实UART二维码时以5 mm/s将Z缓慢下降到−50 mm，下降范围仍须位于现有Z机械限位内。下降或上升中扫到有效新码立即请求停车，确认停稳后报告完成，任务码由原有共享缓存显示到串口屏。到下降下限仍未扫码，等待qr_wait_ms后以同速返回开始时的实际Z高度；一次往返仍未扫码则保持等待，不反复升降。人工停止不会自动返回或续跑。

可用命令：右下 `grab qr begin lower [10..200 mm/s]`，右上 `grab qr begin upper [10..200 mm/s]`；旧 `grab qr begin [speed]` 仍为右上，省略速度为50。`grab qr status` 查询、`grab qr stop` 停止两种测试；普通`grab stop`和全局停止同样中止，保留参数和参考，不自动重启。旧缓存码与模拟码不算本轮成功，二维码模块须产生本轮真实新帧。

参数为`grab get/set qr_scan_y`、`qr_z_min`、`qr_z_speed`、`qr_wait_ms`；统一默认与范围来自`grab_parameters.def`，保存在MCU RAM。二维码页输入初值不是设备已接受值，修改后读取确认，复位恢复程序默认。右下普通固定路线、雷达路线与二维码测试统一−180°初始朝向，保持该朝向斜移至 `(2100,300)` 后再顺时针转至90°；扫码测试结束转去其他路线时，应把车放回相应起点并显式设置该路线的起点。

2026-10-13：正式比赛开始前由操作者清空料盘，点击开始即自动初始化三仓空库存，不再单独确认或因旧库存拒绝。暂停/继续、刷新和重连保留库存；仍需已配置仓位角度和有效转盘参考。

正式比赛二维码接近（2026-10-13最新衔接）：右下入口底盘转向停稳后，取得X收回、Z提起的新鲜静止反馈，Base从原回零参考顺时针转35°与小车沿通道直行并行；右上开局同样允许扫码姿态准备与首段平移重叠。到扫码点仍等Base完成再扫码。扫码结束提Z收X后，Base恢复行驶参考与离开二维码的平移并行，新的车体转向前仍等待完整姿态。原料观察仍为原参考+130°，不累加35°；独立二维码测试入口不变，无需网页额外设置。见[实施记录](../../../../docs/开发记录/2026-10-13-扫码段并行衔接.md)。

比赛速度：统一路线速度10～5000 mm/s，包含扫码接近段；网页转向速度可填5～500°/s，默认100。当前固件比赛上限仍为100°/s，超过该值会被固件拒绝，本次仅放宽上位机输入。固件受理后用于比赛路线原地转向及连续弯道角速度限制，接近目标角度自动减速。工位局部移动仍按原50 mm/s限制。命令速度参数依次为speed_mm_s、turn_deg_s，例如grab mission qr 200 50表示路线200 mm/s、转向50°/s。刷新网页后使用新字段。独立扫码测试不变。

### 比赛工位视觉对准高度（2026-10-13）

“比赛任务 → 本轮任务”新增“工位视觉对准”，默认“高位对准 · Z=0”，下降选项仅保留显式对照测试；加工台空爪对环、加工物料取回、第一批暂存空爪对环、第二批码垛空爪对准第一层物料都在绝对Z=0进行。原料台追踪夹取保持原流程。

高位模式仍核验新鲜坐标、稳定与停车；对准后保持已确定的水平位置，一次下降至实际取放高度，到位夹取或释放，不在最终低位再次请求视觉对准。加工台和暂存第一层先空爪对环、保存位置后回仓取料，再返回保存的X位置下降放置。加工取回/放置及第一层暂存使用`z_proc_place`，第二层码垛使用`z_stack_place`；高度都是绝对坐标，选择高位不修改这些参数。

选择在点击“开始本轮比赛”时随一条启动命令提交，例如`grab mission qr 200 50 lower fixed raised`或`grab mission fixed 156+123+516+231 200 50 upper radar lowered`。省略末尾`lowered|raised`的命令默认高位对准。模式由STM32保存供整轮及暂停/继续使用；网页改选仅修改下一轮草稿，刷新、切页、改选和重连均不发送动作。进度区“本轮采用 · 工位视觉对准”依据状态`align=lowered|raised`回显，与草稿独立；旧固件未报告时显示“设备未报告”，断线重连后已有值标为历史状态，需显式读取比赛状态。源码和软件验证不代表已完成实车验收。

### 比赛起点与雷达选择（2026-10-13）

比赛入口分别选择执行码来源、右下/右上起点、雷达关闭/开启。关闭走固定路线；开启后点击开始，由STM32自动展开雷达、扫描15圈、规划、收回后出发，无需到地图页先操作。扫码接近使用路线速度，转向速度单独设置。右下车头朝左，右上车头朝下。最终返回所选起点。两种执行码来源仍都实际扫码，串口屏只显示实际结果。

### 编号环独立对准高度与完成动作（2026-10-14）

视觉任务 → 编号环 → 第一条“视觉对准”提供两个独立选择：对准高度默认“高位对准 · Z=0”，可显式选“下降对准 · 仅对照测试”（草稿−100 mm）；完成后默认“保持对准高度”，也可选“抬回上限 · 默认Z=0”。统一点击“开始对准”发送一条命令。

高位表示回到绝对Z=0，不是保持任意当前高度；选择高位时下降高度输入禁用但保留草稿，不参与命令校验。抬高复用既有z_max上限（默认0），在该上限完成对准且有本次停车后的新鲜、正常、静止位置反馈时，直接完成，不重复发送抬升。保持高度时继续识别供观察，不继续纠偏；抬高完成停止识别。比赛入口的本轮选择不影响这个独立入口。

四种组合使用现有协议（以1号环、下降−100 mm为例）：

| 对准高度 | 完成后 | 指令 |
|---|---|---|
| 下降−100 mm | 抬高 | `grab align ring 1 -100` |
| 下降−100 mm | 保持 | `grab align ring 1 -100 stay` |
| Z=0 | 抬高 | `grab align ring 1 0` |
| Z=0 | 保持 | `grab align ring 1 0 stay` |

手动命令 `grab align ring 1`、`grab ring align 1` 省略Z高度时也默认Z=0并保持；旧别名 `grab ring align` 省略环号默认1号环。明确填写Z高度时保留原语义：不带stay则完成后抬回上限，带stay则保持该高度。

修改选择、切页、刷新与重连不发送动作。通信故障A/B对照入口保留。后续手动装料在对准停稳后执行，需要高位装料时选抬高；第三步下降松爪后仍按既有规则返回本次放置开始高度。


## 比赛视觉航向矫正（测试）

在“比赛任务”选择“视觉航向矫正”：默认关闭；开启只影响新受理的本轮比赛，暂停继续沿用，刷新与编辑不发送运动命令。每次进入加工区、暂存区后，先等待底盘及Base/X/Z完整作业姿态停稳，仅启动一次三环航向观测。区内换环、逐件放置及加工取回不重复启动；两批再次进站分别重新观测。暂停/恢复续接当前阶段，不因换环重新观测；每件色环/物料DX/DY位置对准保留。加工保存对环位置后和最终下降期间不插入核验。

当前尚未实测标定，开启后显示图像角与“未标定 · 仅观测”，保持原航向映射。STOP=0/1均不控制停车。页面设备采用值独立回显，不以当前下拉框推断在途模式。航向采样使用独立5秒窗口，从机构停稳、开始请求时计时；漏检、USB重试及采样组重置不延长截止时间。允许间断有效帧累计，至少3个不同序号且接收时刻递增的新鲜样本；最后一帧必须新鲜。已标定使用head_spread比较换算后的角度，未标定/独立观测使用图像角最大差0.3°并取三帧平均值；不凭未标定图像角自动更新地图。无效/缺失帧不清空已有有效样本，不一致则重建采样组；机构运动后旧样本作废。5秒内证据不足报告heading_no_observation并沿用原航向继续。尚未成功提交的校准也受该截止时间约束；已采用校准或开始转向后仍完成运动和停稳验证，不以采样超时跳过。人工暂停后重新给予观测窗口，普通物料视觉等待参数不变。不清库存、不重开夹爪。

参数调试的“航向实测标定”组没有预填实测值；不要把0或1当作通用零点/比例。校正方向、亚度角精度、时延及可转包络须实测后采用，详见[实施与验证](../../../../docs/开发记录/2026-10-14-比赛视觉航向分支实现与验证.md)。

## 独立视觉航向测试

“视觉任务 → 航向矫正”可单独测试，无需启动比赛。空爪小车放在加工或暂存三环前，允许小角度摆偏；上电回零后选择工位，点击“准备视觉姿态”（与物料取放共用抬Z、收X、Base+130°并开爪），到位后点击“开始视觉航向矫正”。显示图像角与测试前/当前地图角，未标定仍只观测。

没有定位时自动建立当前位置的本地测试基准(0,0)，已有定位保持；不要求把小车搬去比赛起点。页面转向速度默认5°/s，可选5～10°/s；普通核验命令仍兼容1～10°/s。停止结束本次测试，核验真实停车后可重新准备再测；页面刷新及重连不自动发送命令。角度标定和可转范围仍需实测，详见[独立测试记录](../../../../docs/开发记录/2026-10-14-独立视觉航向测试.md)。

航向观察高度：准备阶段已高于行驶抬升高度时保持实际Z；比赛和独立航向测试结果显示“观察Z”。当前实际高度与标定所依据的`z_car_lift`不匹配时仅观测，不能套用该高度标定转车。后续取放仍使用原绝对目标或明确参考的保存目标，不把更高位置当作已经下降。暂停后重新给予观测窗口。该高度修正的历史实施状态见[记录](../../../../docs/开发记录/2026-10-14-航向观察高度与暂停窗口修正.md)。

独立航向测试接受本次有效的四轮停车监控结果，不要求曾运行过距离路线；仍等待机构和轮速新鲜静止反馈。`heading_pose_wait`表示这些条件尚未齐备，`heading_usb_wait`表示视觉USB发送暂未受理，未标定不影响发送B2/0D请求。


### 按视觉角单次试转

准备视觉姿态到位后，选择“反号”（默认）或“同号”，点击“按视觉角单次试转”。此入口无需角度标定，会实际运动底盘：先取得3次新有效三环角观测，再将三帧一致图像角的平均值乘所选方向作为一次相对转角，按IMU转到目标并确认停车，重新请求三环观测。它不连续追转，也不写入实测标定或重设地图航向；IMU与原地图映射继续记录实际转动。

同号时图像+9.51°对应底盘逆时针+9.51°；反号对应顺时针−9.51°。图像负角的转向相反。页面显示转前/转后图像角、指令转角和实际转角；比较绝对值是否减小，单次结束不表示已完成标定或矫正。源码按图像从左到右排列三环，最外两中心的连线与水平轴夹角减视觉参考角（当前0°）为EA，图像右端向下为正。默认反号、比例1；加工区单次试转图像角10.92°降至0.19°，完整标定仍保留独立流程。

转向精度目标0.1°，使用既有IMU闭环及真实停车判定。未取得转前有效观测不运动；转后未取得观测显示缺失，保留已记录的实际转角，不能据此认定矫正成功。STOP字节不影响运动。点击停止结束本次测试；按角试转前后摄像头Base/X/Z须停稳且保持同一观察姿态。

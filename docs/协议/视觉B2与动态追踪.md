# B2视觉与动态追踪协议

相邻原料入仓交接：上一件原料stored后，可复用已发送完成的四轮同步零速，前提是无待发运动、停车或故障。底盘历史显式停车占用仍保留，原料间追踪及追踪结束后的地图运动/新取放准备通过Mecanum_VelocityHandoffReady区分历史占用与当前动作；不改变报文、不增加FE停车或固定等待。新任务仍按原条件取得新鲜反馈及观察姿态后的新B2观测。

X/Z固定目标动作使用当前轴配置的驱动加速度档位，默认X20、Z255；场景速度和有限绝对终点保持，MCU不再周期重发余弦调速。视觉连续纠偏、渐进下降、回零、Base和ID8沿用各自控制。到位、停稳、机械限位和驱动故障检查保留；Z先抬到0再收X，取仓避让X30 mm并行规则不变。原料追踪夹取在高位进入track_pick_tol_px（默认各±100 px）后连续下降，底盘/X继续跟随，不因下降期间越出像素窗口而停Z；持续视觉失联仍沿原恢复流程处理。其它静态视觉渐进下降按对应工位流程执行。

颜色目标01～06、编号环0A～0C使用同一B2传输，准心各自独立。香橙派实际程序需单独核对，不能由本地源码判定部署。操作见[视觉任务](../../Code/upper-computer-web/local-car/docs/视觉任务.md)，静态对准见[机械臂协议](机械臂与取放.md)。

2026-10-13所有视觉控制入口统一直接使用B2有符号DX/DY，包括真实零值：静态颜色、编号环、第一层暂存对环、动态追踪、加工取回、第二层码垛及漏检恢复均不再从CX/CY减STM32参考重算。删除STM32的ref_u/ref_v参数及网页字段。视觉端仍按目标类型分别管理准心，本地新版物料默认(357,324)、编号环默认(367,316)，实机按实际入口及启动参数核对；调整准心只改对应视觉启动参数。用户已将码垛39/−1补偿加入香橙派，STM32不再执行第二阶段偏移，码垛同样以DX=0、DY=0为目标。CX/CY仅用于记录及视野边缘判断；渐进下降的视野比例由同一报文的CX−DX、CY+DY推得准心，不维护另一组MCU准心。

## 视觉像素与位移尺度

固定识别姿态的画面为640×480 px，用户实测覆盖45×33 cm，按450×330 mm换算。默认响应矩阵J的行分别对应DX、DY，列依次为底盘前进、底盘左移、X伸出，单位px/mm：

| 误差 | 底盘前进 | 底盘左移 | X伸出 |
|---|---:|---:|---:|
| DX | 1.422222222222（640/450） | 0 | 0 |
| DY | 0 | 1.454545454545（480/330） | 1.454545454545（480/330） |

本次只修正原默认模型的尺度，保留原有正负方向、交叉项和底盘/X协同分配。静态对准及predict/visual/feedback追踪共用该J，不在B2坐标上二次缩放，不改底盘编码器/地图毫米单位或X机械脉冲尺度。`grab set j00..j12`及已有响应标定仍可覆盖默认值；普通停止保持RAM，重启/回零等恢复默认行为沿用原规则，网页预填不代替设备读回。

在该测量平面，1 px横向为0.703125 mm、纵向为0.6875 mm；±100 px窗口约为横向±70.3125 mm、纵向±68.75 mm。窗口、速度/加速度、增益及静态稳定时序不随本次换算改变。视野尺寸只提供比例，不构成完整运动响应标定；工位平面、Base姿态或下降高度变化后，方向耦合及局部比例需单独核验，本次不新增按Z估算尺度。

高位静态色环/颜色对准在Z约0、Base姿态保持且IMU/地图及X反馈有效时，用最近有效DX/DY和当前J建立有限目标；按视觉接收时刻插值得到轮/IMU与X实测基线，后续在共同测量时刻扣除底盘与X已走位移，不积分指令、不外推缺少包围样本的实测位置。短暂无效帧可继续剩余目标，新帧替换目标，不能重复累加旧误差。预计到点仅停车等新视觉，最终完成/保存/下降仍须原新鲜在窗及真实停稳判据。新图像保持按帧更新，无新图像的目标控制最多每20 ms更新；制动计入测量年龄及既有驱动响应预算。无合格时序基线、低位/移动Z、参考或姿态变化时沿原漏检处理；停止、暂停、终止、换目标取消旧目标，不充值后重放。动态原料追踪保留独立控制。

## 独立动态追踪 `grab track`

### 实测位移与控制估计

visual/feedback以新鲜DX/DY纠偏，不运行指令位置预测。共用实测通道使用原始轮位置、各轮真实时间及IMU更新时间，在有包围样本的共同时间插值融合；实际速度也取该共同窗口的轮位置差。重复缓存不推进实测时刻。动态允许原600 ms读取窗口内的交错样本（含既有300 ms交错场景），普通底盘默认250 ms组间跨度不变；缺少对齐样本保留原坐标/采样时间，沿原新鲜度与恢复流程处理，不新增等待时长。

predict保留旧的指令积分/平滑校正及X短时外推，用于自身运动补偿，存入独立估计观察器；不将其提交给实测通道。`GrabTracking_Input_t.motion_mm`是控制用运动坐标（predict为估计，visual/feedback为实测），新增`body_left_mm`始终是实测左移坐标。三模式50 mm预算和参考只使用body_left_mm，不能由预测变化扣减或充值。

`feedback_age_ms`取X位置、四轮原位置及共同实测时刻年龄的最大值。三模式的接近预算限速计入该年龄、控制周期和发送批次等待；feedback的速度超调减速继续使用实测速度和反馈年龄，visual不因此加入物料运动拟合。TRACK原19项布局不变，其中forward/left表示控制用坐标，room始终由实测预算计算；预测估计不能当作实测已走距离或停车完成证据。

Base共用作业转角按当前要求统一为原参考+117.5°，需配合既有路线与工位车体转向；Base转角不替代地图车体yaw。当前网页准备入口发送 `grab pose work`，源码使用固定作业目标，不以每次实际角度累积偏差。参考[硬件基线](../硬件与运行基线.md)和[姿态操作说明](../../Code/upper-computer-web/local-car/docs/视觉任务.md#参数与准备)。

2026-10-11增加停转过调对照模式，原`begin/start/pick/observe`继续使用预测算法。操作见[停转过调对照验证](../../Code/upper-computer-web/local-car/docs/视觉任务.md#停转过调对照验证)。

| 新命令/字段 | 语义 |
|---|---|
| `grab track visual [color] [remaining_mm]` | 复用仍新鲜的机械反馈，取得两次不同时间的新坐标后直接纠偏，无物料运动拟合、外推或前馈；只跟随 |
| `grab track feedback [color] [remaining_mm]` | 同上，实际速度参与减速距离，底盘/X独立软件加减速；只跟随 |
| `grab track get <key> [predict\|visual\|feedback]` | 读取指定参数组，省略组名仍为原预测组 |
| `grab track set <key> <value> [predict\|visual\|feedback]` | 显式写入指定RAM参数组，三个组独立；运行中不写入 |
| 状态/实时/冻结行 `mode=predict\|visual\|feedback` | 当前/该行实际计算时的控制方式，行模式加入原CRC；原19项data和IO布局保留 |
| 参数回复 `profile=predict\|visual\|feedback` | 值所属参数组，旧命令兼容 |

切换须先停车并反馈确认，拒绝时保留原任务。通过启动校验后，模式或目标颜色改变时清估计历史，保留参考、预算、反馈坐标和配置。已有参考不按新输入充值；共用机械尺度、视觉B2偏差/J、行程、X位置发送和统一停车，不移动Z/Base/夹爪。

三个组的默认值统一由`grab_parameters.def`维护。原预测组TRACK_PARAM保持底盘160、X60 mm/s、lambda2.5、X前瞻120 ms；2026-10-12纯视觉和反馈减速组由TRACK_COMPARISON_DEFAULT覆盖为底盘160、X60 mm/s、lambda2.0、X前瞻60 ms，其余初值/范围保持。此组恢复追随速度上限，提高纠偏需求，保留较短X领先；本轮仅调整参数，不增加提前减速算法，不代表过调已消除。验证组不使用`fit_ms/latency_ms`；`horizon_ms`仅将X速度变成有限领先的位置指令，不外推物料轨迹。反馈组增加`body_accel=300`、`x_accel=120` mm/s²（范围1～1000，仅该组读写），与联合`accel=300`共同作用；这些是软件联调初值，不是实测能力，不改变底盘档位20或X的config档位。三模式`feedback_age_ms`取X、四轮原位置及实测共同时间年龄最大值，用于预算延迟；feedback还将其用于实际速度减速。

初值用于设备初始化，普通停止或模式切换不重置已写RAM。网页切换参数模式及“填入追踪预设”只修改草稿；运行中的设备参数需显式读取。使用现有固件联调时，先停止并确认停稳，在visual/feedback组分别填入预设、应用并核对；不能仅刷新网页就认为设备值已更新。

反馈减速先将加权纠偏速度换成剩余位移，扣除实际朝目标速度超出上次命令的部分在反馈/发送等待期间的位移，再按`v*delay+v²/(2a)≤room`求限速。随后保留联合限幅，并限制底盘合速度/X各自变化；机械边界限速可覆盖斜坡。重复快照保持最近速度的时间为最近有效帧间隔加一个控制周期，下限两个控制周期、上限原宽限；未测得帧间隔时用原宽限。超过保持时间或明确Valid=0后平滑减速，超过原宽限停车等待，恢复后继续原预算跟随。三模式共用J有限值与满秩检查，已失效的标定不能启动跟随。

速度匹配`track_match`→稳定跟随`track_follow`→保持姿态`track_pause`。纯追踪稳定按误差窗口持续200 ms标记，不要求底盘/X静止。`track_visual_wait`等待新的视觉后继续；`track_window_end`在反馈确认停稳后继续观察和计算可达性，新有效坐标可在原有行程与剩余预算内跟随时自动恢复，原因`track_window_recovered`。重复旧坐标、预测定时器或无效视觉不单独触发续追；等待中的候选速度不发送，恢复仍从静止按原加速度起步。不重新回零、充值接近预算或作抓取；人工stop结束本轮，后续目标返回也不自动重启。主状态`stop_requested`和`stop_confirmed`分别为停车请求及实际反馈确认，不把`OK ... accepted`当作停稳。等待可达期间记录继续更新，需显式stop后再导出冻结记录。

追踪夹取采用`track_match`→`descend`（底盘/X继续追踪）→`close`→`lift`→`complete`。高位窗口为DX/DY各在`track_pick_tol_px`（默认±100 px）内；`track_pick_hold_ms`默认0，正值只由下降前的新有效观测累计，像素数值无需相同，重复缓存不推进保持。已准入后Z连续执行原绝对夹取高度，取消±50 px启停和低位重新对准；Z本次运动完成即可闭爪，不等其他电机稳定，也不再要求停车后的新视觉。闭爪同时通过普通总线调度提交底盘零速及X停保持，原close_ms后提起。动态X绝对前瞻按需使用Receive，仅确认受理并继续依靠实际反馈跟随；后续固定动作按需切回Both。固定Z下降及转移位置动作采用Both的FD/9F完成通知，缺通知则使用实际反馈后备；短暂漏检/持续失联恢复、驱动保护、行程和人工停止保留。

追踪中X速度回落至零时，取消旧前瞻目标的单轴FE停保持使用普通UART5调度，不抢占四轮Receive/同步批次；仍读取X位置和状态。人工`grab stop/track stop`、轴停止及故障停车保持原紧急优先级，不能用正常停保持代替紧急停车。

状态为`OK grab track state=... reason=... color=... ref=... valid=... cx=... cy=... dx=... dy=... vf=... vl=... vx=... x=... room=... xr=... stop_requested=... stop_confirmed=... seq=...`；dx/dy直接来自有效B2报文的DX/DY，本地新版视觉默认DX=CX−357、DY=324−CY，实机以实际入口及启动参数为准。diag中的du/dv为扣除自身运动后的目标像素速度；ff/correction依次是车体前向、左向、X伸出，单位mm/s。`batch`为已完成批次间隔，`feedback_age`为X位置、四轮原位置及共同实测时刻年龄的最大值；forward/left为控制用局部坐标，visual/feedback使用实测，predict使用独立估计，room统一使用实测预算。stats每个新有效视觉样本计一次，包含启动过渡；p95为1 px分箱的保守上界，100箱表示≥100 px，不把溢出视作精确100。

停止后按需`status`另回`OK grab track estimate fit=vu,vv,au,av comp=pu,pv confidence=cu,cv`：fit为最后一次无约束局部拟合的速度(px/s)和加速度(px/s²)，comp为该视觉帧扣除机构位移后的坐标，confidence为线性趋势相对当前测量不确定性的连续权重(0～1)，不是颜色识别可信度。不在运动中广播此额外行，不将最后一次估计信息冒充整段逐帧记录。当前追踪拟合保留240 ms默认窗口，以约0.5 px噪声尺度加入速度/曲率连续先验；运动中再按J投影的“上一控制速度减实际反馈速度”及50 ms不确定性尺度增加拟合噪声方差，避免电机响应和交错反馈造成的补偿残差变成高置信度物料加速度。此尺度只调整估计权重，不改变延迟参数、速度上限、行程或停车条件；仅观察时仍用原量化噪声。一像素范围内不延续加速度，弱趋势慢更新、清楚趋势快更新，不把位置到点窗口当速度前馈开关。

冻结导出为`OK grab track trace_begin count=N`、多行`TRACK row i=... t=... seq=... rx=... data=... crc=XXXXXXXX`、`OK grab track trace_end`。data依次为19项：误差u/v、目标像素速度u/v、实际前/左/X速度、命令前/左/X速度、X位置、控制用局部forward/left、实测剩余接近room、batch、最大实测反馈age、request_age、sent_age、flags。前14项保留两位小数，末5项整数。CRC为IEEE CRC32，覆盖从`TRACK row`起到` crc=`前的ASCII（不含arm提示符和换行）。网页核对数量/索引/CRC，坏条不覆盖好条，结束后仅补读缺条，完整后才导出。

时间为MCU ms，rx是接收时间不是拍摄时间，age为X位置反馈年龄。request_age是速度请求受理年龄，sent_age是同步发送完成年龄，65535表示未知；flags位0有效视觉、位1运动模式、位2稳定、位3预测。记录每次计算，分析误差必须按seq/rx去重；实际批次统计按`t-sent_age`去重，不能把每条计算行都当作新发送。默认运行中仅低频摘要；可以显式开启下述实时记录。冻结导出只在停止后进行，每200 ms一条，不给追踪控制或USART1全局添加等待。

### 逐帧精简像素记录

`camera log start|stop|status` 为被动订阅，不发送视觉请求、不运动；上电默认关闭。网页开启实时记录先读回追踪参数，再发 `camera log start`；可选同时发 `grab track log start 200` 保留低频速度诊断。关闭先停速度诊断、再关闭像素订阅，不停车。

逐帧格式：`PIX id=1 i=0 t=1234 c=3 v=1 m=1 x=334 y=338 dx=-38 dy=7 crc=XXXXXXXX`。

- id为订阅号，i为本订阅候选帧序号，t为MCU收到USB包末字节的毫秒时间；不是拍摄时间。
- c为目标编号，v为有效标志，m表示是否匹配当前控制请求，x/y为中心CX/CY，dx/dy为原始有符号16位B2偏差。v=0记录漏检，坐标和偏差不作有效目标解读；m=0也保留，不能当控制已采纳。
- CRC32覆盖从PIX到` crc=`前的ASCII（含dx/dy），不含提示符/换行。保留序号/CRC用于检查缺帧和损坏；包头尾、B2原校验不重复回传。网页兼容没有dx/dy的旧日志，新日志两项成对，范围−32768～32767，不从固定准心重算。

Camera在逐个解析通过头尾、B2累加校验且Valid为0/1的回复时调用记录回调，不从最新快照定时抽取；粘包中的有效、无效和其他目标均分别记录。损坏/非法B2不作为像素观测回传。现行视觉输入为USB CDC；115200/8N1串口是MCU→电脑链路。

开始回 `OK camera log_begin id=... next=... mode=per_frame fields=rx,target,valid,matched,cx,cy,dx,dy`；重复start不清计数。结束回 `OK camera log_end id=... count=... queued=... dropped=...`；status另回enabled和相同计数。count是候选帧数，queued只表示成功入队，不证明电脑收到。使用现有回复FIFO，积压超过4096字节时放弃当前像素入队并计dropped，不等待控制；紧急停车回复保留优先级。回传完整性须结合电脑收到的序号/CRC与结束计数，不能以波特率直接保证无损。

磁盘按像素订阅起止导出整段TXT，其中包含可选的速度诊断、回复和参数上下文，不受128条窗口限制。`tracking_report.py` 输出pixels统计；页面按像素序号检查完整性，旧TRACK段继续兼容。

### 长时间实时记录
上电默认关闭。`log start`回`OK grab track log_begin id=... period_ms=... next=...`，随后仅在观察/追踪产生控制记录时发送`TRACK live id=... i=... t=... seq=... rx=... data=... io=... crc=...`。data与冻结记录相同19项；CRC覆盖从`TRACK live`到` crc=`前的全部ASCII，包括io。新订阅用新非零id；重复start保留id/索引，仅改周期。`log stop`回`OK grab track log_end id=... count=...`，count为本订阅产生的候选记录数，不是电脑成功接收数。`log status`回enabled/id/period_ms/count。订阅命令可在停车锁定中操作，不解锁、不改变任务状态；刷新、重连不自动订阅。

实时io为34个逗号分隔整数，索引从0起：

| 索引 | 内容 / 单位 |
|---|---|
| 0～3 | 已完成同步批次四轮RPM，逻辑前向符号，不是计算请求速度 |
| 4～7 | 四轮原始位置，int64协议单位，保留协议符号；网页按字符串保精度 |
| 8～11 | 各轮位置反馈年龄ms |
| 12～14 | X最近已发送目标脉冲、RPM、DMA完成年龄ms |
| 15～16 | X原始位置（轴逻辑符号）、已发送动作（3位置、9停止） |
| 17～20 | 底盘总线stage/error/locked、有效位掩码 |
| 21～22 | 底盘motion_sequence/stop_sequence |
| 23～25 | X最近受理目标脉冲、RPM、受理年龄ms，与已发送值独立 |
| 26～29 | 四轮最新速度反馈RPM，保留协议符号 |
| 30～33 | 四轮速度反馈年龄ms |

有效位：bits0～3四轮位置，bit4已发送四轮速度，bit5 X已发送，bit6 X Receive确认，bit7 X位置，bit8四轮确认，bit9批次发送完成，bit10 X目标受理，bits11～14四轮速度。年龄65535表示未知，已知年龄饱和到65534；先看有效位再解读0值。X发送事件在事务结束时发布，但时间戳取真实DMA完成时刻，不把Receive确认时间当成发送时间，更不把确认当成物理移动。

详细IO只用一个当期快照，不扩展128条环形缓存；冻结`TRACK row`仍为原19项，不会把当前IO附到历史行。USART1复用空闲DMA缓冲，无新等待、无诊断历史队列：忙/优先回复时跳过记录，未开始的记录可替换/让位，已开始整行发送完。i在每次候选记录递增，电脑明确报告缺号/坏CRC；默认50 ms是请求采样周期，**不保证DL-20无损20 Hz**，可显式`log start 100`降低占用。停车回复仍优先，原波特率115200/8N1不变。

本地桥接持续、无缓冲写入`.embeddedskills/logs/serial/<连接时间>-rx.bin`（收到的原始字节）及`.jsonl`事件日志，保存时间不受6.4 s环形窗限制。建议运动前开记录，运动停止并取得反馈确认后再关闭记录、留出最后整行传输时间；关闭网页或断串口不是停车。分析用`python Code/tools/tracking_report.py <原始-rx.bin> --source live --kind physical`；冻结与实时不混合，缺条不冒充完整记录。长日志只能保存**已经上传**的信息，无法补回无线丢字或此前未启用的动态段。运行速度、时长可从日志估计，但仍不能当作独立测得的真实转盘角度/转速。

2026-10-09 本地网页提供磁盘目录和整段TXT导出。网页开启记录先逐项读回13项追踪参数，默认显式发送`grab track log start 100`，可选择50/200/500/1000 ms；固件无参数start仍默认50 ms，控制周期不变。`GET /api/logs`列出当前及历史服务记录，`GET /api/logs/tracking?name=<文件标识>`按订阅段统计有效记录、缺号和损坏行，`GET /api/logs/export?name=<文件标识>&kind=rx|console|tracking[&segment=<段索引>]`导出UTF-8 BOM文本。RX/追踪保留原始接收字节与残片，追踪段附开始前最近参数读回；console保留有时间的收发及系统事件，不输出重复raw十六进制事件。导出不发送设备命令、不受浏览器缓存影响，历史文件在服务重启后仍可读取；正在写入的文件按请求时边界导出。无开始或结束标记不判完整。记录路径实际以服务创建时间命名，一个文件可包含多次连接和多段订阅。

## 统一 B2 视觉协议（当前约定）

USB CDC 请求固定 4 字节：`FF B2 Color FF`。
回复固定 14 字节：`FF B2 Color Valid CX_H CX_L CY_H CY_L DX_H DX_L DY_H DY_L SUM FE`。
颜色为 1～6；红色为 1。SUM 为字节 1～11 累加的低 8 位；CX/CY 为大端无符号 16 位，DX/DY 为大端有符号 16 位。

长度、头尾、SUM、功能码及当前请求颜色匹配后才接纳报文。Valid 只能为 0 或 1；1 表示坐标有效，0 表示已收到合法回复但当前无有效坐标，不能继续使用之前的坐标。相同坐标的新报文仍正常接收。非法 Valid、错误颜色、错误校验和 B4 不推进任务。

Camera 的 `Sequence` 是有效坐标在 MCU 的接收序号，`Tick` 是 MCU 解析时刻；均按 uint32 回绕处理，不代表远端采集信息。`InvalidCount` 记录当前请求内合法 Valid=0 的累计数，防止粘包中的失效事件被后续有效坐标覆盖。请求成功提交才清空旧缓存、残帧、有效状态和无效计数；USB 忙或提交失败保留原请求。停止只清空本地请求及缓存，不发送额外香橙派停止协议。

B2 无远端请求编号、采集帧号、阶段或采集时间，因此不能严格区分同色请求的迟到回复，也不能证明多次接收来自不同采集帧或已进入圆心阶段。清缓存和本地时间不能提供这类保证。

`grab start align` 默认使用 B2 蓝色请求（3），`grab start pick` 和路线转交的 pick 默认使用红色请求（1）。直接命令 `grab start align|pick <color>` 可选择 1–6 号 B2 物料颜色；固定位置抓取不接受颜色参数。完成对准要求：像素容差内至少 `frames=3` 次新坐标观测，持续至少 `stable_ms=200` ms，并满足现有机构反馈停稳条件。一次任务更新只采纳最新坐标、最多累计一次观测；同一快照不重复累计。开始停车后重新累计；像素越界、Valid=0、任务停止或重新启动清除稳定证据。首次没有数据或只有合法 Valid=0 则保持停止等待；对准/停稳阶段的合法 Valid=0 按下节先进入短暂容忍或限时视觉暂停；接收过期、USB/请求失效和机械通信故障仍停止并报告故障，不自动恢复。

停止协同对准不会清除仍有效的参考参数；收到 `state=idle stop_confirmed=1` 后，若 `missing=none` 可直接再次启动。外部手动 HOME/ZERO、Base 转向放置处等造成参考失效时，`grab status` 的 `ref_cause` 标记最近原因，`missing` 列出仍缺的参数。空闲且电机总线可用时可手动发送 `grab rehome`，它复用上电的Z/X碰撞、Base就近并行启动流程及0x3B、位置、状态双次稳定读回，不重放已完成的上电ID8回零；轴验证成功后才恢复该轴的默认RAM参考，失败或中止不恢复尚未验证的参考。`OK grab rehome accepted`仅表示启动，最终须检查`reason=home_complete`，再等IMU静止验证通过。执行前移走夹持物并确认运动范围安全。单轴`home`受理不足以自动恢复参考；该命令会覆盖对应轴的自定义参考值，必要时重新设置。

`age_ms=1000` 表示有效坐标自 MCU 接收后的最大允许间隔，不再包含远端采集耗时。`camera status` 的独立调试显示过期阈值仍为 1200 ms；抓取状态和任务门槛按 grab 的 age_ms 判断。

状态示例（示意，非实车记录）：
```text
OK grab state=align ... protocol=B2 age_source=rx rx_seq=123 vision=Ok ... age=25 ...
VISION RX fn=B2 color=1 valid=1 fresh=1 cx=350 cy=321 dx=16 dy=17 rx_seq=123 age_source=rx age=25
OK camera state=Wait protocol=B2 age_source=rx usb=1 active=1 fn=178 target=1 frame=0 current_valid=0 target_valid=0
```
`vision`：Idle 无活动请求、Off USB 未枚举、Wait 等待首个匹配回复、Lost 已收到但无有效坐标、Ok 有效坐标、Stale 接收过期。`rx_seq` 是 MCU 接收序号；`age_source=rx` 标明接收时间来源；已移除相机 phase 字段。`camera status` 中 `frame` 为是否收到过匹配报文（0/1），不是帧数；`last` 为本请求最后有效坐标，仅状态 Ok 时输出数值，其他状态为 na。`stats invalid_reports` 对应 InvalidCount；`seq`/`data_tick` 分别是 MCU 有效坐标接收序号/时刻。

本节参数记录属于历史值；当前全部控制入口使用本文件开头所述B2偏差。Z 抓取 −80 mm、放置 −60 mm、提起 −40 mm；Base 相对转 −180°。没有新增整任务总超时、协议选择菜单或兼容确认开关。


## 静态协同对准的新帧调度与λ

静态ALIGN完成视觉稳定窗口后进入SETTLE，保留该窗口，不因本流程主动停车而完整重计一次视觉stable_ms。停车写入后的三轴/四轮真实停稳证据仍独立重新取得，完成时必须同时收到停车证据起点之后的新有效在窗B2帧；旧快照不能推进。停车期间偏出窗口、漏检、反馈失效、人工停止或暂停沿原流程作废证据并重新核验。视觉frames/stable_ms默认仍为3帧/200 ms，真实停车的稳定保持没有取消。

空爪预对准完成且保持原姿态时，保存位置复用刚完成的视觉稳定窗口，但必须另取一帧新鲜在窗坐标并核验三轴/四轮停稳；不重计完整stable_ms。保存快照至取仓之间没有新动作、反馈仍有效时移交停稳证据，不重复发送停车或重计稳定窗口；新的任务阶段、机构动作、底盘运动/停车、人工停止或反馈失效取消本次移交资格，按原流程重新核验。取仓后的持料放置、避让及夹爪等待保持；重复读取同一视觉快照不能保存位置。

静态颜色、编号环、加工及暂存的水平协同纠偏按新有效B2接收序号更新，取消正常纠偏100 ms门槛。同像素值的新报文仍是新观测；重复读取同一快照不重复积分。总线同步批次、机械臂应答或查询正在进行时保留最新未处理观测，后来的新观测覆盖旧待办；空闲后立即处理，不重新计时等待，也不补发历史帧。速度加减速按两次实际受理速度输出的间隔计算，忙轮询不覆盖该计时；X目标积分使用独立时钟，跳过忙碌/让读期间的位移，不补走积压时间。两者保留单次200 ms上限，启动与视觉恢复时同步重建计时。

静态加权J分配得到的X速度超过x_speed时，先限制X，再用底盘两平移轴的J补足缺少的像素纠偏；不再仅因X限速就同比压低全部输出。底盘仍受body_speed及原加速度限制；底盘能力不足时同比缩放以保留图像纠偏方向。底盘J单独不满秩时沿用原整体缩放，不强求补偿。默认body_speed=160、x_speed=60 mm/s，X机械范围0～130 mm、lead_mm=12及接近边界的X权重衰减保持，不增加RAM参数。

显式低位对照流程的Z目标同样由新帧及原视野/机械条件触发，不再额外限频100 ms；新近具备条件的Z目标先获得一次总线机会，水平纠偏保留待处理帧，在该事务结束后续接。每次实际下发Z后，先让水平纠偏成功受理一次再下发下一个Z目标，避免连续变化的Z占满发送机会而让底盘沿用旧速度。连续X/Z目标之间，到期轴反馈读取保留轮转机会，沿用原25 ms查询间隔，不新增正常纠偏固定周期。默认高位及最终固定下降仍沿各自流程。动态追踪独立调度与参数保持。

共享静态λ使用现有`grab get lambda`与`grab set lambda <0.001..10>`，默认2.5 s⁻¹。上位机入口为“视觉任务 → 物料取放 → 固定夹取与静态对准 → 仅协同对准”，提供输入、“读取λ”和“应用并核对λ”；写入应答后读回同一参数，数值不一致或设备拒绝均不报告成功。输入编辑、页面挂载、刷新与重连不发指令；停止、断连及设备重启取消未完成核对，旧设备值标记为历史。此参数由静态颜色/编号环/工位对准共用，不修改`grab track set lambda ...`的独立参数组；仍由固件拒绝运行中改参。

## 静态对准的短暂漏检容忍与限时恢复

仅 `align`、`pick` 及路线交接 pick 的抓取前 `align/settle` 阶段参与。固定取放、下降后的流程及完成后的 hold 不参与。B2 请求/回复和所有现有命令不变；不根据 B2 推断香橙派粗定位或圆检测阶段。

`align` 和 `pick` 的 `state=align` 阶段，合法 `Valid=0`（包括同批有效→无效→有效），或连续100 ms没有新的有效接收序号，先进入 `state=vision_grace reason=vision_gap_decelerating`。100 ms是独立漏检阈值，不是正常纠偏周期；宽限减速保留独立100 ms更新节奏。默认 `loss_grace_ms=250`，从最后一次被控制采纳的有效坐标接收时刻计时；中途无效包、重复快照或一两次有效观测都不延长窗口。此时丢弃尚未处理的旧纠偏观测，不再按旧误差求新速度，只按当前 `accel` 将上次底盘/X平移速度逐步减小，保持原方向；不累计对准证据。实际命令仍受总线调度约束。250 ms 是超时请求停车的门槛，不是物理停稳保证。

容忍时间内连续得到 3 次新有效坐标观测（一次主循环最多一次）才能回到 align，报告 `reason=vision_gap_recovered`，不计入停车恢复次数；从下一次新坐标重新检查对准。任一无效报文清零观测数，同批最新有效坐标最多作为重置后的第一次。达到容忍时间（elapsed >= loss_grace_ms）即进入停车暂停。临近准心（DX、DY 均在各自容差的 2 倍以内）、恢复坐标明显越过准心（对应轴新旧误差均超出容差且反号）、`settle` 阶段、配置为 0 时，合法漏检直接请求停车。未收到过有效坐标时继续停止等待，不能沿用旧任务坐标。

需停车时进入 `state=vision_pause reason=vision_pause_stopping`。立即停止新增纠偏目标，清除稳定观测，复用底盘/X 停止发送及四轮、三轴停稳确认；保持夹爪、使能及原 B2 请求。停止期间坐标不计入恢复证据。

确认停稳后报告 `reason=vision_recover_wait`，从此刻开始 `vision_wait_ms` 窗口（默认12000 ms），记录当时接收序号。窗口内至少 3 次新有效坐标观测且当前反馈仍停稳，才回到 align，报告 `reason=vision_recovered`。相同坐标的新报文可以累计，一次主循环最多计一次，重复快照不计。任一合法无效报文清零计数，不延长窗口；同批最后一个有效报文最多作为重置后的第 1 次。边界 elapsed <= vision_wait_ms 可接受。

近准心（各轴误差在对应容差2倍内）或settle阶段发生短时漏检，且最后有效坐标尚未超出loss_grace_ms时，停车后保留原识别数据流，等待新帧，不立即重发B2。恢复有效坐标可更新最后有效接收时刻；无效包和重复无效快照不能续期。只有有效坐标持续缺失达到loss_grace_ms（默认250 ms），才在停稳后重发一次当前目标B2请求。远离准心耗尽宽限、越过准心需停车或关闭宽限时仍沿用停车后重发。成功提交USB后报告 `reason=vision_reacquire_wait`。需要重发时必须先提交成功，再累计该次请求后的新接收观测；保留数据流时累计停稳后的新观测。两种路径均需3次新鲜有效坐标及当前停稳反馈，恢复后重新累计正常对准稳定证据，不能用漏检前坐标确认完成。USB忙在原等待窗口内重试，不延长窗口；其他发送错误按 `camera_tx` 停止。每轮暂停最多成功重发一次；短时漏检可不重发。此方式不改香橙派程序，不根据B2推断远端阶段；B2仍不能严格辨认同色迟到回复或远端采集时间。

成功恢复次数只作诊断，不设置累计退出额度；单次等待超窗为 `vision_recover_timeout`。恢复从实测 X 位置重新建目标，速度历史及控制计时重新开始；必须重新经过完整 3 次/200 ms 的对准和停车后稳定判据，不能直接下降。恢复计数在新任务初始化/启动时重置，与原有停稳偏移重试独立。

`vision_pause` 不用漏检前坐标年龄重复报过期；新恢复观测仍检查 `age_ms`。正常对准过期 `vision_stale`、USB 断开 `vision_usb_off`、请求失效 `vision_request_lost`、机械反馈/总线故障均硬故障停止，人工停止清除待恢复资格。停车未确认时不开恢复窗口、不恢复运动；保留反馈检查，不引入整任务总超时。

新增状态字段（MCU 报告值）：

| 字段 | 含义 |
|---|---|
| recovery_used | 本次已成功停车后恢复次数，仅诊断；短暂容忍内恢复不计入 |
| recovery_count | 当前窗口连续新有效观测数，0～3 |
| recovery_left_ms | 窗口剩余毫秒，0～vision_wait_ms（默认12000）；停稳前及窗口外为 na |
| loss_ms | 当前中断持续时间；恢复/停止后保留最近一次。起点为最后有效坐标，包含连续观测确认及可能的停车等待，不等于纯漏检时长 |
| loss_max_ms | 本任务最长中断毫秒数，包含当前未结束中断 |
| grace_count | 减速容忍期间连续新有效观测数，0～3 |

GrabTask.c使用参数`vision_wait_ms`作为停车恢复窗口，`GRAB_RECOVERY_OBSERVATIONS=3`保持不变；不再设置`GRAB_RECOVERY_LIMIT`。窗口可通过`grab get/set vision_wait_ms`读取与修改，范围1500～120000 ms、整数。短暂容忍可用 `grab get loss_grace_ms` 读取、`grab set loss_grace_ms 250` 设置；整数范围 0～300 ms，0 关闭短暂容忍，仅任务未运行时允许修改，存于 RAM。保留 `protocol=B2 age_source=rx rx_seq=...`、`stop_requested`、`stop_confirmed`；紧凑周期状态保留恢复、中断时长及 dx/dy 字段；容忍期间 dx/dy 为 na，原始新坐标可从独立 VISION RX 查看。手动 `grab status` 返回完整状态。

## 电机状态判定与故障快照（2026-10-09）

X42 的 `0x3A` 电机状态位须区分：bit0（`0x01`）使能，bit1（`0x02`）位置到达，bit2（`0x04`）瞬时堵转检测，bit3（`0x08`）堵转保护。依据为本工程 X42 第二代用户手册 V1.0.5 PDF 第73–74页：实际转速低于设定堵转转速且电流高于设定堵转电流时置堵转标志，持续超过驱动设定时间才触发堵转保护。

因此 `0x05/0x07` 本身不终止动作；失能或 `0x08` 保护才触发轴/轮故障停车。原始状态仍完整保存在反馈中；停车确认仍需新鲜速度、位置和停稳证据，到点与取放确认仍按现有视觉、位置与机构条件执行。回零的 `0x3B` 是另一种状态布局，保持原有回零失败判定。

明确查询 `grab track status` 时，真实故障打印 `motor_fault id=… kind=axis|wheel flags=0x… received_ms=… detected_ms=…`，保留本轮首次故障原始位与时间，后续正常反馈不会覆盖；新一轮追踪才清空。启动及恢复的首个控制时刻 `dt=0` 输出保持零速度，后续才按既有加速度增长；同一时间戳不重复增加速度。


## 比赛航向观测：色环B2/0D与前方黑线B2/0E

两种参照使用独立任务码，长度与校验沿用B2；不得把黑线回复伪装为色环0D，也不能进入普通DX/DY位置控制。

| 参照 | 请求 | 14字节回复 |
|---|---|---|
| 色环中心连线 | `FF B2 0D FF` | `FF B2 0D Valid EX_H EX_L EY_H EY_L EA_H EA_L STOP_H STOP_L SUM FE` |
| 暂存码垛色环前方黑线 | `FF B2 0E FF` | `FF B2 0E Valid 00 00 00 00 EA_H EA_L STOP_H STOP_L SUM FE` |

四数据槽均为大端int16；EA为图像角×100，SUM为偏移1～11累加低8位，包含STOP。色环EX/EY为中环像素误差，黑线前两槽固定0不表示位置已对准。Valid=0时槽全零，无测量意义。两者参考角同为图像水平向右0°，右端向下为正；直线方向按模180°解释，不能单凭EA判断地图yaw。STOP只是±5°诊断，STM32不以其决定运动、稳定、完成或失败。

Camera层按当前请求目标匹配并发布带Target的独立姿态快照，切换请求清理旧快照/接收残留；0D与0E不能互相满足采样。报文没有工位、远端图像序号、请求批次或拍摄时间字段；本地接收序号不冒充远端帧身份。本地修正版Python黑线短时漏检保留本地跟踪提示，但线上Valid=0，重获后重新累计三帧；已锁定后也持续核验角度抖动。用户当前仍用上传原版，该版本0D/0E均可能在漏检时继续发送Valid=1历史角度，黑线锁定后还可能绕过抖动检查；当前STM32无法从这14字节区分历史保留与新测量。报文格式兼容不代表新鲜测量资格兼容，见[兼容审查](../开发记录/2026-10-15-原版视觉与STM32兼容审查.md)。

比赛开关默认关闭；开启后每次进站只观测一次，加工区两批和暂存第一批使用0D，暂存第二批码垛使用0E。黑线的实测映射为独立RAM参数`head_line_zero/head_line_gain`，初值NAN；不借用`head_temp_zero/head_temp_gain`。稳定、观察高度、采样5秒、暂停恢复及已开始转向后的验证沿用原流程。黑线未标定仅观测；正式色环采用用户确认的反号1∶1策略，不再受空head_proc/head_temp参数阻断；结束后恢复本件颜色/编号环请求。

### 独立入口及单次试转

先`grab pose work`准备，再使用：

- `grab heading proc [speed]`或`grab heading temp [speed]`：原色环入口，省略转速5°/s，范围1～10。
- `grab heading temp 5 line`：显式请求黑线0E，黑线仅用于暂存区。
- `grab heading angle proc|temp [1|-1 [speed]]`：原色环单次试转，方向默认−1，速度默认5°/s，范围5～10。
- `grab heading angle temp -1 5 line`：黑线单次试转，前后均使用0E。显式附加来源时填写前面的数值参数；可用`ring`明确选择0D。

单次试转先观测，再按EA×所选方向设置一次相对转角，按IMU执行并停稳后复测；不连续追转、不写实测标定或重设地图航向。STOP始终不决定转角或完成。普通核验使用所选参照对应标定，未标定只观测。`grab stop`结束测试，不能自动续转。

状态仍为`OK|ERR grab route ... mode=heading`，增加`heading_source=ring|line`；比赛状态也回传该字段。网页显示设备来源，不从下拉框推测在途来源。`heading_z`为实际观察Z（mm），不是配置目标；`heading_height_unmatched`表示高度不适用，本次仅观测。`heading_before/map_yaw`为度，`local_origin`说明本次是否建立本地基准。像素诊断`POSE`增加`c=13|14`区分两种姿态目标。

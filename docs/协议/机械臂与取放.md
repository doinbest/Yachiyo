## 现行静态对准与码垛

| 命令 | 语义 |
|---|---|
| `grab align color <1..6> [z_mm] [stay]` | 颜色静态对准，参考(334,338) |
| `grab align ring <1..3> [z_mm] [stay]` | 编号环静态对准，参考(378,333)，不预伸50 mm |
| `grab ring align [1..3] [z_mm] [stay]` | 编号环旧入口兼容，省略编号默认1 |
| `grab start align <color>` | 原物料对准兼容入口 |
| `grab stack align <1..6>` | 对准颜色后停稳，再独立执行CX+39/CY+1像素补偿并停稳保持 |
| `grab stack lower <z_mm>` | Z绝对位置，可向上调整或覆盖尚未完成目标，不松爪 |
| `grab stack release` | 松爪并保持高度，不自动提起 |
| `grab stack lift` | 独立提起至最高 |
| `grab ring place <z_mm>` | 已对准并人工装料后，Z下降/松爪/提起，不取仓或改库存 |
| `grab status [base|x|z]` | 任务或短轴诊断，只读 |
| `grab stop` | 结束任务/识别并请求停车，普通停止保留有效参数/参考 |

颜色与编号环共用静态控制参数，动态追踪独立。环对准先抬Z/收X、转Base，再请求编号识别；横向接近后随新坐标逐步下降。640×480边缘左右64 px/上下48 px暂缓下降，Z目标最多领先反馈5 mm、最短100 ms更新，重复坐标不累加下降。完成要求目标高度、±1 px窗口和停稳；省略stay只抬Z到最高等待装料，stay保持低位并继续只读显示偏差，不持续运动纠偏。这些分段阈值为当前调试值，精度待实车验收。

码垛补偿固定来自用户截图，不移动香橙派准心、不写ref_u/ref_v、不按以后红点重新取值；最终相对绿色准心DX=39、DY=-1为预期。普通颜色/编号环、动态追踪和正式任务不启用此手动补偿。

Base任务到位采用2°业务容差、新鲜停稳及正常使能；2～5°残差以≤15 RPM重发同一绝对目标，不用FD模式2。X与Z下降/释放仍核验相应到位条件，Z最高端点单独按有效静止/容差接受。

旧vision和material命令只回复退役提示，不自动转为运动。响应标定使用 `grab calib ref` 人工确认当前观察姿态，再以 `grab calib <1..6>` 启动；`grab calib status` 只读，`grab stop` 取消并停车。GrabTask 唯一管理标定任务，grab_calibration只推进采样；Base/Z/夹爪保持当前状态。成功更新共用 J 的前后与 X 两列：前后为像素/mm，X 像素/电机度乘 `x_ppm × 360 / 3200` 后转成像素/mm；侧向 j01/j11 保持原值。失败/取消保留上次有效模型，姿态确认不覆盖有效模型。手动Base参考P001仍按原延期策略处理。见[退役记录](../开发记录/2026-10-09-MaterialVision退役与控制台保留.md)。

## 车载转盘与单件取放
ID 8、三仓、1∶1 直连为已确认硬件关系。首仓角度固定为软件参考 0°，第二、第三仓角度初始为 `unset`；人工对齐首仓后执行 `turntable origin`，读取实际位置建立偏移。该命令不回零、不清驱动位置计数。常规使用改为首次失能手动对齐第一仓、使能、`turntable save_zero` 保存机械零点；以后执行 `turntable home`，成功后自动同步第一仓参考，无需每次人工建立参考。机械零点保存在 ID 8 驱动器，区别于 STM32 RAM 中的仓位角度和库存。位置指令使用 3200 命令脉冲/圈，反馈使用 65536 协议单位/圈。

| 命令 | 含义 |
|---|---|
| `turntable get <key>` / `turntable set <key> <value>` | RAM 参数读写；`slot1_deg` 只读；其余键为 `slot2_deg`、`slot3_deg`、`speed_rpm`、`acc`、`pos_tol_deg`、`stable_ms`、`feedback_ms` |
| `turntable enable` / `turntable disable` | 单独使能/失能 ID 8，应答后读驱动状态确认 |
| `turntable save_zero` | 将当前单圈机械零点保存到 ID 8 驱动器（0x93，存储标志 1），同时同步第一仓参考 |
| `turntable home` | 单圈就近回零（0x9A，模式 0）；回零状态、速度和位置稳定后自动恢复第一仓参考 |
| `turntable origin` | 人工对齐后的参考采集，受理后等待反馈结果 |
| `grab status base\|x\|z` | 短轴诊断：实际/目标、驱动状态位、新鲜度、停稳、任务到位结果；只读，不发送电机动作 |
| `grab place car` | 机械臂初始车载放料：以已验证后向 Base 锚点为基准，Z 提起、X 收回、Base 转到车载取放方向、X 到 `x_car`、Z 到 `z_place` 后松爪；结束停留在放料姿态。不驱动 ID 8，不更新三仓库存 |
| `turntable index <slot>` | 1～3 仓最短方向分度；未标定仓拒绝 |
| `turntable jog <degree>` | 从当前实际位置相对点动，角度单位 ° |
| `turntable stop` / `turntable status` | 停止请求 / 查询状态；受理、发送和停稳分别报告 |
| `turntable inventory` | 读取三仓软件库存 |
| `turntable inventory empty` | 人工核对后确认三仓为空 |
| `turntable inventory <slot> empty\|unknown\|<color>` | 校正指定仓库存；保留 B2 色号 1～6，`unknown` 表示待核对 |
| `grab start fixed` | 原料固定夹取入最低编号空仓 |
| `grab start fixed <slot> <color>` | 原料固定夹取入指定仓 |
| `grab start pick [color]` / `grab start pick <color> <slot>` | B2 对准后原料入仓；省略颜色仍为红色 1 |
| `grab store proc <slot> <color>` | 已完成水平对准处夹取粗加工物料并入仓 |
| `grab take <slot> rough\|temp1\|temp2` | 从车载仓取出，在已对准处向粗加工/暂存第一层/第二层竖直释放 |
| `grab return` | 有有效外侧参考时显式返回保存的观察姿态 |

转盘调试初值为 30 RPM、加速度档位 8、位置容差 1°、稳定 200 ms、反馈窗口 2000 ms。这些是软件初值，仓位及旋转余量仍需实物验收。分度按新鲜位置、速度、状态反馈判断，不能用命令 ACK 替代到位。上电库存全部待核对，普通停止和恢复不清库存；中断夹取/释放后涉及仓位标待核对。

最高 Z 位置为 0，下移目标为负。旧 `z_grab / z_lift / z_place` 保持绝对目标含义；新参数仍使用 `grab get/set`：

| 界面距离（正数） | 固件绝对目标或换算 | 固件初值 |
|---|---|---|
| 原料夹取下降 | `-z_grab` | `z_grab=-80 mm` |
| 原料夹取后抬升 | `z_lift-z_grab` | `z_lift=-40 mm`，抬升 40 mm |
| 粗加工夹取下降 / 抬升 | `-z_proc_grab` / `z_proc_lift-z_proc_grab` | 两项目标未设置 |
| 车载仓取放下降 / 取出后抬升 | `-z_place` / `z_car_lift-z_place` | `z_place=-60 mm`、`z_car_lift=0 mm` |
| 粗加工释放下降 | `-z_proc_place` | 未设置 |
| 暂存第一层 / 第二层释放下降 | `-z_temp_place` / `-z_stack_place` | 未设置 |

`x_car` 为车载取放口 X 绝对位置，固件默认 `100 mm`（用户 2026-10-05 指定的 10 cm）；初始化和 X 回零验证成功后恢复该值。`grab set x_car ...` 仍仅修改 RAM，普通停止保留修改值，复位后恢复固件默认；手动改变 X 原点仍使相关参考失效，需验证回零后恢复。`base_car_offset=-180°` 是外侧实际参考到车载方向的角度偏转。修改某组下降距离时，界面按该组抬升距离重新计算提起绝对目标。第二层下降距离应以第一层下降距离减实际下层高度标定，不能直接代入赛题名义高度。

仅检查当前场景所需参数，未标定加工区或两层目标不阻断原料首仓测试。入仓先抬 Z、收 X，再分度；车载取出后也先抬 Z、收 X 再转向。Base 使用开始动作时保存的实际外侧反馈作锚点，完成后反馈确认返回，连续两件不累加 −180°。手动改变原点继续使相关参考失效。`align` 到位后仍 HOLD；入仓/取出完成报告 `operation / scene / slot / result` 并释放占用，完整两批路线与自动码垛未实现。

`grab stop`、`stop all` 与总线恢复覆盖 ID 8，保持夹爪当前输出与 Z 使能。反馈不足时停止仅为未确认；总线恢复不续跑，必要时显式 `grab return`。软件库存和结果来自动作反馈，不是物体或碰撞传感器确认。

参数页五标签全部展开，初始“未读取”，`unset` 留空。读取全部顺序查询所有设备组（雷达整组分页一次），路线待用速度属于浏览器本地设置。应用只提交当前标签的改动，先等待受理，再主动读回比较，拒绝和部分成功分别显示。停止可取消剩余参数请求但保留草稿；断线或 MCU 重启将旧值标历史。页内链接只导航，不读写参数、不启用遥测、不启动运动。

`close_ms` 是夹爪开合指令后、下一步 Z 动作前的等待时间，固件默认 500 ms；闭合后提起与松开后退出共用此值。它不控制舵机速度，当前 PWM 夹爪没有到位反馈。该项移至网页“运动与标定”的动作时序组，通常无需调整，协议与默认值不变。

### 自动三轴回零与诊断
上电/复位自动启动 Z 碰撞→X 碰撞→Base 就近回零，三轴验证后才安排 IMU 静止 5 秒验证。`grab rehome` 使用同一流程；逐轴手动命令保留，单轴 HOME 受理不会自动建立三轴参考。不修改驱动器保存的回零电流、方向、模式或电机 ID。

每轴先读取回零标志，过温、过流或编码器/校准未就绪则停止；本次 HOME 发送前的 bit3 表示上一次回零失败，允许新 HOME 重试，不把它判成本次失败。HOME 受理后的 bit3 仍按本次回零失败立即停止。随后发送使能并读取实际电机状态，不能以 ENABLE ACK 代替使能确认。使能状态在 1500 ms 内仍不成立时为 `home_enable_failed`，不开始该轴 HOME。

HOME 完成后仍读取回零状态、位置和电机状态，要求连续两轮使能正常且位置稳定；X/Z 保留 ±182 反馈单位的零点窗口，Base 使用驱动保存的机械原点对应的实际多圈坐标，不清零。若仅使能位短暂为 0，先按 100 ms 查询节奏复查 600 ms（两轮完整的回零/位置/状态查询）；其间使能自行恢复则继续原流程。超过宽限且确认 HOME 成功、位置稳定、无过流/过温/回零失败/堵转保护，输出 `OK grab home_enable_recovery axis=... home_flags=... motor_flags=... raw=...`，仅补发一次 ENABLE，不重发 HOME。补发后 1500 ms 内重新核验两轮位置和使能；持续未使能报告 `home_enable_failed`，位置相对恢复前变化超过 182 单位报告 `home_position_changed`。驱动真实故障、总线错误和人工停止均不会触发补使能。

这些失败沿现有停止和回零中止流程处理，不建立失败轴参考。排除驱动/通信问题后，可用 `grab rehome` 重新验证；普通人工停止后不会自动续跑。诊断报告增加 `enable_recovery=0/1`，表示本轴是否已提交恢复使能。

回零请求未被总线接收且返回 `HAL_BUSY` 时，固件保持当前轴，按原有 100 ms 轮询节奏重试；已受理的 HOME 不重发，原有每轴 60 s 超时不变。真正锁定的总线返回发送错误，不自动清除锁定；停止及回零中止的优先发送仍保留。

请求提交硬失败时先输出 `ERR grab home_request axis=... action=... result=... bus_locked=... bus_reason=... uart_error=... fault_ms=...`，随后状态报告 `reason=home_bus_fault`（总线锁定）或 `home_request_failed`（其他提交错误）。驱动回零标志异常仍为 `home_driver_fault`，与提交错误分开。

三轴回零流程已启动、尚未全部验证时，`missing=home_pending` 表示“回零未完成，参考尚未验证”，不能解释为用户漏设 `x_ppm`。X 验证成功后仍恢复命令脉冲尺度约 `31.746 脉冲/mm` 及 `x_car=100 mm`；三轴完成后才按真实配置输出 `missing=none` 或具体缺项。网页中文摘要不参与协议解析。

## 机械臂通信错误

2026-10-03 启动接收修复：UART5 在本次上电首次发送尝试前、没有活动事务时遇到单独的 FE 帧错误，会清理接收残片并重启接收，按现行2 ms应答交接与队列调度继续提交请求。接收重启成功才算恢复；失败锁定并报告 `rx_restart_failed`。DMA 错误、接收溢出以及首次发送尝试后的错误沿用原处理，不以启动恢复名义忽略。此行为不重发已发送的电机运动命令，也不修改驱动配置。

`info` 在发生过启动恢复时追加 `[MOTOR BUS STARTUP] recovered_fe=<次数> last_ms=<最近一次故障时刻> rx_restarted=1`，表示历史启动接收恢复记录，不是当前实时健康保证。原 `[MOTOR BUS] locked/reason` 仍表示隔离状态与首次隔离原因。当前 `owner=9` 且 `addr=0 func=0 active=0` 表示没有历史发送事务，9 是 owner 枚举的结束标记；单电机通信测试 owner 为8，ID8转盘实际 owner 为7。旧固件未加入测试前的结束标记为8。

### 当前机械臂方向
2026-10-09 参数统一：`config <axis> <rpm> <acc> <limit_pulses>` 中的 `acc` 现在也用于该机械轴的任务位置指令，覆盖 GrabTask 的静态对准、取放、姿态、码垛及动态追踪 X，grab_calibration 的 X 也共用；Base 原来已读取轴配置。未修改轴上电初值：Base/X 为 20、Z 为 120。因此未另设参数时，原来任务中固定为 8 的 X/Z 现在分别使用 20/120。`rpm` 仍控制普通手动位置运动；任务速度由 `x_speed`、`x_transfer_speed`、`z_speed`、`z_pick_speed` 的阶段设置决定。`grab accel` 和 `grab track accel` 仍是独立控制剖面的 MCU 加速度（mm/s²），不能当作驱动器加速度档位。

`grab get/set` 的名称、默认值、范围和启动/回零载入时机由 `Code/template/App/grab_parameters.def` 定义，网页数值元数据由 `python Code/tools/sync_grab_parameters.py` 生成。`z_speed` 和 `z_pick_speed` 范围均为大于 0、至 333.333 mm/s，`grab track pick` 显式速度也使用此范围；运动前仍按当前 `z_ppm` 检查 1～3000 RPM。网页默认 Z 下限同步为 −150 mm、Base 偏转范围同步为 ±360°。默认值载入时机、未知场景高度留空及 RAM 保存规则保留。

- X：`pos x` 正值向外，负值向内；正值协议方向 CCW（1）。
- Z：当前安装实测 CCW 向下，已将正值协议方向改为 CW（0），使 `pos z` 正值向上、负值向下。设备是否具备此方向以当前固件和读回为准；`info` 输出 `arm positive_dir base=1 z=0 x=1 (0=CW 1=CCW)` 可核对。
- `home z collision` 的方向独立采用驱动器 `O_Dir`；当前安装要向上回零，应将其设为 CW。STM32 方向宏不修改驱动器已存储的回零参数。
- Z 普通运动上电默认等效于 `config z 500 120 0`：速度上限 500 RPM、Emm 加速度档位 120、单次脉冲数无限制（不代表机械行程保护）。控制台临时 `config` 只在 RAM，STM32 复位后恢复此默认值。首次低速点动可用 `config z 10 20 0`；回零速度仍由驱动器 `O_Vel` 决定。

现有 `enable/disable/state` 命令不变。单轴错误增加总线隔离状态：

- `ERR motor tx bus_locked=0/1`：请求未能提交到电机发送层。
- `ERR motor communication axis=base bus_locked=0/1`：异步传输失败，没有有效电机返回码。
- `ERR ack_timeout axis=base state_unknown bus_locked=0/1`：未在期限内收到合法应答，不能据此判断电机没有执行命令。

`bus_locked=1` 表示共享 UART5 总线处于故障隔离，后续普通电机请求会被拒绝；不是网页按钮失效，也不是驱动实际复位的证明。参见[UART5 循环 DMA 修复记录](../开发记录/2026-09-12UART5循环DMA与单次失能故障修复.md)。

2026-09-27 起，启动及 `info` 增加 `BUILD motorbus_diag=1 date=... time=...`。上述通信错误后以及 `info` 中输出首次锁定记录：

```text
[MOTOR BUS] locked=1 reason=uart_error fault_ms=12345 owner=2 addr=7 func=0x3A active=0 wait=0 uart_error=0x00000004
```

此行为格式示例，不是实车采样。`fault_ms` 为 MCU 启动后的故障时刻；`owner` 为 0=停车、1=底盘、2=机械臂、3=旧驱动接口、4=四轮反馈、5=尚无事务。`active/wait` 为故障记录时是否存在事务/等待应答；空闲 UART 错误时，`addr/func` 仅标记最后下发的事务，不能据此归责该电机。`drain_timeout` 则标记被取消且尚未收完应答的查询。

| reason | 含义 |
|---|---|
| `none` | 当前没有保留的隔离记录，其他故障字段不用于判断 |
| `uart_error` | UART5 HAL 错误回调；错误码在重新启动接收前保存 |
| `rx_overflow` | UART5 软件接收环形缓冲溢出 |
| `reply_timeout` | 已发送，等待驱动器应答超时 |
| `tx_timeout` | 未在期限内收到发送完成回调 |
| `cancelled_reply` | 取消了等待应答的普通事务，保留迟到应答隔离 |
| `drain_timeout` | 被取消的反馈查询未在期限内收完应答 |

`uart_error` 为位掩码：PE=0x01、NE=0x02、FE=0x04、ORE=0x08、DMA=0x10，可组合。首次记录不会被后续失败覆盖；正常查询不会清除记录或解锁。`info` 只读取 RAM，即使总线锁定也可以查看。详见[首次锁定诊断记录](../开发记录/2026-09-27-UART5首次锁定诊断.md)。

## 后向机械臂两批任务

`grab mission [speed_mm_s]` 显式启动右下固定两批搬运，默认200、范围10～5000 mm/s；`grab mission continue` 在 `config_wait` 补齐当前场景参数后继续本件。物理Base回零朝后，保存其实际多圈计数角；作业为顺时针90°，车载方向为逆时针90°，从作业切车载仍用 `base_car_offset=-180`，`x_car`默认100 mm。`grab pose rear|work` 只切换机构姿态，先抬Z收X，不操作夹爪、不执行HOME/ZERO。

新任务二维码处直接通过、不等待读码，不移动Z搜二维码。启动时冻结现有有效任务码，无码时明确使用模拟码 `156+123+516+231`。每批原料三件入仓→粗加工三件全部放好再取回→暂存；第二批按第一批颜色对应环码垛→返回右下。粗加工环1/2/3为右/中/左，暂存为下/中/上，间距150 mm，按已确认官方图。所有工位交接用station/visit，不依赖中转点序号。

首原料前保持90°向左平移，在最后75 mm接驳前车体顺时针90°到0°、Base顺时针90°朝物料台；加工最终车头180°、暂存90°。出站前收回朝后、返回站中心后续跑。新任务等待真实动作完成；底盘自动路线附加dwell现为0，保留减速与到位停稳反馈。旧 `grab route` 和 `radar task start` 仍是模拟首件调试，不改成两批任务。

任务报告沿用 `OK|ERR grab route state=...`，新字段 `mode=mission source=uart|simulated code=... batch=1|2 item=1..3 station visit stored placed elapsed_ms reason`。`stored/placed`各0～12，仅为控制动作完成计数。`config_wait`的reason为具体缺项；`grab set`在此等待阶段允许补齐，`continue`不会重复已完成物料。三仓角度不代填，启动前需真实转盘参考、三仓已配置且确认空仓。普通取消保留配置、计数及既有库存语义。

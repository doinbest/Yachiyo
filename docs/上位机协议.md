## UART5现行调度（2026-10-07）

ID1～8普通指令由完整匹配Receive应答推进，应答收齐后保留2 ms非阻塞总线交接间隔；取消旧固定10 ms发送间隔、底层重复100 ms批次门槛、追踪80 ms门槛及批后20 ms/两次反馈等待。四轮使用同一目标快照，ID1～4确认后广播FF并收取ID1应答；批间按待办owner轮转，忙时只保留最新目标。普通X停保持FE等待应答，人工/故障FE及9C停车链按TX完成推进并排空各地址的迟到应答；应答不代表实际停稳。`stop all`逐地址发送ID1～8，避免假定广播FE的应答地址。驱动Receive、115200、100 ms真实超时及业务到位标准不变。

追踪`control_ms=20`（20～100）表示定时预测间隔，新有效完整B2包在主循环立即修正；同时到期只计算一次，使用真实dt。`batch_ms=0`（0～200）表示应答驱动，非零为用户显式限频。X目标不再额外等80 ms，位置期望50 ms，年龄≥100 ms优先读一次并与写入交替。底盘160、X60 mm/s、加速度300及250 ms短漏检规则不变。普通停止/恢复不清参考或重充预算。

`bus status`只读返回总事务/普通/紧急/排空计数及各ID请求、成功、拒绝、超时、最近TX/回复、普通ACK耗时和排队耗时。`grab track status`附加`OK grab track timing`：视觉/定时触发次数、rx/parse/control时间、全更新间隔p50/p95/最大值、预测间隔、MCU接收到修正时延、估计/控制求解耗时、实际批次分布及批次耗时。rx来自完整帧末字节所在USB回调，parse沿用主循环解析时间；rx_samples是具有真实接收时间的样本数，缺少此统计时报告未知接收延迟。时钟精度1 ms；0 ms表示小于时钟分辨率，未知拍摄时间不称端到端时延。直方图最后一格200表示≥200 ms，max保留真实值；低样本量须结合计数。统计只随显式状态读取发送，不逐次广播。

Keil使用`MDK-ARM/uart5-memory.sct`，保留原Flash与两块SRAM地址，仅将不参与DMA的`Tracking`估计/128条记录/计时状态放入F407的64KB CCM（0x10000000）；所有DMA缓冲仍在原SRAM。EIDE本轮未维护。当前源码/网页预填不是已烧录状态，实机最小间隔与追踪效果待上板确认。

## 独立动态追踪 `grab track`（2026-10-06）

| 命令 | 行为 |
|---|---|
| `grab track begin [color] [remaining_mm]` | 一键观察、缺少参考时建立参考、随后持续追踪；等待本轮停稳反馈及新鲜视觉，不靠网页延时。默认余量50 mm，显式0～50；已有参考不充值 |
| `grab track pick [color] [z_mm] [speed_mm_s]` | 同上并在目标停留、像素对准、停车反馈确认后下降闭爪提起；默认原料z_grab（−80 mm）、z_pick_speed（111.111 mm/s）。完成picked，不自动入仓、不改库存 |
| `grab track observe [color]` | 视觉请求及反馈读取，不发运动；显式调用重新发送B2请求，支持Pi程序重开；默认沿用观察颜色，无观察默认蓝3 |
| `grab track reference [remaining_mm]` | 静止且反馈有效时建立局部料台参考；默认50 mm，显式剩余预算允许0～50 mm。复位后按实际间隙／保留位移恢复较小预算，不把物理位置当作回到原位；不改地图原点或IMU |
| `grab track start [color]` | 已建立参考后，读取当前姿态开始速度匹配与共同追踪；不回缩X、不移动Z/Base/夹爪 |
| `grab track stop` | 与`grab stop`共用停车处理，优先受理，保留配置/料台参考/累计接近位置 |
| `grab track get <key>` | 只读独立RAM参数 |
| `grab track set <key> <value>` | 停止或仅观察时写独立RAM参数，回复实际值；不覆盖静态`grab set`参数 |
| `grab track status` | 只读当前状态、运动估计、全段新样本误差统计 |
| `grab track trace` | 停止后连续导出最多128条冻结记录；运行中返回`trace_running`，不停止设备 |
| `grab track trace <index>` | 只读补传一条冻结记录，索引0起；不运动、不重新采样 |
| `grab track log start [period_ms]` | 开启被动实时诊断，默认50 ms，允许50～1000 ms；不启动观察/追踪、不改参数或参考 |
| `grab track log stop` | 只关闭实时诊断订阅，**不是运动停车**；追踪停车仍用`grab track stop` |
| `grab track log status` | 只读订阅状态、编号、周期和已产生记录数 |

颜色仍为B2的1红、2黄、3蓝、4绿、5黑、6浅蓝。`get/status/trace`是只读，不因全局停车锁禁止读取；`observe/reference/start/set`不是只读。停止或取消不会自动重建参考，真实轴原点/观察方向变化按现有参考失效处理。

速度匹配`track_match`→稳定跟随`track_follow`→保持姿态`track_pause`。稳定按误差窗口持续200 ms标记，不要求底盘/X静止。`track_visual_wait`等待新的视觉后继续；`track_window_end`在反馈确认停稳后继续观察和计算可达性，新有效坐标可在原有行程与剩余预算内跟随时自动恢复，原因`track_window_recovered`。重复旧坐标、预测定时器或无效视觉不单独触发续追；等待中的候选速度不发送，恢复仍从静止按原加速度起步。不重新回零、充值接近预算或作抓取；人工stop结束本轮，后续目标返回也不自动重启。主状态`stop_requested`和`stop_confirmed`分别为停车请求及实际反馈确认，不把`OK ... accepted`当作停稳。等待可达期间记录继续更新，需显式stop后再导出冻结记录。

追踪中X速度回落至零时，取消旧前瞻目标的单轴FE停保持使用普通UART5调度，不抢占四轮Receive/同步批次；仍读取X位置和状态。人工`grab stop/track stop`、轴停止及故障停车保持原紧急优先级，不能用正常停保持代替紧急停车。

状态为`OK grab track state=... reason=... color=... ref=... valid=... cx=... cy=... dx=... dy=... vf=... vl=... vx=... x=... room=... xr=... stop_requested=... stop_confirmed=... seq=...`；dx=CX-ref_u，dy=ref_v-CY。diag中的du/dv为扣除自身运动后的目标像素速度；ff/correction依次是车体前向、左向、X伸出，单位mm/s。`batch`为已完成批次间隔，`feedback_age`为X位置年龄，forward/left为局部累计位移。stats每个新有效视觉样本计一次，包含启动过渡；p95为1 px分箱的保守上界，100箱表示≥100 px，不把溢出视作精确100。

2026-10-08：追踪反馈失败保存触发快照，状态额外回 `OK grab track feedback_fault id=... kind=position|state|speed age_ms=... limit_ms=... valid=...`；后续停车回读不覆盖，下一次显式 observe/start 清除。`bus status` 另回 `OK bus motion locked=... error=... feedback_allowed=...`，显示底盘锁定及共享总线只读通路；不能仅凭共享总线 locked=0 判定运动可启动。追踪 IO 为 X 最新运动、X 位置、低频轴反馈轮转；原有反馈阈值与任务边界不变。

停止后按需`status`另回`OK grab track estimate fit=vu,vv,au,av comp=pu,pv confidence=cu,cv`：fit为最后一次无约束局部拟合的速度(px/s)和加速度(px/s²)，comp为该视觉帧扣除机构位移后的坐标，confidence为线性趋势相对当前测量不确定性的连续权重(0～1)，不是颜色识别可信度。不在运动中广播此额外行，不将最后一次估计信息冒充整段逐帧记录。当前追踪拟合保留240 ms默认窗口，以约0.5 px噪声尺度加入速度/曲率连续先验；运动中再按J投影的“上一控制速度减实际反馈速度”及50 ms不确定性尺度增加拟合噪声方差，避免电机响应和交错反馈造成的补偿残差变成高置信度物料加速度。此尺度只调整估计权重，不改变延迟参数、速度上限、行程或停车条件；仅观察时仍用原量化噪声。一像素范围内不延续加速度，弱趋势慢更新、清楚趋势快更新，不把位置到点窗口当速度前馈开关。

冻结导出为`OK grab track trace_begin count=N`、多行`TRACK row i=... t=... seq=... rx=... data=... crc=XXXXXXXX`、`OK grab track trace_end`。data依次为19项：误差u/v、目标像素速度u/v、实际前/左/X速度、命令前/左/X速度、X位置、局部forward/left、剩余接近room、batch、X反馈age、request_age、sent_age、flags。前14项保留两位小数，末5项整数。CRC为IEEE CRC32，覆盖从`TRACK row`起到` crc=`前的ASCII（不含arm提示符和换行）。网页核对数量/索引/CRC，坏条不覆盖好条，结束后仅补读缺条，完整后才导出。

时间为MCU ms，rx是接收时间不是拍摄时间，age为X位置反馈年龄。request_age是速度请求受理年龄，sent_age是同步发送完成年龄，65535表示未知；flags位0有效视觉、位1运动模式、位2稳定、位3预测。记录每次计算，分析误差必须按seq/rx去重；实际批次统计按`t-sent_age`去重，不能把每条计算行都当作新发送。默认运行中仅低频摘要；可以显式开启下述实时记录。冻结导出只在停止后进行，每200 ms一条，不给追踪控制或USART1全局添加等待。

### 长时间实时记录（2026-10-07）

上电默认关闭。`log start`回`OK grab track log_begin id=... period_ms=... next=...`，随后仅在观察/追踪产生控制记录时发送`TRACK live id=... i=... t=... seq=... rx=... data=... io=... crc=...`。data与冻结记录相同19项；CRC覆盖从`TRACK live`到` crc=`前的全部ASCII，包括io。新订阅用新非零id；重复start保留id/索引，仅改周期。`log stop`回`OK grab track log_end id=... count=...`，count为本订阅产生的候选记录数，不是电脑成功接收数。`log status`回enabled/id/period_ms/count。订阅命令可在停车锁定中操作，不解锁、不改变任务状态；刷新、重连不自动订阅。

实时io为34个逗号分隔整数，索引从0起：

| 索引 | 内容 / 单位 |
|---|---|
| 0～3 | 已完成同步批次四轮RPM，逻辑前向符号，不是计算请求速度 |
| 4～7 | 四轮原始位置，int64协议单位，保留协议符号；网页按字符串保精度 |
| 8～11 | 各轮位置反馈年龄ms |
| 12～14 | X最近已发送目标脉冲、RPM、DMA完成年龄ms |
| 15～16 | X原始位置（轴逻辑符号）、已发送动作（3位置、9停止） |
| 17～20 | 底盘总线stage/error/locked、有效位掩码 |
| 21～22 | 底盘motion_sequence/stop_sequence |
| 23～25 | X最近受理目标脉冲、RPM、受理年龄ms，与已发送值独立 |
| 26～29 | 四轮最新速度反馈RPM，保留协议符号 |
| 30～33 | 四轮速度反馈年龄ms |

有效位：bits0～3四轮位置，bit4已发送四轮速度，bit5 X已发送，bit6 X Receive确认，bit7 X位置，bit8四轮确认，bit9批次发送完成，bit10 X目标受理，bits11～14四轮速度。年龄65535表示未知，已知年龄饱和到65534；先看有效位再解读0值。X发送事件在事务结束时发布，但时间戳取真实DMA完成时刻，不把Receive确认时间当成发送时间，更不把确认当成物理移动。

详细IO只用一个当期快照，不扩展128条环形缓存；冻结`TRACK row`仍为原19项，不会把当前IO附到历史行。USART1复用空闲DMA缓冲，无新等待、无诊断历史队列：忙/优先回复时跳过记录，未开始的记录可替换/让位，已开始整行发送完。i在每次候选记录递增，电脑明确报告缺号/坏CRC；默认50 ms是请求采样周期，**不保证DL-20无损20 Hz**，可显式`log start 100`降低占用。停车回复仍优先，原波特率115200/8N1不变。

本地桥接持续、无缓冲写入`.embeddedskills/logs/serial/<连接时间>-rx.bin`（收到的原始字节）及`.jsonl`事件日志，保存时间不受6.4 s环形窗限制。建议运动前开记录，运动停止并取得反馈确认后再关闭记录、留出最后整行传输时间；关闭网页或断串口不是停车。分析用`python Code/tools/tracking_report.py <原始-rx.bin> --source live --kind physical`；冻结与实时不混合，缺条不冒充完整记录。长日志只能保存**已经上传**的信息，无法补回无线丢字或此前未启用的动态段。运行速度、时长可从日志估计，但仍不能当作独立测得的真实转盘角度/转速。

## F1 雷达主机协议 `f1_host`（2026-10-04）

`#map/radar` 复用 F407 USART1 的 115200 / 8N1 共享连接；LDS50C 由 F407 USART2 以 921600 / 8N1、DMA 循环接收。F407 冻结完整圈后执行筛选、5×5 建图和确定性四邻域规划，网页只组装并显示设备结果。进入页面、切换页签、重连、刷新、保存浏览器配置或查询本地状态都不自动发送雷达命令，也不启动底盘或机械臂。

### 命令

| 命令 | 含义 |
|---|---|
| `radar host status [fast]` | 读取主机状态、当前结果编号和点数；`fast` 选择紧凑结果并主动同步已有结果 |
| `radar host start` | 请求 LDS50C 开始旋转，不组装完整圈 |
| `radar host stop` | 请求停止扫描/实时预览，并取消尚未发送完的主机分页 |
| `radar host scan [fast]` | 使用活动配置采集一个完整圈；若主机持续模式正在运行，先替换该模式；完成后在 F407 内建图和规划，不中断实车专属采集；网页默认带 `fast` |
| `radar host live start [fast]` / `radar host live stop` | 开始/停止持续完整圈建图和规划，并提供120分区预览；不改实车地图与路径；网页开始时默认带 `fast` |
| `radar host live status` | 读取与 `radar host status` 相同的状态帧 |
| `radar host draft reset` | 从当前活动配置建立 RAM 草稿，并产生新的草稿修订号 |
| `radar host set <key> <value>` | 修改当前 RAM 草稿的一项，不直接改变活动配置 |
| `radar host apply <revision>` | 按修订号原子应用草稿；有完整缓存时同圈重算；持续采集时在下一个完整圈生效，不重启雷达；无完整缓存且已停止时在下次扫描生效 |
| `radar host get active` / `radar host get draft` | 分页读取活动配置或当前草稿 |
| `radar host result <plan>` | 一次请求后连续回传同一冻结结果的全部地图页、路径页和结束标记；只读，不重新扫描或规划 |
| `radar host bundle <plan> all` / `radar host bundle <plan> 0,2,4` | 重传紧凑结果的全部页或指定缺页列表；只读，不重新扫描或规划，正常推送不需要此请求 |
| `radar host fetch <kind>:<id> <page>` | 读取指定编号、指定页；`kind` 为 `config`、`map`、`path`、`preview` 或 `cloud` |
| `radar host ack <plan>` | 网页收齐同圈地图与路径后确认结果；释放无线冻结结果，以便发送最新圈。只影响发送缓存，不控制采集或运动；同编号重复确认幂等 |

`set` 的标量键为 `angle_min`、`angle_max`（0.1°）、`distance_min`、`distance_max`（mm）、`energy_min`、`energy_max`、`radar_x`、`radar_y`（mm）、`x1`～`x4`、`y1`～`y4`、`threshold` 和 `manual_mask`。`planning_mode` 取 `mission` 或 `point`；`mission` 使用连字符格式，例如 `1-5-4-2-3-4-2-3-1`；`start` / `goal` 使用 `<row>,<column>,<anchor>`，其中 `anchor` 为 `cell`、`radar` 或 `goal`。固定障碍和保护掩码只读，不允许网页改写。

成功/失败命令回复为 `OK radar host <reason>` 或 `ERR radar host <reason>`。回复只表示命令在 F407 侧受理或拒绝；USART1 发送完成不等于 LDS50C 已执行。状态和数据帧统一为单行：

```text
@RADAR {"v":1,"profile":"f1_host",...}\r\n
```

上述 v1 帧都包含 `session`、`config`、`scan`、`map`、`plan` 五个无符号身份字段。网页只把同一身份、页数、总数和结果编号的页拼成完整快照；设备重启导致 `session` 改变时，已有完整快照保留但标记为历史。数据分页还包含 `page`、`pages`、`offset`、`total`；状态帧和结果结束标记不属于数据分页。整行连同前缀和 CRLF 不超过 256 字节。

### 当前网页默认：紧凑结果与同圈一起刷新（2026-10-05）

`fast` 仅选择雷达结果传输格式，不改变采集、筛选、判障或规划。采完完整圈后，F407 主动发送状态和同圈地图/路线，不再先等待网页发 `result`。网页收齐整个结果后，在同一次接收事件中替换地图和路径，因此不会出现新障碍已显示但路线还在等后续分页的间隔。无路时同样一起发布障碍和准确的失败工位。

短帧为 ASCII JSON，`d` 为 Base64；CRC 字段 `c` 覆盖删除 `c` 后的整份紧凑 JSON，IEEE CRC-32 算法与文本页一致，身份与分页也在覆盖范围内：

```text
@RADAR {"v":2,"k":"r","i":[session,config,scan,map,plan],"l":0,"p":0,"n":5,"t":404,"d":"...","c":"12345678"}\r\n
@RADAR {"v":2,"k":"e","i":[session,config,scan,map,plan],"l":0,"n":5,"c":"12345678"}\r\n
```

`l` 是冻结结果所属模式（0单次、1持续），也受CRC保护；切换模式时仍在无线队列里的旧模式结果不会冒充新扫描。`p` 为从0开始的页号，`n` 为总页数，`t` 为完整二进制字节数；每页最多84字节，字节偏移为 `84*p`。所有字节先组装再解码；正常33路点为404字节/5个数据页，最大193路点为2004字节/24页。不是上传原始点云，也不是删除中间路线点。布局如下（多字节整数小端）：

| 偏移 | 内容 |
|---|---|
| 0 | 布局版本 `uint8=1` |
| 1、3、5 | 原始、筛选、网格外点数 `uint16` |
| 7、11、15 | 扫描、手工、有效障碍掩码 `uint32` |
| 19、20、21 | 路线有效、失败起/终工位 `uint8` |
| 22 | 完整路点数 `uint16` |
| 24～73 | 全部25格点数，每格 `uint16` |
| 74起 | 每路点10字节：X、Y、下一段距离各 `uint16`，行、列、方向、动作各 `uint8`；全部保留 |

网页收到结束标记便以一个逗号列表请求补齐缺页；结束标记丢失时，1秒无有效推进即可开始补读。已经发出的补读按原10秒无有效推进窗口等待无线回复，有进展便延长窗口，不每秒重复催发。最多三次批量恢复，最后失败保留上一完整结果并提示。CRC 坏页不污染好页，停止/新扫描取消旧读取。地图与路径完成即可 `ack`，不用等结束标记。

持续模式冻结当前结果至确认，之后取最新完整圈，跳过积压的中间圈；保留每4次确认后的一圈完整预览，预览不参与判障，显式新扫描/结果请求仍可打断它。配置、完整点云和旧 `result/fetch` 文本分页继续可用。USART1 仍为115200/8N1、64字节DMA块，不恢复固定30ms等待。实车监控、地图算法与其他控制命令不变。

### 状态与分页记录

以下 v1 文本分页和旧 `result/fetch` 恢复流程用于兼容客户端及显式诊断；当前网页默认的自动同步采用上节紧凑结果流程。状态、配置与点云仍使用 v1。

- `k:"host_status"`：`a` 为单圈采集活动标志，`l` 为持续建图活动标志，`ss` / `ls` 为固件扫描/预览状态枚举，`cloud` / `preview` 为当前点数，`reason` 为当前原因。`scan/map/plan` 在无线读取期间绑定同一冻结结果，而非未发出的最新采集圈；当前配置尚无完整建图结果时 `map/plan=0`，不把旧图标成新配置。
- `k:"host_config"`：每页 `data` 是一条逗号分隔记录。顺序固定为 `source`、`width`、`height`、`x1..x4`、`y1..y4`、`radar_x`、`radar_y`、`angle_min`、`angle_max`、`distance_min`、`distance_max`、`energy_min`、`energy_max`、`threshold`、`fixed`、`manual`、`protected`、`planning`、`mission`、`start`、`goal`；`source` 为 `active` 或 `draft`，掩码是最多8位十六进制。
- `k:"host_map"`：`data` 依次为统计 `s,<raw>,<filtered>,<outside>`，掩码 `m,<scanned>,<manual>,<effective>`，路径结果 `p,<valid>,<failed_from>,<failed_to>`，以及25条 `c,<index>,<count>`；格索引从左下 R1C1 开始按行递增。
- `k:"host_path"`：每个路点为 `w,<x_mm>,<y_mm>,<distance_to_next_mm>,<row>,<column>,<direction>,<turn>`；无路点时为 `n,<valid>,<failed_from>,<failed_to>`。方向与动作保持 F407 枚举值，网页只显示设备返回结果。
- `k:"host_result_end"`：一次 `result` 回传的结束标记，`mp` / `pp` 分别是实际地图页数和路径页数（包含无路径的单页）。身份与本次全部数据页一致；用于识别整组或首尾页丢失，不更新地图或路径。

`host_map` 和 `host_path` 每页按256字节预算合并多条完整记录，以分号分隔；`offset` 是记录序号，`total` 是记录总数，`pages` 是实际页数，不再等于记录总数。网页兼容旧单记录页，但不可写死28页地图或一页一个路点。无路径的 `n` 仍是单页、`offset=0,total=0`。

2026-10-05：地图/路径每页增加8位十六进制 `crc32`，覆盖去掉 CRC 字段后的紧凑 ASCII JSON（无前缀和 CRLF）。字段顺序为 `v,profile,k,session,config,scan,map,plan,page,pages,offset,total,data`，使用 IEEE CRC-32（反射多项式 `0xEDB88320`，初值/末异或均为 `0xFFFFFFFF`）。它与下文完整点云 CRC 的覆盖范围不同。网页在信任身份或存页前检查该页 CRC，坏页不清空其他已通过的页，结束标记后只补坏页/缺页。兼容旧固件无 CRC 页，但路径记录仍逐页检查。同步中的可恢复坏页不弹成终止错误，补读失败才报告。USART1 仍不增加固定 30 ms 等待，判障和规划不变。

显式配置读回也冻结配置值及五个身份字段；持续扫描圈号变化不会让27页配置相互冲突。`get active/draft` 开始新读回，`fetch config:<id> <page>` 可补读相同版本。
- `k:"host_preview"`：额外带非零 `uint32 live_id`，它是独立完整预览圈号，不是静态 `scan`；同次MCU运行内递增，停止再开始不复用编号，溢出跳过0。`data` 为 Base64；每点4字节，小端 `uint16 angle_tenths` + 小端 `uint16 distance_mm`。
- `k:"host_cloud"`：`data` 为 Base64；每点5字节，小端 `uint16 angle_tenths` + 小端 `uint16 distance_mm` + `uint8 energy`。完整圈最多4096点；预览为120个角度分区。

`host_preview` 和 `host_cloud` 每页都带同一份8位大写十六进制 `crc32`，CRC覆盖完整解包字节流，使用 IEEE CRC-32 多项式 `0xEDB88320`。网页按 `offset` 连续拼页、验证点宽和完整流 CRC；身份、页形状、重复页或 CRC 不一致时不替换上一个完整快照。

持续预览发送前复制一圈点数据、身份、点数和CRC到独立冻结缓存；所有分页带相同 `live_id`。采集继续更新不会覆盖正在发送的圈；传完后才取当时最新完整圈，跳过积压的中间圈。`fetch preview:<id>` 中的id对应 `live_id`，允许补读仍保留的冻结圈，不打断另一圈的发送。网页按圈号隔离分页，晚到旧圈页不覆盖新圈，丢页期间继续显示上一完整圈；收到新完整CRC有效圈后才整体更新，并解除该预览的旧分页错误。地图/路线错误不由预览成功掩盖。停止取消后续自动预览发送，断线后保留历史显示并重新接受当前设备圈号。没有 `live_id` 的旧固件预览帧不拼装，须同时更新固件和网页。

扫描阶段或结果编号变化时 F407 发送 `host_status`；网页只发送一次 `result <plan>`，F407 按“地图/25格统计 → 路线 → 结束标记”连续回传，不等待每页请求。F407 冻结广告中的地图/路线结果直到网页 `ack`，因此采集继续更新及最后路径页丢失都不使旧页失效。网页先收齐当前结果对，再处理更新圈，不并发读取地图与路线。新配置、会话及显式单圈扫描仍隔离旧请求。120分区预览改为每4次不同结果确认后发送一圈，重要结果请求可抢占尚未发完的预览；不发送积压圈，显式预览读取仍可用。配置仅在显式读回或参数应用时传输，完整云仍按需读取；“读取状态/结果”可补读并确认原冻结结果，不启动雷达。

结果结束标记到达后，网页按实际页数仅 `fetch` 缺页；如果结束标记也丢失，连续10秒没有有效同圈地图/路径页时，依据已有分页信息补读，整组无页时先读第0页取得页数。只要有效数据仍在推进，就延长等待，不因总传输时长超过10秒中断。地图和路径都完整且身份匹配后才确认，无需等待结束标记。单页10秒未得到有效回复时，只重读该页，最多额外两次；损坏的非 JSON 行及重复 `k` 的拼接 JSON 不计为成功，失败保留已有完整快照并允许显式再读。停止、断线取消读取，不发送新扫描命令。持续模式按 F1 相同投影、筛选、阈值及保护格，对每圈所有原始点流式计数并规划；120分区只作显示，不参与正式判障，也不受4096诊断云容量限制。持续圈不缓存完整点云，静态完整圈缓存及 `fetch cloud` 显式诊断保留；正常建图不上传完整云。USART1保持115200和64字节DMA发送块；按用户2026-10-05要求取消30ms固定等待。网页未收到图/路径时显示等待而非零点或不可达；实际无路仍显示设备规划失败。

### F1 默认值、保护与保存边界

默认场地 2400 × 2400 mm，内部线为 X/Y 各 `550、1000、1400、1850`，雷达位于 `(230,230)`，角度 `0..3600`（0.1°），距离 `100..40000 mm`，能量 `0..255`，障碍阈值为 1。固定障碍掩码 `0x00050140`，任务保护掩码 `0x00404405`；R1C1 起点和其余任务格不会被扫描障碍或手工障碍覆盖。默认任务路线为 `1-5-4-2-3-4-2-3-1`，起点 `1,1,radar`，点到点默认终点 `1,5,goal`。

设备活动配置和草稿都只在 F407 RAM 中，复位或重新上电恢复上述默认值；本协议没有 Flash 保存命令。“保存本机配置”是网页显式写浏览器本地存储，与设备配置分开；编辑输入或应用到设备都不会自动保存浏览器设置。此主机协议只负责旋转、采集、建图和路径显示，不提供 `nav start` 或车辆执行入口。

## 车载转盘与单件取放（2026-10-03）

ID 8、三仓、1∶1 直连为已确认硬件关系。首仓角度固定为软件参考 0°，第二、第三仓角度初始为 `unset`；人工对齐首仓后执行 `turntable origin`，读取实际位置建立偏移。该命令不回零、不清驱动位置计数。常规使用改为首次失能手动对齐第一仓、使能、`turntable save_zero` 保存机械零点；以后执行 `turntable home`，成功后自动同步第一仓参考，无需每次人工建立参考。机械零点保存在 ID 8 驱动器，区别于 STM32 RAM 中的仓位角度和库存。位置指令使用 3200 命令脉冲/圈，反馈使用 65536 协议单位/圈。

| 命令 | 含义 |
|---|---|
| `turntable get <key>` / `turntable set <key> <value>` | RAM 参数读写；`slot1_deg` 只读；其余键为 `slot2_deg`、`slot3_deg`、`speed_rpm`、`acc`、`pos_tol_deg`、`stable_ms`、`feedback_ms` |
| `turntable enable` / `turntable disable` | 单独使能/失能 ID 8，应答后读驱动状态确认 |
| `turntable save_zero` | 将当前单圈机械零点保存到 ID 8 驱动器（0x93，存储标志 1），同时同步第一仓参考 |
| `turntable home` | 单圈就近回零（0x9A，模式 0）；回零状态、速度和位置稳定后自动恢复第一仓参考 |
| `turntable origin` | 人工对齐后的参考采集，受理后等待反馈结果 |
| `grab status base\|x\|z` | 短轴诊断：实际/目标、驱动状态位、新鲜度、停稳、任务到位结果；只读，不发送电机动作 |
| `grab place car` | 机械臂初始车载放料：以已验证后向 Base 锚点为基准，Z 提起、X 收回、Base 转到车载取放方向、X 到 `x_car`、Z 到 `z_place` 后松爪；结束停留在放料姿态。不驱动 ID 8，不更新三仓库存 |
| `turntable index <slot>` | 1～3 仓最短方向分度；未标定仓拒绝 |
| `turntable jog <degree>` | 从当前实际位置相对点动，角度单位 ° |
| `turntable stop` / `turntable status` | 停止请求 / 查询状态；受理、发送和停稳分别报告 |
| `turntable inventory` | 读取三仓软件库存 |

| `grab start fixed` | 原料固定夹取入最低编号空仓 |

| `grab start pick [color]` / `grab start pick <color> <slot>` | B2 对准后原料入仓；省略颜色仍为红色 1 |
| `grab store proc <slot> <color>` | 已完成水平对准处夹取粗加工物料并入仓 |
| `grab take <slot> rough\|temp1\|temp2` | 从车载仓取出，在已对准处向粗加工/暂存第一层/第二层竖直释放 |
| `grab return` | 有有效外侧参考时显式返回保存的观察姿态 |

转盘调试初值为 30 RPM、加速度档位 8、位置容差 1°、稳定 200 ms、反馈窗口 2000 ms。这些是软件初值，仓位及旋转余量仍需实物验收。分度按新鲜位置、速度、状态反馈判断，不能用命令 ACK 替代到位。上电库存全部待核对，普通停止和恢复不清库存；中断夹取/释放后涉及仓位标待核对。

最高 Z 位置为 0，下移目标为负。旧 `z_grab / z_lift / z_place` 保持绝对目标含义；新参数仍使用 `grab get/set`：

| 界面距离（正数） | 固件绝对目标或换算 | 固件初值 |
|---|---|---|
| 原料夹取下降 | `-z_grab` | `z_grab=-80 mm` |

| 暂存第一层 / 第二层释放下降 | `-z_temp_place` / `-z_stack_place` | 未设置 |

`x_car` 为车载取放口 X 绝对位置，固件默认 `100 mm`（用户 2026-10-05 指定的 10 cm）；初始化和 X 回零验证成功后恢复该值。`grab set x_car ...` 仍仅修改 RAM，普通停止保留修改值，复位后恢复固件默认；手动改变 X 原点仍使相关参考失效，需验证回零后恢复。`base_car_offset=-180°` 是外侧实际参考到车载方向的角度偏转。修改某组下降距离时，界面按该组抬升距离重新计算提起绝对目标。第二层下降距离应以第一层下降距离减实际下层高度标定，不能直接代入赛题名义高度。

仅检查当前场景所需参数，未标定加工区或两层目标不阻断原料首仓测试。入仓先抬 Z、收 X，再分度；车载取出后也先抬 Z、收 X 再转向。Base 使用开始动作时保存的实际外侧反馈作锚点，完成后反馈确认返回，连续两件不累加 −180°。手动改变原点继续使相关参考失效。`align` 到位后仍 HOLD；入仓/取出完成报告 `operation / scene / slot / result` 并释放占用，完整两批路线与自动码垛未实现。

`grab stop`、`stop all` 与总线恢复覆盖 ID 8，保持夹爪当前输出与 Z 使能。反馈不足时停止仅为未确认；总线恢复不续跑，必要时显式 `grab return`。软件库存和结果来自动作反馈，不是物体或碰撞传感器确认。

参数页五标签全部展开，初始“未读取”，`unset` 留空。读取全部顺序查询所有设备组（雷达整组分页一次），路线待用速度属于浏览器本地设置。应用只提交当前标签的改动，先等待受理，再主动读回比较，拒绝和部分成功分别显示。停止可取消剩余参数请求但保留草稿；断线或 MCU 重启将旧值标历史。页内链接只导航，不读写参数、不启用遥测、不启动运动。

`close_ms` 是夹爪开合指令后、下一步 Z 动作前的等待时间，固件默认 500 ms；闭合后提起与松开后退出共用此值。它不控制舵机速度，当前 PWM 夹爪没有到位反馈。该项移至网页“运动与标定”的动作时序组，通常无需调整，协议与默认值不变。

## 帧、单位与结果

- USART1：PA9/PA10，当前 115200 / 8N1。端口由现场确认。
- 网页发送单行 ASCII，追加 CRLF；固件接受 CR 或 LF 行结束。命令内容最多 63 字节、6 个空白分隔字段，网页禁止内嵌换行。
- `OK` / `accepted` 表示命令的具体受理或查询结果，不统一代表到位；`ERR` 表示拒绝或错误。命令回显和异步日志可能交错。
- `pos` 是电机轴相对角度；网页限 ±360°，不能将网页限值当作固件所有轴的机械限位。
- `chassis run/heading` 使用车体前向 vx、左向 vy（mm/s）、逆时针 omega（rad/s）；旧 `chassis velocity` 的 yaw 单位为 °/s。
- `chassis move/origin` 使用地图 +X 向右、+Y 向上，地图角度与 HWT101 模块角度分开。
- 网页 `seconds` 转为整数 `hold_ms`；起步和停车各 500 ms。四轮顺序 FL/RL/RR/FR=1/2/3/4。

## 主控重启与 Z 轴归零

| 命令 | 用途 | 条件与结果 |
|---|---|---|
| `system reset` | STM32 软件复位，重新执行启动初始化 | 人工确认整车静止，软件任务及通信空闲；不是整车断电，也不代替停车 |
| `imu zero` | HWT101 当前 Z 轴角度设为零 | 保持静止；不标定零偏、不保存参数，不授予航向控制资格 |

`system reset` 先回复 `OK system reset pending target=stm32 peripherals_not_reset=1`，紧急回复完成 USART1 发送后再等待 200 ms，通过 CMSIS `NVIC_SystemReset()` 请求主控复位。200 ms 只是无线链路留时，不保证网页收到。发送失败或超过 5 秒取消重启；等待期间拒绝新业务命令，Ctrl+C、`chassis stop`、合法的 `stop all/base/z/x`、`material stop`、`camera stop` 可取消重启并执行各自原有停止操作。忙时返回 `ERR system reset busy`。主循环卡死或无线链路中断时无法依靠此命令恢复。

忙检查反映软件任务与通信事务，不是整车静止检测。机械臂 `pos/home` 收到驱动 ACK 后仍可能在运动；发送重启前必须人工确认整车静止。

重启后 RAM 中的任务、验证、地图锚点及订阅重新初始化；电机驱动器、HWT101、香橙派等外部设备并未断电复位，夹爪 PWM 会经历启动初始化。网页收到 `STM32 mechanical arm console ready` 后清除旧状态；请重新验证 IMU、准备跑图和手动开启订阅。本地服务停止锁定期间两条命令均不允许发送，须先确认停车并解除锁定。

`imu zero` 异步执行解锁 `0x69=0xB588` → 等待 100 ms → `CALIYAW 0x76=0` → 等待 100 ms → 读取后续新样本。受理回复为 `OK imu zero started ...`；结束回复 `OK imu zero sample before_deg=... after_deg=... verified=0 control_ready=0`。这表示已收到写入后的样本，是否接近零由实际 `after_deg` 判断；不是漂移验证通过。`imu status` 中结果为 `ZERO_SAMPLE`。I2C 失败、无新样本和取消流程沿用现有标定错误报告。归零会撤销旧航向资格与地图锚点；跑图前重新 `imu verify` 并设置地图起点。`imu cal cancel` 也可取消归零流程。

## 补充接口与操作语义

- `chassis stream on <非零uint32会话编号>` / `chassis stream off`：手动遥测订阅。
- `chassis stop [非零uint32客户端编号]`、`chassis stop-status`：独立停车与查询，详细语义见下文。
- `screen status`：读取 USART3 屏幕通信统计，可通过手动终端发送；不属于网页快捷按钮。
- `imu verify 5` 是 `imu verify` 的兼容别名。`imu verify 120` 已移除，返回格式错误。
- `imu cal clear` 为兼容入口，取消当前标定/验证并清除本次验证资格；`imu cal forget` 返回 `ERR imu cal forget deprecated no_erase=1`，不擦除存储。它们不恢复旧软件补偿方案。
- `chassis run vx vy 0 hold_ms` 保持起步模块航向，须本次 IMU 验证通过且数据新鲜，不要求地图原点；非零 omega 执行给定转向。`chassis heading` 仍需锚点。
- `imu cal start` 为约 20 秒原生标定及 30 秒自动验证；独立 verify 为归零后的 5 秒静止验证。重新验证会撤销旧航向资格，需重新建立地图原点。
- `imu status` 的 `zero_requested/zero_sample_received/zero_before_deg/zero_after_deg` 区分归零请求与后续样本；HAL 成功不单独证明实物归零完成。
- `stop all` 的作用取决于当前任务，不能等同整车硬件急停。`material auto` 的 ALIGNED 仅表示对准完成。
- 本车已确认 Emm42 固件仅修改 ID，控制台准备流程使用默认 Receive 应答及 65536 反馈单位/电机轴圈；无需重复实测协议常量。四轮安装方向与实际地图起点仍需确认，不能以 3200 控制脉冲/圈替代反馈单位。`chassis reset-confirmed` 不操作硬件复位。

## 二维码查询与事件

查询不消费主循环任务码，跟随开关不启动扫码器。

| 命令 | 含义 |
|---|---|
| `qr status` | 读取接收统计，不消费任务码 |
| `qr read` | 读取最新有效缓存，可重复读取 |
| `qr stream on/off` | 开启/关闭新码事件上报，不控制扫码器 |

回复形式：

```text
OK qr status valid=0 seq=0 age_ms=NA received=0 accepted=0 rejected=0 uart_errors=0 stream=off event_dropped=0
OK qr read valid=0 seq=0 code=NA age_ms=NA
OK qr stream=on
EVT qr code seq=1 code=123+231+312+123 age_ms=0
```

有效原码为四组三位数字；`seq` 与 MCU 毫秒时间为 uint32，可回绕。`age_ms` 是 MCU 计算的最新有效码年龄，没有有效码时为 NA。`received` 按字节、`accepted/rejected` 按完整帧、`uart_errors` 按 UART 错误计数。重复有效码同样递增序号；没有新码不表示离线。新码事件最多 5 Hz，只保留最新待发事件，`event_dropped` 与地图丢弃统计独立。格式化与发送在主循环运行；主循环原单次消费接口保留。

详见 [八千代控制台与二维码接入](开发记录/2026-09-12八千代控制台与二维码接入.md)。


## 实车反馈距离与完整路线

`chassis move <map_dx_mm> <map_dy_mm>`用于相对地图位移诊断（长度>0且≤300 mm、50 mm/s）。`chassis turn <map_yaw_deg>`使用地图绝对航向，纯转向时平移输出为零，保留原点与IMU锚点；`chassis heading`仍使用模块角度。原点需显式`chassis origin`设置。

固定路线为15个业务目标，默认平移200 mm/s、距离加减速300 mm/s²；页面平移速度不控制旋转，路线转向采用100°/s上限。首个目标内部按(2250,150)→(2100,300)→(2100,1200)执行，先斜移再直行、全程90°，中间点不触发工位交接；雷达规划的其他绕行路点不变。长段先转向再前进或后退，到工位恢复90°；暂存位在(425,1200)转向，最后75 mm进出不超过min(启动速度,50)。start模式每个业务目标完成后等待人工next，内部阶段自动连续执行；auto模式业务目标停稳后等待0.1秒继续。每个转向/行驶动作更新action_id，业务segment/visit保持不变；取消任意阶段后不再提交后续动作。段预算包含转向和接近，范围60～400秒，修正不延长原截止时间。完整目标及实车检查见[低速转向路线与验收顺序](开发记录/2026-10-03-底盘低速转向路线与验收顺序.md)。

`@CHASSIS`详细快照为v1，紧凑流为v2；原route对象/数组布局保留，增加可选状态：

- `localization`：generation、feedback_tick、origin_valid。
- `route`：state（idle/running/stopping/waiting/done/error/cancelled）、reason、segment（固定路线1～15，规划路线动态）、action_id、target（业务目标地图X/Y mm、航向deg）、error、feedback_valid、stop_confirmed。
- `route_meta`：action_id、total、station、visit、phase、direction、speed_mm_s（本次启动设置）、phase_speed_mm_s（当前阶段限速）、phase_target（内部目标X/Y/yaw）、planned。只与同帧同action_id的route合并。phase可为turn/move/arrival_turn/dock_approach/dock/undock；direction可为turn/forward/reverse/lateral/diagonal。
- `distance`：距离或原地转向任务输出；active、state、reason、action_id、target/error数组及feedback_valid、stop_confirmed。独立move/turn清除旧路线显示；活动路线段显示优先。

`feedback_arrived`和stop_confirmed表示轮子反馈估计到站并满足停止条件，不表示视觉精确对准。等待人工继续期间仍占用任务；查询/停止允许，其他运动/标定/修改定位配置拒绝。详见[实车前四段反馈路线](开发记录/2026-09-12实车前四段反馈路线.md)。

## 机械臂通信错误

2026-10-03 启动接收修复：UART5 在本次上电首次发送尝试前、没有活动事务时遇到单独的 FE 帧错误，会清理接收残片并重启接收，经过原有 10 ms 总线间隔后继续提交队列中的请求。接收重启成功才算恢复；失败锁定并报告 `rx_restart_failed`。DMA 错误、接收溢出以及首次发送尝试后的错误沿用原处理，不以启动恢复名义忽略。此行为不重发已发送的电机运动命令，也不修改驱动配置。

`info` 在发生过启动恢复时追加 `[MOTOR BUS STARTUP] recovered_fe=<次数> last_ms=<最近一次故障时刻> rx_restarted=1`，表示历史启动接收恢复记录，不是当前实时健康保证。原 `[MOTOR BUS] locked/reason` 仍表示隔离状态与首次隔离原因。当前 `owner=8` 且 `addr=0 func=0 active=0` 表示没有历史发送事务，8 是 owner 枚举的结束标记，不是 ID 8 转盘；转盘实际 owner 为 7。

### 当前机械臂方向（2026-09-27 实测修正）

2026-10-09 参数统一：`config <axis> <rpm> <acc> <limit_pulses>` 中的 `acc` 现在也用于该机械轴的任务位置指令，覆盖 GrabTask 的静态对准、取放、姿态、码垛及动态追踪 X，MaterialVision 的 X 也共用；Base 原来已读取轴配置。未修改轴上电初值：Base/X 为 20、Z 为 120。因此未另设参数时，原来任务中固定为 8 的 X/Z 现在分别使用 20/120。`rpm` 仍控制普通手动位置运动；任务速度由 `x_speed`、`x_transfer_speed`、`z_speed`、`z_pick_speed` 的阶段设置决定。`grab accel` 和 `grab track accel` 仍是独立控制剖面的 MCU 加速度（mm/s²），不能当作驱动器加速度档位。

`grab get/set` 的名称、默认值、范围和启动/回零载入时机由 `Code/template/App/grab_parameters.def` 定义，网页数值元数据由 `python Code/tools/sync_grab_parameters.py` 生成。`z_speed` 和 `z_pick_speed` 范围均为大于 0、至 333.333 mm/s，`grab track pick` 显式速度也使用此范围；运动前仍按当前 `z_ppm` 检查 1～3000 RPM。网页默认 Z 下限同步为 −150 mm、Base 偏转范围同步为 ±360°。默认值载入时机、未知场景高度留空及 RAM 保存规则保留。

- X：`pos x` 正值向外，负值向内；正值协议方向 CCW（1）。
- Z：当前安装实测 CCW 向下，已将正值协议方向改为 CW（0），使 `pos z` 正值向上、负值向下。需烧录新固件后生效；`info` 输出 `arm positive_dir base=1 z=0 x=1 (0=CW 1=CCW)` 可核对。
- `home z collision` 的方向独立采用驱动器 `O_Dir`；当前安装要向上回零，应将其设为 CW。STM32 方向宏不修改驱动器已存储的回零参数。
- Z 普通运动上电默认等效于 `config z 500 120 0`：速度上限 500 RPM、Emm 加速度档位 120、单次脉冲数无限制（不代表机械行程保护）。控制台临时 `config` 只在 RAM，STM32 复位后恢复此默认值。首次低速点动可用 `config z 10 20 0`；回零速度仍由驱动器 `O_Vel` 决定。

现有 `enable/disable/state` 命令不变。单轴错误增加总线隔离状态：

- `ERR motor tx bus_locked=0/1`：请求未能提交到电机发送层。
- `ERR motor communication axis=base bus_locked=0/1`：异步传输失败，没有有效电机返回码。
- `ERR ack_timeout axis=base state_unknown bus_locked=0/1`：未在期限内收到合法应答，不能据此判断电机没有执行命令。

`bus_locked=1` 表示共享 UART5 总线处于故障隔离，后续普通电机请求会被拒绝；不是网页按钮失效，也不是驱动实际复位的证明。参见[UART5 循环 DMA 修复记录](开发记录/2026-09-12UART5循环DMA与单次失能故障修复.md)。

2026-09-27 起，启动及 `info` 增加 `BUILD motorbus_diag=1 date=... time=...`。上述通信错误后以及 `info` 中输出首次锁定记录：

```text
[MOTOR BUS] locked=1 reason=uart_error fault_ms=12345 owner=2 addr=7 func=0x3A active=0 wait=0 uart_error=0x00000004
```

此行为格式示例，不是实车采样。`fault_ms` 为 MCU 启动后的故障时刻；`owner` 为 0=停车、1=底盘、2=机械臂、3=旧驱动接口、4=四轮反馈、5=尚无事务。`active/wait` 为故障记录时是否存在事务/等待应答；空闲 UART 错误时，`addr/func` 仅标记最后下发的事务，不能据此归责该电机。`drain_timeout` 则标记被取消且尚未收完应答的查询。

| reason | 含义 |
|---|---|
| `none` | 当前没有保留的隔离记录，其他故障字段不用于判断 |
| `uart_error` | UART5 HAL 错误回调；错误码在重新启动接收前保存 |
| `rx_overflow` | UART5 软件接收环形缓冲溢出 |
| `reply_timeout` | 已发送，等待驱动器应答超时 |
| `tx_timeout` | 未在期限内收到发送完成回调 |
| `cancelled_reply` | 取消了等待应答的普通事务，保留迟到应答隔离 |
| `drain_timeout` | 被取消的反馈查询未在期限内收完应答 |

`uart_error` 为位掩码：PE=0x01、NE=0x02、FE=0x04、ORE=0x08、DMA=0x10，可组合。首次记录不会被后续失败覆盖；正常查询不会清除记录或解锁。`info` 只读取 RAM，即使总线锁定也可以查看。详见[首次锁定诊断记录](开发记录/2026-09-27-UART5首次锁定诊断.md)。

## USART1 DMA、诊断与发送节奏（2026-09-22）

USART1 使用 DMA2 Stream2 / Channel4 循环接收，128 字节 DMA 缓冲，IDLE、半满、全满事件读取实时 DMA 写入位置并投递到 512 字节软件环形缓冲。命令在主循环解析。接收损坏/溢出后丢弃到下一换行；Ctrl+C 始终单独锁存，随后由主循环取消运动生产者并请求停车。UART 错误在主循环恢复 RX，不在错误中断中执行阻塞重启。

发送使用 DMA2 Stream7 / Channel4 普通模式，最多64字节一段，不再添加固定30ms等待；DMA完成后下一次主循环继续发送。已开始的完整遥测帧和文本行不被其他消息插入。边界处按以下顺序选择：停车回复 → 普通回复 → 二维码事件 → 地图遥测 → 雷达分页 → IMU/视觉调试。停车回复有独立 1 KB 队列；普通回复 8 KB；IMU/视觉各一个 320 字节最新值槽、每路发送开始间隔至少 500 ms。连续调试更新覆盖未发旧样本，不占普通回复队列；关闭对应输出取消未发样本。

优先级不能抢占正在发送的完整帧，也不能保证无线送达。旧32字节/30ms为历史试调参数，当前已改为64字节且取消固定等待；115200 / 8N1的UART理论字节率11520 B/s不是DL-20无线净吞吐。DMA只减少CPU中断开销，不提高空中链路带宽，取消等待后的无线完整性需实测。

手动诊断命令（不增加专用按钮）：

| 命令 | 含义 |
|---|---|
| `console status` | RX 字节数、软件溢出次数/峰值、UART ORE/FE/NE/DMA 错误；TX 完成字节数、普通回复排队量/峰值及各类丢弃；接收重启成功/失败次数 |
| `chassis snapshot` | 按需输出完整 v1 底盘状态 JSON，不自动开启遥测；未订阅时 session 可为 0 |

`rx_peak` 最大可用值 511，`reply_pending` 只计算尚未取出的普通回复，不包含正在发送的一段。`tx_bytes` 统计 MCU 发送完成，不代表电脑收到；失败段可能已发部分字节而未计入。`debug_dropped` 包括最新值覆盖/取消/拒绝/发送失败，`dropped` 仍是地图软件统计，均不能当作无线丢包率。所有计数掉电重置，uint32 自然回绕。

## 地图紧凑遥测 v2

订阅仍为 `chassis stream on <session>`，先发送 **v1 config**，之后定期发送 **v2 state**。最短状态生成周期仍为 2000 ms，发送积压时延后生成。网页同时兼容 v1 对象状态与 v2 紧凑状态；新固件须使用本次更新的本地控制台。

v2 保持 `@CHASSIS ` 前缀和 JSON；根字段 `v/kind/session/t_ms/trace_seq/dropped` 保持名称，以下字段改为定长数组。单位和数值精度不变，四轮顺序仍是 FL/RL/RR/FR；数组长度或类型错误会清除当前状态，不能补造有效值。

| 字段 | 数组顺序 |
|---|---|
| `task` | `[state, reason, id, control_dt_ms]` |
| `target` | `[vx_mm_s, vy_mm_s, omega_rad_s, rpm_FL, rpm_RL, rpm_RR, rpm_FR]` |
| `feedback` | `[[rpm×4], [raw_position×4], speed_valid_mask, position_valid_mask, [speed_ms×4], [position_ms×4], seq, span_ms]` |
| `yaw` | `[valid, rad]` |
| `pose` | `[[command_valid,x_mm,y_mm,yaw_rad], [feedback_valid,x_mm,y_mm,yaw_rad]]` |
| `localization` | `[generation, feedback_tick, origin_valid]` |
| `route` | `[state,reason,segment,action_id,[target_x,target_y,target_deg],[error_x,error_y,error_deg],feedback_valid,stop_confirmed]` |
| `distance`（仅位移模式） | `[active,state,reason,action_id,[target_x,target_y,target_deg],[error_x,error_y,error_deg],feedback_valid,stop_confirmed]` |
| `tx` | `[seq,stage,error,ack_profile,tx_complete,acknowledged,acknowledged_wheels]` |

valid mask 的 bit0..3 对应四轮，取值 0..15；其余有效性字段仍为 JSON boolean。网页先展开为具名字段，再复用原来的地图、四轮数据和准备跑图检查。没有删掉停车/新鲜度判断所需字段，也不把“估计到站”改成视觉精确到站。

config 的 `telemetry_period_ms` 当前为 2000；旧 config 没有该字段时按 200 ms 处理。首次配置等待 8 秒，配置后接收超时为周期三倍；重复/乱序 MCU 时间丢弃，配置或 trace_seq 变化断开轨迹。反馈估计仍要求四轮位置、采样时间及航向有效，网页依据 MCU 时间检查 600 ms 新鲜度。`stream off` 取消未发地图快照，已开始的帧发送完整后结束。

历史限速依据见[2026-09-12 记录](开发记录/2026-09-12无线地图遥测限速发送.md)，本轮实现及验证见[USART1 DMA 整理](开发记录/2026-09-22USART1-DMA与无线输出整理.md)。

## 本地服务与独立停车查询

当前网页共享模式从设备列表手动选择串口，不默认选择 COM 号；通信格式默认 115200 / 8N1，由本机服务独占，网页和 CMD 共享接收事件。服务只监听 `127.0.0.1:8765`。GET `/api/status` 获取启动会话 token；POST 须携带同源 Origin 及 `X-Console-Token`，脚本同样遵守这两个请求头。

| 接口 | 用途 |
| --- | --- |
| GET `/api/status` | 连接、停车、配置、准备锁定与最新事件编号 |
| GET `/api/events?after=N` | 读取编号之后的事件；gap 表示记录窗口已过期 |
| GET `/api/ports` | 只读枚举端口号及设备名称，不打开串口 |
| POST `/api/connect` | 显式 `port`、`baudrate`，网页传入用户选中的端口、默认115200 |
| POST `/api/send` | 单条 ASCII `command`；返回排队编号，不等于发送完成 |
| POST `/api/stop` | 清空待发命令、取消准备、锁定运动并优先停车 |
| POST `/api/resume` | 明确解除软件停止锁定，不启动任务 |
| POST `/api/disconnect` | 先请求停车、最多等待 6 秒，再释放串口 |
| POST `/api/config` | 保存人工确认的 profile、units_per_rev、directions_confirmed |
| POST `/api/preparation` | active、owner；限定准备所有者的配置命令，其他来源只允许取消/停止，查询回复也由准备所有者独占；150 秒超时释放 |

事件包括实际 TX、原始 RX 行、连接变化、停止和系统信息。浏览器使用 TX 事件确认已经写入串口；设备处理和物理执行仍以各自回复判断。原始字节和分块时间保存在 `.embeddedskills/logs/serial/`。

2026-09-14 修正：事件对象 `id` 始终为递增流游标；停止事件的 MCU 停车编号使用 `stop_id`，不可覆盖事件 `id`。GET status 返回的 `stop.id` 保持为 MCU 停车编号。

固件新增原始 `0x03`（Ctrl+C）处理，清除未完成输入、取消底盘路线及可继续驱动底盘的自动任务。`chassis stop [非零uint32客户端编号]` 与 `wheel stop` 共用同一停车入口。客户端重发同编号不会重建请求；新的运动会使旧停止确认失效。普通手动停车可省略编号。

`chassis stop-status` 和停车受理返回：

```text
OK chassis stop id=1 token=123 requested_ms=100 tx_complete=0 wheels_stopped=0 reason=pending_tx
```

`tx_complete` 是电机总线停车发送完成；`wheels_stopped` 是发送后至少三组新鲜四轮反馈覆盖 500 ms、各轮速度绝对值 ≤1 RPM、相邻位置变化 ≤2 mm 的独立停止确认。无需到达地图目标、设置地图单位或有效 IMU。停车请求临时获取全四轮速度/位置，按 Emm 固定 65536 单位/圈解释；原轮询关闭或单轮选择也能执行。完成/失败释放临时采集需求，保留用户及任务最近的轮询开关/选择。确认结果作为该 token 的历史结果保留，直到新运动或新请求使其失效；不是永久静止监视。常见 reason 为 pending_tx、monitoring、stopped、missing_feedback、timeout、new_motion、tx_failed。

停车通信节奏（2026-09-22）：立即发送一次 Ctrl+C 和带编号停车请求，不再附加无编号文本停车。未受理时每2秒重试同一编号，最多3次；受理后每2秒查询停车状态以兼容旧固件。2026-09-29 起固件在受理、发送完成、四轮确认或原因变化时主动上报同一格式（包含 token），匹配确认到达即关闭等待中的断开流程，不再等待下一次查询。总等待6秒，超时停止自动发送。连接未断开、未解除锁定且编号匹配的迟到回复仍可更新发送/停止结果，不重新启动查询，不自动解除锁定。

软件请求发出、MCU 受理、发送完成和反馈停止分开显示。旧固件的通用 OK 不能完成本次停车确认；无线失联不能保证停车。详见 [共用控制台与停车记录](开发记录/2026-09-12COM23共用控制台与软件停车.md)。

### 同步取消后的只读诊断（2026-09-14）

运动中停车可能保留 sync_cache_uncertain / locked=1；这表示运动禁止，不应解释为所有状态查询失败。取消底盘运动应答造成隔离时，已开启的四轮反馈可在停车发送结束后继续读取。真实UART故障/超时仍阻止轮询。chassis stop-status 的 wheels_stopped 与运动解锁独立，确认停止不会自动恢复运动。

普通通信锁定可用 `bus recover` 请求停止任务并进行免断电检查，`bus status` 查询结果。检查全部 ID1～8 的速度、故障及回零状态，通过后解锁共享总线，不自动归零或续跑。恢复期间普通命令被拒绝，停止仍可取消恢复。网页停止锁保持不变。

2026-10-06起，`bus recover`也处理停车打断非零同步批次后的缓存不确定锁定：保持旧排空及ID1～8三轮速度/状态/回零检查；随后给ID1～4各写入同步F6零速目标并核对Receive应答，再逐地址发送FF同步、核对应答，最后重新读取四轮速度/状态/回零反馈，全部通过才解锁。严禁广播触发ID5～8。成功回复增加`chassis_cache=cleared wheels_stopped=1`；过程原因依次为`zeroing_chassis`、`syncing_zero`、`verifying_zero`。驱动拒绝、超时、仍运动或人工取消均不解锁，可处理原因后重试同一指令，不自动续跑、不清有效参数或追踪参考，也不重充接近预算。新的运动请求使上一份缓存恢复证明失效。网页停止锁仍需人工解除。

`chassis reset-confirmed`仍保留，仅用于驱动器已经实际复位后的确认，不是强制解锁指令。若`bus recover`返回`chassis_ready=0`，查看`bus status`/`info`的具体原因，不把命令受理当作恢复成功。历史流程见 [电机总线恢复与手动操作检查](开发记录/2026-09-27-电机总线恢复与手动操作检查.md)。

## 2026-09-29：统一 B2 视觉协议（当前约定）

USB CDC 请求固定 4 字节：`FF B2 Color FF`。
回复固定 14 字节：`FF B2 Color Valid CX_H CX_L CY_H CY_L DX_H DX_L DY_H DY_L SUM FE`。
颜色为 1～6；红色为 1。SUM 为字节 1～11 累加的低 8 位；CX/CY 为大端无符号 16 位，DX/DY 为大端有符号 16 位。

长度、头尾、SUM、功能码及当前请求颜色匹配后才接纳报文。Valid 只能为 0 或 1；1 表示坐标有效，0 表示已收到合法回复但当前无有效坐标，不能继续使用之前的坐标。相同坐标的新报文仍正常接收。非法 Valid、错误颜色、错误校验和 B4 不推进任务。

Camera 的 `Sequence` 是有效坐标在 MCU 的接收序号，`Tick` 是 MCU 解析时刻；均按 uint32 回绕处理，不代表远端采集信息。`InvalidCount` 记录当前请求内合法 Valid=0 的累计数，防止粘包中的失效事件被后续有效坐标覆盖。请求成功提交才清空旧缓存、残帧、有效状态和无效计数；USB 忙或提交失败保留原请求。停止只清空本地请求及缓存，不发送额外香橙派停止协议。

B2 无远端请求编号、采集帧号、阶段或采集时间，因此不能严格区分同色请求的迟到回复，也不能证明多次接收来自不同采集帧或已进入圆心阶段。清缓存和本地时间不能提供这类保证。

`grab start align` 默认使用 B2 蓝色请求（3），`grab start pick` 和路线转交的 pick 默认使用红色请求（1）。直接命令 `grab start align|pick <color>` 可选择 1–6 号 B2 物料颜色；固定位置抓取不接受颜色参数。完成对准要求：像素容差内至少 `frames=3` 次新坐标观测，持续至少 `stable_ms=200` ms，并满足现有机构反馈停稳条件。一次任务更新只采纳最新坐标、最多累计一次观测；同一快照不重复累计。开始停车后重新累计；像素越界、Valid=0、任务停止或重新启动清除稳定证据。首次没有数据或只有合法 Valid=0 则保持停止等待；对准/停稳阶段的合法 Valid=0 按下节先进入短暂容忍或限时视觉暂停；接收过期、USB/请求失效和机械通信故障仍停止并报告故障，不自动恢复。

停止协同对准不会清除仍有效的参考参数；收到 `state=idle stop_confirmed=1` 后，若 `missing=none` 可直接再次启动。外部手动 HOME/ZERO、Base 转向放置处等造成参考失效时，`grab status` 的 `ref_cause` 标记最近原因，`missing` 列出仍缺的参数。空闲且电机总线可用时可手动发送 `grab rehome`，它复用上电的 Z 碰撞→X 碰撞→Base 就近回零及 0x3B、位置、状态双次稳定读回，轴验证成功后才恢复该轴的默认 RAM 参考；任一步失败或中止不恢复尚未验证的参考。`OK grab rehome accepted` 仅表示启动，最终须检查 `reason=home_complete`，再等 IMU 静止验证通过。执行前移走夹持物并确认运动范围安全。单轴 `home` 的受理回复不足以自动恢复参考；该命令会覆盖对应轴的自定义参考值，必要时重新设置。

`age_ms=1000` 表示有效坐标自 MCU 接收后的最大允许间隔，不再包含远端采集耗时。`camera status` 的独立调试显示过期阈值仍为 1200 ms；抓取状态和任务门槛按 grab 的 age_ms 判断。

## 短暂视觉漏检容忍与限时恢复（现行，2026-10-03）

仅 `align`、`pick` 及路线交接 pick 的抓取前 `align/settle` 阶段参与。固定取放、下降后的流程及完成后的 hold 不参与。B2 请求/回复和所有现有命令不变；不根据 B2 推断香橙派粗定位或圆检测阶段。

`align` 和 `pick` 的 `state=align` 阶段，合法 `Valid=0`（包括同批有效→无效→有效），或连续一个控制周期（100 ms）没有新的有效接收序号，先进入 `state=vision_grace reason=vision_gap_decelerating`。默认 `loss_grace_ms=250`，从最后一次被控制采纳的有效坐标接收时刻计时；中途无效包、重复快照或一两次有效观测都不延长窗口。此时不再按旧误差求新速度，只按当前 `accel` 将上次底盘/X平移速度逐步减小，保持原方向；不累计对准证据。实际命令仍受总线调度约束。250 ms 是超时请求停车的门槛，不是物理停稳保证。

容忍时间内连续得到 3 次新有效坐标观测（一次主循环最多一次）才能回到 align，报告 `reason=vision_gap_recovered`，不计入停车恢复次数；从下一次新坐标重新检查对准。任一无效报文清零观测数，同批最新有效坐标最多作为重置后的第一次。达到容忍时间（elapsed >= loss_grace_ms）即进入停车暂停。临近准心（DX、DY 均在各自容差的 2 倍以内）、恢复坐标明显越过准心（对应轴新旧误差均超出容差且反号）、`settle` 阶段、配置为 0 时，合法漏检直接请求停车。未收到过有效坐标时继续停止等待，不能沿用旧任务坐标。

需停车时进入 `state=vision_pause reason=vision_pause_stopping`。立即停止新增纠偏目标，清除稳定观测，复用底盘/X 停止发送及四轮、三轴停稳确认；保持夹爪、使能及原 B2 请求。停止期间坐标不计入恢复证据。

确认停稳后报告 `reason=vision_recover_wait`，从此刻开始 `vision_wait_ms` 窗口（默认12000 ms），记录当时接收序号。窗口内至少 3 次新有效坐标观测且当前反馈仍停稳，才回到 align，报告 `reason=vision_recovered`。相同坐标的新报文可以累计，一次主循环最多计一次，重复快照不计。任一合法无效报文清零计数，不延长窗口；同批最后一个有效报文最多作为重置后的第 1 次。边界 elapsed <= vision_wait_ms 可接受。

`align`、`pick` 和路线pick在确认停稳后重发一次当前目标颜色的B2请求，成功提交USB后报告 `reason=vision_reacquire_wait`。必须先重发成功，再累计该次请求提交后的新接收观测；重发前的快照不计入恢复。USB忙在原等待窗口内重试，不延长窗口；其他发送错误按 `camera_tx` 停止。每轮暂停只成功重发一次。此方式不改香橙派程序，不根据B2推断远端阶段；B2仍不能严格辨认同色迟到回复或远端采集时间。

成功恢复次数只作诊断，不设置累计退出额度；单次等待超窗为 `vision_recover_timeout`。恢复从实测 X 位置重新建目标，速度历史及控制计时重新开始；必须重新经过完整 3 次/200 ms 的对准和停车后稳定判据，不能直接下降。恢复计数在新任务初始化/启动时重置，与原有停稳偏移重试独立。

`vision_pause` 不用漏检前坐标年龄重复报过期；新恢复观测仍检查 `age_ms`。正常对准过期 `vision_stale`、USB 断开 `vision_usb_off`、请求失效 `vision_request_lost`、机械反馈/总线故障均硬故障停止，人工停止清除待恢复资格。停车未确认时不开恢复窗口、不恢复运动；保留反馈检查，不引入整任务总超时。

新增状态字段（MCU 报告值）：

| 字段 | 含义 |
|---|---|
| recovery_used | 本次已成功停车后恢复次数，仅诊断；短暂容忍内恢复不计入 |
| recovery_count | 当前窗口连续新有效观测数，0～3 |
| recovery_left_ms | 窗口剩余毫秒，0～vision_wait_ms（默认12000）；停稳前及窗口外为 na |
| loss_ms | 当前中断持续时间；恢复/停止后保留最近一次。起点为最后有效坐标，包含连续观测确认及可能的停车等待，不等于纯漏检时长 |
| loss_max_ms | 本任务最长中断毫秒数，包含当前未结束中断 |
| grace_count | 减速容忍期间连续新有效观测数，0～3 |

GrabTask.c使用参数`vision_wait_ms`作为停车恢复窗口，`GRAB_RECOVERY_OBSERVATIONS=3`保持不变；不再设置`GRAB_RECOVERY_LIMIT`。窗口可通过`grab get/set vision_wait_ms`读取与修改，范围1500～120000 ms、整数。短暂容忍可用 `grab get loss_grace_ms` 读取、`grab set loss_grace_ms 250` 设置；整数范围 0～300 ms，0 关闭短暂容忍，仅任务未运行时允许修改，存于 RAM。保留 `protocol=B2 age_source=rx rx_seq=...`、`stop_requested`、`stop_confirmed`；紧凑周期状态保留恢复、中断时长及 dx/dy 字段；容忍期间 dx/dy 为 na，原始新坐标可从独立 VISION RX 查看。手动 `grab status` 返回完整状态。

### 持续点云预览

`radar live start upper|lower`只配置启动雷达一次，随后连续接收完整圈，直至显式停止或现有运动/参考条件发生变化。短暂坏包、DMA丢字节或单位变化只重新同步当前不完整圈，保留上一圈预览；不使用单圈建图的10秒完成窗口。普通扫描、诊断扫描和实时预览互斥。实时模式使用独立的小缓存，不改变已完成的地图、路径、原始诊断及完整点云。

每圈按原始角度划分120个3°区间，保存各区间最近的有效回波，并保留该回波的实际角度和毫米距离；空区间距离为0。预览覆盖360°，使用当前距离与能量筛选，不套用建图角度扇区或5×5场地边界。显示抽样不能用于代替完整点云的障碍识别分析。

- `k="live_state"`：`v=1`、`s`（运行标记）、`id`（本次实时启动编号）、`active`、`state`、`reason`、`q`（最新完整圈序号）、`pose=[x_mm,y_mm,zero_deg]`、`age_ms`、`points`（有效分区数）。位姿在启动时冻结；查询或状态变化时回复。
- `k="live"`：`v=1`、`s`、`id`、`q`、`o`（起始分区索引）、`n=120`、`d`（Base64）。每片24点、每点4字节：低字节在前的`uint16 angle_tenths`及`uint16 distance_mm`，每圈5片。点投影仍为`x=px+d*cos(zero-a)`、`y=py+d*sin(zero-a)`，原始雷达角按顺时针递增。

发送时冻结一圈，当前圈发送结束后选择最新完整圈，中间采集到的旧圈直接跳过，不累积延迟队列。查询回复优先，预览使用现有低优先级发送槽；USART1当前64字节DMA分块，不加固定30ms等待。浏览器按`s/id/q`组装，分片预览标明进度，停止或断线标记历史；这些帧不触发地图、路径、点云的静态分页下载。打开页面、切换视图和重连均不自动开启扫描。

`raw` 的 `session/origin/scan/map` 是冻结采集身份，`plan=0`；失败或停止没有完成圈时scan/map为0。前五页分别包含：(0) state、complete、truncated、total、crc32；(1) pose、unit、start、auto、points；(2) filter、point_total；(3) window、circle、cloud_truncated；(4) received、losses、bad、restarts、cloud_valid。filter顺序为距离下限/上限、原始角度下限/上限（0.1°）、格点阈值、能量下限/上限。unit用于初始化截取圈的距离单位，未知时沿用现有毫米解释。

诊断缓存为16KB滚动窗口。window表示下载byte0相对诊断开始RX游标的偏移；circle为同一游标基准下最后有效圈的[start,end)字节范围，包含解析所需包头与末包边界。CRC32为IEEE reflected多项式0xEDB88320、初值/异或0xFFFFFFFF，8位十六进制字符串，覆盖下载窗口全部原始字节。字节页offset从下载窗口0开始，连续拼接hex；所有页面不超过256B。

`truncated=true`可仅表示旧前缀被裁剪；只有最后完整圈全部被窗口覆盖、无该圈接收缺段时complete才为true。下载齐全与采集完整不同：网页download_complete表示页面和CRC核对完成，设备complete表示完整圈字节证据。停止/失败可以下载、导出明确标注的部分诊断，不能附带旧图/旧点云。自动起点未确定的完整圈可导出raw及同圈cloud，map=0，不借用历史地图。

网页“诊断扫描一圈”主动启用捕获，成功后读取同圈图/路径、完整cloud及raw；普通扫描仍只自动读取图/路径。诊断导出使用采集时冻结的pose/filter，不用后来实时参数替换。诊断数据下载可能比障碍地图慢，页面显示逐页进度；无需下载它来执行普通地图规划。可用`python Code/tools/radar_capture_unpack.py <诊断JSON>`校验CRC并导出raw.bin、circle.bin及元数据，供原生解析器重放。

mask低25位与counts顺序均为自底部行向顶部、每行从左向右，bit=`row*5+col`，row/col从0开始。原固定四障碍mask为328000。地图pose=`[lidar_x_mm,lidar_y_mm,zero_deg]`是本次采集实际使用位姿；coverage=3600表示该已发布图来自完整一圈，新扫描进度用status查看，不混入旧图。

`radar status` 主动返回一条status和三条diag；已有完整圈时还返回两条start，分别按类型和页合并；网页也兼容旧版单页/两页diag。`tx_done`为USART2发送完成回调累计次数，`last_tx`为最近提交给HAL的6字节命令；二者不表示雷达已经接受指令。`tx_errors`为发送错误/超时次数，`uart_errors`为UART错误回调次数，`rx_ready`为DMA接收启动结果。`last_alarm` 为最近一次6字节报警包的16位码，按传感器低字节在前解析，JSON使用十进制、网页显示十六进制。用户提供的LDS50C说明书电源故障示例 `CE CE CE CE 00 01` 对应主机解析值256（0x0100），不是0x0001；固件保留原值，不交换字节或归一化报警码。其他代码保留原值，不推断含义。计数与最近报警码是累计诊断，恢复后看相邻查询的增量及测量包是否增长，不要求累计报警归零。只有报警包而无有效测量包时无法得到完整点云；`unit=unknown` 表示尚未获得ST单位状态。

`radar probe`与扫描配置共用非阻塞发送队列；扫描中或串口仍在发送STOP等命令时返回忙，查询期间新扫描返回query_in_progress。无需开启底盘遥测、准备跑图或解除网页停止锁定。查询仅发送ASCII `LUUIDH`，不附加CRLF，不设置单位/滤波、转速、波特率，不自动启动、回零或清除地图及RAM参数。USART2发送完成后最多等待2秒；HAL持续忙/发送完成超时各使用现有500ms命令窗口。状态为transmitting/waiting/confirmed/unconfirmed/error/cancelled，只有本次发送之后收到`PRODUCT SN:`及非空身份文本、且MCU发送完成时才为confirmed/sn_reply。支持分包和报警流中夹入身份回复；没有行结束符时以50ms文本间隔收束。身份最多保留24字符。单纯命令回显、测量包、报警以及查询前已在DMA/工作缓存中的旧回复不能证明往返成功。UART恢复或DMA覆盖丢弃未完成身份片段，继续当前查询窗口。

查询受理及发送完成时只主动报告第0页，结束时报告三页；`radar probe status`始终返回三页。第1页为本次实际发出查询后的接收窗口计数，结束后冻结；第2页hex是该窗口首先处理到的最多24字节原始RX，未经过雷达帧解码，sn单独提取。未确认原因包括alarm_only（窗口仅有完整报警）、reply_unknown（数据未构成完整身份回复）、no_reply；发送异常为tx_busy/tx_error/tx_timeout。`radar stop`取消正在进行的查询并保留证据；断线/MCU重启后网页旧结果标为历史，页面进入不自动查询。查询帧记录到网页/CMD终端及桥接JSONL，地图和点云仍走原分页通道。SN应答确认的是查询通信，是否恢复扫描仍以测量包增长及完整圈成功为准；无身份应答不能单独断言TX断线或外部供电不良。

每条数据帧含前缀和CRLF不超过256字节；后台单独槽空闲后即可发送请求页，命令回复与底盘遥测优先。网页等待本页回复后立即读取下一页，完整同版本页才替换快照；超时、取消、版本变化或断线保留此前完整结果。页数随身份字段长度及数据类型变化，具体耗时取决于无线分块发送及其他通信负载，不再按每页一秒计算。F407建图与执行不等待下载点云。重新扫描会暂时使唯一点云缓存不可读，旧完整地图与网页已保存点云仍可作为历史展示。

控制台入口：视觉任务 → 码垛。颜色与编号环统一静态对准入口：`grab align color <1..6> [z_mm] [stay]` / `grab align ring <1..3> [z_mm] [stay]`。旧色环和物料对准指令保留兼容。颜色准心(334,338)、编号环准心(378,333)分别保留；共用静态调速参数，动态追踪参数独立。

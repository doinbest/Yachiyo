# 当前 USART1 文本控制台协议

以当前 `template/App/arm_console.c`、底盘子模块及 `upper-computer-web/local-car/protocol.mjs` 为准，更新于 2026-09-29。适用 STM32 USART1 无线文本控制台；香橙派 USB CDC 使用 B2 二进制视觉协议，不能发送本页文本命令。

新增单件抓取命令：`grab start fixed|align|pick`、`grab start align|pick <color>`、`grab route <speed>`、`grab status`、`grab stop`、`grab rehome`、`grab set <key> <value>`、`grab get <key>`。取放流程与模拟扫码来源见[单件抓取实现与标定](开发记录/2026-09-27-单件抓取实现与标定.md)，视觉协议以本文 B2 约定为准。所有实测参数显式设置，缺项拒绝运动；动作完成后hold等待检查，不自动计数。运行期间参数读回和状态读取可用；外部运动与机械轴读取事务被互锁，停止始终可以请求。

旧 `sys.ping#` / `motor.*#` 协议已退役，仅保存在[历史协议](开发记录/历史Zigbee网页原型协议.md)。B3 命令继续返回 `ERR Unsupported B3`，已移除对应 C API。

## 帧、单位与结果

- USART1：PA9/PA10，当前 115200 / 8N1。端口由现场确认。
- 网页发送单行 ASCII，追加 CRLF；固件接受 CR 或 LF 行结束。命令内容最多 63 字节、6 个空白分隔字段，网页禁止内嵌换行。
- `OK` / `accepted` 表示命令的具体受理或查询结果，不统一代表到位；`ERR` 表示拒绝或错误。命令回显和异步日志可能交错。
- `pos` 是电机轴相对角度；网页限 ±360°，不能将网页限值当作固件所有轴的机械限位。
- `chassis run/heading` 使用车体前向 vx、左向 vy（mm/s）、逆时针 omega（rad/s）；旧 `chassis velocity` 的 yaw 单位为 °/s。
- `chassis move/origin` 使用地图 +X 向右、+Y 向上，地图角度与 HWT101 模块角度分开。
- 网页 `seconds` 转为整数 `hold_ms`；起步和停车各 500 ms。四轮顺序 FL/RL/RR/FR=1/2/3/4。

## 主控重启与 Z 轴归零

| 命令 | 用途 | 条件与结果 |
|---|---|---|
| `system reset` | STM32 软件复位，重新执行启动初始化 | 人工确认整车静止，软件任务及通信空闲；不是整车断电，也不代替停车 |
| `imu zero` | HWT101 当前 Z 轴角度设为零 | 保持静止；不标定零偏、不保存参数，不授予航向控制资格 |

`system reset` 先回复 `OK system reset pending target=stm32 peripherals_not_reset=1`，紧急回复完成 USART1 发送后再等待 200 ms，通过 CMSIS `NVIC_SystemReset()` 请求主控复位。200 ms 只是无线链路留时，不保证网页收到。发送失败或超过 5 秒取消重启；等待期间拒绝新业务命令，Ctrl+C、`chassis stop`、合法的 `stop all/base/z/x`、`vision stop`、`material stop`、`camera stop` 可取消重启并执行各自原有停止操作。忙时返回 `ERR system reset busy`。主循环卡死或无线链路中断时无法依靠此命令恢复。

忙检查反映软件任务与通信事务，不是整车静止检测。机械臂 `pos/home` 收到驱动 ACK 后仍可能在运动；发送重启前必须人工确认整车静止。

重启后 RAM 中的任务、验证、地图锚点及订阅重新初始化；电机驱动器、HWT101、香橙派等外部设备并未断电复位，夹爪 PWM 会经历启动初始化。网页收到 `STM32 mechanical arm console ready` 后清除旧状态；请重新验证 IMU、准备跑图和手动开启订阅。本地服务停止锁定期间两条命令均不允许发送，须先确认停车并解除锁定。

`imu zero` 异步执行解锁 `0x69=0xB588` → 等待 100 ms → `CALIYAW 0x76=0` → 等待 100 ms → 读取后续新样本。受理回复为 `OK imu zero started ...`；结束回复 `OK imu zero sample before_deg=... after_deg=... verified=0 control_ready=0`。这表示已收到写入后的样本，是否接近零由实际 `after_deg` 判断；不是漂移验证通过。`imu status` 中结果为 `ZERO_SAMPLE`。I2C 失败、无新样本和取消流程沿用现有标定错误报告。归零会撤销旧航向资格与地图锚点；跑图前重新 `imu verify` 并设置地图起点。`imu cal cancel` 也可取消归零流程。

## 补充接口与操作语义

- `chassis stream on <非零uint32会话编号>` / `chassis stream off`：手动遥测订阅。
- `chassis stop [非零uint32客户端编号]`、`chassis stop-status`：独立停车与查询，详细语义见下文。
- `screen status`：读取 USART3 屏幕通信统计，可通过手动终端发送；不属于网页快捷按钮。
- `imu verify 5` 是 `imu verify` 的兼容别名。`imu verify 120` 已移除，返回格式错误。
- `imu cal clear` 为兼容入口，取消当前标定/验证并清除本次验证资格；`imu cal forget` 返回 `ERR imu cal forget deprecated no_erase=1`，不擦除存储。它们不恢复旧软件补偿方案。
- `chassis run vx vy 0 hold_ms` 保持起步模块航向，须本次 IMU 验证通过且数据新鲜，不要求地图原点；非零 omega 执行给定转向。`chassis heading` 仍需锚点。
- `imu cal start` 为约 20 秒原生标定及 30 秒自动验证；独立 verify 为归零后的 5 秒静止验证。重新验证会撤销旧航向资格，需重新建立地图原点。
- `imu status` 的 `zero_requested/zero_sample_received/zero_before_deg/zero_after_deg` 区分归零请求与后续样本；HAL 成功不单独证明实物归零完成。
- `stop all` 的作用取决于当前任务，不能等同整车硬件急停。`material auto` 的 ALIGNED 仅表示对准完成。
- 本车已确认 Emm42 固件仅修改 ID，控制台准备流程使用默认 Receive 应答及 65536 反馈单位/电机轴圈；无需重复实测协议常量。四轮安装方向与实际地图起点仍需确认，不能以 3200 控制脉冲/圈替代反馈单位。`chassis reset-confirmed` 不操作硬件复位。

## 二维码查询与事件

查询不消费主循环任务码，跟随开关不启动扫码器。

| 命令 | 含义 |
|---|---|
| `qr status` | 读取接收统计，不消费任务码 |
| `qr read` | 读取最新有效缓存，可重复读取 |
| `qr stream on/off` | 开启/关闭新码事件上报，不控制扫码器 |

回复形式：

```text
OK qr status valid=0 seq=0 age_ms=NA received=0 accepted=0 rejected=0 uart_errors=0 stream=off event_dropped=0
OK qr read valid=0 seq=0 code=NA age_ms=NA
OK qr stream=on
EVT qr code seq=1 code=123+231+312+123 age_ms=0
```

有效原码为四组三位数字；`seq` 与 MCU 毫秒时间为 uint32，可回绕。`age_ms` 是 MCU 计算的最新有效码年龄，没有有效码时为 NA。`received` 按字节、`accepted/rejected` 按完整帧、`uart_errors` 按 UART 错误计数。重复有效码同样递增序号；没有新码不表示离线。新码事件最多 5 Hz，只保留最新待发事件，`event_dropped` 与地图丢弃统计独立。格式化与发送在主循环运行；主循环原单次消费接口保留。

详见 [八千代控制台与二维码接入](开发记录/2026-09-12八千代控制台与二维码接入.md)。


## 实车反馈距离与完整路线

新增`chassis move <map_dx_mm> <map_dy_mm>`（相对地图位移、长度>0且≤300 mm）、`chassis route start|auto|next|status|cancel`。原点仍需显式`chassis origin`设置。路线16段固定，start模式每段反馈确认停车后等待人工next，auto模式确认停车后等待0.1秒自动继续，不由网页动画驱动。`chassis stop`取消路线资格；`chassis task`为距离任务增加目标、误差、反馈有效性和停车确认查询行。

`@CHASSIS`版本仍为1，新增可选状态：

- `localization`：generation、feedback_tick、origin_valid。
- `route`：state（idle/running/stopping/waiting/done/error/cancelled）、reason、segment（0或1～16）、action_id、target（地图X/Y mm、航向deg）、error（地图dx/dy mm、航向误差deg）、feedback_valid、stop_confirmed。
- `distance`：仅距离任务输出；active、state（运动任务状态）、reason、action_id、target/error数组及feedback_valid、stop_confirmed。独立move清除旧路线显示；活动路线段显示优先。

`feedback_arrived`和stop_confirmed表示轮子反馈估计到站并满足停止条件，不表示视觉精确对准。等待人工继续期间仍占用任务；查询/停止允许，其他运动/标定/修改定位配置拒绝。详见[实车前四段反馈路线](开发记录/2026-09-12实车前四段反馈路线.md)。

## 机械臂通信错误

### 当前机械臂方向（2026-09-27 实测修正）

- X：`pos x` 正值向外，负值向内；正值协议方向 CCW（1）。
- Z：当前安装实测 CCW 向下，已将正值协议方向改为 CW（0），使 `pos z` 正值向上、负值向下。需烧录新固件后生效；`info` 输出 `arm positive_dir base=1 z=0 x=1 (0=CW 1=CCW)` 可核对。
- `home z collision` 的方向独立采用驱动器 `O_Dir`；当前安装要向上回零，应将其设为 CW。STM32 方向宏不修改驱动器已存储的回零参数。
- Z 普通运动上电默认等效于 `config z 500 120 0`：速度上限 500 RPM、Emm 加速度档位 120、单次脉冲数无限制（不代表机械行程保护）。控制台临时 `config` 只在 RAM，STM32 复位后恢复此默认值。首次低速点动可用 `config z 10 20 0`；回零速度仍由驱动器 `O_Vel` 决定。

现有 `enable/disable/state` 命令不变。单轴错误增加总线隔离状态：

- `ERR motor tx bus_locked=0/1`：请求未能提交到电机发送层。
- `ERR motor communication axis=base bus_locked=0/1`：异步传输失败，没有有效电机返回码。
- `ERR ack_timeout axis=base state_unknown bus_locked=0/1`：未在期限内收到合法应答，不能据此判断电机没有执行命令。

`bus_locked=1` 表示共享 UART5 总线处于故障隔离，后续普通电机请求会被拒绝；不是网页按钮失效，也不是驱动实际复位的证明。参见[UART5 循环 DMA 修复记录](开发记录/2026-09-12UART5循环DMA与单次失能故障修复.md)。

2026-09-27 起，启动及 `info` 增加 `BUILD motorbus_diag=1 date=... time=...`。上述通信错误后以及 `info` 中输出首次锁定记录：

```text
[MOTOR BUS] locked=1 reason=uart_error fault_ms=12345 owner=2 addr=7 func=0x3A active=0 wait=0 uart_error=0x00000004
```

此行为格式示例，不是实车采样。`fault_ms` 为 MCU 启动后的故障时刻；`owner` 为 0=停车、1=底盘、2=机械臂、3=旧驱动接口、4=四轮反馈、5=尚无事务。`active/wait` 为故障记录时是否存在事务/等待应答；空闲 UART 错误时，`addr/func` 仅标记最后下发的事务，不能据此归责该电机。`drain_timeout` 则标记被取消且尚未收完应答的查询。

| reason | 含义 |
|---|---|
| `none` | 当前没有保留的隔离记录，其他故障字段不用于判断 |
| `uart_error` | UART5 HAL 错误回调；错误码在重新启动接收前保存 |
| `rx_overflow` | UART5 软件接收环形缓冲溢出 |
| `reply_timeout` | 已发送，等待驱动器应答超时 |
| `tx_timeout` | 未在期限内收到发送完成回调 |
| `cancelled_reply` | 取消了等待应答的普通事务，保留迟到应答隔离 |
| `drain_timeout` | 被取消的反馈查询未在期限内收完应答 |

`uart_error` 为位掩码：PE=0x01、NE=0x02、FE=0x04、ORE=0x08、DMA=0x10，可组合。首次记录不会被后续失败覆盖；正常查询不会清除记录或解锁。`info` 只读取 RAM，即使总线锁定也可以查看。详见[首次锁定诊断记录](开发记录/2026-09-27-UART5首次锁定诊断.md)。

## USART1 DMA、诊断与发送节奏（2026-09-22）

USART1 使用 DMA2 Stream2 / Channel4 循环接收，128 字节 DMA 缓冲，IDLE、半满、全满事件读取实时 DMA 写入位置并投递到 512 字节软件环形缓冲。命令在主循环解析。接收损坏/溢出后丢弃到下一换行；Ctrl+C 始终单独锁存，随后由主循环取消运动生产者并请求停车。UART 错误在主循环恢复 RX，不在错误中断中执行阻塞重启。

发送使用 DMA2 Stream7 / Channel4 普通模式，最多 32 字节一段，发送完成后间隔 30 ms。已开始的完整遥测帧和文本行不被其他消息插入。边界处按以下顺序选择：停车回复 → 普通回复 → 二维码事件 → 地图遥测 → IMU/视觉调试。停车回复有独立 1 KB 队列；普通回复 8 KB；IMU/视觉各一个 320 字节最新值槽、每路发送开始间隔至少 500 ms。连续调试更新覆盖未发旧样本，不占普通回复队列；关闭对应输出取消未发样本。

优先级不能抢占正在发送的完整帧，也不能保证无线送达。32 字节 / 30 ms 仍是待实测参数，软件约 976 字节/秒的连续分段预算不是 DL-20 规格。DMA 只减少 CPU 中断开销，不提高空中链路带宽。

手动诊断命令（不增加专用按钮）：

| 命令 | 含义 |
|---|---|
| `console status` | RX 字节数、软件溢出次数/峰值、UART ORE/FE/NE/DMA 错误；TX 完成字节数、普通回复排队量/峰值及各类丢弃；接收重启成功/失败次数 |
| `chassis snapshot` | 按需输出完整 v1 底盘状态 JSON，不自动开启遥测；未订阅时 session 可为 0 |

`rx_peak` 最大可用值 511，`reply_pending` 只计算尚未取出的普通回复，不包含正在发送的一段。`tx_bytes` 统计 MCU 发送完成，不代表电脑收到；失败段可能已发部分字节而未计入。`debug_dropped` 包括最新值覆盖/取消/拒绝/发送失败，`dropped` 仍是地图软件统计，均不能当作无线丢包率。所有计数掉电重置，uint32 自然回绕。

## 地图紧凑遥测 v2

订阅仍为 `chassis stream on <session>`，先发送 **v1 config**，之后定期发送 **v2 state**。最短状态生成周期仍为 2000 ms，发送积压时延后生成。网页同时兼容 v1 对象状态与 v2 紧凑状态；新固件须使用本次更新的本地控制台。

v2 保持 `@CHASSIS ` 前缀和 JSON；根字段 `v/kind/session/t_ms/trace_seq/dropped` 保持名称，以下字段改为定长数组。单位和数值精度不变，四轮顺序仍是 FL/RL/RR/FR；数组长度或类型错误会清除当前状态，不能补造有效值。

| 字段 | 数组顺序 |
|---|---|
| `task` | `[state, reason, id, control_dt_ms]` |
| `target` | `[vx_mm_s, vy_mm_s, omega_rad_s, rpm_FL, rpm_RL, rpm_RR, rpm_FR]` |
| `feedback` | `[[rpm×4], [raw_position×4], speed_valid_mask, position_valid_mask, [speed_ms×4], [position_ms×4], seq, span_ms]` |
| `yaw` | `[valid, rad]` |
| `pose` | `[[command_valid,x_mm,y_mm,yaw_rad], [feedback_valid,x_mm,y_mm,yaw_rad]]` |
| `localization` | `[generation, feedback_tick, origin_valid]` |
| `route` | `[state,reason,segment,action_id,[target_x,target_y,target_deg],[error_x,error_y,error_deg],feedback_valid,stop_confirmed]` |
| `distance`（仅位移模式） | `[active,state,reason,action_id,[target_x,target_y,target_deg],[error_x,error_y,error_deg],feedback_valid,stop_confirmed]` |
| `tx` | `[seq,stage,error,ack_profile,tx_complete,acknowledged,acknowledged_wheels]` |

valid mask 的 bit0..3 对应四轮，取值 0..15；其余有效性字段仍为 JSON boolean。网页先展开为具名字段，再复用原来的地图、四轮数据和准备跑图检查。没有删掉停车/新鲜度判断所需字段，也不把“估计到站”改成视觉精确到站。

config 的 `telemetry_period_ms` 当前为 2000；旧 config 没有该字段时按 200 ms 处理。首次配置等待 8 秒，配置后接收超时为周期三倍；重复/乱序 MCU 时间丢弃，配置或 trace_seq 变化断开轨迹。反馈估计仍要求四轮位置、采样时间及航向有效，网页依据 MCU 时间检查 600 ms 新鲜度。`stream off` 取消未发地图快照，已开始的帧发送完整后结束。

## 本地服务与独立停车查询

当前网页共享模式从设备列表手动选择串口，不默认选择 COM 号；通信格式默认 115200 / 8N1，由本机服务独占，网页和 CMD 共享接收事件。服务只监听 `127.0.0.1:8765`。GET `/api/status` 获取启动会话 token；POST 须携带同源 Origin 及 `X-Console-Token`，脚本同样遵守这两个请求头。

| 接口 | 用途 |
| --- | --- |
| GET `/api/status` | 连接、停车、配置、准备锁定与最新事件编号 |
| GET `/api/events?after=N` | 读取编号之后的事件；gap 表示记录窗口已过期 |
| GET `/api/ports` | 只读枚举端口号及设备名称，不打开串口 |
| POST `/api/connect` | 显式 `port`、`baudrate`，网页传入用户选中的端口、默认115200 |
| POST `/api/send` | 单条 ASCII `command`；返回排队编号，不等于发送完成 |
| POST `/api/stop` | 清空待发命令、取消准备、锁定运动并优先停车 |
| POST `/api/resume` | 明确解除软件停止锁定，不启动任务 |
| POST `/api/disconnect` | 先请求停车、最多等待 6 秒，再释放串口 |
| POST `/api/config` | 保存人工确认的 profile、units_per_rev、directions_confirmed |
| POST `/api/preparation` | active、owner；限定准备所有者的配置命令，其他来源只允许取消/停止，查询回复也由准备所有者独占；150 秒超时释放 |

事件包括实际 TX、原始 RX 行、连接变化、停止和系统信息。浏览器使用 TX 事件确认已经写入串口；设备处理和物理执行仍以各自回复判断。原始字节和分块时间保存在 `.embeddedskills/logs/serial/`。

2026-09-14 修正：事件对象 `id` 始终为递增流游标；停止事件的 MCU 停车编号使用 `stop_id`，不可覆盖事件 `id`。GET status 返回的 `stop.id` 保持为 MCU 停车编号。

固件新增原始 `0x03`（Ctrl+C）处理，清除未完成输入、取消底盘路线及可继续驱动底盘的自动任务。`chassis stop [非零uint32客户端编号]` 与 `wheel stop` 共用同一停车入口。客户端重发同编号不会重建请求；新的运动会使旧停止确认失效。普通手动停车可省略编号。

`chassis stop-status` 和停车受理返回：

```text
OK chassis stop id=1 token=123 requested_ms=100 tx_complete=0 wheels_stopped=0 reason=pending_tx
```

`tx_complete` 是电机总线停车发送完成；`wheels_stopped` 是发送后至少三组新鲜四轮反馈覆盖 500 ms、各轮速度绝对值 ≤1 RPM、相邻位置变化 ≤2 mm 的独立停止确认。无需到达地图目标、设置地图单位或有效 IMU。停车请求临时获取全四轮速度/位置，按 Emm 固定 65536 单位/圈解释；原轮询关闭或单轮选择也能执行。完成/失败释放临时采集需求，保留用户及任务最近的轮询开关/选择。确认结果作为该 token 的历史结果保留，直到新运动或新请求使其失效；不是永久静止监视。常见 reason 为 pending_tx、monitoring、stopped、missing_feedback、timeout、new_motion、tx_failed。

停车通信节奏（2026-09-22）：立即发送一次 Ctrl+C 和带编号停车请求，不再附加无编号文本停车。未受理时每2秒重试同一编号，最多3次；受理后每2秒查询停车状态以兼容旧固件。2026-09-29 起固件在受理、发送完成、四轮确认或原因变化时主动上报同一格式（包含 token），匹配确认到达即关闭等待中的断开流程，不再等待下一次查询。总等待6秒，超时停止自动发送。连接未断开、未解除锁定且编号匹配的迟到回复仍可更新发送/停止结果，不重新启动查询，不自动解除锁定。

软件请求发出、MCU 受理、发送完成和反馈停止分开显示。旧固件的通用 OK 不能完成本次停车确认；无线失联不能保证停车。详见 [共用控制台与停车记录](开发记录/2026-09-12COM23共用控制台与软件停车.md)。

### 同步取消后的只读诊断（2026-09-14）

运动中停车可能保留 sync_cache_uncertain / locked=1；这表示运动禁止，不应解释为所有状态查询失败。取消底盘运动应答造成隔离时，已开启的四轮反馈可在停车发送结束后继续读取。真实UART故障/超时仍阻止轮询。chassis stop-status 的 wheels_stopped 与运动解锁独立，确认停止不会自动恢复运动。

2026-09-27 起，普通通信锁定可用 `bus recover` 请求停止任务并进行免断电检查，`bus status` 查询结果。检查全部 ID1～7 的速度、故障及回零状态，通过后解锁共享总线，不自动归零或续跑。恢复期间普通命令被拒绝，停止仍可取消恢复。网页停止锁保持不变。

存在未确认底盘同步缓存时，恢复可能返回 `arm_ready=1 chassis_ready=0 reason=chassis_cache_or_state_requires_reset`，底盘运动仍锁定。该情况仍要求实际驱动器复位后再使用 `chassis reset-confirmed`（主控未重启时），不自动发送。执行前先停止反馈轮询并等待在途事务完成；主控也重启时按正常准备流程重新建立资格。完整恢复流程、失败原因与手动操作检查见 [电机总线恢复与手动操作检查](开发记录/2026-09-27-电机总线恢复与手动操作检查.md)。

## 上电默认行为（2026-09-22）

Emm42 应答方式固定按已确认的 Receive 默认配置初始化（`chassis task` 中 `ack=2`），不修改驱动器寄存器。控制台与准备跑图均不再发送 profile 设置。

外设初始化完成后自动等待 HWT101 新鲜数据（最多 5 秒），只启动一次 Z 轴归零及完整 5 秒静止验证；请从上电起保持整车静止。通过后 `verified=1 control_ready=1`；失败保持禁止依赖航向的运动，不自动反复归零，可用 `imu verify` 或 `imu verify 5` 手动重试。取消等待不会再自动启动。

5 秒是归零后采样窗口，不包含初始化、等待传感器或无线传输耗时。漂移阈值 0.01°/s、残差 RMS 阈值 0.1°、最大样本间隔 300 ms 保持不变；短时通过不代表长期温漂或断电保存验证。`imu cal start` 仍是手动 20 秒原生标定加 30 秒验证。

2026-09-22：实车路线支持 `chassis route start [speed_mm_s]`（10～1000，默认50）。16段继承启动速度；忙时拒绝重新启动。单段超时按2倍理论行驶时间加10秒限制在60～400秒；仍保留实时数据失效停止条件。状态查询附加 `speed_mm_s`。

自动模式使用 `waiting / auto_dwell` 表示停稳后的1秒等待，手动next在自动模式下被拒绝。总线故障、反馈失效和取消操作中止自动继续。末段等待结束后为 `done / route_complete`。查询附加 `auto`、`total=16`、`dwell_ms=1000`；自动流程不执行扫码与抓放，离线编辑也不会上传目标点。

## 距离任务停车与纠偏（2026-09-22）

## 2026-09-29 控制台显示、负载和启动调度

- 中文摘要仅位于网页显示层，真实命令、所有解析、导出及串口记录仍为原文。未知回复和字段不删除。总线锁定、恢复不完整和任务错误不因 `OK` 前缀而显示为成功。`uart_error=0x02` 是 HAL 噪声标志；组合位同时解释，保留原数值。

## 2026-09-29：统一 B2 视觉协议（当前约定）

USB CDC 请求固定 4 字节：`FF B2 Color FF`。
回复固定 14 字节：`FF B2 Color Valid CX_H CX_L CY_H CY_L DX_H DX_L DY_H DY_L SUM FE`。
颜色为 1～6；红色为 1。SUM 为字节 1～11 累加的低 8 位；CX/CY 为大端无符号 16 位，DX/DY 为大端有符号 16 位。

长度、头尾、SUM、功能码及当前请求颜色匹配后才接纳报文。Valid 只能为 0 或 1；1 表示坐标有效，0 表示已收到合法回复但当前无有效坐标，不能继续使用之前的坐标。相同坐标的新报文仍正常接收。非法 Valid、错误颜色、错误校验和 B4 不推进任务。

Camera 的 `Sequence` 是有效坐标在 MCU 的接收序号，`Tick` 是 MCU 解析时刻；均按 uint32 回绕处理，不代表远端采集信息。`InvalidCount` 记录当前请求内合法 Valid=0 的累计数，防止粘包中的失效事件被后续有效坐标覆盖。请求成功提交才清空旧缓存、残帧、有效状态和无效计数；USB 忙或提交失败保留原请求。停止只清空本地请求及缓存，不发送额外香橙派停止协议。

B2 无远端请求编号、采集帧号、阶段或采集时间，因此不能严格区分同色请求的迟到回复，也不能证明多次接收来自不同采集帧或已进入圆心阶段。清缓存和本地时间不能提供这类保证。

`grab start align` 默认使用 B2 蓝色请求（3），`grab start pick` 和路线转交的 pick 默认使用红色请求（1）。直接命令 `grab start align|pick <color>` 可选择 1–6 号 B2 物料颜色；固定位置抓取不接受颜色参数。完成对准要求：像素容差内至少 `frames=3` 次新坐标观测，持续至少 `stable_ms=200` ms，并满足现有机构反馈停稳条件。一次任务更新只采纳最新坐标、最多累计一次观测；同一快照不重复累计。开始停车后重新累计；像素越界、Valid=0、任务停止或重新启动清除稳定证据。首次没有数据或只有合法 Valid=0 则保持停止等待；对准/停稳阶段的合法 Valid=0 按下节先进入短暂容忍或有限视觉暂停；接收过期、USB/请求失效和机械通信故障仍停止并报告故障，不自动恢复。

停止协同对准不会清除仍有效的参考参数；收到 `state=idle stop_confirmed=1` 后，若 `missing=none` 可直接再次启动。外部手动 HOME/ZERO、Base 转向放置处等造成参考失效时，`grab status` 的 `ref_cause` 标记最近原因，`missing` 列出仍缺的参数。空闲且电机总线可用时可手动发送 `grab rehome`，它复用上电的 Z 碰撞→X 碰撞→Base 就近回零及 0x3B、位置、状态双次稳定读回，轴验证成功后才恢复该轴的默认 RAM 参考；任一步失败或中止不恢复尚未验证的参考。`OK grab rehome accepted` 仅表示启动，最终须检查 `reason=home_complete`，再等 IMU 静止验证通过。执行前移走夹持物并确认运动范围安全。单轴 `home` 的受理回复不足以自动恢复参考；该命令会覆盖对应轴的自定义参考值，必要时重新设置。

`age_ms=1000` 表示有效坐标自 MCU 接收后的最大允许间隔，不再包含远端采集耗时。`camera status` 的独立调试显示过期阈值仍为 1200 ms；抓取状态和任务门槛按 grab 的 age_ms 判断。

状态示例（示意，非实车记录）：
```text
OK grab state=align ... protocol=B2 age_source=rx rx_seq=123 vision=Ok ... age=25 ...
VISION RX fn=B2 color=1 valid=1 fresh=1 cx=350 cy=321 dx=-9 dy=17 rx_seq=123 age_source=rx age=25
OK camera state=Wait protocol=B2 age_source=rx usb=1 active=1 fn=178 target=1 frame=0 current_valid=0 target_valid=0
```
`vision`：Idle 无活动请求、Off USB 未枚举、Wait 等待首个匹配回复、Lost 已收到但无有效坐标、Ok 有效坐标、Stale 接收过期。`rx_seq` 是 MCU 接收序号；`age_source=rx` 标明接收时间来源；已移除相机 phase 字段。`camera status` 中 `frame` 为是否收到过匹配报文（0/1），不是帧数；`last` 为本请求最后有效坐标，仅状态 Ok 时输出数值，其他状态为 na。`stats invalid_reports` 对应 InvalidCount；`seq`/`data_tick` 分别是 MCU 有效坐标接收序号/时刻。

控制参数及已确认取放位置保持不变：准心 (334,338)，Z 抓取 −80 mm、放置 −60 mm、提起 −40 mm；Base 相对转 −180°。没有新增整任务总超时、协议选择菜单或兼容确认开关。


## 短暂视觉漏检容忍与有限恢复（2026-09-30 更新）

仅 `align`、`pick` 及路线交接 pick 的抓取前 `align/settle` 阶段参与。固定取放、下降后的流程及完成后的 hold 不参与。B2 请求/回复和所有现有命令不变；不根据 B2 推断香橙派粗定位或圆检测阶段。

仅蓝色 `mode=align` 的 `state=align` 阶段，合法 `Valid=0`（包括同批有效→无效→有效），或连续一个控制周期（100 ms）没有新的有效接收序号，先进入 `state=vision_grace reason=vision_gap_decelerating`。默认 `loss_grace_ms=250`，从最后一次被控制采纳的有效坐标接收时刻计时；中途无效包、重复快照或一两次有效观测都不延长窗口。此时不再按旧误差求新速度，只按当前 `accel` 将上次底盘/X平移速度逐步减小，保持原方向；不累计对准证据。实际命令仍受总线调度约束。250 ms 是超时请求停车的门槛，不是物理停稳保证。

容忍时间内连续得到 3 次新有效坐标观测（一次主循环最多一次）才能回到 align，报告 `reason=vision_gap_recovered`，不消耗停车恢复次数；从下一次新坐标重新检查对准。任一无效报文清零观测数，同批最新有效坐标最多作为重置后的第一次。达到容忍时间（elapsed >= loss_grace_ms）即进入停车暂停。临近准心（DX、DY 均在各自容差的 2 倍以内）、恢复坐标明显越过准心（对应轴新旧误差均超出容差且反号）、`pick` 或 `settle` 阶段、配置为 0 时，合法漏检直接请求停车。未收到过有效坐标时继续停止等待，不能沿用旧任务坐标。

需停车时进入 `state=vision_pause reason=vision_pause_stopping`。立即停止新增纠偏目标，清除稳定观测，复用底盘/X 停止发送及四轮、三轴停稳确认；保持夹爪、使能及原 B2 请求。停止期间坐标不计入恢复证据。

确认停稳后报告 `reason=vision_recover_wait`，从此刻开始 1500 ms 窗口，记录当时接收序号。窗口内至少 3 次新有效坐标观测且当前反馈仍停稳，才回到 align，报告 `reason=vision_recovered`。相同坐标的新报文可以累计，一次主循环最多计一次，重复快照不计。任一合法无效报文清零计数，不延长窗口；同批最后一个有效报文最多作为重置后的第 1 次。边界 elapsed <= 1500 ms 可接受。

2026-09-30：仅 `mode=align` 在确认停稳后重发一次原有 `FF B2 03 FF`，成功提交USB后报告 `reason=vision_reacquire_wait`。此模式必须先重发成功，再累计该次请求提交后的新接收观测；重发前的快照不计入恢复。USB忙在原1500 ms窗口内重试，不延长窗口；其他发送错误按 `camera_tx` 停止。每轮暂停只成功重发一次，仍最多恢复2次。`pick` 和路线pick不重发，保持原请求接收。此兼容方式不改香橙派程序，不根据B2推断远端阶段；B2仍不能严格辨认同色迟到回复或远端采集时间。

每任务最多成功完成 2 次停车后的自动恢复；额度用尽后再次需要停车恢复时为 `vision_recover_limit`，超窗为 `vision_recover_timeout`。恢复从实测 X 位置重新建目标，速度历史及控制计时重新开始；必须重新经过完整 3 次/200 ms 的对准和停车后稳定判据，不能直接下降。额度与原有停稳偏移重试独立，只在新任务初始化/启动时重置。

`vision_pause` 不用漏检前坐标年龄重复报过期；新恢复观测仍检查 `age_ms`。正常对准过期 `vision_stale`、USB 断开 `vision_usb_off`、请求失效 `vision_request_lost`、机械反馈/总线故障均硬故障停止，人工停止清除待恢复资格。停车未确认时不开恢复窗口、不恢复运动；保留反馈检查，不引入整任务总超时。

新增状态字段（MCU 报告值）：

| 字段 | 含义 |
|---|---|
| recovery_used | 本次已成功停车后恢复次数，0～2；短暂容忍内恢复不计入 |
| recovery_count | 当前窗口连续新有效观测数，0～3 |
| recovery_left_ms | 窗口剩余毫秒，0～1500；停稳前及窗口外为 na |
| loss_ms | 当前中断持续时间；恢复/停止后保留最近一次。起点为最后有效坐标，包含连续观测确认及可能的停车等待，不等于纯漏检时长 |
| loss_max_ms | 本任务最长中断毫秒数，包含当前未结束中断 |
| grace_count | 减速容忍期间连续新有效观测数，0～3 |

常量位于 GrabTask.c：`GRAB_RECOVERY_WINDOW_MS=1500`、`GRAB_RECOVERY_OBSERVATIONS=3`、`GRAB_RECOVERY_LIMIT=2`，这些停车恢复常量不提供设置命令。短暂容忍可用 `grab get loss_grace_ms` 读取、`grab set loss_grace_ms 250` 设置；整数范围 0～300 ms，0 关闭短暂容忍，仅任务未运行时允许修改，存于 RAM。保留 `protocol=B2 age_source=rx rx_seq=...`、`stop_requested`、`stop_confirmed`；紧凑周期状态保留恢复、中断时长及 dx/dy 字段；容忍期间 dx/dy 为 na，原始新坐标可从独立 VISION RX 查看。手动 `grab status` 返回完整状态。

```text
OK grab state=vision_pause mode=align reason=vision_pause_stopping ... recovery_used=0 recovery_count=0 recovery_left_ms=na
OK grab state=vision_pause mode=align reason=vision_recover_wait ... stop_confirmed=1 recovery_used=0 recovery_count=2 recovery_left_ms=350
OK grab state=align mode=align reason=vision_recovered ... recovery_used=1 recovery_count=0 recovery_left_ms=na
```

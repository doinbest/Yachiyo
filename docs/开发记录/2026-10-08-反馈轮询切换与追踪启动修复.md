# 反馈轮询切换与追踪启动修复

日期：2026-10-08。用户授权修复追踪启动，并检查相似控制；Base 手动转动清空视觉参数的问题仍按 [P001](../待解决问题.md) 暂缓。

## 实车现象与原因

COM38 上执行 `grab track start 3` 后请求被受理，却持续显示 `track_match`，`records=0`、`seq=0`，速度为零；相机缓存出现 `(336,342)`，X 反馈年龄仍持续增加。停止追踪后立即刷新 X 反馈并确认停车。本次修复前复测日志位于本机 `.embeddedskills/tests/tracking-retry-after-static-20261008.json`。

`track_process` 在进入反馈采集前调用 `Mecanum_Feedback_Select(0)`。旧选择接口遇到 `MotorBus_OwnerBusy(MOTOR_BUS_FEEDBACK)` 立即返回失败；而轮询处理每次取走回答后又提交下一查询，所以主循环中的选择调用可能始终遇到排队、在途或待取走的应答。任务停在选择步骤，尚未执行 X 读取及追踪计算。

## 最终修改

共用 `Mecanum_Feedback_Select` 保留地址 0～4 的检查、关闭新增轮询及更新后续名单的语义，移除要求反馈队列完全空闲的条件。已有查询的 token 属于总线中的原请求；`FeedbackProcess` 按该 token 解析电机与数据类型，并在消费旧应答后才提交新名单中的查询。因此，修改后续名单无需取消查询或等待队列空闲，不增加固定等待或重试状态。

头文件补充接口完成语义，静止任务准备分支注释同步更新。Receive 应答模式、在途请求、总线仲裁、机械到位及反馈新鲜度检查保持既有行为。

## 相似控制核查

| 入口 | 结论与处理 |
| --- | --- |
| 动态追踪的 observe/start/restart | 共用选择接口修复，反馈采集不再被上述忙条件阻断。 |
| 静止对准及取放的 prepare | 原已有暂停轮询；同样获得选择接口修复，保留其准备及停车流程。 |
| 手动 `chassis feedback <wheel>` | 原来一条命令可能因持续轮询忙被拒绝；共用修复后接受有效选择，仍需显式 on 才继续查询。 |
| 普通停车 | `stop_begin` 已关闭新增查询；planned stop 阻止下一查询提交并消费当前应答，未发现同类等待循环，不改停车条件。 |
| 总线恢复 | 请求和恢复启动前均关闭轮询，未发现同类缺失，不改变恢复行为。 |

# HWT101 手动零漂标定与自动验证

> 历史方案：已由《2026-09-12HWT101原生零偏标定》替代。当前 `imu cal start` 为模块原生标定20秒、自动验证30秒，不再执行本文的外部漂移扣除。

## 当前硬件配置

已核对 CubeMX 配置和生成代码：I2C2 的 PB10/SCL、PB11/SDA 均为内部上拉（GPIO_PULLUP），AF4、开漏，时钟 100 kHz。本轮没有修改 `.ioc` 或 I2C 初始化代码。

内部上拉仅用于临时短线测试。通信无报错不等于电气波形已经合格；若出现错误或不稳定数据，应检查线路并补外部上拉。

## 测试步骤

1. 烧录本次 Keil `template` Target 生成的 HEX。Codex 本轮没有自动烧录。
2. 使用原有 USART1 控制台连接（当前固件为 115200、8N1），以文本模式发送命令，结尾使用 CR、LF 或 CRLF。
3. 启动应看到 `IMU stream=off`，默认不连续打印角度。将模块固定好，预热约 2 分钟，保持底盘和机械臂静止。发送 `imu status`，检查 `fresh=1`，多次查询的 `i2c_errors` 不持续增加。
4. 发送 `imu cal start`。返回 `cal_ms=60000 verify_ms=120000 keep_still=1 stream=off` 后，整个 180 秒保持整车静止。开始成功会自动关闭连续角度日志，每约 10 秒输出一次标定进度。程序不自动停止电机，也无法识别所有缓慢转动。
5. 前 60 秒是 `CALIBRATING`，约 60 秒后自动输出 `[IMU CAL] state=VERIFYING ... result=PENDING_KEEP_STILL`，继续静止，不用再次发送命令。
6. 再过 120 秒，自动输出 `state=DONE ... result=PASS` 或 `state=FAILED ... result=FAIL`，随后停止进度输出。失败也可能提前结束。错过结果可发送 `imu status` 查询当前状态和 `result`。无需人工计时、抄数或计算；可用串口助手保存日志留档。
7. 通过后可发送 `imu stream on`，每 200 ms 查看详细角度；缓慢转动模块，再回到标记的物理起点，观察 `corrected` 能否保留真实转动。发送 `imu stream off` 停止连续日志；采样与补偿仍继续。OLED 仍显示原始角度，不用 OLED 是否漂移判断补偿效果。
8. 发送 `imu cal clear` 可以取消或清除RAM补偿。最新版本在PASS后自动保存到W25Q128，等待 `FLASH state=saved` 后可断电；重启自动恢复并显示 `result=SAVED source=flash`。删除持久化记录使用 `imu cal forget`，详见《2026-09-11IMU标定Flash持久化》。异常处理后可重新发送 `imu cal start` 更新参数。

## 输出含义

| 字段 | 含义 |
|---|---|
| `yaw` | 模块原始角度，单位度，未被补偿覆盖 |
| `relative_raw` | 标定完成后的原始角度变化，跨 ±180° 已展开 |
| `corrected` | 扣除估计漂移后的相对角度，范围 [-180°,180°)，无效时为 NA |
| `bias_dps` | 60 秒标定估计的漂移速度，单位度/秒 |
| `raw_dps` | 后续 120 秒独立验证数据的原始漂移速度 |
| `residual_dps` | 验证窗口原始漂移速度减去固定补偿速度 |
| `cal_rms_deg` | 两个 30 秒窗口中较大的线性拟合残差 RMS |
| `verify_rms_deg` | 独立验证窗口拟合残差 RMS，供分析噪声 |
| `elapsed_ms` | 自标定起点开始的总时长；验证从约 60000 ms 开始 |
| `age_ms`、`fresh` | 最近原始读取的年龄和有效性；过期仍显示缓存原始值，但明确 fresh=0 |
| `i2c_err` | 自传感器驱动初始化以来的读取失败累计数 |

`VERIFYING` 中的补偿值仅供观察；`DONE/PASS` 表示独立静止验证通过。日志中的 `-0.000` 是接近零的负数舍入显示，不是额外故障。

## 失败原因

| reason | 含义与下一步 |
|---|---|
| `not_ready` | 开始时无新鲜角度或设备未就绪；先检查 imu status |
| `i2c` | 新增通信错误或设备失去就绪状态；检查上拉、接线、电源 |
| `stale` / `sample_gap` | 数据过期或两次使用的样本相隔超过 300 ms；检查通信和主循环延迟 |
| `motion` | 标定/验证时单次角度变化超过 5°；放稳后重试 |
| `unstable_bias` | 前后 30 秒斜率差超过 0.02°/s；延长预热并排除移动 |
| `noise` | 标定分段拟合残差 RMS 超过 0.1°；检查振动和数据质量 |
| `residual` | 验证残余漂移绝对值超过 0.01°/s；固定偏置补偿不足，保留日志分析 |
| `samples` | 拟合数据不足；检查时间与采样 |

任何失败均撤销补偿，不影响原始读取。通信恢复不会自动重新采用旧参数。重复开始正在进行的标定/验证返回 `ERR imu cal busy`。

## 实现和验证边界

- 新增 App 模块 `hwt101_drift.c/.h`，只消费 `HWT101_Process()` 生成的缓存，按不快于 100 ms 的间隔处理新读取。读取次数并不等同模块内部独立更新次数。
- 最小二乘只累计样本数与时间、角度的统计量，不存储整段样本，不使用动态分配。用实际时间计算斜率，并处理角度和 HAL tick 回绕。
- 标定时使用完整 60 秒拟合漂移速度，以两个 30 秒窗口检查稳定性。验证时冻结偏置，使用之后的 120 秒数据，目标为残余漂移绝对值不超过 0.01°/s（0.6°/分钟）。这些阈值是工程初值，不是厂商精度保证。
- 通过后继续固定偏置计算相对角度，不在线学习；无外部参考时无法辨别持续缓慢转动与零漂。
- 最初版本只在RAM保存参数；后续已增加W25Q128持久化与独立底盘hold测试。不修改模块内部校准寄存器，视觉搬运尚未接入补偿航向。
- 主机测试覆盖正负和零漂、时间间隔变化、角度和 tick 回绕、独立验证失配、真实转动保留、通信错误、取消重试，以及控制台命令和自动串口结果。具体运行结果见 `.embeddedskills/tests/host-tests.log`。
- Keil 构建结果见 `.embeddedskills/build/template-template-build.log`。实际残余漂移仍需上板验证。

## sample_gap 异常诊断

实物首轮在 20696 ms、186 个样本时出现 `sample_gap`，随后查询 `i2c_errors=0` 且数据新鲜。日志不足以确认阻塞来源，本轮增加诊断，不调整 300 ms 判定或零漂算法。

- `imu status` 新增 `gap_ms`、`max_gap_ms` 和 `limit_ms`。gap 是最新新数据与上一个被标定算法接受的样本之间的时间差，包含主动等待约 100 ms 的采样间隔；不是一次 I2C 交易的耗时。失败后保留，新标定或 clear 清除。若因 `stale` 或 `i2c` 提前退出，gap 仍是此前最后一次比较值。
- 失败时在结果前一次性输出 `[IMU DIAG]` 和 12 条 `[IMU TIME]`；正常运行不打印计时明细。
- `loop_prev_ms` 是上一整圈的耗时，`loop_max_ms` 是本次运行已完成圈的最大耗时，`loop_partial_ms` 是故障圈截至报告前的耗时。
- 每段 `prev_ms` 对应上一圈，`current_ms` 对应故障圈已完成的分段，`max_ms` 是该段本次运行的最大值。故障检测发生在 imu_cal 后，因此之后的 current_ms 为 0 表示尚未执行；0 也可能表示耗时不足 1 ms。
- 分段包含 camera、motor_events、arm_vision、material、chassis、imu_read、imu_cal、imu_log、console、screen、qr_keys、oled。screen 合并串口屏处理，qr_keys 合并二维码与按键处理，motor_events 包含电机事件分发。
- 使用 HAL 毫秒时钟，分段耗时包含期间的中断或调试暂停影响，不能仅凭某段较长就断言该函数自身有故障。各段最大值可能来自不同圈，不能相加解释某一次 gap。
- 从成功启动标定后的下一圈开始计时，失败报告前冻结现场；失败后日志输出耗时不计入。正常通过后继续计时，便于定位补偿期间后续故障。

复测：烧录新 HEX，放稳后发送 `imu cal start`。若失败，保存从 `[IMU DIAG]` 到 `result=FAIL` 的整段日志，再发送 `imu status`；若通过，保留 `result=PASS`。本轮没有自动烧录。

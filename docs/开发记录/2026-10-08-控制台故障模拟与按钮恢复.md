# 2026-10-08 控制台故障模拟与按钮恢复

用户要求模拟各种异常，避免控制台按键因残留状态失效。本轮仅修改本地控制台；未连接实车发送测试命令，未修改固件或烧录。

## 复现与修复

| 已复现问题 | 最终处理 |
|---|---|
| 编号环等嵌套页面构建时，updateControls把尚未挂载的表单从登记列表删除；连接后仍灰色，改输入才恢复 | 登记首次挂载标志，构建中保留，曾挂载后真正移除才清理；恢复全局按钮刷新 |
| HTTP send未返回请求ID或响应体一直无回复，串口TX超时尚未开始，sending长期占用 | API同时覆盖HTTP头/响应体默认12秒期限，终止请求并释放发送占用，结果未确认、不自动重发 |
| 断线重连保留旧routeLocked，路线启动按钮仍禁用 | 连接状态变化清旧路线标志，仍以新设备状态更新，不自动查询或恢复运动 |
| `arm> OK chassis route state=done`未匹配路线完成 | 仅对状态匹配去除前缀和外围空白，原始日志保留 |
| 停止锁定中首件路线/完整任务状态被当作运动拒绝 | 网页readOnlyCommand及Python READ_COMMAND同步加入精确的grab route/mission status；启动/继续及附加非法参数仍不放行 |

离线`radar/plan`复用C核心，服务允许编译30秒及运行15秒，因此单独保留50秒HTTP预算；不把普通串口请求12秒期限套在首次离线编译上。API正常完成、取消、超时均清定时器/父取消监听。

## 模拟覆盖

新增`tests/console-simulation.test.mjs`直接执行app.mjs的实际receive、connection、send、updateControls和controlForm，使用小DOM与内存传输。并非另写一套按钮判断算法。

- idle、prepare、acquire、align、短暂视觉丢失/暂停、hold、error任务状态。
- IMU无效、反馈过期、停车未确认、轮驱动失能/堵转、尚未对准、参数缺项、视觉超时。
- 全部命令表单经历错误、停止锁定、参数操作占用、准备等待、发送中及断线重连，检查恢复状态和输入保留。
- 普通发送失败、HTTP头/响应体卡住、父取消；停止路径可用，结束后sending释放且无自动重发。
- 路线运行/完成/取消/故障及带提示符回复、过期连接状态。
- 同一环号/可调高度下两个对准按钮，超范围禁用、纠正后恢复、交替忙状态恢复。
- 参数读回超时释放busy，下一次显式读回可成功。

原有回归继续覆盖串口实际写出确认、ACK先于HTTP、迟到连接/解除停止回复、服务重启、事件缺口、共享准备、参数取消及雷达页面。

## 载入

刷新网页载入前端修复；重启start.cmd对应本地服务后，Python新增只读查询分类才生效。重启服务会结束旧串口连接，重新人工选择串口连接。本轮未重启正在连接COM38的实车服务，无需烧录STM32或重启香橙派。

# F407 雷达建图上位机第二阶段

日期：2026-10-04

## 目标与边界

本阶段把已经验证过的 LDS50C 直连上位机行为迁移到主车 F407 链路：LDS50C 原始数据由 USART2 进入 F407，单片机冻结完整圈并完成筛选、5×5 建图和路线规划，再经 USART1 / DL-20 的 115200 无线链路把低带宽结果和按需点云送给网页。

修改范围只包含 `http://127.0.0.1:8765/#map/radar` 的雷达建图工作区、对应 F407 固件服务和协议。实车监控、离线对照、底盘执行、机械臂与参数页的既有行为不变；本阶段没有增加自动运动，也没有修改 IOC、引脚、时钟或 EIDE 配置。

第一阶段 USB-UART 直连服务和页面模块仍保留，用于历史追溯和独立诊断，但当前雷达页不再连接它，也不再请求 `/api/radar-direct/`。

## 数据流与职责

```text
LDS50C
  │ 921600 / 8N1，原始测量帧
  ▼
F407 USART2（PA2/PA3，DMA循环接收）
  │ 完整圈冻结 → 筛选 → 5×5障碍图 → 四邻域规划
  ▼
F407 USART1（PA9/PA10）
  │ 115200 / 8N1，既有32字节 + 30 ms无线发送节奏
  ▼
DL-20 / 电脑串口
  │ `radar host ...` / `@RADAR profile:"f1_host"`
  ▼
本地网页 `#map/radar`
```

F407 是配置、地图和路径的权威来源。网页负责显式操作、分页组装、身份与 CRC 校验、显示和浏览器本地草稿，不在 JavaScript 中复制一套正式判障或规划算法。

## 与 F1 上位机对齐的行为

- 场地为 2400 × 2400 mm，内部 X/Y 分界线均为 `550、1000、1400、1850 mm`。
- 雷达默认坐标为 `(230,230)`，筛选范围为 `0..360°`、`100..40000 mm`、能量 `0..255`。
- 障碍阈值默认为 1。
- 固定障碍掩码为 `0x00050140`。
- 保护掩码为 `0x00404405`，包含 R1C1 起点和其余任务格；扫描与手工障碍都不能覆盖这些格。
- 默认编号任务为 `1-5-4-2-3-4-2-3-1`，使用与固件共享的确定性四邻域规划。
- 默认点到点起点为 `R1C1/radar`，终点为 `R1C5/goal`。
- 修改筛选、分区、雷达位置、手工障碍或规划参数后，F407 可使用已经冻结的同一完整圈重新建图和规划，不启动新扫描。

## 采集与无线传输策略

单次扫描只发布完整、未截断的一圈。坏帧、单位变化或 DMA 覆盖只使当前不完整圈重新收集；旧的完整地图、路径和网页快照继续保留，不用半圈替换。

扫描成功后优先发送活动配置、地图和路径，使 115200 无线链路先恢复可操作画面；完整点云随后按需在后台下载。完整点云每点5字节，包含角度、距离和能量，最多4096点；持续预览每点4字节，使用120个角度分区，仅用于显示。两类二进制分页均使用 Base64 和完整流 IEEE CRC-32，不能把120点预览用于正式判障。

协议沿用 USART1 每发送32字节等待30 ms的节奏，没有为了雷达传输提高 DL-20 波特率。地图和路径不等待完整点云，因此点云下载较慢时仍可先看到判障与路线。

## 配置与页面操作语义

设备修改采用“重置草稿 → 逐项设置 → 按修订号原子应用 → 读回活动配置”。设备活动配置和草稿都只存在 F407 RAM，复位或断电后恢复固件默认值；没有借用 W25Q128，也没有新增 Flash 保存协议。

“保存本机配置”只在用户明确点击时写浏览器本地存储。输入框草稿、浏览器保存值、F407 活动配置和历史地图是四种不同状态，页面以设备读回及带身份的完整快照为准。

以下操作不会发送雷达命令：打开页面、切换页签、切换主题、刷新串口列表、页面刷新、重连、编辑输入、保存本机配置。只有“启动旋转”“停止”“单次扫描”“持续扫描”和“应用筛选”对应显式设备操作。当前 `radar host` 协议没有导航执行命令，地图和路线显示不会自动驱动车辆。

## 主要实现

固件新增：

- `Code/template/App/radar_host_map.c/.h`：F1 默认配置、保护格、判障和路线规划。
- `Code/template/App/radar_host.c/.h`：活动/草稿配置、完整圈快照、同圈重建及预览状态。
- `Code/template/App/radar_host_console.c/.h`：命令、状态、分页、Base64 和 CRC-32。
- `Code/template/App/radar_scan.c/.h`：与原实车雷达工作流隔离的主机单圈/持续采集接口。
- `Code/template/App/radar_map.c/.h`：复用完整云的公开建图能力。

网页新增或调整：

- `radar-host-model.mjs`：严格解析 `profile:"f1_host"`，按身份组装分页并保留历史快照。
- `radar-host-client.mjs`：显式命令、配置事务、地图/路径优先和后台点云下载。
- `radar-direct-view.mjs`：保留已对齐的 F1 页面外观，数据源改为共享 F407 连接。
- `app.mjs`：先路由 `f1_host` 帧，未接收的行才进入原雷达/终端路径；实车监控和离线对照保持原入口。

Keil 工程已加入新固件文件；EIDE 按本轮约定不维护、不构建。

## 首次上板验证顺序

本轮软件验证不等于实物验收。首次上板建议按以下最短闭环进行：

1. 核对实物线序和电平：雷达 TX → F407 PA3，F407 PA2 → 雷达 RX，信号地共地；F407 PA9/PA10 接 DL-20。雷达电源按手头型号资料单独保证容量和稳定性，不从 CH340 的不稳定5V继续供电。
2. 将两端 DL-20 保持在已确认的 115200 / 8N1；LDS50C 与 USART2 保持 921600 / 8N1。不要因为点云下载耗时改无线波特率。
3. 完成 Keil 构建后再按实际调试器显式烧录。本阶段不自动烧录、复位或发送串口命令。
4. 启动 `Code/upper-computer-web/local-car/start.cmd`，在左侧人工选择 F407 对应 COM 口，以115200连接。
5. 进入雷达页，先确认没有自动旋转、扫描或运动；读取到活动配置后核对 `(230,230)`、阈值1、任务和保护格。
6. 显式点击“启动旋转”，观察雷达实际状态；再执行一次“单次扫描”，确认状态从采集中进入完整，地图与路径先出现，点云随后完整显示且 CSV 可用。
7. 用已知位置障碍验证角度、距离和5×5格；确认 R1C1及任务保护格不变障碍，普通格能按点数或手工设置变化。
8. 修改一个筛选条件并点“应用筛选（不重新扫描）”，确认 `scan` 不变、`config/map/plan` 更新且雷达没有重新启动。
9. 启动和停止持续扫描，确认只用完整预览刷新，停止后保留最后完整快照；随后切到实车监控和离线对照，确认原布局、遥测和控制仍可用。
10. 记录 USART2 有效帧、坏帧/重采、完整圈点数、USART1 下载耗时和实际供电电压纹波，再决定是否需要进一步优化；不能只凭发送完成或网页有回复断言雷达链路全部正常。

## 尚未由本轮软件验证确认的事项

- LDS50C、F407 和 DL-20 的实物接线、电源稳定性与长时间运行。
- 921600 USART2 在实际雷达输出下的完整圈成功率与 DMA 覆盖情况。
- 115200 DL-20 环境中的实际吞吐、丢包和完整点云下载时间。
- 障碍坐标、格位、方向和路线在真实2400 mm场地上的测量验收。
- 任何车辆运动、导航或赛事任务完成率；本阶段协议没有自动执行路线。

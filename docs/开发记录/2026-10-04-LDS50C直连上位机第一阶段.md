# LDS50C USB-UART 直连上位机第一阶段

日期：2026-10-04

## 目标与范围

把用户提供的 Windows `Lds50cHost` 上位机中与 LDS50C 直连、整圈点云、地图和路径规划有关的功能移植到现有本地网页控制台，并尽量保持参考界面的信息结构和操作习惯。第一阶段让雷达通过 3.3 V USB-UART 直接连接电脑；后续改接 F407 时再单独设计数据源切换。

本轮明确不纳入参考软件的 STM32 配置、路径下载、配置读回和 Flash 保存模式；不修改 F407 固件、Keil、EIDE、IOC、主车 USART1 协议和实车控制逻辑。网页“实车监控”“离线对照”及其他功能保持原实现，“雷达建图”页改为独立直连工作区。

## 已完成能力

### 独立串口与扫描生命周期

- 新增独立雷达串口所有者，与主车 `SerialBridge` 分开；两者可选择不同 COM 口并各自维护连接状态。
- 雷达端支持 384000、500000、768000、921600，默认 500000 / 8N1、无流控；页面不默认或自动选择 COM 号。
- 显式连接、断开、`LSTARH` 启动和 `LSTOPH` 停止。
- 单圈及持续扫描按 `LMDMMH → LOCONH → LFFF1H → LSSS1H → LSTARH` 预置并启动；单圈收齐后自动请求停止，持续模式每收齐一圈才整体发布。
- 支持普通 `CE FA`、固定角分辨率 `CF FA`、状态帧和报警帧；错误字节可重新同步，距离单位中途改变会丢弃当前不完整圈，避免一圈内混用毫米和厘米。
- 断开和停止保留最后完整圈。只读轮询按版本读取，不重复下载未变化点云；旧响应不能覆盖较新版本。

对应实现：`radar_direct_protocol.py`、`radar_direct_bridge.py`、`serve.py`、`radar-direct-client.mjs`。

### 参考功能与界面

- “接收原始”与“上位机筛选”显示；角度范围可跨0°，距离和能量范围可调，同一冻结圈可反复重算而不重新扫描。
- 2400×2400 mm 第一象限场地和 `-2400～2400 mm` 四象限回波；鼠标位置缩放、左键拖动、坐标/顺时针角度读数。
- 5×5 网格的8条内部边界支持输入和拖动，最小格宽校验与参考实现一致。
- 固定障碍、手工障碍、扫描障碍、任务点保护格分层显示；普通格短按切换手工障碍。
- 编号任务路线与普通点到点两种四邻域 A*；支持重复格、回退、分段不可达原因、路径距离/方向/转向表。
- 默认任务顺序 `1-5-4-2-3-4-2-3-1`；任务点1跟随雷达坐标，任务点2～5跟随对应分区中心。
- 黑/白地图主题、串口和状态诊断、原始点预览、日志、完整原始圈 CSV、本机配置显式保存。
- 当前雷达页不显示旧 F407 雷达操作面板；切回“实车监控”或“离线对照”恢复原工作区。页面导航本身不发送设备命令。

对应实现：`radar-direct-model.mjs`、`radar-direct-planner.mjs`、`radar-direct-map.mjs`、`radar-direct-view.mjs`、`app.mjs`、`index.html`、`styles.css`。

## 操作与数据语义

角度采用雷达正前方0°、顺时针增加：

```text
X = 雷达X + 距离 × sin(角度)
Y = 雷达Y + 距离 × cos(角度)
```

“接收原始”指雷达固件处理后由 UART 发回的完整圈数据，不是未经雷达内部滤波的光学原始采样。障碍判定和路线规划始终使用网页筛选后的点，切换显示模式不会改变地图和路径。CSV 导出冻结圈的 `index`、`angle_deg`、`distance_mm`、`energy`，不会导出尚未完成的半圈。

网页刷新、页签切换和状态轮询只读，不自动连接、启动或扫描。持续扫描需要显式停止；页面离开不会擅自停止硬件。断开雷达或关闭本地服务会结束当前会话并尝试发出 `LSTOPH`，但软件命令不是硬件急停。

## 与现有工程的隔离

- F407 主车仍使用原左侧共享连接和115200 / 8N1；直连雷达使用雷达页内的独立连接。
- 雷达 HTTP 路由复用现有本地令牌，但状态、事件、串口句柄、扫描版本和点云均独立。
- 原 `radar-model.mjs` / `radar-view.mjs` 与 F407 固件命令仍保留，供原实车监控、离线对照和历史代码使用；当前雷达页不调用它们。
- 新页面的筛选、地图、障碍和规划在浏览器本地计算，不发送车体运动指令，不上传路线给 F407。
- 未修改 `Code/template/`、Keil/EIDE 清单、`template.ioc` 或 `docs/上位机协议.md`。

## 第一阶段实物验收清单

1. 核对雷达版本、线序、3.3 V UART、电源极性和共地；测量雷达侧电源满足 DC 5.1 ± 0.2 V，启动压降和纹波符合手册要求。
2. 确认 USB-UART 的实际 COM 口和雷达当前波特率；主车与雷达不得占用同一端口。
3. 连接后分别验证显式启动、停止；核对诊断中的毫米、能量、去拖点和设备滤波四项状态。
4. 单圈模式在8秒窗口内取得完整圈并停止；扫描过程没有把半圈发布为完整结果。
5. 将雷达0°朝已知方向，在已知距离放置目标，核对顺时针角度、毫米距离、X/Y方向和四象限显示。
6. 对同一冻结圈改变筛选条件，确认点云、障碍和路径重算但雷达不重新启动。
7. 拖动网格边界、切换手工障碍、运行默认编号任务和点到点规划，核对路径、距离和不可达原因。
8. 持续模式连续更新多个完整圈；显式停止和断开后最后一圈仍可查看、筛选、规划和导出。
9. 导出 CSV，与页面原始点数量、角度、距离和能量抽样比对。
10. 完成真实雷达验证后再决定第二阶段 F407 数据源、串口所有权和页面切换协议；本阶段不据此宣称车载链路已经完成。

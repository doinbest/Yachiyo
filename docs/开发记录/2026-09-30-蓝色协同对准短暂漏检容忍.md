# 蓝色协同对准短暂漏检容忍

## 需求与依据

用户同意修改STM32，允许短时间视觉漏检时继续沿原运动趋势减速，并放宽停车后的恢复等待。保持香橙派实际程序和B2协议，不使用SSH；不将本地orange_pi/change.py视为实机入口。

上一轮实测日志 `.embeddedskills/logs/blue-align-once-20260930-023152.jsonl` 中，有效接收序号1→34对应MCU有效坐标接收时刻差984 ms，34→68对应1012 ms，约29.8 ms一次（33.5～33.6 Hz）。这是连续有效区段的接收频率估计，不是香橙派实测处理FPS；B2没有采集时间戳，不能证明每个报文对应独立图像。250 ms约覆盖8个这样的发送周期，并包含连续3次恢复观测的时间，不能保证整整250 ms无坐标后仍不停车。

## 当前行为

| 情况 | 修改前 | 修改后 |
|---|---|---|
| 蓝色align移动中短暂漏检 | 立即请求停车 | 默认最多250 ms内沿原速度方向减速；不按旧误差加速 |
| 连续3次新有效观测恢复 | 停稳后才能重新运动 | 容忍时间内可恢复控制，不消耗停车恢复额度 |
| 连续漏检或断续有效 | 进入停车恢复 | 起点固定为最后采纳的有效坐标接收时刻，不重置截止时间 |
| 接近准心、恢复误差明显反号 | 请求停车 | 提前请求停车，不等待容忍耗尽 |
| 确认停稳后的恢复等待 | 500 ms | 1500 ms，包含蓝色B2重发忙等待 |
| 状态日志 | 恢复次数及窗口剩余 | 增加当前/最近中断、最长中断、减速期间有效观测次数 |

只在mode=align且state=align时允许短暂减速容忍。pick、路线pick、settle阶段仍在合法漏检时请求停车；固定取放不参与。丢失首个目标之前保持停止等待。两轴误差同时在各自容差2倍内视为临近准心；新旧误差在对应轴均超过容差且反号时提前停车。USB、请求、机械反馈、总线及行程故障保留原停车处理，人工停止取消恢复资格。

控制周期仍为100 ms，减速命令受电机总线可用时机约束；250 ms是发起停车的截止门槛，不能视为已物理停稳。保持底盘速度上限20 mm/s、lambda=0.6、accel=20 mm/s²及X/Z速度上限5 mm/s。短暂停顿恢复保留减速后的速度历史，下一次新坐标再参与正常控制；重新累计完整对准和停稳判据。停车恢复仍从反馈X位置重建目标并清零速度历史，每任务最多成功恢复2次。

无新接收序号达到100 ms时也进入容忍；同一快照不计入恢复观测。一次主循环最多采纳一个最新有效坐标，序号跳过多包不自动算多次。合法无效报文清空连续观测数；偶尔一两次有效不会延长当前中断。

## 接口

- `grab get loss_grace_ms`：读回，默认250。
- `grab set loss_grace_ms 250`：整数0～300 ms，仅任务未运行时修改，RAM保存；0关闭短暂容忍。
- `state=vision_grace reason=vision_gap_decelerating`：减速等待，尚未请求停车。
- `reason=vision_gap_recovered`：短暂恢复，不占停车恢复额度。
- `loss_ms`：从最后有效坐标起，至恢复或任务停止请求的时间；恢复后保留最近一次。包含连续观测确认和可能的停车等待，不等于纯漏检时长。
- `loss_max_ms`：本任务最长中断，包含正在发生的中断；新任务清零。
- `grace_count`：容忍期间恢复观测0～3；`recovery_left_ms`范围更新为0～1500。

网页新增参数、中文状态和时长显示。容忍期间任务dx/dy输出na，独立VISION RX仍可观察新收到的有效坐标；不会把上次误差显示成新鲜控制数据。周期精简状态保持完整字段和CRLF，仍限制在320字节调试槽内。普通完整状态缓冲增加为640字节。

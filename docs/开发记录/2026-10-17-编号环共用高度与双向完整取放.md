# 编号环共用高度与双向完整取放

用户要求编号环区域外部放置高度统一，只留一个输入；增加车仓下降/上升高度。随后明确两个独立流程：正向矫正、对环、取仓放置后必须抬好Z；反向从当前物料处下降夹取、抬升、转车仓放料、再伸X并回位。用户已确认反向放回指定车仓、放料后X伸出30 mm再让机械臂回作业方向。沿用只改源码、不测试、不编译、不烧录。

## 两个完整指令

- grab ring run <ring> <slot> <place_drop> [car_drop]：例如grab ring run 2 1 110 25。显式car_drop锁定到父任务，CarPickStartEx复用原车仓取起流程；外部释放Z保存到本件快照。原AlignedPlace返回RingReturnZ=z_max（默认0）并以arrived反馈确认后才released，父任务随后才DONE，不在松爪或Z刚发出上升指令时提前结束。旧省略car_drop的短命令保留原默认行为。
- grab ring store <slot> <pick_drop> <car_drop>：例如grab ring store 1 110 25。在当前已正确对准的位置及已验证作业姿态启动，独立完成下降夹取→抬Z收X→车仓分度/Base回仓→下降放料→抬Z→X伸至收回参考+30 mm→Base回原锚点+117.5°作业方向→确认高位及X30后stored。无需先运行第一条，但必须已经在正确水平位置；不重新视觉对准、不扫码、不跑路。最终Z=z_max默认0，X保持伸出30 mm。

两者大于0至150 mm的距离受实际Z/X边界约束；所有显式距离只作用本次，不改z_proc_place/car_pick_drop_mm等RAM比赛参数。反向不另设抬升距离，车仓目标为z_max-car_drop并返回z_max。原grab ring take <slot>继续兼容；扩展grab ring take <slot> <place_drop> <car_drop>复用当前已对准的环及同一高度输入。

## 页面与实现

编号环区域顶部只有“外部放料/夹取下降距离”（源码初值110）和“车仓下降/等量上升距离”（源码初值25）两项共享输入。正向完整、反向完整及分步自动取仓都取这两项；手动下降放置通过同一外部输入换算负Z，不再另有高度框。选择环/仓和改高度不发送命令，表单按按钮时构造一条完整指令；运行中的任务/快照已锁定值，暂停/继续不读取网页后改草稿。

反向复用GrabTask固定OP_STORE/SCENE_PROC状态机，仅独立RingStoreActive的目标使用本次PickZ/CarZ/LiftZ/ReturnX；放料后GRAB_RETRACT先到高位，再在原X阶段到30，最后RETURN_TURN到作业方向并完成观察高位确认。不修改正式比赛返回策略，普通任务仍用原目标。已有ResumeState/绝对目标/闭爪松爪等待用于暂停续接，不重放已发生的夹取或放料；取消撤销独立资格，保持夹爪输出。未知颜色不伪造，反向放入后只将指定盘标UNKNOWN；已知颜色沿用，占用记录仍在正常释放等待后进行。

父任务独立mode=ring_store及ring_store_prepare/ring_store_complete显示反向实际完成阶段，不误报成正向取仓放置。新普通比赛清除RingStoreOnly，独立任务与高度不外溢。新接口均在已有生产模块内，未增加Keil编译单元。现有共享测试桩及网页预期源码按新接口衔接，未执行。

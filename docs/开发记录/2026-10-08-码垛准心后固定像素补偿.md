# 码垛准心后固定像素补偿

用户澄清：绿色点仍为今后的屏幕准心，截图中红点仅用于这次量取补偿。截图目标Center为(373,339)、Error X=39、Error Y=-1，对应绿色准心(334,338)。补偿固定为CX向右39 px、CY向下1 px，只用于本轮手动码垛功能，不将红点设为共享准心，不根据后续目标更新补偿。

## 行为与入口

控制台“视觉任务 → 码垛”的“静态对准并补偿”发送 `grab stack align <color>`，蓝色为 `grab stack align 3`、绿色为 `grab stack align 4`。

1. 通过 `GrabTask_AlignStart` 执行原准心静态对准，保持Z最高，用底盘与X接近原绿色准心。
2. 新鲜视觉满足窗口并确认停车后进入 `stack_compensating`。保留同一目标颜色和原视觉矩阵，将控制误差变为 `(DX−39,DY+1)`，使用相同速度、加速度和误差窗口完成补偿。
3. 补偿后再次按新鲜视觉和机械反馈停稳，报告 `stack_aligned_ready`，关闭运动纠偏并等待人工装料。
4. 人工 `grip catch`，再用原滚轮/`grab stack lower <z_mm>` 调高，独立 `grab stack release` 松爪、`grab stack lift` 提起。

39和1是像素，不是毫米；实际位移由当前J矩阵、机构位置和视觉回授确定。准心参数及香橙派图像叠加不变；补偿完成时DX≈39、DY≈−1（按现有误差窗口确认）属于预期，不能再要求该阶段DX/DY回到0。普通颜色静态对准、编号环、动态追踪及正式赛事任务不启用此码垛补偿。开始其他静态任务或动态追踪时清除当前码垛补偿阶段，不清除原模型。

## 验证

真实固件状态机回归先将目标给在最终偏移处，证明任务仍须先对准绿色点；随后绿色对准停稳才进入补偿阶段，绿色误差为0时继续移动、最终39/−1才完成。检查ref_u/ref_v不变、无自动夹爪和库存操作，并验证普通颜色对准及动态观察不继承补偿。网页真实面板测试覆盖专用入口与短进度报文下的“补偿中/等待装料”提示，滚轮下降和独立松爪流程保留。

软件回归与编译不代表实车补偿位置验收；本轮未烧录、未发送实车运动指令。香橙派源码无需改变，绿色准心仍为原值。

验证结果：网页484项通过；码垛、静态对准、短时漏检恢复、取放、调速仿真、串口分发及动态追踪回归通过。Keil Target template最终构建0错误、0警告。

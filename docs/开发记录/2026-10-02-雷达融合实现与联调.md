# LDS50C 雷达融合实现与联调

正式工程为 `Code/template/`，主控 STM32F407VGT6。USART2 的 IOC 与生成代码均为 PA2/PA3、921600/8N1、16倍采样；RX 使用 DMA1 Stream5/Channel4、循环、字节、内存递增、高优先级，DMA和USART2中断为3/0。USART1的DL20无线仍为115200，USART3串口屏、UART5电机和USB B2视觉接口保持原用途。

## 软件职责与入口

F407负责静止单圈采集、筛选、5×5建图、毫米四邻居A*规划与显式路线执行；网页负责图层、参数读写和离线对照。网页离线服务通过 `Code/tools/radar_plan_cli.c` 调用同一 `radar_map.c`，无需npm或云服务，需要PATH中的GCC。参考来源为用户提供的两份代码，见 `Code/reference/README.md`；本实现适配F4 HAL与现有ASCII控制台，不使用旧C#二进制下载协议。

上电仅启动USART2接收，不自动扫描或运动。操作顺序为：完成现有准备与起点设置 → 静止扫描 → 读取地图与路径 → 显式执行。初期也可未设置底盘原点就按参考雷达位姿做静止方向检查；建立新的底盘原点后需重新扫描，让图与实际原点对应。

```text
radar status                 当前状态和接收诊断
radar scan                   非阻塞配置后采完整一圈
radar stop                   仅停止雷达扫描
radar plan                   从最近完整地图重新规划
radar get                    参数第0页，余页按fetch读取
radar set threshold 3        修改RAM参数，下一次采集使用
radar fetch map 1 0          读取地图1第0页
radar fetch path 1 0         读取路径1第0页
radar fetch points 1 0       读取扫描1的降采样预览
radar fetch cloud 1 0        读取完整缓存，最多4096点
radar nav start 50           显式按规划路线运行，速度mm/s
radar nav status             规划路线执行反馈
radar nav cancel             取消规划路线，异步停车
radar task start 50          规划路线扫码→原料→红色首件pick组合测试
```

`nav`运行完整几何工位路线，不执行全赛事搬运动作。`task`沿规划路线到QR工位visit1，停车后保持现有1秒模拟扫码、`156+123+516+231`任务码及串口屏发送确认，再到原料工位visit2交接既有pick。抓取控制、视觉容错和实际香橙派部署不属于本次修改；原固定16段路线继续可用。

“停止扫描”与“停止底盘”分别操作。底盘停车入口常驻；取消不会清空图或参数，也不会松开夹爪。网页离线计算、导入、缩放、图层切换、读取快照和重连均不提交运动。

## 坐标与方向

统一沿用当前二维地图：场地2400×2400mm，左下角(0,0)，X向右、Y向上，yaw从+X逆时针。底盘默认起点 `(2250,150,90°)`，车体前向vx、左向vy保持已有实测方向。参考图数据只在导入时绕场地中心逆时针90°：

`x=2400-y_old; y=x_old; row_new=col_old; col_new=6-row_old`。

| 参考工位 | 原参考点 | 旋转后参考点 | 当前底盘到点坐标 |
|---|---|---|---|
| 1 启停/雷达 | (230,230) | (2170,230) | (2250,150) |
| 5 扫码 | (1200,350) | (2050,1200) | (2100,1200) |
| 4 原料 | (2050,1200) | (1200,2050) | (1200,2100) |
| 2 粗加工 | (350,1200) | (1200,350) | (1200,350) |
| 3 暂存 | (1200,2050) | (350,1200) | (350,1200) |

顺序为 `1→5→4→2→3→4→2→3→1`。旋转的是雷达参考世界坐标，不能给当前IMU/底盘yaw再加90°。

原始角a仍从雷达零线顺时针计。默认参考零线为当前地图180°，因此a=0/90/180/270°分别对应左/上/右/下。投影为 `x=lidar_x+d*cos(zero-a)`、`y=lidar_y+d*sin(zero-a)`。

参数 `lidar_x_mm=2170, lidar_y_mm=230, zero_deg=180` 表示车辆在已验证起点时的雷达参考安装位姿，保留原测试摆放。由这两个预设点算出的(-80,+80)mm只是参考差值，不能记为实测安装偏移。已有有效车辆反馈时，固件按车辆相对起点的平移与yaw变化转换雷达位姿；地图快照中的pose是本次实际使用值，参数页显示的仍是起点安装预设。实物确认后在参数页调整这三项即可。

## 接收、圈恢复与内存

4KiB循环DMA保留HT/TC/IDLE，结合NDTR与整环进度识别覆盖；中断只记录，主循环每次最多解析512字节。六条6字节ASCII `LSTOPH/LMDMMH/LOCONH/LFFF1H/LSSS1H/LSTARH` 使用发送完成后20ms间隔、IT非阻塞发送；主循环无HAL_Delay。扫描期间暂缓可选OLED阻塞I2C刷新。

支持CEFA、CFFA、ST状态与CECE报警。CE包按下一包起始角插值；CFFA暂保持已验证参考的sector/(N−1)，手册示例存在/N差异，实机出现该类包时需用原始包确认。921600请求在42MHz APB1下按当前HAL整除产生实际约933333bit/s（约+1.27%）；时钟与HAL未改，联调以校验/错误计数和真实雷达接收为依据。

完整圈需要真正跨越0°边界并累计360°。坏校验、丢字节、异常角下降和厘米/毫米单位变化会丢弃本次不完整圈，继续等下一圈；10秒总窗口内不设固定恢复次数。未知单位按毫米请求的默认值处理，厘米状态则×10。超过uint16毫米容量的点作无效点并计数，避免坐标溢出。

完成图才发布新scan/map版本。参数、普通停止、接收重启和取消不删除完整旧图。缓存只有一份4096点云，重新采集期间点云接口不可读取，网页已下载旧云仍可标历史保留；超出容量只截断展示云，全部有效点继续参与建图。

格边界为150/550/1000/1400/1850/2250mm，测点用半开活动区，规划允许起点2250边界。默认阈值3，加上四固定障碍。没有整工位格豁免，也不把未观察区域当成全部堵塞；覆盖信息与已知固定地图一起展示。A*仅检查占据格与轴向路径，车辆/夹爪实际外廓及净空仍需实车验证。

## 网页与链路

沿用当前二维SVG，实车监控/雷达建图/离线对照共享视角。右键在指针处放大，滚轮缩放、左键拖动、恢复视图；操作坐标由SVG矩阵逆变换得到mm，不修改地图方向。设备规划为实线，离线对照为虚线。车辆、障碍、路线默认展示，点云和点数按需显示；结果标明设备/离线来源、版本和年龄。

无线 `@RADAR` JSON单页不超过256字节，独立低优先级槽，每秒最多一页，普通命令与底盘遥测优先，紧急停车回复在完整页边界优先。地图6页、路径每页2点、点云每页3点、参数10页，按ID逐页读回。360点预览120页，完整4096点1366页，DL20分别需约2分钟和23分钟且会受高优先级流量延长；建图与执行不等待网页下载。终端默认突出状态/异常，大点云与地图分页进入快照模型，原始记录可导出。

最终软件验证：固件完整主机回归通过；网页Node 149/149、桥接与离线服务Python 33/33通过；`radar_wire_contract_test.py`将实际C格式化的完整map/path/points/params页送入正式网页模型，验证快照拼装与工位语义。真实本地HTTP离线规划返回`radar_map_c_v1`，前后串口均未连接。Keil `template`构建0错误、0警告，RAM81536字节（约79.6KiB），生成`Code/template/MDK-ARM/template/template.axf`与`template.hex`。浏览器交互已做DOM回归，当前工具没有可用浏览器，未完成实际渲染目视检查。

集成阶段修正了首次扫描把旧图origin当成本次采集origin而误取消、旧地图被新圈覆盖角误标、长32位编号四点报文超过256字节、可变路线回复仍显示16段，以及网页不可达段号偏移一段的问题。前三项有针对性的控制台回归，路线状态与网页段号也已补检查。没有为雷达新增固定恢复次数上限。

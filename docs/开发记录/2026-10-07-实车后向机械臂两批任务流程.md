# 实车后向机械臂两批任务流程

## 已确认条件

用户确认右下起点、车头沿二维码方向向上；实物 Base 回零位置改为朝车后。俯视 Base 正方向为顺时针，作业为回零锚点 +90°，车载取放为锚点 −90°。`base_car_offset=-180°` 表示从作业方向切到车载方向，`x_car=100 mm` 沿用既有默认值。本轮不修改驱动原点计数。

用户确认三个加工/暂存位置与官方图一致。依据[官方命题与运行PDF](../赛事资料/智能搬运赛题/原始资料/附件2-1-第九届中国大学生工创大赛智能+工程创新赛道命题与运行.pdf)第3页图1、第5页图3，中心间距150 mm：粗加工1号在右、2号在中、3号在左；暂存1号在下、2号在中、3号在上。坐标来自官方图与当前地图基线，尚未作为实车定位验收。

## 行驶与机构衔接

地图角度从 +X 逆时针计；Base 角度另按物理顺时针计，两者不能混用。

| 阶段 | 底盘位置 / 车头地图角度 | 机械臂与衔接 |
|---|---|---|
| 开始 | (2250,150)，90°向上 | 先确认后向姿态，Z抬升、X收回；保留上电回零实际多圈角作为锚点 |
| 二维码通道 | (2100,300) → (2100,1200)，90° | 朝后行驶，不发二维码扫描、不做Z搜码 |
| 上方直角 | 到(2100,2100)后向左侧移 | 首次原料长段保持90°，到(1275,2100)附近准备作业 |
| 原料台 | 最后75 mm切到0°车头向右，低速到(1200,2100) | 底盘顺时针90°时允许已收回的Base同时顺时针90°，机械臂指向地图上方物料台 |
| 原料三件完成 | 从原料台转向−90°向下，直行至加工区 | 先抬Z收X并回后向锚点，三轴反馈完成后离站；不重新HOME或ZERO |
| 粗加工 | 最后75 mm前切到180°车头向左 | Base作业+90°面向地图下方。按编号平移到各环，先全部放好，再全部取回 |
| 暂存 | 90°车头向上到(350,1200) | Base作业+90°面向地图左方，按编号平移到各环；第二批按第一批同色环码垛 |
| 返回 | 沿固定路线经中心、右侧通道回右下，90° | 先收回并朝后，再续跑；最终机构朝后 |

各工位采用当前75 mm接驳尺度，末段速度不超过 `min(启动速度,50)` mm/s。普通长段默认200 mm/s，转向上限100°/s不变。转向/对接与取放以实际反馈完成，取消额外100 ms定时停留；旧2秒说明为历史。

任务通过 `station/visit` 交接。作业时路线保持 `work` 预约，局部换环/视觉对准可以移动底盘；每站结束先回后向姿态，再低速返回工位中心，续跑下一腿。共享C生成任务阶段，绕行保留原路点，新增接驳点只截取原线段最后75 mm。

## 两批取放与编号

启动时冻结已有有效任务码；尚无任务码时发布明确模拟码 `156+123+516+231`。不在二维码点更新任务码。当前实现要求每批三色不重复、位置1/2/3各一次，两批颜色集合相同。

每批使用仓1、2、3记录对应颜色。原料区执行现有B2 `pick`；粗加工固定位置释放三件后才依次取回；暂存第一批用第一层高度，第二批用第二层高度，按第一批的颜色→环号映射放在同色下层之上。

| 工位 | 1号中心/mm | 2号中心/mm | 3号中心/mm |
|---|---|---|---|
| 粗加工 | (1350,350) | (1200,350) | (1050,350) |
| 暂存 | (350,1050) | (350,1200) | (350,1350) |

粗加工与暂存沿用独立实物Z参数 `z_proc_grab`、`z_proc_lift`、`z_proc_place`、`z_temp_place`、`z_stack_place`，不代填高度。启动前需要建立车载转盘参考，三仓角度已标定且库存确认为空；slot2/3不预填120°。到具体场景缺Z参数时停在当前件的 `config_wait`，页面显示缺项。用 `grab set <key> <value>` 补齐RAM参数后执行 `grab mission continue`，不重复先前已完成取放。

`stored/placed`各最多12：六件原料入仓 + 六次加工取回入仓；六次加工释放 + 六次暂存释放。屏幕原计数控件支持0～12，控件名称、HMI文件与字库未改。计数表示控制动作完成，不是物理夹持/放置成功检测。

## 入口与状态

网页“视觉任务 → 单件抓取 → 6 · 后向机械臂两批任务”，默认 `grab mission 200`。操作说明：

```text
grab mission [speed_mm_s]  # 新固定两批任务，默认200
grab mission continue     # 仅config_wait时，补齐后继续当前件
grab pose rear            # 抬Z、收X，朝后
grab pose work            # 抬Z、收X，顺时针90°外侧作业
grab status               # 同时报告任务调度与单件控制状态
grab stop                 # 取消推进并沿现有机制请求停车
```

本机C预览增加 `task_fixed`、`task_planned`，各阶段标识 `arm_pose=rear|work`，只播放底盘阶段与朝向，不计三轴/夹爪/视觉耗时，不发送设备命令。旧纯底盘 `fixed/planned` JSON字段保持兼容，旧 `grab route` 模拟首件调试保留在折叠区。现有 `radar task start` 仍为旧首件入口；新两批任务目前网页/控制台使用固定路线，规划任务API留供后续接入。

机构姿态转换保留视觉准心及矩阵，仅在离开观察方向期间暂停适用性。普通取消保留RAM配置、参考、已完成计数和仓位库存；涉及夹持中的槽位沿既有规则标为待核对。取消后不会自动重跑或重新回零。

工位期间短暂轮反馈间隔导致定位generation变化时，若原点/位置单位未变，局部返回已取得新鲜到位与停稳反馈，就沿原任务续跑；真实原点改变报告 `station_reference_changed`。机构完成前排空自身在途反馈读，底盘启动忙时短暂等待，避免正常总线读取造成整任务失败。新任务和姿态命令沿用现有雷达静止采集运动互锁。

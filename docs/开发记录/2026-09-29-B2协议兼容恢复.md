# B2 协议兼容恢复

用户批准恢复原 B2，与实机 test_connect.py 对接。此前单独 camera 测试用 B2，GrabTask 却请求 B4 并要求远端圆心阶段、采集帧号、采集年龄和请求编号，造成兼容断层。本轮统一所有固件视觉入口为 B2，不修改香橙派程序或自启动项。

## 实现

- Camera 删除 B4 发送和解析、远端元数据，保留 USB 分包/粘包/重同步和统计。成功请求及停止清空旧数据；忙/失败保留旧请求。增加本请求 InvalidCount，避免“有效→无效→有效”批量接收掩盖失效。
- GrabTask 根据本地接收序号去重消费，接收时间判断 age_ms。相同坐标的新报文计数，同一快照不计数；至少 3 次观测且至少 200 ms，叠加原有停稳反馈。进入停稳阶段后重新计数；失效、越界、停止及重新启动清除稳定证据。无首包时停止等待，开始对准后失效则停车报错。
- 状态使用 protocol=B2、age_source=rx、rx_seq、vision。终端保留简洁坐标及原文导出；页面显示接收含义，旧固件未提供字段显示“未报告”。camera status 的无效/过期状态不输出历史坐标冒充当前数值。
- 保持原准心、像素响应矩阵、取放位置、速度、机械与总线互锁。未改引脚、时钟、USART1 DMA 或无线发送节奏。

B2 的本地接收序号不能替代远端采集帧号；同色迟到回复无法严格辨别，也不证明圆心阶段。用户接受按“坐标持续在容差内 + 机构停稳”完成对准。

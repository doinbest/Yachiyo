# 无线地图遥测限速发送 — 2026-09-12

## 问题与依据

COM23、115200 8N1 经 DL-20 连接小车。前轮直接抓串口原始字节，绕过网页仍出现残缺 JSON：12 秒捕获的 21 条遥测均无法解析，而关闭遥测前后的 info 完整。短暂开启后关闭曾收到完整状态帧。证据见《2026-09-12地图遥测COM23实测定位》及 `.embeddedskills/logs/serial/map-20260912-050334/`、`map-20260912-050515/`。

这说明格式破坏发生在网页解析之前，长数据连续输出是应先减少的变量。尚未抓取 PA9 波形，不能确认具体在哪一级丢字，也未证明 DL-20 内部配置异常。软件 dropped=0 不代表无线没有丢字。

## 本次实现

- `console_tx.c/.h`：USART1 每次最多 32 字节，发送完成后间隔 30 ms。主循环计时，不阻塞控制。整帧冻结，发送中途不会插入回复；下一帧按命令回复、二维码事件、地图遥测排序。首次 HAL_BUSY 保留待发队列，中途 HAL_BUSY 保留当前帧偏移。
- `chassis_telemetry.c`：最短状态周期由 200 ms 调整为 2000 ms；已有发送积压时延后生成。关闭流取消待发状态，已开始的帧完整结束。保留 v1 字段、数值精度及定位含义。
- config 增加可选 `telemetry_period_ms=2000`。网页初次等待配置 8 秒，随后接收超时为报告周期三倍（当前 6 秒）；旧固件仍按 200 ms / 600 ms 处理。轨迹间隔依据报告周期调整。
- 页面显示“最近一帧”和报告周期。MCU 反馈安全时限、控制周期和网页依据 MCU 时间判定的反馈有效性不变；接收超时不是反馈有效性。
- 更新入口及地图模块资源版本为 `wireless-1`。固件与网页需要一起更新。

32 字节 / 30 ms 是待验证的试调参数，不是模块规格保证。约 1 KB 的状态在本地分段发送也需要约 1 秒，完整 2 KB 约 2.1 秒；查询回复可能等当前 JSON 完成。命令接收和主循环仍持续处理。本次没有改变电机控制或自动设置地图原点。

## 作者上板步骤

1. 烧录本轮 hex，保持小车静止。关闭其他占用 COM23 的程序。
2. 打开 `http://127.0.0.1:8765/?v=wireless-1#map`，强制刷新，连接 COM23 / 115200。
3. 点击开启遥测，等待约 5 秒观察配置与状态；连续观察 30 秒，记录完整收发日志。正常时约每 2 秒一帧，拥塞时可能更慢。
4. 点击关闭遥测，等待当前帧结束，发送 info，确认回复完整。此流程不需要启动底盘路线或轮子。
5. 若仍提示格式错误，导出日志，比较坏帧数量和长度；结合原始串口数据继续调整发送节奏或检查链路。不要通过放宽 JSON 解析掩盖残缺字段。

“反馈估计不可用”与“遥测格式错误”是不同问题。未建立原点、未确认位置单位或未获得有效轮子/IMU反馈时，格式正常也应显示反馈不可用；本次不伪造位置或到站状态。

# 默认 Receive 与上电 IMU 验证

日期：2026-09-22。

用户已确认 Emm42 仅更改 ID，其余为出厂默认。以前 MCU 的 ACK 配置初始化为 UNKNOWN，导致每次复位后需要设置 profile；现在直接初始化为 Receive。控制台删除 profile 命令控件与准备流程中的设置步骤；固件保留 receive 的兼容入口，拒绝 none。没有向驱动器写配置。

外设初始化结束后安排一次自动验证，等待新鲜 IMU 数据最多5秒；等待期间标记 busy。全部软件运动任务空闲且数据新鲜后，复用现有归零/静止验证状态机，归零后的新样本开始完整5秒窗口。成功授予航向资格；超时、通信失败、漂移或运动失败不重试。取消也清除待启动动作。保持原先漂移、噪声及采样间隔门槛，手动重新验证改为5秒。准备跑图复用已通过的上电验证，否则请求5秒验证；原点仍须人工确认。

原生标定仍为20秒加30秒验证，不在启动时执行。之前约10秒出现的 I2C/normal_mode_unconfirmed 故障没有在本次修复；缩短静止验证不能解决该故障，也不证明长期温漂正常。

软件验证：固件主机回归通过，含新鲜数据等待、51个样本覆盖5秒、一次性成功/失败、等待取消、启动运动占用与超时；控制台 JavaScript 68项和桥接 Python 18项通过。Keil template 构建0错误0警告。日志见 .embeddedskills/tests/boot-verify-* 和 .embeddedskills/build/boot-verify/。

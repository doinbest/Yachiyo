# 2026-10-02 抓取参考诊断与终端精简

用户反馈：曾在恢复总线、重启或其他操作后，再次启动视觉抓取时遇到参数错误，但不记得具体触发指令；终端逐条展开抓取状态的几十个字段，难以阅读。

本次检查、修复范围为参数/参考生命周期、状态诊断和网页中文摘要，未改动视觉算法、B2 协议、align/pick 的运动与漏检恢复策略，未操作实车硬件。

## 指令路径核查

| 操作 | 当前源码行为 |
|---|---|
| 普通 `grab stop` | 停止任务并等待反馈，不清除有效配置；参考未变化时可再次启动 |
| `bus recover` | 停止任务、检查电机及恢复通信，不调用抓取初始化或作废参考；不自动续跑，也不恢复此前已经失效的参考 |
| `system reset` | 主控重新初始化，RAM 自定义值恢复默认；自动 Z/X/Base 回零全部验证完成后，fixed/align/pick 所需默认参考就绪，之后仍需满足 IMU 与总线资格 |
| `grab rehome` | 按现有顺序重新回零；对应轴通过真实状态/位置反馈验证后恢复默认参考；失败/中断不误恢复 |
| 手动 HOME/ZERO、Base 外部移动 | 对应机械参考或视觉准心/响应模型失效，后续视觉启动被拒绝 |
| 自动取放的 Base 放置转向 | 观察姿态改变，下一次视觉任务的准心和响应模型失效；需重新建立三轴参考 |

现有 [2026-09-30 连续视觉任务参考恢复记录](2026-09-30-连续视觉任务参考恢复.md) 已说明类似现象和 `grab rehome` 入口。源码与主机模拟不能确定用户当时实际执行了哪个指令，不把它直接归因为总线恢复清参数。

## 复现与修复

使用实际 `GrabTask.c` 状态机，机械、视觉、时钟和串口端点采用既有主机测试替身，完整跑 `pick → hold → grab stop → 再次 pick`。

修复前，`base_turn()` 已清除 `ref_u/ref_v/j00..j12` 并设置 `ref_cause=base_place_turn`，但没有刷新缓存 `Status.missing`。因此任务完成及停止后仍报告 `missing=none`，实际 `GrabTask_ConfigReady("pick")` 已为 false；下一次启动时才报告全部参考缺项。此误导与需要重建观察参考的正常门槛应区分。

修复仅在 `base_turn()` 清除模型后同步计算 `Status.missing`，不恢复旧参考、不改变拒绝启动的门槛、不自动回零或发送动作。现有 Init、ReferenceInvalidate、grab set 和验证回零路径已同步缺项，未增加每次读取快照都重算配置的逻辑。

`Code/tests/grab_task_test.c` 新增回归：完整取放后立即报告 `missing=ref_u`，停车后仍保持缺项，下一次启动报告全部参考缺项且被拒绝，显式 `grab rehome` 完整验证后 pick 可以受理。修复前确实在预期断言失败，修复后通过。

## 终端中文摘要

`terminal-format.mjs` 为抓取状态采用字段白名单：模式、状态、原因；只有 `vision=Ok` 且 dx/dy 为有限数值时显示像素偏差；按实际字段显示缺项、异常参考和停车反馈。正常参考、空值、NaN、轴位置和目标、协议来源、接收序号、模型、速度、耗时和恢复统计不再在中文抓取状态中展开。

参考变化引起 `config_missing` 时保留具体参考原因，并提示“请重新建立三轴参考”。故障标识和实际停止请求/确认的区别保持。

原始日志、导出、协议解析、相机坐标行、参数读取与路线报告不改。视觉任务状态页保留完整快照。更新网页入口和模块导入的缓存版本，刷新后加载新格式器；页面不会因此自动连接串口或发送任何指令。

示例：

```text
故障 · 抓取任务：模式：视觉取放；状态：故障；原因：恢复次数耗尽；停止：该次已确认
```

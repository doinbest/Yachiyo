# UART5 循环 DMA 与单次失能故障修复

## 现象与依据

作者报告：网页可以点击底座 base 失能，之后使能仍能点击，但电机没有反应。尚未获得本次实物完整 RX 日志；本轮修复的是源码中已确认、主机测试可复现的故障路径。

- `template/Core/Src/usart.c`：UART5 RX 使用 `DMA_CIRCULAR`。
- 本工程 HAL `stm32f4xx_hal_uart.c`：循环模式 IDLE/HT/TC 不结束接收；`HAL_UARTEx_ReceiveToIdle_DMA()` 在 RxState 不是 READY 时返回 HAL_BUSY。
- 旧 `MotorBus_RxEventCallback()` 每次回调重新启动 DMA，将 HAL_BUSY 转成 io_error；主循环据此隔离总线，后续使能提交失败。
- 旧回调把 Size 当作本次数据长度；循环 DMA 的 Size 实际是缓冲区位置，连续回调会重复提交旧字节。

因此，电机可以已经执行失能并正常回复，MCU 却因接收回调处理错误锁住总线。此前测试直接注入字节，或将启动接收桩固定返回 HAL_OK，未覆盖这一模式差异。

## 修改

1. `motor_bus.c/.h`：明确 UART5 循环 DMA 前置条件。DMA 只在初始化及真实错误恢复时启动，普通回调不重启。
2. 新增接收位置游标，只复制新增数据；跨尾部时分两段复制。保留位置 64，TC 与同位置 IDLE 重复通知不重复提交数据。
3. 保留半传输 HT 通知，使连续无 IDLE 数据在半缓冲和满缓冲处及时进入软件环形队列。新启动 DMA 前重置游标。
4. `arm_console.c`：应答超时仍输出 ack_timeout；提交失败输出 `ERR motor tx bus_locked=0/1`；异步通信失败输出 `ERR motor communication axis=base bus_locked=0/1`，不再伪造电机错误码 0x00。
5. 真实通信故障、应答超时、迟到应答保护与同步运动故障锁存保持原行为；未以自动清除锁定掩盖错误。

本轮未修改 CubeMX、引脚、DMA 模式、工程源文件列表或网页业务。

## 作者上板步骤

1. 烧录上述 HEX；底座空载或确认失能后不会自行转动，先不启动底盘路线或视觉任务。
2. 用现有上位机连接实际 USART1/Zigbee 串口，115200。
3. 机械臂与夹爪页选择“底座 Base”，点击“失能”，应见 `OK disable base`。
4. 点击“使能”，应见 `OK enable base`；点击“读取状态”，检查 `en=1`。
5. 再点击“失能”并读取状态，检查 `en=0`。按此顺序重复 10 轮，每步等待回复；保存完整 TX/RX。
6. 本轮通过后，再逐项恢复底盘反馈与其他任务；不要把单轴验证通过当成全车实物验证通过。

若仍失败，保留第一条错误。`ack_timeout` 表示没有在期限内得到合法应答，仍需检查实际驱动应答方式、UART5 接收线路与波形；`bus_locked=1` 表示固件已隔离电机总线，反复点击不会解除。不要仅为解锁而点击“确认驱动已实际复位”。

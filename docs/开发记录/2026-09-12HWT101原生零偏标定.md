# HWT101 原生零偏标定（2026-09-12）

## 本次改变

原来的 `imu cal start` 在 STM32 中拟合角度漂移，再按时间扣除；它没有执行 HWT101 内部标定。本轮由 HWT101 获取自己的零偏，STM32 只负责流程管理及测量结果，不再扣除外部偏置。

HWT101 使用 I2C2：PB10/SCL、PB11/SDA，7 位地址 0x50，100 kHz。现有 GPIO 内部上拉保留，CubeMX 配置未修改。软件内部上拉不等同于外部 4.7 kΩ 上拉。

本轮只实现用户提供 FAQ 的 WORKMODE 流程：`0x48=1` → 20 秒 → `0x48=0`。新版 AGV 0xA6、上位机其他版本的 0xA7、角度归零及比例系数调整不在本次范围。

依据：用户提供的 HWT101 FAQ 和协议截图；本机官方上位机 `Witmotion(V2026.8.31.0)/Config/CommandPanel/hwt101.xml` 中的 KEY=0xB588、SAVE=0、100 ms 间隔；[维特官方 SDK 的 I2C 写寄存器分支](https://github.com/WITMOTION/WitStandardModbus_WT901C485/blob/main/ESP32/ESP32_sdk/mian/wit_c_sdk.c)。I2C 发送寄存器地址及两个低字节在前的数据字节，不发送 UART 帧头 FF AA。

## 操作与预期结果

1. 烧录新固件，保持整车静止；本轮软件交付不自动烧录。
2. 若之前进行过底盘、单轮或位置测试，先执行 `chassis stop`。软件只能知道命令是否仍可能运动，没有编码器静止检测；停车命令成功后仍需人工确认整车确实静止。
3. 输入 `imu status`，记录 VERSION、WORKMODE、零偏原始值及 I2C 错误数。版本原始值不猜测转换成厂家固件名称。
4. 输入 `imu cal start`，整个约 50 秒内不要碰车。每 5 秒输出进度：开始/恢复阶段包含短寄存器间隔，原生标定 20 秒，恢复正常模式后从新样本起独立验证 30 秒。
5. 观察最终结果，必要时再次输入 `imu status`。连续日志自动关闭，直到用户再次输入 `imu stream on`。

命令：

| 命令 | 行为 |
| --- | --- |
| `imu cal start` | 模块标定20秒、验证30秒，通过后请求内部保存 |
| `imu verify` | 只验证30秒，不写入任何配置 |
| `imu verify 120` | 只验证120秒，不写入任何配置 |
| `imu cal cancel` | 取消并异步尝试恢复正常模式，清除本次控制资格 |
| `imu cal clear` | cancel兼容入口，不擦除模块零偏 |
| `imu cal forget` | 已停用，返回说明，不擦除任何存储 |
| `imu status` | 查询最新状态；空闲时只读刷新模块寄存器 |
| `imu stream on/off` | 模块角度连续输出；流程运行时禁止打开 |

## 如何判断结果

- `result=PASS` 表示这次静止验证通过，不表示零漂绝对为零，也不表示模块保存已经过断电验证。
- 验证条件为拟合漂移速度绝对值不超过 0.01 °/s、拟合残差 RMS 不超过 0.1°。这是项目检查阈值，不是厂家精度承诺。30秒只是短时检查，需要时使用120秒验证。
- `verified` 是本次验证测量结果；`control_ready` 才是当前是否可用于独立底盘航向测试。通信失效、数据过期或重新标定/验证后，控制资格失效，新的角度数据不会自动恢复资格。
- 零偏前后值是 `0x4C` 原始寄存器值，没有换算成 °/s，不能与旧软件 `bias_dps` 直接比较。标定前后相同并不自动代表失败。
- `save_requested` 表示保存命令发送成功，`save_readback_ok` 表示其后模式/零偏可读。保存失败与测量验证结果分开报告；无法恢复正常模式时最终流程失败。
- `persistent=UNTESTED` 表示程序不能单靠一次写入证明断电保持。
- `yaw_deg` 是模块输出，已经过模块自身算法处理；软件不再输出旧 `corrected`，也不加载 W25Q128 中的旧偏置。

## 断电保持与底盘验证

保存请求及回读正常后，先记录零偏值，再完全切断 HWT101 电源并重新上电。仅复位 STM32 不能验证模块的非易失保存。重新读取寄存器并执行 `imu verify`，检查保存保持和重新上电后的漂移。该步骤由用户完成，并保留两次日志。

每次 MCU 启动没有有效的本次验证资格；执行 `imu verify` 通过即可使用模块已有零偏，不必每次重新标定。`chassis hold` 使用验证过的模块角度和现有 PID 参数。本轮不将航向控制接入视觉搬运。

## 异常与实现边界

- 启动条件：IMU新鲜、模块正常模式、机械臂/视觉/底盘软件运动任务空闲。软件不能替代人工静止确认。
- 内部使用非阻塞状态机，20秒等待后重新解锁，避免复用已经超时的解锁状态。
- 标定/验证/恢复/保存期间暂停 OLED 刷新及离线初始化重试，避免未连接 OLED 阻塞采样；退出后恢复。
- 校准开始命令一旦尝试发送，后续异常需恢复正常模式；恢复最多三次，每次重新解锁、写0并回读。上电读到非正常或未知模式时，cancel也可尝试恢复。
- `normal_mode_unconfirmed`：恢复正常模式失败。先检查连接和供电，再执行 `imu cal cancel` 重试；不要开始运动。
- `start_readback`：WORKMODE回读与FAQ流程不符。保留实际VERSION/模式日志，核对固件，不自动尝试A6/A7。
- `sample_gap`/`stale`/`i2c`：采样不连续或通信异常；检查gap、错误计数。最大允许间隔300ms；通信故障不发送保存命令。
- `motion`/`drift_or_noise`：验证窗口检测到角度跳变或漂移/噪声超限，检查是否碰车、振动或模块标定无效。保存只在验证通过后请求。
- 不将旧外部偏置写入GYROBAIS；不恢复旧补偿掩盖实际输出；不保证取消后恢复标定前的内部零偏。
- 旧 `hwt101_drift` / `hwt101_store` 源码保留作为历史，但已从固件及回归运行入口移除。W25Q128通用驱动和ID检测保留，旧IMU扇区不擦除。

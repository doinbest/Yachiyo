## 入口与实施顺序

“0 · 测试前准备”现精简为Base、X、Z三行，每轴一个按钮：Base就近回零（`home base near`），X/Z碰撞回零（`home x collision`、`home z collision`），不再放置底盘/IMU、清零或查询控件。先完成位置参考，再填写标定参数。直接放在转盘前测试不要求地图起点，前四段路线联动仍在地图页准备跑图。

网页“视觉物料”的单件抓取区域提供相应操作；串口仍为115200/8N1、空格ASCII命令，不需要手写控制程序。

| 命令 | 行为与终点 |
|---|---|
| `grab start fixed` | 人工水平对准后，检查静止反馈，打开夹爪、Z下降、闭合、提起、Base转−180°、下降放置、松爪、提起，进入hold等待人工验收 |
| `grab start align` | Z到观察高度、X到预备位置，底盘/X共同修正；精定位稳定且水平停止后进入hold，不下降 |
| `grab start pick` | 观察准备、共同对准、水平停稳、下降、闭合、提起，再自动转向、下降放置、松爪、提起，进入hold |
| `grab route <speed>` | speed为路线mm/s；原起点执行前四段，第2段停车后模拟扫码，第4段交给pick；不进入第5段 |
| `grab status` | 路线与抓取状态、缺项、位置、误差、视觉阶段/年龄及停止请求/确认 |
| `grab stop` | 取消自动推进，请求停车，保持夹爪输出与Z使能 |
| `grab set <key> <value>` | 设置单个RAM参数；运行中拒绝修改，不落盘到外部Flash |
| `grab get <key>` | 读取单个参数；未配置返回unset |

`stop_confirmed`记录最近一次停止请求的反馈确认；流程之后可能进入Z下降/提起，须结合当前state理解，不能单凭该字段认定所有机构一直静止。`elapsed`为本次任务耗时。

`hold`只表示取放或对准流程结束，仍保留机构所有权；正确抓取数不自动增加。人工检查后显式停止，确认停车，再进行下一次调试。闭合后的故障也不自动松爪或失能Z。

先进行fixed的机械动作验收，再调align，随后pick，最后route。所有命令均为操作说明，本次代码工作没有向硬件发送它们。

## 参数、单位与缺项

同日现场初测：用户确认采用电机1080°对应Z下降20 mm，换算为480命令脉冲/mm；最高点反馈 `en=1 reached=1 raw_units=-4` 接近计数零点。最初预计下降约100 mm，后续用户实测确认每次顶部回零后下降80 mm（8 cm），网页Z夹持位置现预填−80 mm，显式发送后生效。任务1增加运动配置、开爪、毫米点动、位置查询和参数集中配置；初测比例仅预填到该点动输入，点击设置才发送至MCU。标尺精度、实际夹持高度与抓牢情况后续分别验收。

现行默认值：启动时载入pos_tol=1 mm、stop_speed=2 mm/s、feedback_ms=2000、close_ms=500；上电Z回零成功后载入z_ppm=480、z_min=−80、z_max=0、z_grab=−80、z_lift=−40、z_place=−60。网页同步预填这些数值，预填不代表设备读回，未知视觉标定参数留空。配置只存在本次STM32运行的RAM，复位后重新载入默认值。位置参考须对应本次驱动器实际计数零点：`origin`保存机械回零点与`zero`清当前位置计数是不同操作；不能在测好位置后随意改变计数零点。Base已有零点保持，不为本流程重新执行zero all。

X/Z执行zero或home后，软件撤销对应轴的边界/位置配置，保留已知机械比例；Base发生位置运动或回零后撤销观察准心与像素响应。重新建立相应参考后再填写这些参数。单独保存origin不会触发运动或撤销位置配置。

| 参数 | 单位与意义 |
|---|---|
| `x_ppm`, `z_ppm` | 位置命令脉冲/mm，正数；由机械位移测得。命令3200脉冲/圈，反馈65536单位/圈分别换算 |
| `x_min`, `x_max`, `z_min`, `z_max` | 相同参考零点下的机械可用边界，mm；Z正向上、X正向外 |
| `x_pre` | 观察时X预备位置，mm |
| `z_observe`, `z_grab`, `z_place`, `z_lift` | 观察、夹持、放置和提起高度，mm；提起高度必须高于夹持及放置高度，均在边界内 |
| `pos_tol` | 轴到位允许误差，mm；还须reached、使能、反馈新鲜及位置稳定 |
| `stop_speed` | 允许静止判定的速度阈值，mm/s；不能仅检查目标速度为0 |
| `close_ms` | 500 us松开及800 us带物料闭合共用的等待时间，ms |
| `feedback_ms`, `age_ms` | 机械反馈、视觉数据允许最大年龄，ms；结合实际吞吐设定 |
| `timeout_ms`（已删除） | 后续用户明确要求取消阶段耗时退出；不再作为配置项，底层通信/上电回零超时独立保留 |

| `travel_mm` | 视觉阶段相对起点允许的车轮行程范围，mm |
| `lead_mm` | X目标领先实测位置的最大距离，mm |
| `ref_u`, `ref_v` | 观察高度下可可靠抓住时的圆心准心，640×480图像像素 |
| `dx_tol`, `dy_tol` | 由实际夹持容差确定的误差半窗，像素 |
| `j00`, `j10` | 底盘前进每毫米导致的DX、DY变化，px/mm |
| `j01`, `j11` | 底盘左移每毫米导致的DX、DY变化，px/mm |
| `j02`, `j12` | X伸出每毫米导致的DX、DY变化，px/mm |
| `retarget_ok`（已删除） | 原人工确认开关，后续按用户要求取消；协同任务不再要求单独X轴测试或设置此开关 |

fixed需要Z换算/边界/抓取、放置与提起位置、到位容差、静止速度、闭合时间及反馈年龄，上电回零成功后这些参数已有默认值；X仅做原始位置稳定检查，不要求猜X毫米换算。align/pick再要求X位置、观察高度、准心/响应矩阵、窗口、行程等参数。

建议控制初值保留为可调软件参数：`lambda=0.3`（1/s）、`body_speed=10`、`x_speed=5`、`z_speed=5`（mm/s）、`stable_ms=200`、`frames=3`、`retries=2`、`x_weight≈2.333`。速度换算必须能够生成1～3000 RPM有效命令；毫米比例未知时不会执行。X权重不是保证70%的固定贡献，实际贡献取决于局部矩阵及边界。

## 视觉详细帧

旧B2调试请求及14字节回复继续可用。新抓取使用单独B4详细颜色帧；它不是已退役的B3圆环编号协议，也没有恢复旧CRC协议。香橙派需部署本仓库更新后的`orange_pi/change.py`，继续用实际USB设备路径的`--uart-port`启动。原附件脚本仅支持B2，不能直接用于新抓取的自动下降。

- 请求6字节：`FF B4 Color RequestId_H RequestId_L FF`。
- 回复23字节：`FF B4 Color Valid CX(2) CY(2) DX(2) DY(2) Phase FrameId(4) AgeMs(2) RequestId(2) SUM FE`。
- 多字节字段大端；DX/DY有符号；SUM为字节1～20的累加低8位。
- Phase=1粗定位、2圆心；Valid仍为0/1。FrameId来自相机采集计数；AgeMs为采集返回至发送的时间，不包含相机内部缓冲及USB传输延迟。
- MCU核对请求编号，隔离上次同色请求的迟到包；新抓取只发送一次识别请求，不周期重发打断精定位。
- MCU计算数据年龄为AgeMs加接收后的经过时间。不同接收包不等于不同图像，稳定判据必须使用递增FrameId；粗/精切换清空稳定累计。

首轮下降阶段不做水平追踪。采集或总线异常终止当前抓取，用户处理后重新显式启动，不在恢复通信后自动续跑。

## 扫码、显示与任务所有权

组合路线沿用前四段和现有到点/停车反馈判据。第2段停车确认后等待1000ms，发布共享任务码`156+123+516+231`，来源为simulated；UART4字节与真实扫码帧统计不变。第一批颜色从第一组156读取，第二组123为放置编号。OLED、串口屏与控制台共享任务码。

串口屏分行为`156+123+`和`516+231`。两行及计数字段须完成实际DMA发送后才能推进第3段；发送失败或5秒仍未完成停止推进。发送完成不表示屏幕文字已完成实物验收。

新station状态表示站点控制权交接，区别于纯路线的waiting。组合调度期间拒绝其他运动/IMU标定入口；抓取任务接管机械臂事件，拒绝外部读轴事务干扰反馈匹配。Ctrl+C、底盘停止、grab stop与相关停止命令取消自动生产者，断开或重新连接网页不会恢复运动。

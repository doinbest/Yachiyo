# IMU 零漂标定持久化

> 历史方案：2026-09-12已停用外部Flash标定加载和保存。当前改为HWT101原生标定及内部保存请求，旧扇区保留但不使用；以《2026-09-12HWT101原生零偏标定》为准。

## 使用流程

1. 烧录本次 `template/MDK-ARM/template/template.hex`。以前固件只保存在RAM中的值不会自动出现在Flash，首次仍需预热、放稳，运行 `imu cal start`。
2. 等待60秒标定和120秒验证。出现 `result=PASS` 后会自动开始保存；继续等待 `[IMU FLASH] state=saved saved=1 ... HAL=0`。PASS表示算法验证通过，saved才表示回读确认保存完成。
3. 断电后重新上电，应看到 `[IMU FLASH] state=restored saved=1 ...`。发送 `imu status`，应有 `result=SAVED`、`source=flash`、`comp_valid=1`，bias_dps与保存时一致。
4. `imu stream on` 可直接查看corrected。新上电以第一份可用角度建立相对零点，不恢复旧的角度或计时。`chassis hold`可以使用这份已恢复的补偿；上电不会自动驱动电机。
5. 重新运行 `imu cal start`，新结果通过后自动替换持久化记录。新标定失败时不覆盖旧记录，当前RAM保持失败；下一次启动仍可恢复旧记录。

保存参数不代表每次冷启动的零漂完全一致。`SAVED`表示恢复了历史验证通过的值，不代表本次上电又验证了120秒；温度/安装改变或实际残余漂移变大时，预热后重新标定。

## 清除与异常

| 操作/状态 | 含义 |
|---|---|
| `imu cal clear` | 只取消/清除本次RAM补偿；保存记录保留，重启可恢复 |
| `imu cal forget` | 异步写入删除记录并清除RAM，等待 `state=forgotten` 后再断电 |
| `state=empty` | 两个槽均无有效记录，保持IDLE，需要标定 |
| `state=waiting_imu` | 已读到参数，等待传感器提供新鲜样本 |
| `state=stored_not_applied` | 本次启动主动取消了待执行恢复，记录仍保留 |
| `state=error` | SPI、型号、忙超时或回读校验失败；查看HAL状态 |

存储忙时forget返回HAL_BUSY，稍后再试。运行中传感器故障仍按现有逻辑令补偿失效；不会在运动中偷偷重新加载旧参数。Flash保存失败不撤销已验证的RAM补偿，但不能宣称重启后会采用新参数。

## 存储布局与实现

W25Q128为16MiB；预留最后8KiB：槽A `0xFFE000..0xFFEFFF`，槽B `0xFFF000..0xFFFFFF`。后续其他用途不得覆盖这两个扇区。当前工程之前只有读取ID，没有其他Flash存储用途。

每份记录28字节，按小端编码：magic(4)、格式版本(4)、序号(4)、记录类型(4，1=偏置，0=删除)、IEEE754 float偏置(4)、前20字节CRC32(4)、提交标记(4)。仅接受有限且绝对值不超过5deg/s的偏置；这是存储有效性检查边界，不是模块精度规格。

更新步骤：擦除非当前槽 → 编程前24字节 → 等待BUSY清零 → 单独写提交标记 → 等待BUSY清零 → 回读并检查全部字节、版本和CRC。写入目标始终与上一份有效记录分开，未提交/损坏的新槽在启动时不被采用。两个槽均有效时按可回绕序号选最新。删除记录同样参与序号选择，避免重启直接回退到旧偏置。

器件命令与页/扇区约束参照 [Winbond W25Q128JV Rev F](https://www.winbond.com/resource-files/w25q128jv%20revf%2003272018%20plus.pdf)：8.2.1写使能06h、8.2.4读状态05h、8.2.6读取03h、8.2.13页编程02h、8.2.15扇区擦除20h。当前只接受实物已测得的JEDEC EF 40 18；不同型号不自动尝试擦写，也不改保护寄存器。

W25Q128驱动仅发送擦除/编程命令，不阻塞等待芯片内部完成。hwt101_store在主循环轮询BUSY，单阶段等待上限1000ms，期间IMU仍采样。每次新标定验证成功只触发一次保存，日志输出和重启恢复不重复擦写。

新增 `App/hwt101_store.c/.h`，仅将源文件加入Keil App组。SPI1、PA4片选及CubeMX配置沿用原工程。

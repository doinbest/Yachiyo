# 夹爪 700 µs、视觉任务颜色选择与偶发回零分析（2026-09-30）

用户实测 800 µs 夹取会使舵机堵转电流过大，改用 700 µs。50 Hz PWM 下对应 3.5% 占空比。`Arm_GripperSet(ARM_GRIPPER_CATCH)` 是手动 `grip catch` 与自动抓取闭合阶段共用入口；OLED PE3 夹紧预设、网页标签和当前协议文档同步为 700 µs。松开和待机维持 500 µs，手动 `grip duty` 标定能力不变。

视觉任务页在步骤 1 前提供 B2 颜色 1–6 选择。点击任务 2 或 3 分别发送 `grab start align <color>` 和 `grab start pick <color>`；固件在任务开始时锁定目标颜色，后续请求、回包匹配、重新识别和状态显示都使用该颜色。原有不带颜色命令与路线交接保持默认蓝色对准（3）和红色抓取（1）。固定位置抓取不接收颜色参数。抓取状态面板移至页面最下方；任务旁停止按钮保留。

上电回零的初始化顺序核查：`main.c` 先初始化 UART5 电机总线，再初始化机械臂模块，最后启动 Z→X→Base 回零。机械臂初始化再次调用 `MotorBus_Init`，但同一 UART 句柄时直接返回成功，不重新启动 DMA 或清除队列，因此暂未发现这处重复调用能解释约五次一次的间歇性失败。启动约 1 秒后的第一次 Z 回零若请求立即返回非 BUSY 错误，抓取任务目前统一报告 `home_request_failed`。此日志不能单独区分总线隔离、发送未受理和参数错误。电机总线可因 UART 错误、接收溢出或发送/应答超时进入隔离；隔离时新的回零请求会被拒绝。需要在下一次故障后、执行恢复或复位前，读取 `info` 中的 `[MOTOR BUS] locked/reason/fault_ms/owner/addr/func/uart_error` 和 `bus status`，才能判定首次故障是否发生在回零请求之前。现阶段不凭偶发率推断供电、线序或驱动器原因，也不增加上电自动重试或解除总线锁定。

验证：主机固件回归、网页 Node 测试与桥接 Python 测试通过；Keil 构建 0 错误、0 警告。颜色测试覆盖 1–6 号 B2 请求、原默认颜色、非法颜色及固定任务拒绝带颜色参数；夹爪测试检查实际 PWM 比较值为 700 µs。尚未烧录或完成实车夹持电流、各颜色识别及多次上电复现验证。

## 主循环与数据流

初始化外设和模块后，主循环依次处理 USB 字节、机械臂应答、两套视觉流程、底盘速度刷新、HWT101 采集及日志、控制台、串口屏、二维码、按键，最后刷新 OLED。电机事件仍按原方式分发。

`Camera_Process()` 发布共享快照。ArmVision、MaterialVision、控制台、OLED 分别读取快照，两套控制任务用各自序号去重。读取不会清除其他模块的新数据，也不会发起新识别请求。

`Camera_DataGet()` 保留兼容语义：消费它自己的新数据通知。`ArmVision_DataGet/Peek()` 保留旧接口，其历史缓存不能单独用来判断当前目标有效性。新代码优先读 `Camera_SnapshotGet()`。

`HWT101_Process()` 独立负责最短 10 ms 读取和未就绪时每 1000 ms 探测，单次 I²C 超时保持 5 ms。`HWT101_Angle_Get()` 和统计接口只读缓存；删掉日志调用、翻页或多次查询都不会改变采集次数。日志仍按 200 ms 输出，数据年龄超过 300 ms 时停止输出旧角度。

这些周期是调用时的间隔限制，不保证主循环实时周期。

## 已修正的运动流程

- 物料标定顺序：基准采样 → 底盘前移 → 稳定等待 → 前移采样 → 返回 → X 基准采样 → X 外移 → 稳定等待 → X 采样 → X 返回 → 响应检查。
- 每次进入新采样组时跳过已经发布的旧帧，运动期间缓存的坐标不会计入稳定后的新采样组。
- `|Dx| > 15` 时优先调整底盘；窗口内 `Dy` 未达标时调整 X；`Dy` 达标而 `Dx` 未达标时继续调整底盘。`Dx=10、Dy=0` 不再误报零修正。
- 完成仍要求 `Dx/Dy` 均在 ±1 像素内，连续满足原有 3 组条件；每组 5 帧中值。
- 标定持续时间由距离/速度计算并保存；普通修正 200 ms，累计位移估算使用同一持续时间。
- 电机脉冲换算使用机械臂配置常量；原 PID 系数、符号和输出限幅保持不变。
- 电机发送失败、忙、参数错误、到位超时、X/底盘行程限制、USB 未配置、摄像头忙等分别记录。底盘发送失败显示 `Chassis tx`。
- 两套视觉任务的启动入口均先检查对方和共享电机忙状态，拒绝后不切换摄像头目标、不启动电机。
- **Z 轴默认加速度从 500 改为 20**。原字段为 `uint8_t`，旧值会截断为 244。本轮是实际运动参数变更，需单独上板验证。Base/X 参数保持原值。
- `Mecanum_VelocityRefresh_Stop()` 只停止周期刷新；`Mecanum_Test_Stop()` 才发送实际停车命令。UART 电机发送宏改为 `Emm_UartSendCmd`。

**测试模式保持：**`MATERIAL_VISION_TEST_NO_TIMEOUT` 仍为 `1U`。物料任务不会因为首帧等待、丢失、数据过期或任务高层时间自动退出。原电机应答、到位、回零超时和 ArmVision 超时保持有效。上板测试继续使用既有手动停止命令。

## 三页布局

6×8 ASCII，每屏 8 行、每行最多 21 字符。以下是布局示例，不是上板截图。

```text
1/3 Overview Test
123+231+312+321
Item:2 Color:Blue
Task:Arm Align
Usb:On Vis:Ok
Yaw:+123.4 Ok
Err:None
2:Run 3:Sel 4<5>
```

任务码完整显示；未扫码显示 `Code:Waiting`。`Item` 为第二组第 1～3 项，`Color` 为准备选中的颜色。`Task` 区分标定、机械臂对准、物料回零、搜索、对准、完成及错误。姿态未取得或过期时显示 `Yaw:--- Wait/Stale`。

```text
2/3 Vision Test
Target:3 Blue
Cx:0334 Cy:0338
Dx:+012 Dy:-008
Age:120ms Vis:Ok
Ref:Ok Cal:Ok
Err:None
4:Prev 5:Next
```

`Target` 是实际请求目标，可能不同于总览页准备选择的颜色。没有请求显示 `Target:None`。只有当前目标新鲜有效时显示坐标；其他状态显示占位符。`Age` 是最近当前目标报文年龄，含 `Valid=0`；历史有效坐标仍可通过控制台诊断。`Ref` 为机械臂参考；`Cal` 对应最近启动的视觉任务，完成后仍保留该任务的标定结果。上电默认查看 ArmVision 标定，物料任务完成后不会误切回另一套标定。

| Vis | 意义 |
| --- | --- |
| Idle | 无请求 |
| Off | 有请求，USB 未配置 |
| Wait | 有请求，尚未收到当前目标有效协议报文 |
| Ok | 最近当前目标报文有效，年龄不超过 1200 ms |
| Lost | 最近报文明确 `Valid=0`，年龄不超过 1200 ms |
| Stale | 最近当前目标报文超过 1200 ms 未更新 |

`Usb:On` 只表示 USB 已配置，不能代替 `Vis`。`Lost/Stale` 为显示和诊断状态，不新增物料任务自动停车。

```text
3/3 Link Test
Usb:On Rx:1234
Vis:Ok Age:120ms
I2c:Ok Err:0
Sum:0 Drop:0
Screen:T12 R3
Err:None
4:Prev 5:Next
```

`Rx` 是 USB 接收字节累计数；`Sum` 是视觉候选帧校验失败数；`Drop` 是接收缓冲区溢出次数；I²C `Err` 是 HWT101 读取错误累计数。

**布局小调整：**串口屏行使用 `T/R`，分别表示 DMA 发送完成数、完整接收帧数。这样两个计数均显示 `9999+` 时仍不超过 21 字符。发送完成不代表屏幕在线。所有大计数和年龄使用 `9999+` 上限标记；完整值通过控制台查看。未启用的雷达不显示在线状态。

## 按键与错误

| 引脚 / 事件 | 总览页 | 其他两页 |
| --- | --- | --- |
| PE2 / KEY_EVENT_PE2 | 检查任务码、忙、参考和标定后启动机械臂对准 | 无业务动作 |
| PE3 / KEY_EVENT_PE3 | 空闲时循环选择第二组项目 | 无业务动作 |
| PE4 / KEY_EVENT_PE4 | 上一页，循环 | 上一页，循环 |
| PE5 / KEY_EVENT_PE5 | 下一页，循环 | 下一页，循环 |

20 ms 消抖，长按只触发一次。主循环只取一次按键事件。任务运行中允许翻页，不能用 PE3 改选项目。翻页不切换摄像头目标，也不改变任务和选色；不增加按键停车功能。

三页共用 `Err` 行，错误不强制跳页。启动拒绝显示简短原因；任务错误保留到明确停止或新的任务成功启动，翻页不清除。

`oled_ui` 每 200 ms 生成显示内容，正常运行只发送改变的行，每圈最多一行。切页将全部行标记待更新，不先清屏。显示初始化失败不阻止其他模块；初始化或运行发送失败后，每秒最多重试一次，成功后继续待刷行。

## 当前控制台命令

USART1 / Zigbee，115200 8N1，ASCII、回车结束。原有轴控制、夹爪、底盘命令及异步提示格式保留，`help` 查看完整列表。

| 命令 | 作用 |
| --- | --- |
| `camera material 3` | 仅请求蓝色识别和坐标跟踪，不启动运动 |
| `vision ref` | 确认已由作者手动到达的机械参考姿态 |
| `vision calib material 3` | Base/X 视觉标定，需要有效参考 |
| `vision material 3` | Base/X 机械臂对准，需要参考和标定；PE2 调用同一任务 |
| `vision calib chassis 3` | 底盘前后 + X 响应标定 |
| `material auto 3` | 底盘参与的物料搜索与对准 |
| `camera status` | 实际请求、目标有效性、年龄、历史坐标、USB 和接收统计 |
| `imu status` | I²C 就绪、缓存角度、新鲜度、读取次数、错误数 |
| `screen status` | 发送完成、完整接收帧、溢出、串口错误、发送忙状态 |
| `vision status` / `material status` | 对应任务与标定状态、错误 |
| `camera stop` | 仅识别请求停止；视觉任务忙时按原规则拒绝 |
| `vision stop` / `material stop` | 按现有命令停止对应视觉流程 |
| `stop all` | 保留原全轴停止入口 |
| `chassis stop` / `wheel stop` | 保留原底盘停止及忙状态限制 |

颜色 1 红、2 黄、3 蓝、4 绿、5 黑、6 浅蓝。旧 `vision calib <1..3>`、`vision ring <1..3>` 对应不支持的 B3，已从正常帮助移除，收到时明确返回 `Unsupported`。USB 未配置、发送忙、发送失败分别报告。

三个新增 `status` 命令只读缓存，不改变任务或发起 I²C/摄像头请求。`config` 修改 RAM 中后续位置命令的参数，复位恢复默认；角度、速度、加速度和脉冲上限单位与旧命令一致。

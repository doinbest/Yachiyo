# 准备跑图与10秒验证

用户已授权添加“准备跑图”，并将日常 IMU 验证缩短为10秒。本轮沿用既有前四段距离任务，不修改电机发送、闭环算法、引脚或工程源文件列表。

## 操作与实现

入口：底盘页最上方“准备跑图”。保持整车静止，连接后点击：

1. `chassis stream off`，暂停长遥测。
2. `chassis task`，要求底盘空闲、总线未锁定、应答模式已确认、位置单位已确认。
3. `chassis route status`，拒绝已有运行/停车/等待继续的路线。
4. `chassis feedback 0`、`chassis feedback on`；等待2秒后读取 `chassis feedback`，检查四轮速度/位置有效且速度不超过1 RPM。
5. `imu status`；本次控制资格有效则跳过验证，否则 `imu verify 10`，等待11.5秒后再次查询，要求新一轮资格通过。
6. 显示人工确认：车体中心在右下 `(2250,150)`、车头朝地图上方、整车静止。确认后才发送 `chassis origin 2250 150 90`。
7. 创建新的遥测会话并开启，地图切到在线反馈来源；只有该会话反馈位置/航向在起点容差内、轮子静止、定位有效且没有活动任务，才显示“准备完成”。

等待单条回复上限12秒，人工确认上限120秒。每次等待先识别本条命令回显，再接受相应回复；IMU多行状态等最后一行后才进入下一步。只读查询检查失败不自动重试。此流程是当前网页的准备操作，不是 MCU 常驻运动任务。

准备期间拦截其他网页命令，停止类命令始终允许并中断准备。取消或断线后不再设原点、不自动续跑；已开始的短时验证可自行结束。不同串口、实物按键仍由固件既有任务互斥及启动条件控制。新按钮从不发送路线启动、下一段、车轮速度、使能或复位。

`route-preparation.mjs` 管理阶段；`app.mjs` 接入共用收发和控件禁用；`map-view.mjs` 复用现有单次挂载及遥测解析，不创建第二个串口或解析器。旧准备结果在遥测失效或起点反馈变化后撤销。

MCU 驱动应答模式/位置单位仍是原有 RAM 配置。重启后未确认时需人工重新配置；本轮没有自动猜参数或新增保存。10秒验证仅测短时静止漂移，原有斜率、RMS、采样间隔及通信异常阈值不变。`imu verify` 默认10秒，显式 `imu verify 10` 新增，`imu verify 120` 保留；原生标定20+30秒不变。

## 用户验收

1. 烧录本轮hex；打开 `http://127.0.0.1:8765/?v=prepare-1#chassis` 并强制刷新。
2. 连接 COM23 / 115200，静止点击“准备跑图”。未确认配置按页面具体提示处理。
3. 需要时自动进行10秒验证；确认实物起点后点击“确认已在起点，继续准备”。
4. 显示准备完成后才点击“开始第1段”；每段仍检查实物再“手动下一段”。准备本身不会启动车轮。
5. 保存失败步骤及完整日志。不要把“准备完成”当作反馈轮径、侧滑误差或视觉对位已经通过实物验收。

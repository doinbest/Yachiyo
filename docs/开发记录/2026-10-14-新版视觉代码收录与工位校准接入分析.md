## 0D报文与当前接收端的关键差别

请求：`FF B2 0D FF`。响应长度、帧头尾、校验规则沿用B2：

```text
FF B2 0D Valid EX_H EX_L EY_H EY_L EA_H EA_L STOP_H STOP_L SUM FE
```

| 字节位置（从0计） | 普通01～06、0A～0C | 新0D |
|---|---|---|
| 4～5 | 无符号CX | 有符号EX，中环X−386，px |
| 6～7 | 无符号CY | 有符号EY，345−中环Y，px |
| 8～9 | 有符号DX | 有符号EA_X100，图像连线角误差×100，° |
| 10～11 | 有符号DY | 有符号STOP，0或1 |

均为大端，SUM为字节1～11之和的低8位，Valid=0时四槽全零。无采集时间、工位号、检测阶段或置信度字段。

`build_three_ring_pose_detection()`按图像X从左至右排列三圆心，以 `atan2(y_right-y_left, x_right-x_left)` 计算角度，参考0°。图像Y向下，因此正角表示右端在图像中较低；这个正负号不能直接当成底盘地图yaw的正负号。显示的R1/R2/R3是左右顺序，不是识别出的赛场编号1/2/3。

STOP仅检查 `abs(angle_error_deg) <= 5`，完全不检查EX/EY。离线例子：中环(406,355)、三环水平时，EX=20、EY=−10、STOP仍为1。因此应在STM32命名为角度窗口标记，绝不能解释成车辆已经停车或整项对准完成。±5°是本文件的视觉默认值，不是实车确认的工位到位精度。

当前 [`Camera.c`](../../Code/template/Hardware/Camera.c) 的 `Camera_DataPublish()`将这四槽固定解释为CX/CY/DX/DY；[`Camera.h`](../../Code/template/Hardware/Camera.h) 只有颜色和编号环启动API。当前不会主动请求0D；即使仅补一个请求入口，直接复用普通快照也会把角度当DX、STOP当DY。`arm_console.c`中的 `ArmConsole_PixelFrame()`也按普通坐标解释报文，诊断解析需要一并区分。

## 推荐接入结构

### 1. 先打通只读姿态观测

在Camera层新增0D请求API及独立姿态快照，明确EX、EY、角度百分之一度、角度窗口标记、Valid、接收时刻和序号。复用USB环形缓存、分包/粘包解析、校验和请求目标匹配；普通坐标快照不得发布0D。控制台增加只观察姿态的独立命令，网页显示加工/暂存工位及姿态误差，打开页面或重连不自动请求。

这一步就能核验两工位能否看全三环、姿态误差符号、帧率和新准心，不必先加入运动控制。具体命令名与API名在实施时确定，本文不宣称它们已经可用。

### 2. 增加工位校准状态机，再接比赛

建议由独立工位校准模块管理0D观测和底盘微调，比赛父任务拥有资源交接。开始运动前让现有路线及GrabTask完成准备并交出控制权，禁止与逐件对准同时抢B2请求、底盘或X轴。Base继续使用原参考+128°，不因三环角度修改Base回零参考。

当前 [`contest_mission.c`](../../Code/template/App/contest_mission.c) 的 `M_DRIVING` 在路线station停稳、WorkReady成立后记录Station/Visit/CenterX/CenterY/WorkYaw，再转 `M_RING_CLEAR`。推荐在这里、首次 `ring_target()` 换位前，为Station=2加工区、Station=3暂存区增加工位校准分支；Station=4原料和二维码流程保持现状。

推荐流程：到站准备完成 → 获取三环稳定观测 → 按已测映射纠正工位角度 → 停车后获取新观测 → 保存本次工位局部参考 → 原逐件换位/对环/取放。初期EX/EY用于观测与定位合理性分析，是否参与工位中心平移由实测像素—车体运动映射确定，不能把像素直接作为mm发送。逐件精定位继续由普通B2 DX/DY完成。

图像连线角是相机投影角，文件未提供相机外参或从角度误差到车体yaw的映射。先用两工位的实测小角度变化确认方向、响应比例及单调性，再设置控制增益/速度。现有 `ChassisMotion_TurnToSpeed()`/速度控制接口可复用，但不能直接套用 `yaw_target = yaw + EA_X100/100`，也不能机械复用只控制平移的视觉J作为转角映射。

在近工位校正底盘角度仍须遵守完整车体投影规则：检查转动包络和进退路径，可转时微调；不可转时沿已验证方向退到可转位置再校正并进站。实测外形和允许纠偏范围尚不能从视觉文件推导。不能仅因角度小就默认白色工作区边缘允许原地转动。

### 3. 必须连同后续换位一起接入

当前 `WorkYaw` 在加工区为180°、暂存区为90°，`local_move()`每次都用它调用 `ChassisMotion_MoveTo()`；`ring_target()`又把加工区X或暂存区Y写成以1200为中心、间隔150 mm的名义地图目标。因此只在入站时转一下小车，后续换位会要求它恢复原角度，位置纠正也可能被名义目标覆盖。

需要保存每次访问的工位局部参考（所在工位/访问轮次、合格时实际车体位置、校正后作业航向、视觉映射适用的观察姿态）。以此推导后续三个环的接驳目标，并让校正后的航向贯穿 `M_RING_MOVE`、逐件操作和退回工位中心。150 mm仍是现有场地间距；工位沿线方向与车体yaw并非同一个量，不能未经映射就一起旋转。离站退到允许转向的位置后再交回原路线。

采用局部工位参考不要求重设整场地图原点或IMU。加工和暂存分别保存，普通暂停、通信恢复保留本次工位参考；真正改变观察姿态或定位资格时仅重建受影响部分。正在运动的绝对目标、待提交目标和阶段随暂停保存，继续时重新核验新鲜停稳/定位证据，不重复追加纠偏量。

### 4. 保留已验证的取放顺序

- 加工放置：工位校准之后，仍先空爪编号环对准并保存实际X/Z，再取仓、持料返回、恢复X、直接下降到z_proc_place释放。不得用三环校准取代本件对环或提前回仓取料。
- 加工取回：沿用 `GrabTask_ProcessedStoreStartEx()`；低位模式−100 mm物料对准后固定水平位置下降至−130 mm闭爪。最终下降不因0D或普通视觉变化再纠偏。
- 暂存/码垛：保留 `GrabTask_HeldPlaceStartEx()`及两批颜色—仓位—目标关系；第一层编号环、第二层物料仍走各自普通B2目标。三环按左右排列不能取代编号/颜色选择。
- raised/lowered继续按本轮锁定值控制逐件对准。三环观察能否共用Z=0或−100 mm须分别验证视野与遮挡；不能自动将固定(386,345)推广为所有高度的已验证准心，也不能顺带改变现有取放高度。

## 接入前要解决的源码行为

1. **运动时可能没有Valid=1。** 三环检测要求置信度至少0.90、连续3帧、三个圆心相对窗口中位数最大抖动不超过1.5 px，否则发送Valid=0。实际移动较快时可能持续不满足该条件。首轮推荐“稳定观测→小幅纠偏→停稳重测”，步幅和速度取实测响应；若需要连续伺服，再区分可用于运动的观测有效与可用于完成判定的稳定，不能把旧误差反复累加。
2. **三环被物料遮挡。** 当前算法要求同时识别三组同心圆。加工摆入物料后、第二批暂存码垛时可能缺环，源码没有遮挡回退模式。已校准且姿态/定位仍合格时应保留局部参考，交给逐件物料对准；离站再进站后的参考适用性单独核验，不应在每件取放或最终下降强制重新等三环。实车须核验第二批有料场景后再定何时复用、何时等待重获。
3. **数字粗定位也返回Valid=1。** `_process_digit_coarse()`在进入精定位前已发布坐标，连着3帧进入±20 px才切精定位，14字节报文不标明phase。现有STM32无法证明收到的是精定位结果；其稳定条件可能在数字粗定位阶段就满足。要保证最终使用环中心，需要让视觉端区分用于接近的粗坐标与用于完成的精坐标，并在协议和MCU完成判定同步表达；不能仅增大固定延时假定已经切换。
4. **重发目标的语义。** 同一0D重复请求不重置三帧窗口，普通颜色/编号环的重复请求仍重新激活。启动新校准应在MCU建立新的请求/停车时间基准，等待之后的合格观测；不要用高频请求清零本地快照，也不要误以为重发0D必然清空视觉历史。跨工位切换目标后的新鲜观测必须与当前阶段匹配。
5. **部署参数不完全兼容。** 新版不接受旧ring-center参数，图形显示仍依赖OpenCV窗口；`--usb-port`仍必填。端口发现虽优先指定路径，但路径不存在时会回退by-id/ttyACM，部署时需核对实际选中的设备。具备USB重连代码不等于已完成本次无线/实机验证，也不要求烧录后重开香橙派程序。

以上是本地源码事实与接入风险分析，不在本次原样收录过程中擅自修改用户算法或加严现有停车条件。

## 建议实施及验收顺序

1. Camera层独立0D快照、只读控制台及诊断分流；测试负EX/EY/角度、零值、Valid=0、损坏校验、分包粘包、目标切换、断线与过期帧，保证旧01～06和0A～0C不回归。
2. 两工位只读实测：空/有料、Z=0/当前低位、视野、角度正负、实际帧间隔、±5°是否达到所需放置精度；核对实机码垛补偿与新启动参数。由此确定姿态校准适用范围和控制映射。
3. 独立工位校准状态机和局部参考；测试短暂漏检、低帧率、USB重连、忙重试、停车后的新反馈、暂停续接/结束，保留原任务及库存，不按恢复次数终止。
4. 接入正式两工位访问和换位/离站；回归两批、遮挡、加工先对环后取仓、第一/第二层、高低位模式及最后下降不依赖视觉。新增C模块时仅同步Keil清单，参数如需新增由grab_parameters.def维护。
5. 实施完成再做对应C测试和Keil构建，按已授权且当前检测合格的DAP链路烧录校验。香橙派源码部署单独处理，最后按独立校准→单工位取放→两批比赛分阶段实车验收。

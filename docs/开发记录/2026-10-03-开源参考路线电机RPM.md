## 生效分支、单位与四轮换算

- `User/zpc_zxc_Parameter.h:12` 的 `//#define Fast` 被注释；`Project.uvprojx:341` 的编译宏只有 `USE_STDPERIPH_DRIVER,STM32F40_41xxx`，未定义 Fast。当前生效的是 `Chassis_Path.c` 中各 `#else` 分支。
- 当前业务在 `CarBody/zpc_zxc.c:39,145,259,325,348` 调用 `Chassis_MoveOncePath`，每个平移子点从零加速、匀速、减速到零；右转子点改调 `Chassis_TurnRight`。二维码到转盘单点在 `zpc_zxc.c:45` 调用 `Chassis_Move`。
- 张大头走 `CarBody/Chassis.c:51–61` → `Hardware/StepMotor.c:287–300` → `StepMotor_ZDTSetSpeed`。速度字段单位为 RPM（`StepMotor.c:147,156–157,282`），这里没有轮径或减速比换算。
- 四轮顺序为 **左前 / 右前 / 左后 / 右后**，电机 ID 是 **1 / 4 / 2 / 3**（`Chassis.c:12–15`）。下表采用带符号 RPM：正值发送 `Dir=0`，负值发送 `Dir=1`，协议速度字段发送绝对值（`StepMotor.c:289–298`）。
- `CarBody/Mecanum.c:110–118` 的半径、19倍减速与米每秒转换属于 **M3508 CAN 电机** 控制链；其 `Mecanum_ControlSpeed` 在第95行调用 `M3508_CANSetLIDCurrent`，不参与这里的张大头路径计算。

设路径平移要求为 `(vx,vy)`，姿态偏差为 `θ=HWT101_Yaw−本段起始角`，角度 PID 输出为 `w`。实际发送要求为（源码浮点转整数，截去小数）：

```text
vx' = vx*cosθ + vy*sinθ
vy' = -vx*sinθ + vy*cosθ
左前 RPM = int(vx' + vy' - w)
右前 RPM = int(vx' - vy' - w)
左后 RPM = int(-vx' + vy' - w)
右后 RPM = int(-vx' - vy' - w)
```

坐标旋转与角度修正在 `Chassis.c:72–80`；角度 PID 输出限幅 `[-200,+200]`（`Chassis_PID.c:21–30`，`Control/PID.c:144–147`）。**下表是姿态正确、没有角度修正时的名义 RPM（θ=0,w=0）。** 直线运行若有偏航，四轮会按上式变化，不能把表值当作每时刻固定转速。

## 读取表格时需要区分的行为

- 当前路线平移名义最高是 **260 RPM**（回家第3点）；二维码到转盘不是四轮统一200 RPM，而是215/185 RPM两组；转盘到粗加工长段是255/245 RPM两组。
- 原地右转由 `Chassis.c:282–294` 令目标角减90°，按当前角度误差运行，四轮同为 `-w`；因此不是固定200 RPM。角度误差大时可以达到200，随后减小，达到误差死区并连续两次误差为零时结束。
- 所有平移子点都有软件正弦加减速：`s(i)=0.5−0.5*cos(π*i/K)`，加速平移要求为 `s(i)*(vx,vy)`，减速为 `(1−s(i))*(vx,vy)`；`i=0..K−1`（`Chassis.c:94–100,141–151`）。表中RPM是目标平台，不代表加减速段始终用该值。
- 转盘→粗加工第4点 `t=0` **仍执行加速和减速，各约200ms**；只是没有匀速平台。减速循环第一个样本使用完整目标速度，不能解释成该点被跳过。
- 每个平移子点随后还有约100ms角度稳定动作，平移设为零但角度PID仍工作（`Chassis.c:109–121,153–154`）。驱动发送的 `Acc=0`（`StepMotor.c:357,364,371,378`）表示驱动层不额外加减速；上层的软件曲线仍生效。
- 颜色变体只改变表中对应的匀速时间；当前这些变体的 vx/vy 和名义RPM相同。未启用的 Fast 分支及其连续过渡速度不混入当前结果。

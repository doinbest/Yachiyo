# 独立编号环取仓先抬Z再转Base

## 已确认范围

用户要求下降夹取后先上升再转，X回缩可与Z同时执行；经确认，仅调整车仓→编号环的独立`grab ring run / take`，正式比赛与反向`grab ring store`不改。

此方向夹取发生在车仓中，仓1/2取料后的X动作是伸出30 mm避让，不能改成回缩。本次保留该动作与Z抬升并行；X回缩并行应用于对环后、空爪回车仓准备取料的阶段。

## 新顺序

1. 对准并保存编号环位置后，空爪Z抬回本次高位、X收回并行；两轴均以原新鲜反馈确认到位后，才转Base到车仓，ID8仍按原条件提前选仓并在进仓前汇合。
2. 下降取仓、闭爪并保留原夹爪等待。
3. Z抬回本次高位；仓1/2同时将X伸至原30 mm避让位置，仓3保持收回。Z与X均实际到位后，Base才持料回工位方向。首件ID8正90°避让及外部下降前到位检查保留。
4. 恢复保存的X，下降放置、松爪并抬回高位；沿原独立流程完成。

## 实现

新增C层`GrabTask_RingCarPickStart`，由父任务独立编号环`RingOnly`分支调用，旧短命令的NAN仓深使用原配置默认值，显式高度继续沿原绝对目标锁定。新任务记录`CarPickLiftFirst`，暂停继续保留该策略和已接受的深度；原普通取仓与正式比赛入口仍采用原并行回转策略。

独立空爪`GRAB_RETRACT`阶段同时受理Z高位与X回缩目标，双到位后移交原后续阶段，并保留X已取得的到位证据。持料`GRAB_LIFT`在新策略下须Z高位和X避让均到位，才允许Base回转；正式比赛仓1/2仍可在X避让到位、Z继续上升时转Base。

只修改GrabTask、头文件及contest_mission的对应分流、必要测试替身和现行文档；不新增串口参数、不改默认高度/速度、机械零点、夹爪脉宽、库存记账或Keil源清单。

## 验证

先在真实GrabTask与比赛父任务集成测试中冻结夹取后的Z，复现旧代码在Z尚低时提前转Base的断言失败，再实现修改。

AGENTS、比赛约定、机械臂协议、视觉任务手册、主车README和开发索引已同步独立流程例外；正式比赛与反向入仓约定保留。按现行交付流程，本轮不提前开展独立代码审查。

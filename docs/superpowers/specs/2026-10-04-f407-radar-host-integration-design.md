# F407 雷达建图上位机第二阶段设计

日期：2026-10-04  
状态：已完成对话设计确认，待用户审阅本文后编写实施计划

## 1. 目标

把当前“地图与遥测 → 雷达建图”页面的数据源从电脑 USB-UART 直连 LDS50C，切换为：

```text
LDS50C -> F407 USART2 -> F407 建图与规划 -> F407 USART1 / DL-20 -> 网页上位机
```

F407 负责雷达帧解析、完整圈冻结、点筛选、5×5 障碍地图和路径规划。网页保留现有雷达页面的信息结构、操作方式、地图交互、诊断和导出能力，不再直接打开雷达串口。

建图和规划行为以 `Code/reference/Radar_2026-10-01/Radar` 的 F1 实现为基准。已确认的关键值为雷达位置 `(230,230) mm`、障碍阈值默认 `1`，并保护起点格 R1C1。

## 2. 范围边界

### 2.1 本次包含

- F407 USART2 以 921600/8N1、DMA 循环接收 LDS50C 数据。
- F407 组装完整扫描圈，保存最近一圈原始点云并处理短暂坏帧、单位变化和 DMA 覆盖。
- F407 按 F1 坐标、筛选、分区、障碍和四邻域 A* 规则计算地图与路径。
- F407 通过 USART1 115200/8N1 输出紧凑状态、地图、路径、实时预览和按需完整点云。
- “雷达建图”页面复用主车共享串口连接，不再拥有独立雷达 COM 口。
- 页面保留启动、停止、单圈扫描、持续扫描、原始/筛选点切换、筛选、分区、手工障碍、编号任务、点到点规划、诊断、主题、本机配置和 CSV 导出。
- 筛选或地图参数修改后，F407 使用已冻结完整圈重新计算，不要求重新扫描。
- 更新当前协议、上位机说明、开发记录和相关测试。

### 2.2 明确不包含

- 不修改“实车监控”页面的布局、遥测来源、车辆轨迹、按钮、命令或状态语义。
- 不修改“离线对照”页面及其当前路线模拟。
- 不把本轮 F1 页面规划结果用于底盘自动运动，不修改 `radar nav start`、固定路线或赛事任务执行。
- 不修改机械臂、视觉、二维码、串口屏、转盘、IMU、底盘及其页面。
- 不修改 USART1 的 115200 波特率、32 字节发送分块和现有回复优先级。
- 不修改 USART2 引脚、DMA、时钟或 IOC，不运行 CubeMX 重新生成。
- 不增加 Flash 参数持久化；F407 雷达页面参数复位后恢复固件默认值，浏览器本机偏好仍需显式保存。
- 不维护或构建 EIDE；本轮固件清单和验证以 Keil 工程为准。

## 3. 功能基准

F1 基准位于：

`Code/reference/Radar_2026-10-01/Radar`

默认规则如下：

| 项目 | 值 |
|---|---|
| 雷达位置 | `(230,230) mm` |
| 雷达角度 | 正前方 0°，顺时针增加 |
| 场地投影 | `X=230+d*sin(a)`，`Y=230+d*cos(a)` |
| 角度筛选 | 0°～360°，支持跨零范围 |
| 距离筛选 | 100～40000 mm |
| 能量筛选 | 0～255 |
| X/Y 分界 | 150、550、1000、1400、1850、2250 mm |
| 障碍阈值 | 1 点 |
| 固定禁区 | R2C2、R2C4、R4C2、R4C4，即 `0x00050140` |
| 保护格 | R1C1、R3C1、R5C3、R3C5、R1C3 |
| 任务顺序 | 1-5-4-2-3-4-2-3-1 |
| 寻路 | 5×5 四邻域 A*，按 F1 的邻居顺序和相同代价时选择规则 |
| 空地图默认结果 | 33 个展开路径点，首尾均为 `(230,230)` |

网页第一阶段源码里障碍阈值 `3`、保护格缺少 R1C1 的差异在本轮修正，以本表和 F1 源码为准。

## 4. 总体架构

### 4.1 单串口所有权

第二阶段不再由 `RadarDirectBridge` 打开第二个串口。网页只使用现有 `SerialBridge` 连接 F407 USART1：

- 左侧全局连接和雷达页连接区显示同一个端口、同一个 115200 波特率和同一个连接状态。
- 雷达页“连接/断开/刷新”调用现有共享连接入口，不新建串口对象。
- 雷达页断开共享连接时，其效果与左侧全局断开一致；页面文案必须明确这是主控连接。
- 打开页面、切换页签、刷新端口和恢复网页均不自动连接、启动雷达或扫描。
- 第一阶段 `/api/radar-direct/` 后端和源码暂不删除，但新的雷达页面不再调用它们。

### 4.2 F407 处理链

```text
USART2 循环 DMA
  -> 现有 LDS 帧解析器
  -> 完整圈组装和冻结
  -> F1 兼容筛选与极坐标投影
  -> 25 格计数、扫描/固定/手工障碍合并
  -> F1 兼容四邻域 A* 与路径诊断
  -> 结果版本化
  -> USART1 高优先级状态/地图/路径
  -> 低优先级预览或完整点云分页
```

F1 兼容规划通过扩展当前 `radar_map` 核心实现，不在网页或固件中另写一套不同的 A*。原有实车雷达导航入口继续使用现有行为，本轮新增的页面配置和规划结果不自动进入运动模块。

### 4.3 页面数据适配

保留当前 `radar-direct-view.mjs` 的 DOM 结构、画布和交互，在其下替换数据客户端：

- 第一阶段客户端：HTTP `/api/radar-direct/` + 电脑雷达串口。
- 第二阶段客户端：共享 `BridgeLink` + F407 文本命令 + `@RADAR` 数据帧。

第二阶段页面只消费带 `profile:"f1_host"` 的雷达帧；旧 F407 雷达快照仍由原模型消费，避免把页面专用结果注入“实车监控”。

## 5. F407 地图与规划模型

### 5.1 配置与生效

F407 维护“活动配置”和“草稿配置”：

- 网页逐项发送筛选、雷达位置、八条内部分界、阈值、手工障碍、规划模式、任务顺序和点到点端点到草稿。
- `apply` 对完整草稿统一校验；全部合法后一次性替换活动配置并增加配置版本。
- 任一字段非法或传输中断时，活动配置和当前地图保持不变，网页明确显示失败字段。
- 有冻结完整圈时，应用配置立即重建地图和路径；没有完整圈时只保存 RAM 配置并显示“等待扫描”。
- “应用筛选（不重新扫描）”和“应用场地与规划参数”均不得启动雷达或底盘。

### 5.2 完整圈

- F407 只发布完整扫描圈，不把未完成半圈用于障碍和规划。
- 普通单圈扫描在 10 秒窗口内允许坏帧、单位变化和 DMA 覆盖后重新收当前圈，不设置固定恢复次数。
- 成功、超时或用户停止后均请求 `LSTOPH`；发送完成与雷达物理停止分别记录。
- 新扫描失败时保留上一份完整地图、路径和点云，并标记为历史结果。
- 仅保留一个完整原始圈缓存，重新筛选和分区复用该缓存，不再复制第二份完整点云。

### 5.3 障碍与路径

- 25 格点数始终按 R1C1 到 R5C5 排列。
- 达到阈值的普通格进入扫描障碍；固定禁区始终阻塞。
- R1C1 及任务点 2～5 所在格保留点数，但扫描障碍和手工障碍不得阻塞这些格。
- 手工障碍只改变活动地图，不删除扫描计数。
- 编号任务路线和点到点路线都在 F407 计算；网页显示 F407 回传结果，不自行生成另一条权威路径。
- 路径结果包含展开格、物理坐标、下一段距离、方向、转向和不可达任务段。

## 6. USART1 协议与带宽

### 6.1 命令命名空间

新增页面专用 `radar host ...` 命令，避免改变旧 `radar scan`、`radar live` 和实车导航语义。至少包含：

- `radar host status|get`
- `radar host start|stop|scan`
- `radar host live start|stop|status`
- `radar host draft reset`
- `radar host set filter ...`
- `radar host set field ...`
- `radar host set manual ...`
- `radar host set mission ...`
- `radar host set endpoints ...`
- `radar host apply <draft_rev>`
- `radar host fetch map|path|preview|cloud <id> <page>`

确切字段顺序、范围和每行长度在实施计划中以控制台现有限制和自动化测试固定。查询、分页读取和状态属于只读命令；启动、扫描、停止、配置应用继续使用现有控制台互锁和停止语义。

### 6.2 数据帧

继续使用一行一个 `@RADAR <JSON>`，新增 `profile:"f1_host"` 和页面专用 `k` 类型。每帧包含会话、配置、扫描、地图和路径版本，分页包含 `page/pages/offset/total`。

页面先接收：

1. 扫描/解析状态与累计计数；
2. 25 格点数、障碍掩码和配置版本；
3. 路径和诊断；
4. 点云预览或完整点云。

地图和路径不得等待完整点云下载完成。

### 6.3 点云传输

- 单圈扫描完成后先显示 F407 地图和路径，再在后台读取同圈完整点云。
- 完整点云每点按角度 0.1° `uint16`、距离 mm `uint16`、能量 `uint8` 打包后 Base64 分页，减少 JSON 数组开销；完整结果带点数和 CRC32。
- 下载完成前，页面显示 F407 返回的原始总点数、筛选点数和轻量预览；CSV 按钮等待完整同圈点云。
- 持续扫描只发送最新完整圈的 120 分区预览、格计数和路径，不排队传输过时完整圈。
- 用户显式请求当前完整圈时暂停旧点云下载并读取最新冻结圈；取消只取消低优先级下载，不停止扫描或清除地图。
- 现有普通回复、停止回复和控制台状态优先级高于点云分页；保持 32 字节/30 ms 无线发送节奏。

## 7. 页面行为

### 7.1 连接与扫描

- 雷达页串口选择展示全局主控端口，波特率固定显示 115200。
- 雷达页连接按钮复用全局连接；连接成功只表示 USART1 已连接，不预先宣称 USART2 雷达正常。
- “启动旋转”“停止”“单次扫描”“持续扫描”分别发送页面专用 F407 命令。
- 页面离开或切到“实车监控”不自动停止雷达；用户必须显式停止，状态在返回页面后继续恢复显示。

### 7.2 地图、筛选与配置

- 雷达中心默认显示 `(230,230)`。
- 默认障碍阈值显示 `1`。
- R1C1 显示为任务保护格，不能通过点击设置为手工障碍。
- 其他筛选、分区线拖动、任务顺序和点到点端点交互保持第一阶段页面行为。
- 应用设置时页面显示草稿发送、设备校验、重建及结果下载进度；只有读回配置版本和结果身份匹配才标记成功。
- 浏览器本机保存的是页面草稿和主题，不代表 F407 已应用；重连后必须读回设备活动配置再区分“设备值”和“本机草稿”。

### 7.3 历史与错误

- USART1 断线、F407 重启或会话变化时保留已完成地图、路径和点云，并标为历史。
- 新页缺失、CRC 错误、ID 变化或超时不得发布部分点云，也不得替换完整地图。
- 雷达没有状态回复、USART2 没有有效帧、扫描超时、路径不可达和点云下载失败分别显示具体原因。
- 点云传输失败不把已经完成的地图和路径改成失败。

## 8. 不影响实车监控的隔离措施

- `#map/monitor` 继续挂载当前 `radar-view.mjs`、车辆遥测和轨迹模型，不改 DOM、命令和数据选择。
- 页面专用 `profile:"f1_host"` 帧不写入旧 `RadarModel.snapshots`。
- 页面专用路径不写入 `mapView` 的设备导航路径，也不触发 `radar nav start` 或 `radar task start`。
- `app.mjs` 只增加第二阶段客户端的接收、连接状态和共享端口适配钩子；现有 monitor/offline 页签切换保持不变。
- 第一阶段直连服务继续留在代码中但不由当前雷达页调用，避免顺带删除和重构后端。

## 10. 实物验收顺序

1. 保持底盘和机构静止，只连接 F407 USART1，读取 `radar host status`。
2. 给 LDS50C 独立稳定 5 V 供电，与 F407 共地，按 3.3 V UART 电平连接 USART2。
3. 验证 F407 能发送配置命令并收到合法测量帧；发送完成和雷达回复分别判断。
4. 单次扫描，核对原始点数、筛选点数、25 格计数、障碍掩码和 33 点空场路径基线。
5. 改变筛选条件并在不重新扫描时重算，确认扫描编号不变、配置/地图版本更新。
6. 验证地图和路径先于完整点云出现，点云下载期间停止指令和其他控制台功能仍能响应。
7. 验证持续扫描只保留最新预览，不累积无线积压。
8. 切换到实车监控，确认没有自动运动、没有使用页面专用路径覆盖车辆路线。

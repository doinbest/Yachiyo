# 比赛视觉矫正分支修改计划

> 实施方式：在当前项目中按下述依赖顺序执行并验证，保留现有未提交修改。本文的软件分支已实施并通过回归、Keil构建及DAP下载校验；用户确认尚未标定，当前开启后只观测。详细结果见[实施记录](../../开发记录/2026-10-14-比赛视觉航向分支实现与验证.md)。下方勾选项保留原验收清单，不代表已逐项实车验收；视觉绝对角映射须由对应观察姿态的实测证据确定，不猜测常数。

**目标：** 比赛任务增加独立“视觉航向矫正”选项，默认关闭；开启后在原比赛到站/换环边界使用固定场地环列修正IMU到地图的角度映射，后续路线继承，既有两批取放顺序保持。

**架构：** Camera独立发布姿态结果；工位航向模块负责观测、提交与必要纠偏；比赛调度负责插入时机、所有权和暂停恢复。网页只提交本轮选项和展示状态。

**技术：** STM32F407 HAL/C、现有USB CDC B2/0D姿态报文、Python/OpenCV视觉、现有原生JavaScript网页；仅同步Keil。

**设计依据：** [色环参照校正地图航向方案](../specs/2026-10-14-色环参照校正地图航向方案.md)。

## 必须贯穿各步骤的约束

- 摄像头随Base/X/Z运动。复用既有Base参考+128°作业准备，等完整姿态到位静止，不在并行转Base期间采集用于修正的观测。
- 用户IMU测角准确。修正全局角度映射，不复位IMU，不改底盘/电机极性，不把地图目标旋转成视觉偏角。
- 网页默认关闭。新比赛成功受理才锁定本轮开关；网页草稿、刷新和重连不改变在途配置。
- 关闭时不发送新姿态请求、不增加校正运动和等待；旧命令省略开关等效关闭。
- 开关独立于起点、雷达、执行码来源、raised/lowered；两批、加工放/取、暂存/码垛均遵循同一采用值。
- 沿用现有B2/0D，不新增协议版本或任务码。STOP字段保留接收和校验，仅供可选诊断，不参与运动、稳定计数、完成或失败判定；STOP=0也不能否决已满足的完成条件。
- 纠偏目标是标定后的0°，不是±5°边缘。STM32独立按实测精度设置完成容差，并核验新鲜观测与真实停车；不将视觉±5°作为默认完成容差。
- 保留扫码、原料追踪、ID8提前分度、2120 μs取料、1秒等待、X避让和所有取放高度。暂停保留；停止本轮撤销待提交校正。
- 两份现存视觉代码在正式确定活动入口前保留，Python本地更新、远端部署、STM32烧录与实车验收分别报告。

## 1. 与当前两批比赛逐阶段对齐

| 原阶段 | 开关关闭 | 开关开启的插入位置 |
|---|---|---|
| 起点准备→可选雷达→扫码→原料台 | 原样 | 原样；不拿动态原料/二维码冒充固定环列参照 |
| 原料三件追踪入仓→末件行驶姿态 | 原样 | 原样；不延误提前ID8分度/末件策略 |
| 加工区进站，车体180°、Base+128° | 原样进入换环 | 等路线停车、完整work_ready后先安排到站观测；已有姿态直接复用 |
| 加工每件放置：换环→空爪对环 | 原样 | M_RING_MOVE停车且work_ready完成之后、M_TRANSFER_REQUEST之前做本次核验；结束后恢复普通0A～0C目标 |
| 空爪对环→保存X/Z→回仓取料→恢复X→下降释放 | 原样 | 原样；保存本件位置后不插入转車或改变参考的动作 |
| 加工三件放完，逐件识别取回入仓 | 原样 | 每次换位后、ProcessedStoreStartEx之前核验；之后保留2120 μs及原对准/最终下降流程 |
| 第一批暂存：换环→取仓→持料对环→释放 | 原样 | 换环且空夹准备完成后、CarPickStart之前核验；持料后不调用会开爪的准备姿态 |
| 第二批码垛：按第一批同色位置换位→取仓→物料对准→释放 | 原样 | 同上；场地环列被遮挡则沿用可信映射，不将下层物料方向当场地基准 |
| 工位退回中心→离站→最终返回所选起点 | 原样 | 使用已校正的全局映射，仍按既有名义地图角和接驳点行驶 |

推荐新增父状态为“工位航向核验”，前后分别保存来源阶段和续接阶段。一次中心到站恰好也是目标中环且没有发生新运动时，可复用同次合格观测；如果发生换位，则是新的核验机会。避免同一停稳点无意义重复等待。

工位核验只在父任务拥有底盘且GrabTask完成准备后运行，不嵌入已进行的抓取状态机。已有角度/定位仍合格而暂缺三环时，状态明确报告沿用；不因新测试分支无条件阻塞原本能完成的取放。

## 2. 先验证观测与映射，保留来源文件

涉及：`Code/orange_pi/combined_color_digit_ring.py`、新增对应离线测试、`Code/template/Hardware/Camera.c/.h`、`Code/template/App/arm_console.c`。

- [ ] 给现0D独立姿态结构与观察入口，按signed EX/EY/EA_X100/STOP解析；STOP只存诊断值，不能落入普通DX/DY快照和像素日志。
- [ ] 离线测试先覆盖14字节校验、负角/零值、Valid=0时零字段不算对正、普通帧不变、切目标/粘包/重复读取；再完成解析。相同有效观测只改变STOP并重算校验时，控制输出、稳定计数和完成结果必须一致。
- [ ] 两工位实测候选观察姿态是否看全三环，确认Base实际静止后角度表现，重点验证±0.5°；记录图像零角与场地标准方向的对应关系、符号、比例及精度。
- [ ] 依据实测在STM32建立适用观察姿态的局部角度映射，内部显式区分原始图像角与真实车体偏角；保留线上EA含义。未完成映射时只报告观测，不发布“地图已校正”。若现有观测量不足以达到精度，记录实测结果后另行调整算法，不把扩展协议作为本次接入前提。

线上协议固定如下，偏移从0计：

| 方向 | 字节布局 |
|---|---|
| STM32请求 | `FF B2 0D FF`，4字节 |
| 视觉回复 | `FF B2 0D Valid EX_H EX_L EY_H EY_L EA_H EA_L STOP_H STOP_L SUM FE`，14字节 |
| 数据与校验 | EX/EY/EA/STOP均为大端int16；EX/EY为像素，EA为图像角×100；SUM为字节1～11累加取低8位，包含STOP |

工位、姿态标定标识、本地请求批次、接收序号/时间和转换后的车体偏角均由STM32内部管理，不要求视觉端新增字段。EX/EY不直接作为毫米位移或航向完成条件；原01～06及0A～0C继续按原坐标语义解析。

现协议没有请求回显、图像序号或拍摄时间；本地接收序号只能避免重复消费快照，不能证明图像唯一或排除所有滞留帧。切换目标时清理本地旧快照及残留接收数据；运动、暂停或恢复后重新建立静止观测窗口，按实测链路延迟收集后续有效报文。重复发送0D不会重置视觉端稳定窗口，不将重发当作强制重新拍摄。通过延迟/粘包回放验证适用范围，不能声称具备线上协议未提供的严格新鲜性保证。

## 重点审查项

1. 界面真的关闭时是否完全保持旧流程，而不是后台仍请求0D或增加等待。
2. 摄像头随Base运动时的图像角是否被错误写为全车yaw；是否等完整姿态到位。
3. STOP是否仍通过任何间接路径参与运动、稳定计数或完成；忽略该字段后是否仍保持Valid、校验和真实停车要求，以及零偏角目标。
4. 校正是否改变了起点/XY、重复累计误差，或者在离站时被旧控制缓存覆盖。
5. 新状态是否破坏加工“先空爪对环再取仓”和最终下降不依赖视觉，以及第二批有料遮挡后的可完成性。

本计划仍需现场观测确定真实角度映射；这属于功能测量输入，不能用猜测常数补全。网页与固件已接通该开关，实车角度标定与完整比赛验收仍待完成。


## 独立单次试转的范围

在保留比赛未标定观测模式的基础上，增加显式“按视觉角单次试转”。三环最外两中心连线对水平轴的当前角度EA乘所选方向（默认−1，可选+1）作为一次相对转角；先观测、一次IMU转向、停车确认、再观测。不自动重设地图角或写标定，不连续追转。默认反号依据已提供的加工区单次试转结果；前后图像角继续用于验证，正式标定另行确认。操作与协议见现行视觉任务手册、机械臂与取放协议。

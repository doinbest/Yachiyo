# 统一比赛任务代码修改计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.
> 用户后续已授权执行：由当前会话连续实现，保留已有未提交修改，不自动提交或操作实车；按executing-plans执行最终独立审查。

**Goal:** 通过一个正式入口连续完成真实扫码及显示、两种任务码执行依据、两批原料入仓/加工/暂存码垛与返回，并能按当前阶段停止续接。

**Architecture:** 扩展现有ContestMission、ChassisRoute、GrabTask及串口屏，不另造总控框架。任务码来源、实际扫码与执行数据分离，父任务直接调用C动作接口；网页只发开始/查询/停止/继续，持料对准和释放在固件状态机内衔接。

**Tech Stack:** STM32 HAL裸机主循环、C99主机模拟、Keil Target template、原生网页ES modules、Python本地串口服务。

**Spec:** [统一比赛任务流程设计](../specs/2026-10-12-统一比赛任务流程设计.md)。以AGENTS及用户2026-10-12答复为约束；实施状态见文末与开发记录；新增API及命令已实现。

## Global Constraints

- 右下(2250,150)、yaw−180°；保持朝向斜移至(2100,300)，再顺时针转90°。扫码后保留真实位置/yaw，不重新设置起点或重跑首段。
- 两种来源都真实前往扫码；串口屏只显示本轮实际码。固定执行码不写QR共享模拟缓存，不显示在串口屏；无真实码不冒充成功。
- 车仓入/出均X保持x_min；删除x_car参数、校验、默认恢复和网页字段，保留外侧视觉X运动。ID8先分度到位，再Base回后向参考。
- Base作业为后向参考+128°；空夹准备可OPEN=2500 µs，持料期间不得OPEN；CATCH=1920 µs。取出默认40 mm下/上、等待1秒；现有close_ms仍保留。
- 控制参数不借集成重新调节：反馈追踪当前160/60 mm/s、lambda2、X前瞻60 ms；夹取±100 px/最小10 ms、下降启动±50 px、原料Z−50 mm。实际运行参数读回与预设分开。
- 两批：每批粗加工全部三件放完再取回；第二批暂存目标按第一批同色位置。缺项只在相应阶段等待，实际高度不得猜测。
- 保留单项测试、普通停车上下文、现有真实机械边界及故障停车。EIDE、F103、GPIO/时钟/HAL和官方驱动不改；main.c只改相关USER CODE逻辑。
- 执行前再次检查Git差异。当前另有雷达盘舵机、Core/tim、IOC、Keil清单和网页改动，不能回滚、覆盖或把它们算成本计划的修改成果。

## Review Focus

1. 真实扫码与固定码不同：固定顺序执行，串口屏实际码；重复码不清进度、不换执行码（Task3）。
2. 扫码后车头是扫码姿态而非出发姿态：从当前站连续接原料路线，不重设原点、重走第一段（Task2）。
3. 已持料进入色环/码垛对准：全过程只在最终放置阶段开爪（Task5）。
4. 松爪命令已发但停在抬起/记账之前：继续只补未完成阶段，不重复投料或计数（Task6）。
5. 全局停车、断线及后续工位高度未配置：保留码/批次/当前件，读回/补齐后显式继续，不自动重跑（Task6/7）。

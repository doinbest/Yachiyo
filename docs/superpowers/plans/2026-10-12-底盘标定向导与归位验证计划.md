# 底盘标定向导与归位验证 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在现有上位机“底盘”页提供直行、横移、转向标定向导，让用户通过按钮测试和实测输入完成参数计算、应用、读回与复测，并使右下返回路线恢复起始180°航向。


### 3. 操作与测量

#### 3.1 准备

1. 在与比赛相同的地面和载荷条件下，选择有足够空间的位置；不在300×300 mm蓝格中直接启动长距离测试。
2. 用四轮轮心矩形的中心作为底盘测量点，在车体上选定可重复定位的对应点。不要用轮胎边缘、机械臂或LCD边缘代替中心。
3. 用地面参照线记录起始中心和车头方向。每次测量均取该次开始至结束的变化。
4. 点击“读取设备参数并准备”：读回当前系数，复用有效IMU资格，显式准备四轮反馈，等待已有停车证据。已有有效原点可复用。
5. 无有效原点时，显示“建立局部测试坐标”按钮；用户点击后将当前静止位置定义为(0,0,0°)，不移动、不开雷达、不改驱动器零点。正式跑图前仍使用正式“准备跑图”流程重新确认实物起点。
6. 测试按钮按车体“前进/后退/左移/右移”标记。旁边画地图位移箭头；180°时前进对应地图-X，左移对应地图-Y。

#### 3.2 平移测试

| 阶段 | 距离 | 速度 | 次数及用途 |
|---|---:|---:|---|
| 初始采样 | 300 mm | 50 mm/s | 前/后/左/右各3次；用于拟合 |
| 长距离复测 | 600或1000 mm | 50 mm/s | 四方向各3次；检查尺度误差 |
| 比赛工况复测 | 1000 mm或现场可用长度 | 200、300 mm/s | 沿已验证方向单项启动，观察速度和载荷影响 |

新标定入口支持10～1000 mm的单轴有符号位移、10～300 mm/s。1000 mm取自第一版1米验收需求，不扩大其他普通调试入口的原有范围。

每次保持起始车头方向，移动完成后等待当前停稳链确认。用户填“实际沿测试方向距离”和“垂直方向偏移”。方向选择由界面转换为起始车体系下的有符号 `actual_dx_mm / actual_dy_mm`，不要求用户自行换算地图坐标。

可手工摆回，也可点击独立的反向测试；两种情况都重新记录该次起点。页面不自动往返，不把“回到估计起点”当作物理回到了同一位置。

#### 3.3 转向测试

- 原地顺/逆时针90°、180°，初始限速30°/s；后续可选择最高100°/s验证。
- 正值为逆时针、负值为顺时针；180°也须按所选方向执行，不能因最短角差的符号规则走反方向。
- 用地面方向参照、角尺或可量化的俯视图测实际角度；不能把网页IMU角度作为独立实测输入。
- 同时测中心前后/左右偏移，记录IMU展开角变化、轮子累计理论转角和实际转角。
- 转向结束后的中心偏移只展示诊断，不自动以XY纠偏动作抹掉，否则无法看出原地旋转漂移。
- 第一版角度输入为相对起始方向的有符号转角，避免±180°跨界读数被当成一圈以上的误差。

### 4. 参数语义与计算

#### 4.1 三个校正系数

新增 `ChassisModel_Calibration_t`：

```c
typedef struct {
  float forward_scale;
  float lateral_scale;
  float rotation_scale;
} ChassisModel_Calibration_t;
```

默认值全部1.0。基准 `L/W/D/G`仍来自 `chassis_config.h`，第一版不通过网页改这些物理定义，也不修改电机方向或3200/65536常量。

设基准正解为 `v0=(vx0,vy0,w0)`，校正后正解：

```text
vx = forward_scale × vx0
vy = lateral_scale × vy0
w  = rotation_scale × w0
```

逆解先将期望速度或车体位移分别除以对应系数，再交给原X型麦轮分解。四轮共同限幅、整数RPM量化及其顺序保留。统一处理连续速度、保航向、距离控制、旧毫米位移和轮反馈速度；单轮RPM诊断、机械臂ID5～8不乘底盘校正。

原 `ChassisModel_Forward/Inverse/WheelLinearInverse`保留恒等校正语义供纯模型测试和标定原始量使用；实际控制调用新增的 `...Calibrated`接口。禁止只有网页、定位或某个速度入口单独使用校正。

#### 4.2 未补偿累计量

四轮顺序FL/RL/RR/FR，符号沿当前前向宏归一。每轮基准轮缘位移：

```text
di = π × D / G × Δposition_i / 65536
sx = Σ(dFL + dRL + dRR + dFR) / 4
sy = Σ(-dFL + dRL - dRR + dFR) / 4
wheel_angle_rad = Σ(-dFL - dRL + dRR + dFR) / (4 × ((L+W)/2))
```

这里的Σ表示按新鲜完整轮组累计。差值先提升到64位再计算，避免有符号整数减法溢出。同步保存每轮起止反馈和时间戳，识别复位/位置参考改变导致的不可比较样本。

平移用于拟合的实验保持起始航向；保存全程最大航向偏差。最大偏差超过现有2°到角容差的平移样本保留为诊断，默认不选入比例拟合：1米上2°方向变化已可能产生约35 mm侧偏。该条件只影响平移样本推荐，不新增运行中的停车条件，不用于筛除90°/180°转向样本。

#### 4.3 拟合

对用户选择的完整、方向一致、同一基准几何及地面/载荷/速度组的样本，按过原点最小二乘计算：

```text
forward_scale  = Σ(sx × actual_dx_mm) / Σ(sx²)       // 前进、后退样本
lateral_scale  = Σ(sy × actual_dy_mm) / Σ(sy²)       // 左移、右移样本
rotation_scale = Σ(wheel_angle_deg × actual_angle_deg) / Σ(wheel_angle_deg²)
```

- 系数是相对于未补偿基准的绝对值，不是旧系数上的再次乘法。原系数0.9、基准累计300 mm、实际285 mm时，建议仍为0.95，不是0.855。
- 默认每个方向3次；不足时可查看单次诊断和草稿，不显示“完整标定已验证”。缺少某轴样本时保留当前该轴参数，明确标注“本次未标定”。
- 显示各方向均值、标准差、最大侧偏及拟合残差。不同条件分组，不强行平均前后方向或不同地面之间的明显差异。
- 记录手工排除及原因；不自动删除异常数据。实际运动反向导致负拟合系数时提示检查方向/测量，不生成可应用的正比例模型。
- 非有限值、零分母、非正系数和不能形成有限逆解的值拒绝为建议参数；用户输入的零移动仍可保存为诊断，不能覆盖旧有效方案。
- 旋转系数修正轮模型和转向前馈。反馈航向仍由IMU给出，不把旋转系数乘入HWT101角度。
- 另列 `IMU展开角变化－实际角度`。IMU显示90°而实际86°属于角度测量问题，不能仅靠轮模型系数宣布修复。

### 5. STM32测试所有权与结果

新增标定模块复用 `ChassisMotion_MoveTo`及新受限相对转向入口，不另建电机发送链。

设备状态：`idle → preparing → running → stopping → complete`；取消/故障保留 `cancelled/error`原因与部分证据。网页状态另有 `waiting_measurement / ready_to_fit / ready_to_apply / validating`，不占用设备运动所有权。

- `preparing`只由显式测试请求进入：等待新鲜四轮位置/速度及合格IMU并记录起点。等待预算沿现有运动准备/总超时处理，不新增累计次数退出。
- 接受参数后生成 `action_id`并关联网页 `token`，保存系数版本与基准几何。测试期间参数不可应用，其他运动入口沿已有任务占用判断拒绝；只读及停止允许。
- 模块每轮主循环观察新轮组和IMU，而不是从网页遥测反推数据。暂缺样本不改变原运动的恢复策略；确实丢失无法补算的区间标记 `sample_complete=false`，不用于拟合。
- 只有本次动作完成并有本次新鲜停稳证据，才产生可拟合结果。取消、超时和总线故障的部分记录始终不能误作完成。
- MCU保留最近一条结果及对应5页直到下次测试或复位；关闭网页遥测不删除结果。网页下载、测量录入并保存后才允许该向导启动下一条。
- 相同token重试当前/最近一次同参数请求，只返回既有状态；参数不同则拒绝。网页对发送结果不明的运动只查询状态，不自动重发。
- 标定模块提交内部运动时使用 `ChassisCalibration_IsSubmitting()`区分所有者；避免新增busy判断反过来拒绝自身提交。
- 全局 `chassis stop` / Ctrl+C / 现有网页立即停止继续优先。标定仅记录取消和停车证据，不增加另一套停车命令或自动总线恢复。

### 6. 协议草案

以下接口是待实现接口，不能用于当前固件实车测试：

| 指令 | 类型 | 约定 |
|---|---|---|
| `chassis calib get` | 只读 | 当前校正、版本、基准几何、支持的协议版本 |
| `chassis calib status` | 只读 | 当前/最近测试状态、token、action_id、reason |
| `chassis calib result <token> <page>` | 只读 | 读取最近结果页，page=0..4；身份不匹配返回result_missing |
| `chassis calib linear <f\|l> <signed_mm> <mm_s> <token>` | 运动 | 单车体轴，绝对距离10～1000 mm，速度10～300 mm/s |
| `chassis calib turn <signed_deg> <deg_s> <token>` | 运动 | ±90°或±180°，速度1～100°/s；按指定转向方向 |
| `chassis calib set <expected_revision> <forward> <lateral> <rotation>` | 参数写入 | 全组三系数原子应用，静止且任务不占用时允许 |
| `chassis calib defaults <expected_revision>` | 参数写入 | 恢复[1,1,1]；不擦除存储、不改物理几何和电机参数 |

结果格式：`@CHCAL <JSON>\r\n`，`v=1`，每页包含 `k=result, token, id, rev, p, n=5`，整行包含前缀及CRLF不超过256字节。打印数值保持有限，三系数至少保留6位有效数字。

| 页 | 内容 |
|---|---|
| 0 | kind/axis/有符号目标、测试速度、起止MCU时间、本次停稳、sample_complete、结果原因 |
| 1 | 基准累计sx/sy/wheel_angle_deg、当前校正下的起始车体系反馈位移、IMU展开转角、最大航向偏差 |
| 2 | 起始四轮原始位置与接收时间，起始IMU角度/时间 |
| 3 | 结束四轮原始位置与接收时间，结束IMU角度/时间 |
| 4 | 测试冻结的L/W/D/G、三系数、原点generation、反馈单位 |

页载荷固定采用以下紧凑字段，数组顺序就是协议顺序：

- 页0：`test:[kind,axis,signed_target,speed]`、`time:[start_ms,end_ms]`、`ok:[stop_confirmed,sample_complete]`、`r:reason`。kind为linear/turn，axis为f/l/yaw；r采用complete/cancelled/timeout/bus_error/feedback_invalid/stop_unconfirmed/sample_incomplete/action_mismatch之一。
- 页1：`raw:[sx,sy,wheel_angle_deg]`、`est:[estimated_dx_mm,estimated_dy_mm,imu_delta_deg]`、`h:max_heading_error_deg`。est的位移在起始车体系表达；raw是未补偿的车体轴累计量。
- 页2/3：`w:[FL,RL,RR,FR原始位置]`、`t:[FL,RL,RR,FR接收时间]`、`y:[IMU展开角,IMU接收时间]`。
- 页4：`g:[L,W,D,G]`、`s:[forward,lateral,rotation]`、`og:origin_generation`、`u:65536`、`dir:[FL,RL,RR,FR前向宏]`。

所有数值用能满足6位有效数字的紧凑表示；最长ID/时间戳、负位置及指数表示纳入256字节测试，不能截断或动态改变页数。每页身份一致，坏页/缺页仅重读该页，不能拼接两次动作。

参数帧 `k=params`包含 `rev, geometry:[L,W,D,G], scale:[forward,lateral,rotation]`。状态帧 `k=state`包含 `token,id,rev,state,r`，state沿第5节状态表，空闲且无结果时token/id为0。上电revision=0、scale=[1,1,1]；每次成功应用递增revision。版本只标识本次运行，网页不能只靠版本数判断跨复位参数一致，须读回实际三系数与基准几何。

旧固件未知指令时显示“当前固件不支持底盘标定，请更新固件”，现有手动测试仍可使用。停止锁定中可读取get/status/result，不能写set/defaults或启动测试。准备跑图占用期间不允许开启标定；保持现有准备接口和白名单语义，不增加一套服务端串口所有者。

### 7. 应用、生效与持久性

1. “保存本机方案”仅存浏览器：用户命名、地面/载荷、基准几何、拟合系数和证据。
2. “应用设备并读回”是明确写入动作：先读取当前版本，整体set，再get确认三系数与基准一致，才显示已应用。
3. 应用前须四轮新鲜速度/位置证明静止、无运动/路线/视觉标定任务占用，且停车链无未完成请求。触发原因是防止一个动作中途切换模型；拒绝时保留草稿，停稳后原按钮可重试。
4. 校正值仅要求正且有限，并验证正逆解仍有限；不静默截成“看起来合理”的范围，不以未经实测的统一比例上限阻断使用。
5. 新系数只影响后续轮组积分。应用时重建指令及反馈积分基线，保持当前X/Y/yaw、地图原点和generation；不按新系数缩放整段旧位置。
6. IMU反馈航向不重置，雷达已完成图不清除。显示“已应用，历史定位不追溯修正；从准确起点复测”。
7. 第一版设备RAM保存，本机方案可跨刷新保留；复位后显示待重新应用，重连不自动写。设备Flash持久化不在本版范围。
8. 以旧底盘毫米响应建立的视觉J前后/侧向列标注“底盘尺度改变，待复测”；保存旧值供对照，不自动清空准心、X列、机械臂参考或库存。该关联先落实到控制台状态和操作手册，沿已有视觉响应标定入口复测，不新增整车运动互锁。
9. 通过“应用上一次方案并读回”回退，仍要求静止；保留全部样本和当前方案，不自动启动验证运动。

### 8. 控制台页面与记录

卡片顺序：

1. **设备参数**：当前设备值、本机方案、是否一致；读取、应用并读回、恢复默认。
2. **本次条件**：地面、载荷、测量点说明、距离、速度、起始方向和动作箭头。
3. **单项测试**：前进/后退/左移/右移/顺转/逆转；一个主启动按钮及全局立即停止。
4. **当前结果**：受理、运动、等待停车、等待测量、完整结果；显示反馈估计与实测起终点，不能把两点连线冒充实测全过程轨迹。
5. **样本与建议**：方向次数、平均误差/离散、拟合值；勾选、排除原因、计算建议。
6. **应用后复测**：修正前后表格；矩形闭合与整场终点实测入口；导出JSON及Markdown报告。

浏览器存储键 `car.chassisCalibration.v1`，记录结构：

```text
schema_version = 1

records[]:
  id, created_at, phase(calibration|validation), profile_id
  token, action_id, device_revision, geometry, scale_snapshot, origin_generation
  test: kind, axis, signed_target, speed, start_ms, end_ms
```

导入/导出保持单位、方向、原始样本、参数版本和校准/验证分组。不同基准几何不合并拟合；验证样本不默认回填训练样本，避免“用同一数据证明自己”。

刷新/切页保留记录。断线将当前状态标为历史/待核对，不产生完成结论；用户点击“恢复上次结果”后只读status及缺页。服务已有串口日志继续存于 `.embeddedskills/`，导出报告注明对应日志窗口。

### 9. 返回区行为与验收

普通固定路线和雷达规划路线的最终返回目标为 `(2250,150,180°)`：

- 保留既有行驶路径和离开起点时的180°朝向。
- 返回末点先完成原移动阶段，再增加 `arrival_turn`到180°。
- 转向后按当前反馈核对XY；需要时复用既有位置修正，不额外开新计数/停车链。
- 只有最后转向及必要位置修正完成，并确认四轮停稳，路线才显示done。
- “返回起点”通过station=1、visit=8及坐标识别，不能把绕障后变化的路点编号19硬编码为最后目标。
- `BuildTask`对最终station=1当前委托共用Build，因而最终返回也统一180°；原料/加工/暂存工作朝向不改变，现有task profile测试要覆盖此差异。
- 共用C CLI计划输出及网页预演同步出现最终arrival_turn，网页不另写一套末点航向规则。

第一版软件通过条件：正逆解一致、设备应用读回一致、结果完整保存、正常及中断流程可恢复、末点180°，相关测试通过且Keil零错误。

初步实物验收目标：

| 项目 | 测量方法 | 初步目标 |
|---|---|---|
| 1米直行/横移 | 独立测量中心沿轴位移与侧偏，每方向3次 | 沿轴误差绝对值≤20 mm；侧偏单独报告，目标≤20 mm |
| 90°/180°转向 | 独立角度参照，两方向各3次 | 实际角度误差≤2°；中心漂移单独记录 |
| 600×600 mm矩形往返 | 四边按车体/地图关系明确执行；顺、逆序各3次 | 输出实际闭合误差与参数修正前后对照；不凭定位估计判闭合 |
| 整场归位 | 同一中心点、同一初始姿态，蓝区中心参照 | 最终180°±2°；实际中心误差争取≤30 mm，作为后续定位纠偏是否必要的依据 |

20 mm/2°/30 mm是拟定验收目标，不是当前已达精度。实际中心测量要固定参照，照片轮胎间距不能直接填成中心误差。若短程通过、整场仍漂移，不能通过不断改系数拟合某一次整场终点；转入后续绝对定位阶段。

### 10. 后续绝对定位边界

第一版报告区分：初始摆放误差、轴向比例误差、侧偏/旋转中心漂移、IMU实际角度误差、长程累计漂移。

后续先用现有雷达核对扫描高度是否能看见位置已知的固定特征，再决定局部扫描匹配；若缺乏特征而现有相机能看到蓝区边缘，再评估视觉归位。两条路线均须先完成安装位姿/坐标标定及实测可观测性验证。

二维雷达不靠颜色识别平铺蓝区；现有建图投影也不等于定位匹配。运行中新位置校正接口、点云匹配、Pi部署与实车绝对定位验收另立实现任务，不在本计划第一版夹带SLAM或新硬件采购。

# 实车监控对齐备用雷达判障与规划实施计划

> **执行状态（2026-10-05）：** 用户已批准原生实施。任务1～5及软件回归、Keil重建、文档已完成；DAPLink探针查询失败、COM14无回复，烧录和本轮现场扫描未完成。未启动子代理、模拟审查或电机运动。

**Goal:** 保留正式全场判障，同时对齐已验证备用 F1 的筛选、逐格计数、扫描保护格和确定性四邻域规划规则；同圈地图、路线和实车预演使用同一结果。

**Architecture:** 正式 `radar_map.c` 保留全场占用网格，备用 `radar_host_map.c` 的功能和协议不变。规划复用已有 `RadarGrid_Path`，在搜索入口统一到 F1 参考方向，再把结果转回正式坐标；实车工位接驳是明确的适配层，不再用另一套跨格捷径替代 F1 搜索结果。

**Tech Stack:** STM32F407 / HAL C、Keil MDK、原生 JavaScript、Python 本地桥、现有 C 主机测试。

**Spec:** 用户确认“仍然全场参与判障”及方向要求，并随后批准“执行计划”。软件实施状态见下方勾选项，实机未完成项目保持未勾选；详见[实施与验证记录](../../开发记录/2026-10-05-实车监控F1算法对齐实施与验证.md)。

## Global Constraints

- 正式判障边界维持 X/Y `[0,550,1000,1400,1850,2400]` mm。精确边界点按 F1 参考系的半开区间归格后旋转回正式格号，不加夹取或外扩；这与正式现有直接按 X/Y 半开区间归格的边界归属有差别，须由任务 2 的测试锁定。
- 五列/五行宽度为 **550、450、400、450、550 mm**。用户选择全场判障，因此撤回“五格尺寸必须全部等于备用页”的要求；不另增外圈网格或扩成 7×7。
- 备用网格仍为 `[150,550,1000,1400,1850,2250]`，宽度 **400、450、400、450、400 mm**。同圈全场外圈点可能造成正式页多出障碍，属于保留要求，不宣称两页必然同图。
- 默认原始角 0～360°、距离 100～40000 mm、能量 0～255、每格最少 1 点。完整圈所有点参与；120 点预览不参与正式判障；不恢复轮廓聚类、背景删除或径向 2400 mm 裁剪。
- 正式坐标为左下原点、X 向右、Y 向上；仅参考转换使用 `T(x,y)=(2400-y,x)`。不改底盘、IMU 或电机方向。
- 正式默认安装继续 `(2250,150,180°)`，上方继续 `(2250,2250,270°)`；对应备用验证安装 `(230,230)` 的正式位置是 `(2170,230,180°)`，仅显式复制备用安装时使用，不自动覆盖实际安装。
- 保留工位坐标、`station/visit`、任务顺序 `1-5-4-2-3-4-2-3-1`、已验证首段和返回启停区接驳。固定 15 目标路线、备用雷达页、USART 波特率和无线发送节奏不改。
- 新扫描或改配置不伪装历史结果为实时；地图/路径身份和分页校验不关闭。进入页面、切页、重连和本机保存不发送配置或运动命令。
- 本计划的硬件验收仅静止扫描/读回，不运行 `radar nav start`、`radar task start` 或步进动作。烧录、复位与串口发送须在实施轮明确授权，不能把本轮制定计划视为硬件授权。

## Review Focus

1. 两页使用不同冻结位姿或不同原始圈：不得把结果差异直接归因于算法；任务 1、4、6 固定证据。
2. 外圈回波：正式应保留，备用可能排除；任务 1、2 单独验证外圈差量。
3. 保护格：必须保留真实点数与原始阈值证据，不能仅清诊断值制造一致；任务 2 验证。
4. A* 等长路线：参考系旋转会改变同分支选择；任务 3 比较有序格路径，不只比较长度或可达性。
5. 历史地图/路径串圈与预演另算路线：任务 4、5 检查身份及 C 路点一致，保留旧快照的历史标记。

## 方向契约与专门验收（用户补充：记得处理好方向）

- **参考导入只转换一次：** F1 点坐标使用 `T(x,y)=(2400-y,x)`；方向向量使用 `(dx,dy)→(-dy,dx)`；若输入为从 +X 逆时针的地图航向，则 `yaw正式=wrap(yaw参考+90°)`。F1 原始顺时针扫描角不是地图航向，不能直接加 90° 当成 yaw。
- **原始角与投影分开：** 原始角和筛选范围保持原值；正式按 `地图射线角=zero_deg-原始角` 投影。下方 `zero_deg=180°` 时，原始 0°/90°/180°/270° 的回波分别位于雷达左/上/右/下。上方静态预设继续使用 `zero_deg=270°`，不把上下角落的静态 +90° 关系误改成车辆刚体转向 180°。
- **格号/掩码同步转换：** 1 基旧格 `(R,C)` 转为正式 `(C,6-R)`；例如备用 R4C3→正式 R3C2、备用 R5C5→正式 R5C1。counts、扫描证据、保护格及规划格链按同一映射，不能只旋转障碍色块。
- **路线方向同步转换：** F1 北/东/南/西对应正式西/北/东/南；转左/转右语义在纯旋转下保持不变，不交换左右、不把轨迹镜像。实车执行方向由正式实际路点及地图航向产生，不直接沿用未转换的 F1 方向枚举。
- **正式数据不二次旋转：** MCU 已发布的正式 map.mask、counts、pose 和路径直接显示/预演。SVG 的 Y 轴翻转只属于屏幕绘制；鼠标读数、航向箭头和轨迹应使用同一世界坐标，不能再 T 一次。
- **任务 1/2 的方向测试：** 从场地中心采四个原始基准角，独立断言正式左/上/右/下点与格号；再覆盖上方零角、四角转换、上述两个具体障碍格、逆变换往返。期望值写成明确坐标/格号，不调用待测转换函数生成自身期望。
- **任务 3/5 的方向测试：** 同一个有方向的 L 形格链经 T 后检查有序路点、前进航向、左/右转保持，随后检查 C 预演和页面箭头一致；同时回归固定路线，确认底盘/IMU/电机符号及驱动命令单位未改。
- **任务 6 的现场核对：** 在已知安装位姿下，用已确认物理位置的障碍核对点云、红格、绕行线三者方向一致；若现场摆放方向未确认，仅报告串口坐标证据，不把截图颜色当成方向验收完成。

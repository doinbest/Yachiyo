# 比赛动作连续衔接实施计划

> 执行：使用 superpowers:subagent-driven-development 的独立实现与审查流程；用户已批准上一轮列出的四项衔接及纯途经点连续通过，直接实施，不再重复请求设计批准。

**目标：** 消除末件入仓往返、重叠可并行的 Base 与底盘动作，并减少相容途经点的停车。

**结构：** GrabTask 提供新鲜 X/Z 避让完成资格与末件入仓结束策略；比赛调度决定何时开始、何时汇合；路线层在总线忙时保留待提交阶段，连续通过只覆盖保持航向且共线同向的纯途经点。

**技术：** STM32 HAL 裸机 C、共享 UART 电机总线、现有 GCC 主机回归与 Keil 主车构建。

**设计依据：** 本对话 2026-10-13 流程 review 及用户“前面4处……可以执行优化”的批准；现行 AGENTS.md。

## 约束

- 保留所有既有未提交修改，在当前完整工作区集成；不移动或重置工作区，不提交其他轮次的改动。
- Z 安全提起、X 收回并通过本次新鲜反馈后，才允许 Base 与保持既定航向的底盘平移重叠；不放宽低位/伸出状态。
- 工位作业开始前仍等底盘停车与 Base 完成；工位外侧车体转向点、真实扫码点、最终终点保持停车确认。
- QR 入口转向停稳→Base+35°确认→直行，取料前1秒、1/2仓 Z/X 避让后才转 Base，保持原约定。
- 暂停及通信恢复保存原动作目标、末件结束策略、已释放/库存提交状态；真正停止取消续接。
- 不改变路线几何：仅合并同航向、共线同向的纯途经段；方向变化、作业、扫码、转身和绕障拐点不得直线切角。
- 编译与必要验证通过后，检查已确认 DAP/SWD 链路，连接正确则烧录并校验；实车连续任务另行验收。

## 审查重点

1. 重叠中暂停/恢复：不得只停一方、重复启动或丢掉未完成 Base 姿态。
2. 末件已松爪记账后暂停：不得再投料或转回观察姿态，stored 只在安全结束姿态确认后报告。
3. 忙碌拒绝：保留正确目标与阶段，自动重试，不跳阶段或终止比赛。
4. 连续通过：不能跨扫码/工位/转角，也不能改变绕障折线路径；暂停后恢复未走完目标。
5. X/Z 资格过期或反馈更新：不能用历史姿态标志放行并行。

## 任务2：机械臂结束策略与并行资格

文件：`GrabTask.c/.h`、`grab_track_store_test.c`、`grab_processed_store_test.c`、`grab_pose_test.c`。

接口：
- `bool GrabTask_StoreFinishTravel(void)`：刚受理的入仓任务选择直接行驶结束；成功则在本次任务内保存，普通单项默认仍返回观察。
- `bool GrabTask_PoseClearanceReady(void)`：仅姿态切换有效，X 在收回位置、Z 不低于车仓转移高度、二者有本次新鲜静止证据、Base 无故障，表示可重叠底盘运动；不代表整个姿态完成。

- [x] 失败用例覆盖末件直接结束、普通件返回观察、库存仅记一次、暂停继续策略不丢、旧/移动反馈不放行。
- [x] 入仓松爪并记账后提起到行驶安全高度、收X、保持/到达后向参考，直接报告 stored；不走观察 Z/X 和 Base128°。
- [x] 姿态开始/继续重新建立资格；最终 work_ready/travel_ready 仍要求完整 Base 到位。

# 八千代·巡航：控制台 UI 布局细化

日期：2026-09-12  
状态：本轮软件实施完成；交付与验证结果见下方实施记录。

主方案：[八千代控制台改版与二维码接入方案](2026-09-12八千代控制台改版与二维码接入方案.md)。本文细化空间与操作设计，不改变主方案中的协议含义，也不把尚未实现的二维码命令视为现有能力。

## 1. 本次优化决定

采用 **左侧导航、中间工作台、右侧人物与反馈、底部公共终端** 的桌面结构。

主要解决四个问题：

1. 首屏标题与装饰占高过多：取消大横幅，让连接后直接看到常用操作。
2. 大下拉列表混合查询、运动和标定：查询变直达按钮，运动独立表单，标定默认收起。
3. 视觉概念难分辨：用“操作哪个机构、会不会运动、完成到哪一步”解释差别。
4. 页面随日志与地图不断变长：地图独立一页；公共终端固定区域、可收起，保留原始记录。

六个导航入口：**机械臂与夹爪、底盘、视觉任务、二维码、地图与遥测、系统与标定**。第一版默认进入机械臂与夹爪；不新增空的“比赛总览”或“一键比赛”入口。

## 2. 品牌与视觉规范

名称暂用 **八千代·巡航**。英文为 `INTELLIGENT MATERIAL HANDLING · 2027`，只在品牌区出现一次。赛事届次仍按主方案等待确认。

顶部只保留品牌、主题和背景设置。移除“小车实验室”、WORKSPACE / 01、KEEP EXPLORING 等装饰文案。每个模块以中文标题表达用途，不重复增加英文副标题。

开发板名称完整放在连接区：**立创·天空星STM32F407VxT6开发板**。名称来自项目配置，不冒充串口自动识别结果；实际设备信息查询结果另列。

建议的设计值如下，最终实现需在人物原图上验证文字对比度：

| 项目 | 浅色主题 | 深色主题/共用值 |
|---|---|---|
| 页面底色 | `#F4F7F8` | `#111E2A` |
| 操作面板 | `#FFFFFF` | `#1A2D3B` |
| 主要文字 | `#213444` | `#E5EEF3` |
| 主要操作 | 深青绿 `#007D82` 配白字 | 使用足够对比度的青绿按钮 |
| 当前导航 | 淡青绿底 + 文字 + 左侧标记 | 深青绿底 + 明亮文字 |
| 停止操作 | 暗红文字/边框或暗红按钮，始终写明停止对象 | 同样保留文字，不只靠颜色 |
| 品牌字体 | 22～24 px，字重 650～700 | 不依赖网络字体 |
| 正文/控件 | 14 px / 14～16 px | 参数值与状态正文不缩成装饰小字 |
| 面板圆角 | 12 px | 不使用所有组件都很大的胶囊圆角 |
| 间距 | 8、12、16、24 px | 同层级保持一致 |
| 普通按钮高度 | 36～40 px | 手机窄屏提高至至少 44 px |

按钮层次：主要操作实色、读取/设置次要操作描边、说明/展开使用文字按钮。失能是独立控制操作，不与断开串口混淆。禁用时同时给出短原因，如“未连接”“请选择单轴”“需先完成 IMU 验证”。

人物继续使用原图，不替换或增加另一个人物。桌面右侧显示头部和上半身，原图文件不裁切；显示区域可通过 CSS 遮罩弱化下半部。参数、状态正文与日志使用稳定底色，避免人物衣服从文字背后透出。

### 3.2 尺寸约定

- 顶部品牌约 64 px；连接区约 64～76 px，允许开发板名称自然换行。
- 桌面导航宽 156～176 px；右侧人物/反馈栏约 240～300 px；中间工作区获得剩余空间。
- 普通页面最大整体宽度约 1800 px，宽屏居中；不用超大留白挤压输入控件。
- 公共终端默认高约 200 px，包含标题和输入行；短屏压至 160 px。可展开至可用内容高度的约 40%，或收起成 40 px 标题行。
- 停止操作条约 44 px，并在终端收起时仍可见。停止按钮始终走对应已有命令，不能把四条停止合并成未经验证的全车急停。
- 1366×768 的目标：高级区关闭时，轴选择、四个常用按钮、相对角度和执行、夹爪两个按钮均无需整页滚动即可到达。
- 工作台与日志分别滚动；第一版不增加多层嵌套滚动。右侧反馈只显示少量关键字段，完整回复进入终端。

可用空间不足时，先收起人物栏，再压缩终端；不能通过缩小字体来塞入全部调试项。

## 4. 模块级设计

### 4.1 机械臂与夹爪

**上方对象选择：** `[底座 Base] [升降 Z] [伸缩 X] [全部轴]`，采用分段按钮；不再先选“操作”后猜目标对象。

**常用行：** `[使能] [失能] [读取状态] [停止]`。切换对象只更新目标，绝不发送命令。

**相对运动：** 单个带正负号的角度输入、单位 °、执行按钮。范围遵循现有前端/固件约束；本次布局修改不偷偷更改运动限值。输入旁写“电机轴相对角度”。

**位置：** 显示协议真实单位的当前位置与 `[读取位置]`，不自动把脉冲数换算成机构毫米值。

**夹爪：** 下方独立的小面板只列 `[打开] [夹取]`，与机械臂轴选择无关。当前接口没有抓取成功传感反馈时，只显示动作请求结果。

**高级区：** 用“回零与零点”“运动参数”“夹爪调试”三个可展开分组；不一次展开所有字段。回零模式、保存零点、计数清零分别保留说明。

选中全部轴时，仅提供固件支持全部轴的动作；相对角度和读取单轴位置禁用并说明原因，不自动循环发送三条动作。

### 4.2 底盘

底盘页按**有限时长测试、位置测试、高级诊断**划分。新的有限时长测试在底盘计划交付并确认接口后成为主要入口；原定距位置测试作为独立区保留，不能与速度规划混成一套参数。

有限时长测试表单：

| 项目 | 显示/行为 |
|---|---|
| 模式 | `给定角速度` 或 `目标航向`，二者互斥 |
| 前向速度 | mm/s；正前、负后 |
| 左向速度 | mm/s；正左、负右 |
| 转向项 | 角速度 rad/s，或目标航向 °；随模式切换，保留单位 |
| 持续时间 | 页面可用秒展示，在命令构建处明确转换为交付接口所需单位 |
| 起步/停车过渡 | 首版展示固件默认 500 ms；接口未开放时只读，不制作无效可编辑项 |
| 操作 | `[执行测试] [停止底盘] [读取任务状态]` |

示例默认速度保持 0，选择模式不自动填入会导致运动的目标。执行值须由用户明确填写。

新的首轮测试约束来自底盘计划：平移合速度 100 mm/s、角速度 0.15 rad/s、单轮 100 RPM。页面必须检查合速度，不仅分别限制 vx/vy；最终限值与状态以底盘交付接口为准。它们不能被误当成所有旧位置测试的限制。

右侧状态用 `空闲 / 运行 / 停车中 / 结束 / 异常`；结束原因单独展示。“时长结束”“已发送停止”“反馈确认停止”分别呈现，不显示“已到达地图目标”。

持续速度、旧 hold、单轮、ACK/单位等早期或底层测试放高级区。新的有限时长测试不暴露无限期运行选项。视觉仍使用原有策略，不因 UI 合并自动切换控制路径。

### 4.3 视觉任务

模块内用三项二级导航：**任务执行 / 相机调试 / 标定与分步测试**；三个面板互斥展示，避免长页叠加。

任务执行布局：

```text
物料搜索与对准
目标颜色： [红 1] [黄 2] [蓝 3] [绿 4] [黑 5] [浅蓝 6]

操作范围：Base 回零，底盘搜索并与 X 轴配合对准
[开始搜索与对准]  [停止物料任务]  [读取任务状态]

当前状态：等待状态
当前目标：—    相机数据：未知    更新时间：—
流程说明：回零 → 请求识别 → 搜索 → 对准
```

流程说明默认是静态说明；只有匹配设备状态时高亮对应阶段，未知状态显示原文。不得按时间自动推进流程，不新增假完成百分比。

相机调试页写明“仅识别，不主动驱动机构”，只提供目标选择、开始识别、读取状态、停止识别请求；图像中心/误差坐标放这里，不挤占任务页。

标定页明确区分“Base/X 机械臂路径”与“底盘/X 路径”，每种路径的参考、标定和分步对准就近分组。UI 不假定两条路径存在完全相同的标定前提，按固件真实状态显示。

`camera stop` 不能标成“停止物料任务”；`vision stop` 标明停止 Base/X 对准；`material stop` 对应物料搜索与对准任务。

### 4.4 二维码

顶栏为 `[检查功能支持] [读取任务码] [读取接收状态]`。前者供旧固件/新固件兼容检查，发送行为必须由用户点击触发；其余动作在支持确认前禁用。

中部为主信息：

```text
最新任务码                         [复制]
123 + 456 + 123 + 456               ← 示例，真实页面不预填
第1组  第2组  第3组  第4组

有效码序号：—    最近接收：—
[跟随新任务码]  [暂停跟随]
▸ 接收统计与协议详情
```

没有有效数据时使用 `—` 和“尚未收到任务码”，不能展示示例并看似真实。四组码用等宽数字排版；每组允许独立复制但不添加自动执行业务动作。

将字节数、拒绝数、UART 错误收在下方详情。任务码没有更新不等于模块离线。没有主动扫码协议时不提供“开始扫描”和“停止摄像头”。

### 4.5 地图与遥测

进入独立页面后，中间工作区与右侧栏合并为大画布，人物退到低对比背景或隐藏。开发板连接、导航和公共终端仍然保留。

```text
地图与遥测     [离线模拟 / 在线遥测]       数据来源 / 更新时间
┌─────────────────────────────────┬──────────────────┐
│                                 │ 当前来源说明     │
│          正式赛题地图           │ 位姿/航向/有效性  │
│          小车姿态与轨迹         │ 目标与反馈       │
│                                 │ 轨迹段与会话     │
└─────────────────────────────────┴──────────────────┘
离线：初始位姿 / 速度 / 模型 / 开始模拟 / 暂停 / 重置模拟
在线：显式开启遥测 / 关闭遥测 / 只读 MCU 参数
```

模式边界完全继承底盘计划：

- 离线有理想模型与整数 RPM 命令近似模型，编辑参数只影响模拟。
- 在线区区分指令推算与反馈估计；反馈不可用就显示不可用，不能静默用目标轮速代替测量。
- 参数来源、单位确认、反馈有效性、航向有效性、会话切换可见；不因好看而隐藏关键来源。
- 地图点击、拖动、模拟开始均不发送运动命令；在线页面不新增地图控制实车按钮。
- `开始模拟` 和 `开启遥测` 使用完整名称，不共用模糊的“开始”。
- 切离当前页面后继续处理已开启遥测，保证状态完整；导航本身不发送订阅启停命令。连接栏显示遥测仍开启。
- 地图容器隐藏再显示或终端伸缩后，需要重新适配可视尺寸；保留遥测解析与轨迹段状态，不能重复挂载接收处理器。

### 4.6 系统与标定

分为设备信息、IMU 两块；其他未实现诊断不制作大量灰色空卡。

IMU 默认显示模块 yaw、验证状态和数据新鲜度。按钮为 `[读取状态] [原生标定] [验证30秒] [验证120秒] [取消]`，原始连续输出开关放详情中。

标定时显示设备实际阶段和已用时间；旧外部 `bias_dps/corrected` 不返回主页。模块保存请求成功、寄存器读取正常、断电保持已实测分别展示，不能合并成一个绿色“保存成功”。

## 5. 操作、反馈与日志的统一规则

### 5.1 直接按钮和参数表单

- 使能/失能/状态/停止按钮使用当前对象立即构建命令；鼠标悬停与键盘聚焦能看到实际指令，发送后在终端记录。
- 带参数操作在表单底部保留一行紧凑命令预览，旁边放执行按钮；不再为预览占用一整块大卡片。
- 默认不设全局键盘运动快捷键；输入框中的 Enter 不跨模块触发其他按钮。
- 发送过程中按钮短暂显示“发送中”；发送完成不等于硬件动作完成。是否允许后续动作由设备状态和现有互锁决定。
- 用户输入格式错误就地提示；运动忙、标定未验证等设备拒绝显示在当前模块反馈中，原文保留。
- 停止请求使用底盘基线的优先发送规则，不能排在自动查询或二维码事件之后。

### 5.2 右侧反馈

最多突出三个关键字段：当前对象、当前状态、最近更新时间；具体字段随模块变化。短原因靠近状态，完整回复放“查看详情”。

区分 `未连接 / 已连接未查询 / 数据有效 / 数据失新或历史 / 设备拒绝`。串口已连接只表示通信端口打开，不能自动点亮所有外设状态。

常用收藏改为当前模块底部一行，最多直接展示四项，其余点击“更多常用”。用户旧收藏保留，不自动执行或静默删除；调试项不占据默认主操作行。

### 5.3 公共终端

- 标题行：模块筛选、TX/RX 筛选、跟随、导出、清空、展开/收起。
- 默认跟随当前模块显示，但“全部”一键可达；过滤只影响视图，不影响保存、状态解析或地图处理。
- 用户向上滚动时暂停自动跟随，底部显示新增条数；明确点击后恢复。
- 关键失败同时出现在模块反馈和原始日志，不能只有一闪而过的提示。
- 终端收起后保留未查看错误数与手动展开入口；清空只清日志，不清二维码缓存或轨迹基准。
- 继续保留现有条数限制、导出功能和手动单行命令校验；不把输入内容当 HTML 插入。

## 6. 窗口大小适配

以下宽度均指浏览器 CSS 视口，不能用显示器物理像素直接判断。

| 视口 | 布局 |
|---|---|
| ≥1440 px | 六项文字导航 + 工作台 + 人物/反馈栏；公共终端默认展开 |
| 1100～1439 px | 收窄导航；人物栏约 240 px，参数尽量两列；高度不足时终端压至 160 px |
| 900～1099 px | 移除独立人物栏，将状态放到工作台标题下；保留文字导航 |
| <900 px | 导航改顶部可横向滚动的文字标签；表单按实际空间变单列；不使用只剩图标的猜测式导航 |
| 高度 <700 px | 终端默认收起；停止条和主要执行按钮不被遮挡；文档流允许必要滚动 |

切换浅深主题不改变布局高度。背景设置用右上角浮层/抽屉，避免当前展开后把整页操作往下推；打开时不丢弃表单内容，关闭后焦点返回触发按钮。

面板背景与前景叠层在普通截图中检查；若仅整页拼接截图出现人物重复切片，先区分截图拼接问题与页面真实渲染，不能据此反复改背景代码。

## 7. 与正在实施的底盘计划对齐

### 7.1 当前可做与暂缓

现在只更新本文和主方案，继续确认按钮命名、页面层次、文案和验收条件。暂不改 `index.html`、`styles.css`、`app.mjs`、`protocol.mjs`、地图文件、`main.c`、`arm_console.c` 或共享测试入口。

底盘计划交付后先记录其实际接口，再按“品牌/外壳 → 常用操作 → 视觉分层 → QR 桥接”实施。不以文档里的示例命令覆盖底盘任务最终交付的协议。

### 7.2 UI 必须继承的约定

| 底盘基线约定 | UI 的责任 |
|---|---|
| 前为 +x、左为 +y、逆时针为正 | 字段、箭头和帮助统一，不沿用向右为 vx 的示例 |
| 轮序左前、左后、右后、右前 | 四轮卡片和曲线顺序固定，显示对应地址 |
| 参数含待确认标记 | 在线参数显示来源，不能把暂定轮径画成已标定值 |
| 命令/编码器/位置协议单位分离 | 不再用一个“脉冲”标签覆盖所有量，不用 16384 猜反馈 |
| accepted、tx_complete、acknowledged 分开 | 反馈分别显示，不以写串口成功作为驱动器已应答 |
| idle/running/stopping/done/error | 映射为中文，但保留真实结束或错误原因 |
| 专用前缀、版本化 JSON 遥测 | 保留原分流解析，二维码走文本分支，不写第二套遥测解析 |
| MCU 会话改变开启新轨迹段 | UI 清除本次有效资格，历史轨迹不接成连续实测路径 |
| 无地图选点控制实车 | 布局里不出现“移动到此处”与隐含运动手势 |

二维码日志和回复复用底盘计划的 USART1 非阻塞发送管理。需要先阅读交付版本的队列优先级和拥塞策略，再接 QR 事件；不能在新的主循环路径直接加入可能阻塞控制周期的串口输出。

## 8. 布局验收清单

### 8.1 视觉与可达性

- [ ] 1366×768、1920×1080 和 125% 浏览器缩放下，品牌与开发板全称不被截断，停止条可见。
- [ ] 机械臂常用操作无需展开下拉列表；高级区关闭时主操作在首屏可达。
- [ ] 视觉默认仅显示任务执行；相机坐标、两类标定不混入同一表单。
- [ ] 地图独占内容区；终端展开/收起不会让地图坐标比例失真。
- [ ] 更换背景、切换主题、恢复默认后，同一张人物图的布局一致。
- [ ] 键盘可遍历按钮和输入；当前对象、失能/使能和错误提示不只靠颜色表示。

### 8.2 行为与兼容性

- [ ] 导航切换、打开背景设置、切换主题、展开调试区都不发串口命令。
- [ ] 一个执行动作只对应一次明确发送；快速连续点击的排队行为遵守底盘基线，不积压过期运动目标。
- [ ] 选择全部轴不生成单轴运动，不因状态未知显示已使能或到位。
- [ ] material auto 不附带额外 camera/vision 启动命令；ALIGNED 只标为对准完成。
- [ ] 地图模拟不控制实车，在线反馈失效不变成伪测量。
- [ ] 新 QR 事件、地图遥测、普通命令回复同时到达时分别更新正确面板。
- [ ] 旧收藏、透明度、主题和原图设置保留；未支持的新命令不能直接触发。

以上是待实施验收项，本轮没有执行前端改版测试或硬件测试。UI 方案落地前应先拿到底盘与地图计划的稳定交付版本。

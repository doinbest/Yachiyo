# 取放与ID8并行衔接优化 Implementation Plan

> **For agentic workers:** 使用superpowers:executing-plans在当前工作区逐项实施，保留已有修改。以下复选框仅在对应工作实际完成后勾选。

**Goal:** 提前执行条件已满足的ID8和机构动作，减少取放串行等待，并将三项夹爪等待默认值调整为100 ms。

**Architecture:** 在现有GrabTask与比赛状态机内拆分动作启动条件和最终汇合条件。同一件任务持有提前分度的绝对目标，跨阶段保留，不能用全局取消忙检查代替任务交接。

**Tech Stack:** STM32F407 HAL / Keil C、现有C回归、JavaScript本地控制台。

**Spec:** 本对话最新分析与用户要求；现行基线见[比赛与取放约定](../../比赛与取放约定.md)。本计划是待实施目标，不代表当前源码已改变。旧计划中的300 ms等待和“Z到0后才收X”仍是当前基线；本计划分别注明拟替换范围和待确认候选。

**状态：** Task 0/1及Task 2已确认部分、Task 4软件联调已实施并通过验证；原料提前收X及普通入仓Base并行候选按计划暂缓。未编译主车固件、未烧录、未进行实车验收。详见[实施记录](../../开发记录/2026-10-16-取放与ID8并行衔接实施.md)。

## Global Constraints

- 保留加工区三件全放完再取回、两批暂存/码垛、库存及仓位映射。
- 加工区放置、暂存第一层及第二层码垛的取仓选仓，在目标仓已确定、Base外侧姿态和新鲜静止反馈满足时，即可与视觉对准并行；不以视觉对准完成或位置快照保存作为分度启动门槛。加工取回前两件同样提前分度；原料追踪保留已有提前分度。
- 闭爪后等待close_ms、松爪后等待release_ms、车仓开口后等待car_pick_wait_ms，拟由默认300 ms统一改为100 ms；视觉和机构实际到位稳定时间不随之缩短。
- 仓1、2取仓后仍执行X到x_min+30 mm避让；X到位可启动Base及首件ID8避让，Z继续抬升。仓3不套用无X避让的提前转Base规则。
- 最终下降前汇合核验本阶段所需的X/Z/Base及ID8真实到位反馈；提前执行不等于提前报告取放完成。
- 车仓下降夹取前确认选仓到位；外部工位下降释放前确认本件首件避让完成。提前选仓与夹起物料后的首件+90°避让是两个独立目标，后者仍在X伸出30 mm避让到位后启动，不提前到视觉对准阶段。
- ID8目标按绝对角和任务归属保存，暂停续接不重复追加90°；停止、取消、驱动故障及有效参考约束保留。
- 不把提前转Base的受理当成取仓完成：仓库存沿用原抬升与避让均已确认后的置空时机，picked还须满足本阶段全部条件；提前转Base后，保存位置的X恢复仍须等Z抬升及Base到位，不能提前撤掉X30 mm避让。
- 用户已授权执行代码及主机验证；本轮不编译主车固件、不烧录，实车验收另行安排。

## Review Focus

- X先完成而Z仍在抬升：Base可启动，Z必须继续原目标，不能因切换阶段漏掉抬升或提前下降。
- 同件ID8仍在转动：只允许原任务交接，不放行其他手动操作或不同目标。
- 提前动作中暂停/恢复：保存目标和夹持阶段，补齐剩余动作，不重复闭爪、释放及库存记账。
- 首件已到90°、下一件选仓2且反馈过期：先补读，区分仍在原位与真实偏移，不能依赖旧缓存直接成功。
- 网页旧值300 ms可能覆盖固件新默认：核对元数据、显式下发和读回；刷新、重连不能自动写设备。

## 复审结论与联调顺序

以下为实施前发现的衔接点；已纳入实现和回归，不仅调整启动条件。

| 级别 | 具体发现 | 纳入步骤 |
|---|---|---|
| P1 | transfer_preindex只由transfer_process调用；ACQUIRE/ALIGN/SETTLE分支不会进入它，只放宽阶段判断仍不能在对准期间分度 | Task 0：在同件活动流程中持续调度目标，视觉控制与分度互不阻塞，并及时接收ID8失败 |
| P1 | start_operation直接拒绝Turntable_IsBusy，并重置IndexSubmitted；新非取仓任务会清CarPickTrayClearance，car_pick_complete也会清该状态 | Task 0：先完成任务归属及目标移交，再允许取仓/放置衔接；不能先放行入口再丢掉待确认目标 |
| P1 | 现有取仓抬升只在GRAB_LIFT推进；若X到位后直接切RETURN_TURN，暂停继续会清commanded，而该分支不会续发未完成的Z抬升 | Task 0/1：保存Z绝对抬升目标并跨转向阶段持续推进；暂停、总线恢复后补齐，X避让也独立保持 |
| P1 | 提前270°若仅写在第三件取回入口，仍晚于换环移动；若从上件提前启动，下一次pose_start/start_operation又可能被ID8忙拦住或重置目标 | Task 0/2：显式移交下一件的预备目标，不向正在完成的第二件覆盖slot、库存或结果 |
| P2 | 首件避让到90°后，选仓2遇到反馈过期可能重发位置命令；简单复用旧arrived又不能证明当前仍到位 | Task 2：保留同目标身份，补读位置/速度/状态，按实际稳定条件确认；不重复FD，不承诺失鲜后免除实际稳定取证 |
| P2 | 网页元数据是由def生成的；100 ms计时若放在阶段入口或每次轮询重置，可能提前下降或一直等不到结束 | Task 1：由实际夹爪输出时刻启动各自计时；生成元数据并测试旧值、暂停及刷新路径 |

实施顺序：Task 0交接与调度基础 → Task 1取仓放置和参数 → Task 2其他ID8路径 → Task 4软件联调及交付。Task 3原料台提前收X是独立候选，未确认净空条件时不执行、不阻塞其余项目。

对每件动作核对三种正常完成顺序：ID8先完成、机构先完成、两者交错完成。记录实际命令发送与反馈完成顺序，不用任意固定延时模拟已到位，也不以ACK/TX完成替代机构完成。总线短时忙只续接本件待办，不重复运动或清空上件结果。

# UART5八电机应答驱动统一调度修改计划

> **For agentic workers:** 使用 `superpowers:executing-plans` 按任务实施；未经用户要求不派审查代理。以下复选框是实施进度，本文生成时尚未修改固件或进行上板验证。

**Goal:** 让主车ID1～8共用的UART5以完整应答推进普通事务，取消固定10 ms发送门槛及追踪额外80 ms批次门槛；追踪采用“新有效视觉包及时修正＋20 ms定时预测与边界处理”，在反馈不饥饿、四轮同步和人工停车保持有效的前提下提高响应速度。

**Architecture:** 沿用现有 `MotorBus`、DMA接收、owner事件和业务状态机，不新增RTOS或第二套电机驱动。视觉包事件和20 ms定时到期共用主循环中的追踪控制入口，中断只接收数据，不执行估计与控制。通信完成与动作完成分离；普通事务应答后让出总线，四轮批次保持原子性，批次之间公平调度其他待办事务。紧急停车为明确例外，不能因某台电机没有回复而延误其他电机停车。

**Tech Stack:** STM32F407、STM32 HAL、UART5 DMA、Emm42 Receive、C99主机回归、Keil Target `template`、现有本地网页。

**Spec:** 本文第1～5节为本轮需求与设计基线；依据用户2026-10-07“8个步进电机都改成应答驱动、不保留额外批次门槛”及随后确认的“新视觉包及时修正、20 ms定时预测与边界处理”要求和当前 `AGENTS.md`。本次追加只更新计划，不代表固件已修改。

官方依据为 `docs/硬件资料/执行机构/闭环步进电机/ZDT_X42S第二代闭环步进电机用户手册V1.0.5_260527.pdf`：

- 第37页同步示例：四轮类写入确认后广播FF，由ID1回复；并提醒命令间留几毫秒以避免粘包。
- 第40页：0x02为成功，0xE2/0xEE为拒绝；0x9F是动作完成，不能当Receive确认；0x12/0x22有专门回零语义，不能一律套用成功码。
- 第46页：未标X/Emm专属的命令为通用命令；位置指令可在上一动作运行中更新，不必等到位才发送下一目标。
- 第60、62页：FE停止、FF同步和9C中断回零存在应答格式。
- 第105页Emm配置说明：115200、Receive、0x6B默认值。

因此，**先取消人为10 ms等待并用完整应答形成事务间隔，但不宣称手册保证零间隔。** 上板若发生可复现粘包/丢回复，比较0、1、2 ms应答后间隔，只保留实测必要的最小值；不恢复80 ms整批等待，不修改驱动板配置。未发现问题则不预先增加延时。

## 3. 统一事务合同

### 3.1 普通事务

流程：`请求受理 → DMA发送 → TX完成 → 完整匹配应答 → 发布事件 → 调度下一条`。

- 全总线同时仅一个等待回复的普通事务，8个电机不是8路并发发送。
- 应答匹配发送后的来源、预期应答地址、功能码、长度和0x6B帧尾。0x6B是固定协议帧尾，不能描述为CRC校验。
- 普通控制确认检查成功码；位置/速度/状态查询按数据格式解析，不能要求数据字节为0x02。
- E2/EE是完整的拒绝应答：结束当前通信事务并交给原业务错误流程，不推进该业务的下一运动步骤，也不等100 ms冒充失联。
- 查询原本预期6/8字节时，也要识别手册定义的4字节拒绝帧；按查询数据合法范围与错误帧格式区分，不能一直等不存在的剩余数据。
- 回零0x12/0x22遵循现有回零处理，不因为提速重新定义回零成功。
- 接收分片、连续应答、TX回调处理前已到达的应答，继续使用现有DMA缓冲和接收时间戳处理。
- 提交成功、TX完成、Receive确认、实际运动/到位分别保留；保持 `tx_ms` 是真实TX完成时间。

### 3.2 应答地址与兼容接口

保留 `MotorBus_Submit(owner,data,length,reply_length,token,priority)` 现有接口。

新增仅用于发送地址与应答地址不同的接口：

```c
bool MotorBus_SubmitReplyTo(MotorBus_Owner_t owner,
                           const uint8_t *data, uint8_t length,
                           uint8_t reply_address, uint8_t reply_length,
                           uint32_t token, bool priority);
```

- 两个入口复用同一提交实现，不建立第二条队列。
- 普通已支持的单播控制/读取命令，现有调用误填 `reply_length=0` 时，总线层依据当前Emm命令格式补足应答长度；由小型内部函数 `ExpectedReplyLength(data,length)` 完成。只覆盖项目实际使用的命令，保留显式长数据长度，不假定所有命令都是4字节。
- 广播FF使用 `reply_address=1, reply_length=4`。这是手册规定的回复来源，不是在0和1间宽松任选。
- 其他广播按当前命令逐项核对，不能因为FF由ID1回复，就将任意广播都套成相同合同。
- 报文含有0x6B的数据仍按固定长度收齐，不靠“遇到第一个0x6B”截帧。

### 3.3 四轮批次与普通FE

- 保留一批四轮同一目标快照：ID1确认 → ID2确认 → ID3确认 → ID4确认 → 广播FF确认。
- 批次开始后不被普通X/反馈请求插入；人工停车仍可打断。不能混入新一轮计算的部分轮速。
- 最多保留一个“下一批最新目标”，忙时替换未发送目标，不排队积压历史速度。
- X速度归零后的普通 `MechanicalArm_StopScheduled` 等FE确认，确认后再继续读反馈；不得以它抢占四轮批次。
- 0x02只证明驱动收到FE，不证明轴已经停稳。

### 3.4 紧急停车例外

人工停车/故障停车不能依赖某台驱动及时应答：

- 在正在发送的DMA完成后优先发送停机帧，不损坏在线帧。
- 多电机停车链继续以TX完成推进后续停机发送，不因第一台缺应答而让其余7台多运动100 ms。
- 将这些停车帧可能返回的FE/9C应答纳入排空记录，按地址/功能消耗；不能当成后续普通请求的应答。
- 所有紧急帧发送后，再按现有新鲜速度/位置/状态确认实际停机。必要的排空超时、未知同步缓存处理及 `bus recover` 保留。
- 不把“紧急发送不等ACK”推广到普通运动指令；不清参考、不自动回零、不自动恢复运动。

## 4. 取消额外批次门槛，统筹8个电机

### 4.1 总线仲裁

沿用每个owner一个待办槽，不增加通用任务框架：

1. 紧急停车优先。
2. 活动中的原子批次/采样组继续完成；只保留现有确有必要的短预留，不预留整个转盘运动时间。
3. 无预留时，普通owner用轮转游标选择，不再每次从固定ID较高优先的owner开始。
4. 每批四轮结束时先释放总线；若其他owner有待办，至少服务一个轮转选择的非底盘事务，再允许下一四轮批次取得预留。没有待办则不等待。
5. 没有新目标、不需要保活、没有到期反馈时不重复发送空批次；不能将“应答驱动”实现成无变化速度无限刷屏。

该轮转机会替代20 ms及固定两次轮反馈，不额外规定“等满一段时间”。持续请求的X、轮反馈、机械臂和ID8不得饿死。

### 4.2 追踪与其他模式

- 追踪按第4.3节混合触发产生新目标：新有效视觉包及时修正，无新包时每20 ms预测更新。上一批已完成且总线可用时发送，不再另等80 ms；总线慢则只发送最新待办目标。
- `batch_ms` 保留串口兼容，默认改为0表示应答驱动；0～200 ms可读写，非零仅是用户显式设置的限频，不自动写回80。
- 修改接口为 `void Mecanum_TrackingTiming(bool enabled, uint32_t interval_ms)`：追踪开启且interval=0，与追踪关闭明确区分，不能沿用“0恢复100 ms”的旧含义。
- 普通底盘的100 ms业务计算/保活不在本轮变频；删除底层发送器重复的100 ms门槛，新业务目标能及时发送。
- 伸缩目标按实际控制更新序列去重，忙时保留最新尚未提交的绝对目标；正在发送的目标缓冲不改写。视觉事件和定时事件不能重复提交同一份控制结果。
- X位置反馈期望50 ms更新一次；目标写入与查询交替获得机会，位置年龄≥100 ms时优先补读一次。不能让“总是先读X”使X目标永远发不出去。
- 四轮位置按轮转连续查询，速度/故障状态保持低频公平读取。移除旧16 ms提交节流，不要求每个控制周期读取所有8台全部项目。
- Z/Base和ID8的到位、停稳、反馈新鲜度和采样组周期保持现有业务含义；组内事务应答后即可推进，不因为电机正在运动而锁住整条总线。
- 算法积分、估计和刹车距离使用真实计算/反馈/发送间隔；默认batch=0不等于实际发送耗时为0。不改视觉估计器、J或增益。

### 4.3 新视觉包及时修正＋20 ms定时预测

视觉来自香橙派的USB CDC B2链路，与UART5电机应答是两类独立事件。采用现有接收缓存、完整包解析和接收序号，不将“发生一次USB中断”当成“收到一帧新视觉”。

- **中断只接收。** USB/串口接收回调只完成必要的数据保存、时间记录和事件标记，尽快返回；拟合、运动补偿、控制求解、边界判断和电机目标提交均在主循环执行。不新增定时器中断中的控制计算，不修改IOC。
- **完整新包及时修正。** 主循环解析出完整、有效且序号更新的视觉测量后，更新一次估计器并及时调用控制入口，不等待下一个20 ms时刻，也不等待上一电机批次完成。视觉分片未收齐不触发；重复快照不作为新测量。
- **20 ms预测兜底。** 没有新有效测量时，距上次控制更新达到20 ms后，用最近有效目标运动及更新的自身反馈进行预测、误差修正、速度分配和行程/接近预算检查。这里不是重复拟合旧像素，也不是把旧误差反复积分为新运动。
- **双触发只计算一次。** 新包和定时到期同时出现时，优先融合新测量，仅执行一次控制更新；两种触发都刷新统一的上次计算时刻。后续定时更新从该时刻计时，避免紧邻重复计算。视觉更新率高于50 Hz时仍可及时修正，不用20 ms门槛挡住新包。
- **使用真实时间差。** 积分、加速度限制及预测使用实际dt，不写死0.02 s；主循环偶发晚调度时只按当前时间更新一次，不补跑积压的旧控制周期。保留现有同USB批次/同时间戳样本合并规则，避免零dt速度和重复计数。
- **估计与发送分开。** 电机总线忙不阻塞新视觉融合或定时预测。只替换尚未发送的最新目标，活动四轮批次保持同一快照；无变化目标按现有保活需求处理，不为凑50 Hz发送空批次。
- **保留当前模型。** 240 ms拟合窗口、自身运动补偿、J、增益、前馈平滑与预测参数不随调度提速擅自改变；只调整必要的触发、时间戳和dt衔接。新观测出现换向时及时更新当前预测，不沿已失效的旧速度继续排队运动。
- **漏检与恢复不加严。** 现有250 ms短漏检预测、逐步衰减与重新识别后的恢复规则保持；超过预测窗口仍按原流程停车等待。不能因20 ms更新产生更多诊断次数，就缩短宽限或增加累计恢复耗尽条件。
- **机械边界持续处理。** 即使没有新视觉，定时预测仍检查X行程、累计接近预算及提前减速；普通停车保留参考与预算，窗口边界暂停仍需原来的人工入口继续。人工停车与实际驱动故障不等待视觉或20 ms周期才受理。

参数含义同步调整：`control_ms`表示“定时预测/控制更新间隔”，默认20 ms，保留现有20～100 ms可调范围；它不是新视觉修正的等待时间，也不是每个电机的发包周期。`batch_ms`默认0仍表示应答驱动。网页预填不能冒充设备读回配置。

**20 ms作为本阶段默认值的依据：** 物料运动半径100 mm时，6/8/10 rpm线速度约62.8/83.8/104.7 mm/s，每20 ms移动约1.26/1.68/2.09 mm；匀速圆周运动用瞬时速度作20 ms短预测，10 rpm下曲率引起的位置差约0.022 mm。这说明20 ms适合当前速度量级的短预测，不保证像素误差同样小；真实误差还受标定、视觉延迟、反馈和电机响应影响。现有50 ms延迟补偿参数不因更新周期20 ms而自动改成20 ms，接收年龄仍不等于拍摄延迟。先验证本方案，再根据实测决定是否有必要缩短周期。

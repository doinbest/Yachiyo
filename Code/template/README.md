## 按需求定位

正式比赛加工进站先在(1200,380)停稳转至180°，再保持朝向以不超过50 mm/s平移至(1200,350)；到点停稳且作业姿态就绪后，才启动视觉核验和对准；同次工位作业保存首次成功对准的实际底盘XY及环号，后续按环距150 mm保留位置偏移换环，每件仍重新视觉确认，加工取回顺序不变。中心到暂存区在中心停车，按较小转角选0°倒车或180°前进至(425,1200)，停车转90°作业朝向，保留最后75 mm低速接近。暂停/恢复保留工位锚点，再次进站重建；无需网页写入新参数，预览共用固件C核心。

底盘直线平移提供linear与cosine两种模式：linear为默认，普通MoveTo加减速度300 mm/s²，正式比赛按路段起步500/800/1000、停车300 mm/s²；cosine为K=200、名义400 ms半余弦速度过渡，短段降低峰值；余弦保留半余弦起步与距离制动参考，位置P收敛按反馈和驱动响应时间降低有效增益；同一平移段保留已观测的最大反馈年龄作为制动预算，避免新反馈突然放宽限速。反馈引起的速度矢量变化受该段曲线峰值加速度约束，末端接近速度按到点窗口和延迟进一步限速，避免目标前提前归零后反复补走。两者都计入反馈年龄和驱动响应的制动余量，共用1000 mm/s路线默认速度、工位局部限速、位置/航向及新鲜停稳判定。除线性模式恢复分段开局外，其他连续转弯和原地转向保持现行独立控制。驱动档位仍为0，位置与停稳确认独立。余弦模式正式右下开局采用共享 `chassis_path.h` 的右通道曲线：保持180°到(2125,350)，600 mm内转至(2100,950,90°)后直行；开局上限200 mm/s，保留原前瞻、向量变化率和航向限速。第一批从右侧保持90°横移到物料台中间(1200,2100)，到点停稳后原地顺时针转90°至0°；第二批中央进站曲线保留。余弦模式开局接近段尚未改为余弦控制。线性模式的正式右下标准开局恢复分段路线：(2250,150,180°)保持朝向斜移到(2100,300)，新鲜反馈确认停稳后顺时针原地转到90°，再直行至本轮二维码纵坐标；各平移段同时受本轮路线速度上限与分段参数限制：起步短斜移500/停车300、速度300，右下扫码直线起步800/停车300、速度上限800，不套连续弯道200 mm/s上限。转向停稳后才准备Base扫码姿态，并可与后续直行并行。余弦模式保留右通道连续开局；右上起点、右上角至物料台、第二批进站、非标准绕障和独立二维码测试保持各自现行路线。详见[比赛与取放约定](../../docs/比赛与取放约定.md)。

普通雷达扫描统一为15个有效完整圈；`radar scan lower 15` 采集并规划，`radar live map start lower` 持续更新最近15圈，`radar stop` 停止采集。下方默认情况二 `(2280,314)` 和精确Q16标定；车体起点为 `(2250,150,-180°)`，工位、首段接驳和取放流程保留。上方独立雷达安装为 `(2050,2250,270°)`，与右上车辆名义起点 `(2250,2250)` 分开，不套用下方矩阵。稳定点XY是独立结果，原始点云仅来自最后一圈诊断。

机构实物条件见[硬件与运行基线](../../docs/硬件与运行基线.md)：Base作业为原参考+117.5°、扫码为原参考+35°，车仓方向为原参考；ID8仓1/2/3默认0°/+90°/+180°，与Base及车体yaw独立。源码默认、烧录版本及设备RAM分别核对。

坏帧、缺段和DMA覆盖只回滚当前圈。更改标定或筛选需新15圈；阈值和路线参数可用匹配的完整稳定证据重算。CPU工作区及稳定点传输副本使用CCM，接收DMA仍在普通SRAM。操作与协议见[地图与雷达](../upper-computer-web/local-car/docs/地图与雷达.md)、[雷达协议](../../docs/协议/雷达.md)。

离线程序 `Code/tools/radar_plan_cli.c` 支持原有 `RADAR1` 历史单圈语义，以及 `RADAR2 mask circle_count`：随后为原10项参数、情况编号、4项矩阵Q16、2项平移Q16、零角0.1°，再依次为每圈点数及 `[angle_tenths distance_mm energy]`。输入至少15个有效完整圈，超过15圈按最近15圈计算；自动双起点输入为15圈。离线程序调用同一投影、稳定证据和规划C核心，不操纵串口。

## 统一比赛入口

2026-10-13增加[比赛动作连续衔接](../../docs/开发记录/2026-10-13-比赛动作连续衔接.md)：末件入仓直接结束在行驶姿态，实时X/Z避让完成后重叠Base与底盘平移，复用进站姿态；路线busy保存原目标重试，相容共线纯途经点合并。串口入口不变，主机回归与实车验证分别记录。

车仓选仓共用`Turntable_Index()`：1号仓执行ID8单圈就近回零，2/3号仓按最短方向定位。仓1按回零完成、新鲜位置稳定及零速/使能反馈确认后继续，不依赖普通位置到位标志；不清库存或重建机械臂参考。入仓、取出和比赛流程同时适用，参见[实施记录](../../docs/开发记录/2026-10-13-车仓1号采用就近回零.md)。实现与各次下载证据见开发记录，车仓实物验收另记。

`grab mission qr [speed] [turn_deg_s] [lower|upper] [fixed|radar] [lowered|raised] [linear|cosine]` 或 `grab mission fixed <code> [speed] [turn_deg_s] [lower|upper] [fixed|radar] [lowered|raised] [linear|cosine]`，省略选项默认路线速度上限1000 mm/s、linear采用正式比赛分段起步/停车参数（见比赛分配表）、转向100°/s、右下、固定路线、raised（Z=0高位对准）；低位对照须显式指定lowered。两种来源都真实扫码，屏幕只显示实际码，采用码独立冻结。`grab mission pause`及`grab stop`暂停，`grab mission stop`终止，`grab mission continue`停稳后续接；终止停车未确认时不能新开比赛。完整字段、取放和恢复见[现行约定](../../docs/比赛与取放约定.md)及[协议](../../docs/协议/机械臂与取放.md)，软件、烧录和实车结果分别记录。

加工区第三件取回入仓采用ID8直接270°避让、Z提起到位后回180°，回转可与Base并行；角度随仓3配置计算，暂停保留目标。见[实施记录](../../docs/开发记录/2026-10-14-加工第三件车仓避让.md)。后续编译及DAP烧录校验已通过，实车验证另记。

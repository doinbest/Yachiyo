# 八千代·巡航 · 本地小车控制台

## 机械轴与抓取参数（2026-10-09）

X/Z 静态取放、姿态切换、码垛和动态追踪读取 `config x|z` 中的轴加速度档位，不再固定为 8。Base 继续读取其轴配置。速度仍按任务阶段使用 `x_speed`、`x_transfer_speed`、`z_speed`、`z_pick_speed`；`grab accel` 与 `grab track accel` 是 MCU 控制加速度，单位 mm/s²，与驱动档位分开。

抓取参数名称、默认值、范围和默认值载入时机统一维护在 [`grab_parameters.def`](../../template/App/grab_parameters.def)。修改后运行 `python Code/tools/sync_grab_parameters.py`（从仓库根目录），生成网页数值元数据；固件回归会检查生成文件是否同步。网页预填仍不代表设备读回，不会自动写参数。Z 普通速度和夹取下降速度均允许大于 0、至 333.333 mm/s，任务还会按当前脉冲/mm 检查 1～3000 RPM。

## 动态追踪与物料夹取（2026-10-08更新）

入口 `http://127.0.0.1:8765/#vision/track`，视觉任务“动态追踪”标签。这不是静态对准或抓取的新默认模式；原来的align/pick保留。

1. 使用共享串口连接，现场调试为COM14、115200/8N1。刷新、导航和重连不发送运动指令。
2. 香橙派B2程序运行后，先点击“准备抓取姿态”（`grab pose work`）：Z抬起、X收回、Base转至作业方向。等待work_ready；Base停稳但差1～5°时会进行相对小角度修正，完成容差仍为1°。
3. 选择颜色，点击“一键持续追踪”（`grab track begin`）。固件先观察，取得本轮停稳反馈和新鲜坐标后，缺少参考才建立料台参考，随后追踪。首次余量可填0～50 mm；50 mm来自初始中心间距370 mm、半径150 mm、车缘150 mm及保留间隙20 mm，不是自动测距。已有参考/已耗预算不会因重新点击充值。
4. “追踪并夹取”（`grab track pick`）共用追踪入口，对准窗口水平/垂直各±5 px，目标停留时停车并用停车后的新鲜坐标确认，再下降、闭爪、提起。原料夹取高度默认−80 mm，抬起−40 mm；高度和下降速度可在面板调整，写入共享z_grab/z_pick_speed供正式原料取料复用。默认下降111.111 mm/s（1000 RPM），色环下降设置不变。完成后保持物料，不自动入仓或改库存。首次夹取缺少参考时采用50 mm，已有参考沿用；其他初始余量先点一键追踪建立。原观察/reference/start串口指令继续保留。
5. 到点仍连续跟随；短漏检在250 ms内预测衰减，超过后停车等待视觉恢复。行程/接近窗口暂不足时停稳并保持观察，新有效坐标返回可追范围后自动续追，沿用原有行程和剩余预算。“停止追踪”结束本轮，保留参数、参考、姿态和已耗预算；人工停止后不自动重启，设备明确区分请求停车与实际反馈确认。
6. 停车后“导出本段”取得冻结128条记录，逐条CRC校验、按需补读缺条后才生成日志；无线导出约26秒，不影响运动控制节奏。展开诊断查看前馈/修正、实际更新节奏、X反馈年龄和估计延迟。重复启动不刷新50 mm预算；重新建立参考只应在恢复已确认初始几何后显式执行。MCU复位或真实位置参考变化才使相应局部参考失效。

默认独立速度为底盘160、X60 mm/s，联合加速度300 mm/s²，lambda2.5，X权重2.333333，X前瞻120 ms且领先不超过12 mm，新完整视觉包即时修正、定时预测20 ms；额外四轮批次限频默认0（应答驱动），显式非零值保留。实际节奏由Receive应答、同步和轮转反馈决定，20 ms不是每台电机的发包周期。延迟50 ms是联调初值，不是测得的拍摄延迟。

冻结日志分析：`python Code/tools/tracking_report.py <日志路径> --kind physical --rpm 6 --direction cw`。分别保留启动过渡、全段新样本误差及稳定部分；128条环形窗口与MCU全段统计分别列出。实际转盘转速、方向和几何验收需人工记录，分析工具不会发送串口命令。详细实现、软件/实机证据和待完成验收见[本轮记录](../../../docs/开发记录/2026-10-06-第一阶段底盘伸缩轴稳定追踪.md)。

2026-10-07新增“开启实时记录／关闭实时记录／读取记录状态”。先开记录，再按原操作观察或追踪；**开记录本身不启动运动，关记录也不停车**。本地服务自动把收到的全部原始字节写到项目`.embeddedskills/logs/serial/<连接时间>-rx.bin`，不受MCU约6.4秒的128条窗口限制，网页只保留最新诊断，不累积大量内存。实时行额外提供实际发送四轮RPM、X受理/发送脉冲与RPM、原始编码器及各反馈年龄，帮助区分计算、发送、执行或反馈问题。

先“停止追踪”并确认停车，再关闭实时记录。默认请求50 ms周期，链路忙时丢弃诊断而不阻塞控制，索引缺口和CRC错误单独统计；必要时终端显式`grab track log start 100`改为100 ms。实时日志分析：`python Code/tools/tracking_report.py <原始-rx.bin> --source live --kind physical`。`--source frozen`分析同文件中的最后冻结导出，不把两套数据混合。原始bin实际含文本，可用串口助手或文本查看工具查看；无需修改香橙派。当前仅软件验证及编译通过，新固件尚未烧录和实车采集。

## F407 雷达建图页（第二阶段，2026-10-04）

“地图与遥测 → 雷达建图”现在复用左侧“设备连接”的 F407 USART1 链路。网页与 DL-20 之间固定为 115200 / 8N1；F407 USART2 以 921600 / 8N1、DMA 循环接收 LDS50C 原始数据，并在单片机内完成整圈冻结、筛选、5×5 障碍地图和路径规划。页面不再直接占用雷达 USB-UART，也不再从 `/api/radar-direct/` 取数。

第一阶段的 `radar_direct_protocol.py`、`radar_direct_bridge.py` 及直连页面模块仍保留，便于独立雷达诊断和历史追溯，但不是当前 `#map/radar` 的数据源。实车监控与离线对照继续使用原有实现，本次切换没有改变它们的布局、遥测、路线或操作命令。

当前页沿用 F1 上位机的主要行为和界面：场地 2400 × 2400 mm，默认雷达坐标 `(230,230)`，障碍阈值 1，任务顺序 `1-5-4-2-3-4-2-3-1`。固定障碍掩码为 `0x00050140`，任务保护掩码为 `0x00404405`；R1C1 起点及其他任务格不会因扫描点或手工点击变成障碍。地图、路径和完整点云都以 F407 返回结果为准，网页不再独立执行另一套规划算法。

推荐首次操作顺序：

1. 双击 `start.cmd`，打开 `http://127.0.0.1:8765/#map/radar`。
2. 在左侧刷新设备，人工选择连接 F407/DL-20 的实际 COM 口，以 115200 波特率连接。页面不会自动选择串口；如果共享连接当前使用其他波特率，雷达按钮会保持禁用并提示按 115200 重连。

## 参数页与单件取放（2026-10-03）

“参数调试”使用物料取放、车载转盘、视觉对准、运动与标定、雷达与路线五个顶部标签，卡片全部展开。背景可切换蓝色或黑色，不再提供白色主题；默认蓝色，选择保存在本机浏览器，旧浅色偏好改用黑色。该页占满主工作区，固定两行结果栏显示读取进度、设备拒绝或读回结果；其他页保留完整终端，原始日志继续记录。

先选设备并连接，再点击“读取当前全部参数”，一次覆盖五个标签的设备参数，路线速度属于浏览器设置、不参加设备读取。初始空框为未读取；设备返回 `unset` 时留空并标记未设置。正常参数行只显示名称、输入框和单位，未读取、读取进度及完成数量统一显示在顶部，不逐项重复“设备值”或“已读取”。修改项用边框颜色标记待应用；未设置、读取失败、写入被拒绝等特殊项显示局部原因。鼠标悬停输入框可查看已读设备值或历史值，用于比较草稿。

读取成功刷新输入及内部设备值，失败项保留草稿。点击“应用本页修改”只应用当前标签改动，每项等待受理后主动读回比较，结果在两行结果栏汇总；“发送完成”不能当作参数成功。参数操作期间普通操作互锁，停止可取消剩余请求；切页保留操作和草稿，普通停止保留已读值，断线或 MCU 重启将旧读回值标为历史。

Z 距离以正数下降/相对抬升显示，底层继续使用最高处 0、下方负值的绝对目标。修改下降距离时保留当前输入的抬升距离。所有设备参数仅作用于 STM32 RAM；路线待用速度明确标为浏览器本地设置。当前没有 STM32 Flash 参数保存及启动加载功能。

物料取放高度按场景块排列为下降距离与夹取后抬升距离，释放场景无需抬升输入时显示“—”。场景按工作区宽度排为一至三列；车载位置与自动取放速度并排。其他标签的参数按宽度自动排为一至四列，数值及单位对齐。RAM/读取提示移到“参数调试”标题旁，不单占参数区行；组内说明放在标题旁，减少上下滚动。

“夹爪到位等待”位于运动与标定的动作时序组，通常无需调整。它控制发出夹爪开合 PWM 指令后，到下一步 Z 动作之间的等待，不控制舵机速度，也不是到位反馈。固件默认 500 ms，闭合后再提起、松开后再退出各等待一次；保留 `grab get/set close_ms`，本轮未改变固件默认和取放流程。

ID 8 车载转盘为三仓、1∶1 直连。首次失能后人工对齐首仓，再使能并“保存机械零点”；以后点击“就近回零”，成功后自动建立第一仓参考。机械零点保存在 ID 8 驱动器；旧“建立转盘参考”仅记录 STM32 软件偏移，仍不回零/清零。第二、第三仓角度和车载 X 位置需要标定，未设置时拒绝相关动作。上电三仓待核对，确认实物后可点击“三仓为空”或逐仓校正。转盘参考、到位和库存可从状态区查看；库存来自人工核对和软件动作结果。

视觉页按编号环、物料取放、动态追踪、路线任务和仅识别分组，通过参数链接直达对应页。单件支持原料入仓、加工区夹取入仓、从仓内取出向粗加工区/暂存第一层/第二层竖直释放、显式返回外侧观察姿态。完成后可以显式开始下一件；`align` 继续保持只对准及 HOLD。路线任务标签中后向机械臂两批任务使用 `grab mission`。

旧“历史视觉诊断”页面入口已删除。2026-10-09进一步删除独立Base/X对准 `ArmVision` 固件模块、相关 `vision` 命令目录和PE2旧启动调用；当前使用 `grab align color|ring`。`material auto/status/stop` 保留，旧物料搜索的参考/标定命令改为 `material ref`、`material calib <颜色>`，不再依赖已删除模块。运动配置表单统一位于“参数调试”，通过“调整运动参数”进入。

参数顶部返回链接恢复来源子页与滚动；侧栏直接进入没有虚构来源。地图图层选项、视觉选项和参数草稿保留，地图始终显示完整场地；离线模拟切出后暂停，返回不自动续播。`#params/<分类>/<参数>`、`#map/<子页>` 兼容原短链接，导航不会自动读取、写入、开启遥测或运动。

软件回归与界面预览不替代实车标定；具体参数键、动作顺序与停止语义见[当前协议](../../../docs/上位机协议.md)。

4. 看有效点数、当前圈编号和更新时间。每圈120个角度分区各取最近有效点，保留实际角度与距离；收片中、完整圈、无新数据及已停止分别标明。无线传输只取最新圈，采集圈号可能跳跃，这是跳过过时圈以避免延迟。
5. 要分析小圆柱、墙面或解析细节，停止实时查看后使用“诊断扫描一圈”保留完整点云和原始字节。实时120点是显示预览，不用于替代完整建图或诊断结论。

实时查看不清除已有完整地图、路线或诊断，图层保留来源；也不会自动执行小车路线。切页、切视图、打开页面或重连均不启动实时扫描，断线后的点云标为历史。实时点云和静态扫描不能同时占用雷达。

导出JSON包含 `snapshots.map/path/points/cloud/params` 与参数、离线副本。也可导入最小 `{mask,counts,pose,params,points,cloud,coordinate_frame}`；mask低25位，counts从底部行到顶部行、每行左到右；path points为 `[x_mm,y_mm,station,visit]`，cloud.points为 `[angle_tenths,distance_mm,energy]`。选择“旧参考地图”时点和pose按 `T(x,y)=(2400-y,x)`、格位按90°逆时针变换到当前图；raw极坐标角保持原值。设备快照只有相同session/origin/map/scan的点云用于离线重过滤，防止新地图和旧点云混用。

USART1继续115200 / 8N1、由用户选串口。雷达数据为 `@RADAR <JSON>` v1：map第0页元数据，后续页按offset拼齐25格计数；path第0页含路线元数据，各页按offset拼接完整路径点；points/cloud按scan ID读取；params10页按`radar fetch params 0 <page>`读取。2026-10-06正式监控“扫描3圈并规划”使用`radar scan lower|upper 3`，同一安装/筛选连续三个有效完整圈，每圈判障后取有效障碍并集，再统一规划；任一圈命中保留，不要求三次命中，counts为累计诊断，按需cloud仅最后一圈。旧单圈命令及备用F1雷达页不变。扫描完成后一次`radar result <plan>`回传map/path（常见2+3页，实际页数随数据长度），只补缺页；不反复逐页往返，不自动下载完整云。结果页100ms非阻塞调度用于避免无线突发丢字，不恢复USART1全局30ms等待。进入页面及重连不发指令，不自动运动。点云页走独立数据通道，不铺到网页/CMD终端与JSONL终端日志；底层RX二进制仍保留诊断。扫描、规划及完整点云读回不要求先开启实车遥测，运动按钮才发 `radar nav start <speed>` 或 `radar task start <speed>`。组合测试保留模拟任务码，在扫码工位交接后到首个原料工位执行红色pick。

`radar status` 返回状态、三页诊断和最近完成圈的起点证据（兼容旧版诊断）；`radar start status`只读起点结果。qr/raw/conflicts均为[右上,右下]原始计数和冲突掩码，详细证据保留在诊断及原始报文。终端中文摘要显示接收字节、有效测量包、校验/长度异常、覆盖丢失字节、报警次数、最近报警码及距离单位，还显示USART2累计发送完成、最近发送命令、发送/串口错误及DMA接收就绪。发送完成属于MCU侧结果，不能当作雷达已经接受指令。切到“原始报文”后再次查询，可查看完整 status 和 diag。右栏“配置摘要、诊断与执行说明”也保留这些字段。雷达帧允许带控制台 `arm>` 提示符，提示符不参与 JSON 解析，原始终端文本保持原样。地图/点云/参数分页仍不铺到终端。`frame_resync` 表示校验或长度错误后重采当前不完整圈；`scan_timeout` 表示10秒内未得到完整有效圈，不能仅凭该状态判断接线、波特率或雷达故障，需结合诊断计数定位。

“雷达建图 → 通信检查 → 验证雷达通信”发送`radar probe`，通过原有USART2查询雷达序列号，不增加接线、不启动旋转或扫描，不改参数和地图；也可在手动终端输入同一命令。等待约2秒看右栏结果，再点“读取验证结果”（`radar probe status`）取得完整证据。它不重复查询，可在停止锁定期间使用；正在扫描时先正常停止扫描并等当前STOP发送结束。进入页面不会自动发送。

| 验证结果 | 含义与下一步 |
|---|---|
| 往返通信已确认，显示SN | 本次LUUIDH查询后收到PRODUCT SN身份应答；再用radar status/scan检验测量数据是否恢复 |
| MCU USART2发送完成，只收到报警 | MCU已完成发送，雷达接收流仍在报故障，尚未确认查询回复；保留SN/原始RX/报警码进一步定位，不直接判定降压模块有问题 |
| 收到数据但身份未确认 | 查看原始RX片段；命令回显和测量流都不能作为身份应答 |
| 查询窗口无数据 | 查询没有得到接收证据；结合radar status的DMA就绪、串口错误及发送计数分析 |
| 发送忙、错误或超时 | 问题位于MCU发送阶段，不能描述为雷达拒绝；保存完整诊断 |

日志中的“雷达通信证据”显示最多24字节原始RX和单独提取的SN；查询帧也保留在桥接JSONL/CMD终端。原始片段为`CE CE CE CE 00 01`时，可独立核对报警字节与网页0x0100解码；它仍是雷达报告的故障，不等于已经测出外部5V实际异常。停止/查询结束保留结果，重连或MCU重启标为历史。软件模拟验证覆盖了持续报警中插入分包SN、无回复、回显、发送失败和历史地图保留，实机身份回复须使用新固件现场验证。

如果接收字节数恰好等于报警次数×6且有效测量包为0，当前接收的是报警包，无法生成点云。用户提供的LDS50C说明书电源故障示例为 `CE CE CE CE 00 01`，按低字节在前解析，网页最近报警码为 `0x0100`（JSON为256）；不能将示例中的字节 `00 01` 直接当成数值 `0x0001`。其他码只显示原值。计数是累计值，故障排除后检查测量包增长、报警增量停止，并重新静止扫描。底部“停止锁定”会禁用扫描等普通命令；确认车辆实际静止后点击“解除停止锁定”恢复入口，该操作不发送运动命令，也不自动续跑任务。


### 原始包诊断与真实网格（2026-10-04）

地图网格按固件实际的5×5边界绘制：`150、550、1000、1400、1850、2250 mm`，场地边缘150 mm范围不属于这25个计数格。黄色为四个固定工位格，红色为本圈扫描新增障碍格；两者不能都算作实际放置的黑色圆柱。

雷达建图页新增“诊断扫描一圈”“下载本次诊断”“导出同圈诊断”。先确认现有起点与朝向读回，再点击诊断扫描；命令为`radar debug scan upper|lower|auto`。它仍只静止采集一个有效完整圈，并请求停止；不执行底盘路线。普通扫描不会记录原始包。

诊断自动下载绑定本次扫描的地图、规划、完整点云及USART2原始字节，全部下载完成后才开放同圈导出。自动起点无法区分时仅下载本圈点云和原始字节，不混入历史地图。停止、超时或原始记录未覆盖完整圈时，可导出明确标为不完整的原始诊断，不能当作完整圈重放。原始字节页不铺到终端；页面单独显示下载进度，可取消并重新下载。

固件为显式诊断保留16KB滚动窗口，记录解析前的测量包、状态包、报警、ASCII及异常字节，附同圈字节范围、CRC32、单位和冻结过滤/位姿参数。窗口前缀被覆盖不一定丢失有效圈，以`raw.complete`及圈范围为准；新普通扫描不会改写已下载的诊断文件。导出按钮位于雷达建图页诊断区，也可从离线对照页导出已完成的当前诊断。

解包命令在项目根目录执行：`python Code/tools/radar_capture_unpack.py <诊断JSON路径>`。结果保存到`.embeddedskills/radar-replay/`，含`raw.bin`、完整圈对应的`circle.bin`、元数据和完整点云JSON。工具只核对传输与身份并提取字节，后续用真实数据分别重放F1/F4解析器；本轮没有凭截图修改围墙过滤或障碍识别算法。

## 连接、断开与回复

- 终端默认“中文摘要”，可切换“原始报文”，选择在浏览器保存。命令仍为 ASCII；解析、导出和桥接日志保持原文。摘要隐藏已发送命令的回显与空提示符，未知回复/字段保留，故障即使以 `OK` 开头也会标红。
- `info` 会解释串口、ID、方向、速度及总线状态；`bus recover complete` 明确区分完整恢复和部分恢复，不自动续跑。普通恢复保留有效配置、参考和库存；网页“解除停止锁定”不代表电机总线恢复。
- 视觉无效帧显示“当前无有效视觉数据”；这不等于识别程序确认没有物体。有新鲜坐标时继续显示 `Color = red，CX = …，CY = …`。
- 点击“断开”立即显示“正在停车并断开”，禁止普通发送和重复断开。匹配本次 token 的四轮停稳反馈到达后关闭串口；最多等 6 秒，失败显示停止未确认并保留停止锁。
- 各任务停止按钮可在普通发送未结束时使用。待写出的普通命令会取消，停止命令按顺序优先发送，仍保持原作用范围；“停止协同对准”仍是 `grab stop`。已写出的命令不会伪装成未发送，也不会自动重发。
- 准备流程持有专属回复期间，其他页面的查询也会被拒绝，以免同名回复混入。先取消准备后查询。连接/断开不会自动续跑。
- 启动状态按实际报告展示回零、等待验证、验证中、就绪或失败。正常启动不再输出六次 Flash ID；OLED 在控制空闲后初始化。

固件需更新后才能使用停车主动上报和独立反馈采集；新版桥接仍保留旧固件每 2 秒查询的兼容路径。原有本地服务进程须退出并重新启动 `start.cmd`，网页刷新后加载新显示逻辑。实车使用前独立验收无线吞吐和停止耗时；浏览器断开不是全机械臂停稳确认。


适配当前 STM32 USART1 文本控制台。网页、CMD 和调试脚本通过本地 Python 服务共享一个串口连接。本地服务是唯一连接方式。

当前实车路线输入范围为10～5000 mm/s（默认200）；固定、雷达和首件组合入口共享“下次启动速度”。距离任务以300 mm/s²加减速，暂存位最后75 mm进出不超过min(启动速度,50)。浏览器旧速度高于200时一次性迁移为200并保留原值，已有10～200设置保留；之后允许主动设置至5000。保存或切页不发运动命令，启动后整条路线继承速度。轮速软件上限仍为Emm F6的3000 RPM，尚未验证带载性能。页面分别显示启动设置、阶段限速和四轮反馈；自动模式在反馈确认停稳后继续，附加等待已取消。

## 速度曲线实验（离线教学）

启动控制台后，在「地图与遥测」点击「打开速度曲线实验」，或访问同一服务下的 `speed-lab.html`。实验复用原2400×2400 mm场地、300×300 mm车体外框和默认16段离线路径，每次选择其中一段比较；不读取路线编辑器尚未保存的临时修改，不连接串口、不发送实车指令。

- 蓝色：线性加减速，短段形成三角速度曲线，达到速度上限则加入匀速段形成梯形。
- 橙色：半余弦加减速，两头加速度为零，中间逐渐增大再减小。
- 「相同用时」保持两条曲线的路程、峰值速度、加速/匀速/减速时间相同，半余弦峰值加速度为线性的π/2倍。
- 「相同最大加速度」同时遵守相同速度上限和峰值加速度限制，分别计算可达峰值及运动时间。
- 可播放、暂停、复位，拖动时间滑杆或曲线观察两车位置、速度、加速度。页面隐藏或动画停顿超过250 ms自动暂停。
- 红色表示绝对加速度超过手动设定的假设牵引上限，并显示整段超限时间。它是牵引需求示意，不是实测摩擦系数、打滑率或滑移距离；地图仍按无滑移运动学绘制。

实验不套用原离线模拟100 RPM上限，也不复刻固件的距离反馈、延迟制动、末端慢速和停稳逻辑，不能将演示结果当作实车速度或停车验收。公式、验证条件见[开发记录](../../../docs/开发记录/2026-09-24速度曲线离线地图实验.md)。

## 启动与连接

需要 Python 3 和 pyserial；缺少时执行 `python -m pip install pyserial`。Windows 推荐双击上一级目录的 **启动控制台.lnk**：自动启动服务并打开网页，服务窗口初始最小化；已有默认端口服务时直接打开现有页面。也可双击本目录 `start.cmd`，或运行：

```powershell
python serve.py
```

用桌面 Chrome/Edge 访问 `http://127.0.0.1:8765/`，不要直接双击 HTML。服务仅监听回环地址，无需 npm、云部署或网络字体。更新程序后退出旧服务再启动。

- 启动服务不会自动连接串口，连接、刷新和重连不会启动运动。
- 网页共享模式先在“串口”列表中选择设备，再点击连接；没有默认 COM 号。列表显示端口号及设备名称（如 CH340），默认通信格式仍为 115200 / 8N1。
- CH340 换 USB 接口后点击“刷新串口”，重新选择当前端口。刷新仅枚举设备，不打开串口、不发送指令；只有一个端口时也不自动选中。页面不持久保存端口选择。
- CMD 输入 `ports` 查看列表，输入 `connect COM7` 连接指定端口（COM7 仅为示例）。仅当启动时明确传入 `--serial-port COM7`，才允许省略端口输入 `connect`；网页始终自行选择。
- 工程工具配置中的串口与网页默认值独立。占用时先释放其他串口助手。

## 工作台布局

桌面采用左侧连接与导航、中央终端、右侧任务操作；参数页占满侧栏右侧工作区并只留两行结果栏，地图页使用专用地图与操作区布局。默认打开“系统与标定”；七个工作页见下表。操作区单独滚动，底部停车区始终保留；窄屏改为上下分区。当前默认蓝色，可切换黑色。本版不展示人物背景，浏览器中已有的背景偏好不删除。

点击发送操作时，终端顶部立即显示原始命令与“待发送”，日志记录请求；串口实际写出后才增加 TX，并显示“已写出 · 待设备确认”。写出不代表动作完成，失败或拒绝发送不会增加 TX。顶部最近操作不受日志筛选影响。共享服务停车单独显示“请求停车”，以底部停车状态和实际 TX/RX 为准。

主界面只保留常用操作：读取位置、夹爪 PWM/释放、单轮调试及旧速度测试等不再单独铺设控件，协议能力仍保留，可在手动终端输入。夹爪“打开”发送 `grip open`（500 µs），“夹取”发送 `grip catch`（700 µs）；页面脉宽标注依赖同步更新的固件，点击只表示命令已发送，不表示已实际抓住物料。回零与零点、四轮状态、准备跑图及高级运动默认折叠，参数页的参数组全部展开。底盘反馈对象固定为四轮，不再提供单轮或协议单位选择菜单。离线地图的播放按钮独立可见，路线表和模拟参数按需展开。

### 单件取放与视觉诊断

视觉页默认打开“编号环”。“物料取放”提供单件动作；“回零与通信恢复”提供三轴/单轴回零与总线恢复，参数通过链接进入统一参数页。仅协同对准与视觉抓取可选择 1～6 号物料颜色，原料入仓可指定仓位或自动选择最低编号空仓。直接输入不带颜色命令时，仍默认蓝色对准（3）和红色抓取（1）。

| 显式操作 | 命令与终点 |
|---|---|
| 原料固定夹取入仓 | `grab start fixed [slot color]`，从人工已对准位置夹取，抬升、收回 X、分度并放入车载仓，再返回外侧观察姿态 |
| 仅协同对准 | `grab start align [color]`，识别所选颜色，底盘与 X 协同修正；停稳后 HOLD，不执行下降夹取 |
| 原料视觉夹取入仓 | `grab start pick [color slot]`，沿用协同对准，通过到位判据后完成夹取、入仓与返回 |
| 加工区夹取入仓 | `grab store proc <slot> <color>`，在人工已完成水平对准的位置夹起加工物料并入仓 |
| 从车载仓取出释放 | `grab take <slot> rough\|temp1\|temp2`，取出后向已对准的粗加工区、暂存第一层或第二层竖直释放 |
| 返回外侧观察姿态 | `grab return`，参考仍有效时显式返回，不改变库存 |
| 蓝色首件路线入仓 | `grab route [speed]`（默认200），右下起点、后向姿态，二维码直接通过，到原料台固定抓蓝色入第一仓并收回朝后结束；不改任务码 |
| 读取状态 | `grab status`，显示操作、场景、仓位、完成结果及组合路线状态 |
| 停止当前任务 | `grab stop`，取消自动推进并请求停止；保留夹爪输出与 Z 承载，停止反馈独立确认 |

单件完成后释放任务占用，可以显式开始下一件。Base 内部转向以保存的实际外侧参考为基准；仓内动作结束后返回同一参考及观察姿态，连续取放不累加 −180°。人工改变原点或观察姿态仍会使相关参考失效，原因由状态说明。普通停止和 `bus recover` 保留有效配置、参考和库存；涉及占用变化的中断只将对应仓位标记为待核对。

状态快照显示任务阶段、目标颜色、操作/场景/仓位、缺项、X/Z 反馈、视觉坐标状态及停止确认。超过5秒或断线后标为历史；点击刷新才查询，不额外自动轮询。`state=stopping` 表示仍在等停止确认；取消后 `state=idle stop_confirmed=1` 才表示设备报告停止完成。`state=complete` 表示软件单件流程完成，`result=stored/released/returned` 分别表示入仓、释放或返回；真实夹持、释放和碰撞余量由实物验收。`align` 的 HOLD 仅表示对准完成。

“仅识别”单独检查 B2 编号环/物料圆心和坐标，停止识别请求不等于停止当前取放任务。当前抓取参数请使用参数页。

当前视觉联动默认：底盘上限40 mm/s、X上限10 mm/s、收敛增益1.2 s⁻¹、加速度60 mm/s²；自动Z速度55.5556 mm/s，在现有尺度下对应500 RPM，观察/提起/色环共用；物料夹取下降独立使用z_pick_speed默认111.111 mm/s（1000 RPM），正式取料与追踪夹取共用，回零速度独立。参数页“视觉对准”中的`vision_wait_ms`默认12000 ms，用于首次等待颜色及停稳后重新识别；有效坐标年龄仍为1000 ms，短漏检减速宽限仍为250 ms。恢复次数仅作诊断，不因已恢复两次退出任务。超过当前等待窗口报告原因并请求停车，人工停止仍随时生效。12秒是识别等待窗口，不是比赛判停计时器。

抓取参数与普通轴配置只在 STM32 RAM 生效；参数页打开、切页和连接不自动读写，也不使用网页预填值代替设备值。调试预设只填草稿，仍须主动应用并读回。普通轴配置通过参数页“运动与标定”调整，手动终端保留 `config <axis>` 兼容命令。关于软件默认值、读回和标定单位，见[当前协议](../../../docs/上位机协议.md)及[ID 8 单件取放记录](../../../docs/开发记录/2026-10-03-参数控制台与ID8单件取放.md)。

二维码页的 `qr read` 读取缓存，不触发扫码器，也不消费主循环任务码；跟随通过显式 `qr stream on/off` 控制，新码通知最多 5 Hz。没有新码不等于扫码器离线。

## 准备跑图与实车路线

在“地图与遥测 → 实车监控”展开实车路线准备与执行，点击“准备跑图”。本车采用已确认的 Emm42 默认配置：3200 控制脉冲/电机轴圈、65536 位置反馈单位/电机轴圈、Receive 应答，仅修改 ID。准备流程直接采用这些协议参数，不再要求选择应答模式或勾选实测位置单位。旧配置文件中的 profile/units 不覆盖本车预设。

“本车配置”只需保存四轮安装方向确认，取消勾选后也可保存以撤销资格。准备时只应用到 MCU RAM，不修改驱动器或 Flash。现场仍须确认小车实际摆放位置与朝向。协议数值已知不代表实车距离已验收。

“准备跑图”依次检查任务空闲、应用位置单位并检查固件默认 Receive、开启四轮反馈并检查静止状态、检查 IMU 资格；已有上电验证资格时直接复用，必要时执行 5 秒静止验证。操作者确认车体中心在右下起点 `(2250,150)`、车头朝上、整车静止后，程序设置 `(2250,150,90°)` 原点并开启新遥测会话，收到有效起点反馈后完成准备。

准备期间共享服务限制其他来源修改状态，查询、取消和停止仍可用。准备完成不启动运动。

| 实车操作 | 命令 |
|---|---|
| 开始第 1 段 | `chassis route start <速度mm/s>` |
| 自动跑完整路线（停稳后继续） | `chassis route auto <速度mm/s>` |
| 手动下一段 | `chassis route next` |
| 取消路线 | `chassis route cancel` |
| 查询路线 | `chassis route status` |

固件固定15目标依次到 `(2100,1200)`、`(2100,2100)`、`(1200,2100)`、`(1200,350)`、`(1200,1200)`、`(350,1200)`、`(1200,1200)`、`(1200,2100)`、`(1200,350)`、`(1200,1200)`、`(350,1200)`、`(1200,1200)`、`(2100,1200)`、`(2100,300)`、`(2250,150)`。首腿保持90°先斜移到(2100,300)，再沿X=2100直行到扫码位；长段先转向再前进/后退，工位最终恢复90°；暂存在(425,1200)转向后低速侧移75 mm进站，退出顺序相反。每个业务目标只需一次next，内部阶段自动执行。第13目标只经过扫码坐标。到点是编码器反馈估计进入容差，不代表完成扫码、视觉精对准或抓取。完整实车检查按[验收顺序](../../../docs/开发记录/2026-10-03-底盘低速转向路线与验收顺序.md)执行。

`chassis run vx vy 0 hold_ms` 自动保持起步HWT101航向，需要本次验证通过且数据新鲜，不需要地图原点；非零角速度执行给定转向。`chassis heading`使用模块角度；新增`chassis turn <地图航向_deg>`使用地图绝对角度（−180～180），两者均需地图锚点。网页角速度输入和地图速度显示采用°/s，`chassis run`底层协议仍采用rad/s（网页100对应发送1.745329）。turn纯转向、500 ms起步、转向上限100°/s，进入2°容差并取得三组至少500 ms的新鲜四轮停稳反馈后完成；转后角度偏离在原超时内继续修正，保留原点和锚点。直行航向纠偏仍采用0.15 rad/s限幅。网页刷新与新固件烧录分别生效，旧固件会拒绝超出旧上限的转向请求；原始终端与遥测协议中的rad/s不改单位。当前C路线预览从服务读取转向上限，旧预览需重新规划。

## 停车与解除锁定

底部常驻两项：“立即停止底盘”与“全部轴 / 关联任务停止”（`stop all`）。前者走本地服务停车流程；后者沿用固件全部轴/关联任务停止逻辑。抓取自身的 `grab stop` 统一放在视觉页顶部“停止并退出”。停止命令及反馈语义没有改变。

CMD 按 Ctrl+C 或网页“立即停止底盘”会取消准备、清空待发普通命令、锁定新的运动请求并优先请求底盘停车。CMD 窗口继续运行；`quit` 先执行停车流程、最多等待 6 秒后退出。

停车通信节奏（2026-09-22）：立即发送一次 Ctrl+C 和带编号停车请求，不再附加无编号文本停车。未受理时每2秒重试同一编号，最多3次；受理后每2秒查询停车状态。总等待6秒，超时停止自动发送。连接未断开、未解除锁定且编号匹配的迟到回复仍可更新发送/停止结果，不重新启动查询，不自动解除锁定。

状态依次区分请求已发出、MCU 受理、电机总线停车发送完成、四轮反馈确认停止；没有新鲜有效反馈时不能显示已确认停车。查看结果后明确解除锁定，任务不会自动恢复。

`stop all`、视觉停止、底盘停止各有范围；统一停车属于软件措施，不是硬件急停。关闭网页、强制关窗口或无线失联无法保证停车。本地服务的主动断开有停车流程。

## 地图与遥测

### 离线模拟

“历史16段时间示意／手工编辑”保留原时间路线和100 mm/s、100 RPM模拟限制，可编辑至50段，刷新恢复默认。“当前固件路线预览”通过离线服务编译同一C路线/阶段模块，网页只显示和运动学播放转向、前进/后退及接驳；不发送运动命令。足迹诊断标出坐标、阶段和干涉对象，格路可达与300 mm车体能否转向分别展示。

离线播放只作用于浏览器，**不会上传路线或发送实车运动命令**。1/4/10 倍速只改变观看速度；离开页面、隐藏浏览器或停顿超过 250 ms 会暂停。模型采用半余弦起停、最大 20 ms 中点积分，并可量化整数 RPM。

场地为 2400×2400 mm，原点在左下；车体名义外框 300×300 mm，碰到边界、工作区或转盘时终止模拟。默认几何 L=210、W=240、D=80 mm、G=1，包含估计和假设，只用于模拟；不涵盖展开机械臂、随机障碍、驱动器动态和实车定位误差。

默认理想路线运动 154 秒、含占位停留 170 秒，不包含实际取放和视觉耗时。整数 RPM 模式末段可能触发边界保护，需要末端精定位；路线结束与整车返回原启停区合格分别判断。

### 在线遥测

手动选择指令推算或反馈估计并开启遥测，发送 `chassis stream on <非零会话编号>`；关闭发送 `chassis stream off`。准备跑图也会显式建立遥测会话。

`@CHASSIS` JSON 必须先收到同会话 config，再接受 state。在线几何来自 MCU 配置，不使用离线假设。指令推算不等于测量；反馈估计使用 MCU 位姿、轮位置与航向有效性，不以目标 RPM 代替原始反馈。

当前状态周期 2000 ms，首次等待配置最多 8 秒，配置后超时为周期三倍；旧 config 缺少周期字段时按 200 ms 计算。样本相对 MCU 时间的 600 ms 新鲜度要求保持不变。坏帧或超时清除实时状态，保留标记为过期的最后位置与会话；同会话恢复后自动显示，并断开旧轨迹。串口重连、主控重启或主动关闭后需要手动开启；时间跳变、会话或轨迹序号变化会断开轨迹。

## 日志与排障

- 公共终端支持模块与 TX/RX/系统筛选、跟随、清空和导出，最多保留 500 条；清空日志不清二维码或地图状态。
- 终端默认勾选“精简抓取日志”：重复的 `OK grab state=...` 状态报告隐藏并显示隐藏条数；状态、原因、停止确认等关键字段变化、错误、视觉坐标及手动查询回复仍显示。取消勾选可查看当前保留的完整日志，偏好会记住。此功能仅影响显示，不发送设备命令、不代表任务已停止；导出和本地桥接原始日志不受影响。
- 设备回复中的 `accepted` 只表示请求受理；到位与停止必须读取对应反馈。
- 主题与日志显示偏好保存在浏览器；旧常用指令收藏不再作为现行操作入口。
- 服务原始收发记录在项目 `.embeddedskills/logs/serial/`，用于排查丢字、串口写出及反馈。
- 服务不可用时检查 CMD；串口占用时释放其他程序；准备超时时看回显、ERR、四轮反馈和 IMU 状态，不自动重复运动。
- `bus_locked=1` 是总线隔离；`chassis reset-confirmed` 只能在驱动器已经实际复位后使用，它不会复位驱动器。
- 上电首次电机发送前的单独 UART5 帧错误可自动重启接收，恢复后继续原回零流程；`info` 的 `[MOTOR BUS STARTUP]` 保留恢复次数和时刻。首次发送后的故障仍按总线隔离处理，接收重启失败报告 `rx_restart_failed`。`home_request_failed` 后的 `x_ppm` 缺项可能是回零未完成的结果，应先读 `info` 的总线首次故障，不以手动填写参数代替回零验证。
- 本车 TTL 多机接线实测（2026-09-27）：四轮驱动器断电但 TX/RX 仍接入公共总线时，出现 UART5 帧错误并锁定；全部驱动器上电后连续四次 `state x` 正常。测试机械臂时保持总线上驱动器上电；若需要单独供电，应在全断电后隔离未供电节点的 TX/RX 支路并保持工作节点正确共地。详见[首次锁定诊断记录](../../../docs/开发记录/2026-09-27-UART5首次锁定诊断.md)。

## 2026-10-07 粗加工1号黑白环手动装料测试

入口：视觉任务 →「粗加工1号黑白环 · 手动装料放置测试」。小车人工摆在1号环前，先空爪对准，再人工装入蓝色物料并点击闭合夹爪，最后执行下降放置。官方地图粗加工环从左到右为3、2、1，圆心间距150 mm；环是黑白印刷标记。

- `grab ring align`：使用现有B2黑色（5）通道，复用协同对准、停稳与反馈流程，观察X起始10 mm；完成后停止视觉请求，保持底盘/X，进入等待装料状态。
- `grip open` / `grip catch`：色环对准完成的保持阶段允许人工夹爪操作；下降期间仍由任务控制夹爪。
- `grab ring place -150`：Z绝对位置下降至−150 mm，到位后松爪，再提起到本次对准的观察高度；保持Base/X，不从车载仓取料、不改变库存。完成后可再次人工装料并放置。
- `grab status`：读取ring_align/aligned、ring_place/pending或ring_place/released；`grab stop`结束测试。

B2仅返回目标颜色圆心，不识别数字1。此入口依赖人工摆位，让1号环成为相机主要目标，不能保证画面中多个环时自动选择编号1。沿用香橙派现有程序，未修改或部署视觉脚本。黑色环实际识别与放置精度需实测。

Z回零验证后软件下限由−80改为−150 mm，依据本轮用户确认的实际可夹取高度；原料夹取、车载放置和正式粗加工参数各自保留，未以此次测试覆盖正式任务高度。

- `grab ring place <z_mm>`：完成对准并人工闭合夹爪后，Z下降、松爪、提起；不从仓取料或改变库存。

## 静态对准与手动码垛测试（2026-10-08）

控制台入口：视觉任务 → 码垛。颜色与编号环统一静态对准入口：`grab align color <1..6> [z_mm] [stay]` / `grab align ring <1..3> [z_mm] [stay]`。旧色环和物料对准指令保留兼容。颜色准心(334,338)、编号环准心(378,333)分别保留；共用静态调速参数，动态追踪参数独立。

1. 选择下层物料颜色，点击“静态对准并补偿”，例如蓝色发送 `grab stack align 3`（绿色为4）。Z保持最高，底盘和X先对准原绿色准心并停稳，再执行码垛专用固定补偿：让目标在画面中向右39、向下1像素（DX=39、DY=-1），再次停稳后等待装料。准心参数不修改，实际位移由现有视觉矩阵换算；普通颜色/编号环对准和动态追踪不启用此补偿。
2. 人工放入上层物料，点击闭合夹爪：`grip catch`。
3. 调整Z绝对高度：`grab stack lower -100`。仅移动Z并保持夹持，可向上调整或覆盖尚未完成的目标。
4. 确认高度后单独松爪：`grab stack release`。松爪保持当前高度；另用 `grab stack lift` 提至最高。
5. 随时用停止并退出：`grab stop`。

鼠标悬停高度尺滚动，每格1 mm；滚动期间仅预览，停滚满1秒后发送最后一个高度。数字输入只更新目标，点击下降按钮执行。停止、断线、切页、故障与设备重启取消待发高度，不自动重发。网页范围−150～0 mm，固件按当前Z实际配置限制；收到设备到位反馈才显示到位。此测试不从车载仓取料、不驱动转盘或修改库存。

# 八千代·巡航 · 本地小车控制台

## 参数页与单件取放（2026-10-03）

“参数调试”使用物料取放、车载转盘、视觉对准、运动与标定、雷达与路线五个顶部标签，卡片全部展开。背景可切换蓝色或黑色，不再提供白色主题；默认蓝色，选择保存在本机浏览器，旧浅色偏好改用黑色。该页占满主工作区，固定两行结果栏显示读取进度、设备拒绝或读回结果；其他页保留完整终端，原始日志继续记录。

先选设备并连接，再点击“读取当前全部参数”，一次覆盖五个标签的设备参数，路线速度属于浏览器设置、不参加设备读取。初始空框为未读取；设备返回 `unset` 时留空并标记未设置。正常参数行只显示名称、输入框和单位，未读取、读取进度及完成数量统一显示在顶部，不逐项重复“设备值”或“已读取”。修改项用边框颜色标记待应用；未设置、读取失败、写入被拒绝等特殊项显示局部原因。鼠标悬停输入框可查看已读设备值或历史值，用于比较草稿。

读取成功刷新输入及内部设备值，失败项保留草稿。点击“应用本页修改”只应用当前标签改动，每项等待受理后主动读回比较，结果在两行结果栏汇总；“发送完成”不能当作参数成功。参数操作期间普通操作互锁，停止可取消剩余请求；切页保留操作和草稿，普通停止保留已读值，断线或 MCU 重启将旧读回值标为历史。

Z 距离以正数下降/相对抬升显示，底层继续使用最高处 0、下方负值的绝对目标。修改下降距离时保留当前输入的抬升距离。所有设备参数仅作用于 STM32 RAM；路线待用速度明确标为浏览器本地设置。当前没有 STM32 Flash 参数保存及启动加载功能。

物料取放高度按场景块排列为下降距离与夹取后抬升距离，释放场景无需抬升输入时显示“—”。场景按工作区宽度排为一至三列；车载位置与自动取放速度并排。其他标签的参数按宽度自动排为一至四列，数值及单位对齐。RAM/读取提示移到“参数调试”标题旁，不单占参数区行；组内说明放在标题旁，减少上下滚动。

“夹爪到位等待”位于运动与标定的动作时序组，通常无需调整。它控制发出夹爪开合 PWM 指令后，到下一步 Z 动作之间的等待，不控制舵机速度，也不是到位反馈。固件默认 500 ms，闭合后再提起、松开后再退出各等待一次；保留 `grab get/set close_ms`，本轮未改变固件默认和取放流程。

ID 8 车载转盘为三仓、1∶1 直连。人工对齐首仓后“建立转盘参考”；不会自动回零/清零。第二、第三仓角度和车载 X 位置需要标定，未设置时拒绝相关动作。上电三仓待核对，确认实物后可点击“三仓为空”或逐仓校正。转盘参考、到位和库存可从状态区查看；库存来自人工核对和软件动作结果。

视觉页常规标签为“单件抓取”和“相机调试”，保留任务操作及状态，通过“调整取放参数”“调整视觉参数”直达对应页。单件支持原料入仓、加工区夹取入仓、从仓内取出向粗加工区/暂存第一层/第二层竖直释放、显式返回外侧观察姿态。完成后可以显式开始下一件；`align` 继续保持只对准及 HOLD。完整两批赛事路线与自动码垛调度待后续。

旧 `material auto`、独立 Base/X 对准和旧标定收拢到按需展开的“历史视觉诊断”，不再作为常规标签或当前单件取放的准备步骤。旧标定不会更新当前 GrabTask 的抓取响应矩阵，相关命令和固件模块仍保留；固件 PE2 实体按键调用不变。机械臂页只保留运动、夹爪、回零及零点操作，运动配置表单统一位于“参数调试”，通过“调整运动参数”进入。

参数顶部返回链接恢复来源子页与滚动；侧栏直接进入没有虚构来源。地图图层选项、视觉选项和参数草稿保留，地图始终显示完整场地；离线模拟切出后暂停，返回不自动续播。`#params/<分类>/<参数>`、`#map/<子页>` 兼容原短链接，导航不会自动读取、写入、开启遥测或运动。

软件回归与界面预览不替代实车标定；具体参数键、动作顺序与停止语义见[当前协议](../../../docs/上位机协议.md)。

## 雷达地图工作区

当前地图保留原 SVG 场地、车辆尺寸与坐标朝向，分为“实车监控 / 雷达建图 / 离线对照”三个页签。完整场地、场外原料台及标注等比适配可用区域，取消滚轮缩放、右键放大、左键拖动和“恢复视图”；滚轮用于页面正常滚动，远处点云不改变场地比例。鼠标读数仍通过地图坐标逆变换得到毫米，车辆、路径和点云的坐标变换保持一致。底部常驻最近操作与设备结果，可展开终端，停车区始终可见。

桌面右侧操作栏按工作区宽度的 38% 分配，范围 400～640 px；1001～1150 px 窗口使用 360 px，窄屏上下排列。SVG 背景按完整场地的比例和可用高度收紧宽度，减少左右空白，不裁剪场地或改变世界坐标。低高度窗口可滚动查看；场地名称至少 11 px、刻度与格内计数至少 10 px。坐标与障碍/点云图层集中在地图顶边，轨迹图例位于上方右侧，窄屏移到上方左侧；快照年龄和地图说明保留在图下。

右栏按当前页签展示：实车监控保留导航状态和遥测，15目标实车准备/执行、四轮数据按需展开；雷达建图按扫描与规划、读取快照、实车执行分组；离线对照保留副本规划、当前固件路线预览和历史16段时间示意，初始模型、路线表、过滤参数及详细结果按需展开。实车监控和雷达建图统一使用反馈估计的车辆标记与坐标读数，指令轨迹作为对照；离线对照显示独立的模拟车。切页只切换显示，不读取设备、不发送命令，也不自动运行模拟。

轨迹图例可点击显隐：紫色实线为编码器＋IMU反馈估计，橙色虚线为已发送轮速的指令推算，绿色实线为F407规划；离线对照另显示粉色虚线规划预览与蓝色实线模拟轨迹。在线两条轨迹默认都显示，图例选择和累计轨迹在切页后保留，隐藏轨迹不停止采集。规划路径由图例统一控制，不再保留重复的“规划”复选框；设备工位标记随F407规划一起显隐。两种位置不作平均，反馈不可用时不会用指令坐标冒充反馈位置。

- 实车监控使用固定15目标路线与原准备流程。雷达路线仍由F407执行，网页切页、刷新、重连不启动运动、不清设备任务。
- 雷达建图用于静止扫描、设备规划与主动分页读回。默认显示车辆、25格障碍和绿色实线设备路径；点云与格内点数按需打开。未扫描区域沿用场地底图，旧完整地图不会因停止扫描、失败或参数变化被清空；历史来源、结果年龄及需重新扫描原因会显示。
- 设备路径实线、本机离线规划虚线；离线16段运动学模拟独立保留。离线规划使用 `/api/radar/plan` 编译并调用 `Code/tools/radar_plan_cli.c` 和固件同一份 `radar_map.c`，算法标识 `radar_map_c_v1`，没有第二份JS寻路器。需要现有主机测试用GCC，无需npm安装。mask规划无需点云；点云重过滤可用显示抽样或完整4096点，抽样结果可能与完整设备建图不同。
- 点云每页3点、每秒请求一页；360点预览120页约2分钟，4096点完整缓存1366页约23分钟，只在按需慢速读取时传输。读取严格等待同ID页回复，期间可取消，取消只保留已完成快照。完整结果单独保存在浏览器本机存储，可导出JSON，不依赖终端历史2000条事件；重启或连接变化丢弃未完成页，已保存结果标历史。换设备后主动读取状态和新结果再使用。
- 参数调试页的“雷达与路线”含10项雷达设备参数，读取全部时复用完整分页读取；应用后读回核对。参数只存STM32 RAM，重启恢复固件默认值。起点安装参考预设为(2170,230,180°)，对应车在(2250,150,90°)，尚未实测标定；扫描结果的world pose单独用于投影，不覆盖此安装参数。

导出JSON包含 `snapshots.map/path/points/cloud/params` 与参数、离线副本。也可导入最小 `{mask,counts,pose,params,points,cloud,coordinate_frame}`；mask低25位，counts从底部行到顶部行、每行左到右；path points为 `[x_mm,y_mm,station,visit]`，cloud.points为 `[angle_tenths,distance_mm,energy]`。选择“旧参考地图”时点和pose按 `T(x,y)=(2400-y,x)`、格位按90°逆时针变换到当前图；raw极坐标角保持原值。设备快照只有相同session/origin/map/scan的点云用于离线重过滤，防止新地图和旧点云混用。

USART1继续115200 / 8N1、由用户选串口。雷达数据为 `@RADAR <JSON>` v1：map第0页元数据、1..5页各5格计数；path每页2点；points/cloud按scan ID读取；params10页按`radar fetch params 0 <page>`读取。点云页走独立数据通道，不铺到网页/CMD终端与JSONL终端日志；底层RX二进制仍保留诊断。扫描、规划及完整点云读回不要求先开启实车遥测，运动按钮才发 `radar nav start <speed>` 或 `radar task start <speed>`。组合测试保留模拟任务码，在扫码工位交接后到首个原料工位执行红色pick。

`radar status` 返回一条状态和两页诊断（兼容旧版单页诊断）。终端中文摘要显示接收字节、有效测量包、校验/长度异常、覆盖丢失字节、报警次数、最近报警码及距离单位；切到“原始报文”后再次查询，可查看完整 status 和 diag。右栏“配置摘要、诊断与执行说明”也保留这些字段。雷达帧允许带控制台 `arm>` 提示符，提示符不参与 JSON 解析，原始终端文本保持原样。地图/点云/参数分页仍不铺到终端。`frame_resync` 表示校验或长度错误后重采当前不完整圈；`scan_timeout` 表示10秒内未得到完整有效圈，不能仅凭该状态判断接线、波特率或雷达故障，需结合诊断计数定位。

如果接收字节数恰好等于报警次数×6且有效测量包为0，当前接收的是报警包，无法生成点云。最近报警码0x0001按用户提供的LDS50C说明书解释为电源故障；其他码只显示原值。计数是累计值，故障排除后检查测量包增长、报警增量停止，并重新静止扫描。底部“停止锁定”会禁用扫描等普通命令；确认车辆实际静止后点击“解除停止锁定”恢复入口，该操作不发送运动命令，也不自动续跑任务。


## 连接、断开与回复

- 终端默认“中文摘要”，可切换“原始报文”，选择在浏览器保存。命令仍为 ASCII；解析、导出和桥接日志保持原文。摘要隐藏已发送命令的回显与空提示符，未知回复/字段保留，故障即使以 `OK` 开头也会标红。
- `info` 会解释串口、ID、方向、速度及总线状态；`bus recover complete` 明确区分完整恢复和部分恢复，不自动续跑。普通恢复保留有效配置、参考和库存；网页“解除停止锁定”不代表电机总线恢复。
- 视觉无效帧显示“当前无有效视觉数据”；这不等于识别程序确认没有物体。有新鲜坐标时继续显示 `Color = red，CX = …，CY = …`。
- 点击“断开”立即显示“正在停车并断开”，禁止普通发送和重复断开。匹配本次 token 的四轮停稳反馈到达后关闭串口；最多等 6 秒，失败显示停止未确认并保留停止锁。
- 各任务停止按钮可在普通发送未结束时使用。待写出的普通命令会取消，停止命令按顺序优先发送，仍保持原作用范围；“停止协同对准”仍是 `grab stop`。已写出的命令不会伪装成未发送，也不会自动重发。
- 准备流程持有专属回复期间，其他页面的查询也会被拒绝，以免同名回复混入。先取消准备后查询。连接/断开不会自动续跑。
- 启动状态按实际报告展示回零、等待验证、验证中、就绪或失败。正常启动不再输出六次 Flash ID；OLED 在控制空闲后初始化。

固件需更新后才能使用停车主动上报和独立反馈采集；新版桥接仍保留旧固件每 2 秒查询的兼容路径。原有本地服务进程须退出并重新启动 `start.cmd`，网页刷新后加载新显示逻辑。实车使用前独立验收无线吞吐和停止耗时；浏览器断开不是全机械臂停稳确认。


适配当前 STM32 USART1 文本控制台。网页、CMD 和调试脚本通过本地 Python 服务共享一个串口连接。本地服务是唯一连接方式。

当前实车路线输入范围为10～5000 mm/s（默认200）；固定、雷达和首件组合入口共享“下次启动速度”。距离任务以300 mm/s²加减速，暂存位最后75 mm进出不超过min(启动速度,50)。浏览器旧速度高于200时一次性迁移为200并保留原值，已有10～200设置保留；之后允许主动设置至5000。保存或切页不发运动命令，启动后整条路线继承速度。轮速软件上限仍为Emm F6的3000 RPM，尚未验证带载性能。页面分别显示启动设置、阶段限速和四轮反馈；自动模式业务目标停稳后额外等待0.1秒。

## 速度曲线实验（离线教学）

启动控制台后，在「地图与遥测」点击「打开速度曲线实验」，或访问同一服务下的 `speed-lab.html`。实验复用原2400×2400 mm场地、300×300 mm车体外框和默认16段离线路径，每次选择其中一段比较；不读取路线编辑器尚未保存的临时修改，不连接串口、不发送实车指令。

- 蓝色：线性加减速，短段形成三角速度曲线，达到速度上限则加入匀速段形成梯形。
- 橙色：半余弦加减速，两头加速度为零，中间逐渐增大再减小。
- 「相同用时」保持两条曲线的路程、峰值速度、加速/匀速/减速时间相同，半余弦峰值加速度为线性的π/2倍。
- 「相同最大加速度」同时遵守相同速度上限和峰值加速度限制，分别计算可达峰值及运动时间。
- 可播放、暂停、复位，拖动时间滑杆或曲线观察两车位置、速度、加速度。页面隐藏或动画停顿超过250 ms自动暂停。
- 红色表示绝对加速度超过手动设定的假设牵引上限，并显示整段超限时间。它是牵引需求示意，不是实测摩擦系数、打滑率或滑移距离；地图仍按无滑移运动学绘制。

实验不套用原离线模拟100 RPM上限，也不复刻固件的距离反馈、延迟制动、末端慢速和停稳逻辑，不能将演示结果当作实车速度或停车验收。公式、验证条件见[开发记录](../../../docs/开发记录/2026-09-24速度曲线离线地图实验.md)。

## 启动与连接

需要 Python 3 和 pyserial；缺少时执行 `python -m pip install pyserial`。Windows 推荐双击上一级目录的 **启动控制台.lnk**：自动启动服务并打开网页，服务窗口初始最小化；已有默认端口服务时直接打开现有页面。也可双击本目录 `start.cmd`，或运行：

```powershell
python serve.py
```

用桌面 Chrome/Edge 访问 `http://127.0.0.1:8765/`，不要直接双击 HTML。服务仅监听回环地址，无需 npm、云部署或网络字体。更新程序后退出旧服务再启动。

- 启动服务不会自动连接串口，连接、刷新和重连不会启动运动。
- 网页共享模式先在“串口”列表中选择设备，再点击连接；没有默认 COM 号。列表显示端口号及设备名称（如 CH340），默认通信格式仍为 115200 / 8N1。
- CH340 换 USB 接口后点击“刷新串口”，重新选择当前端口。刷新仅枚举设备，不打开串口、不发送指令；只有一个端口时也不自动选中。页面不持久保存端口选择。
- CMD 输入 `ports` 查看列表，输入 `connect COM7` 连接指定端口（COM7 仅为示例）。仅当启动时明确传入 `--serial-port COM7`，才允许省略端口输入 `connect`；网页始终自行选择。
- 工程工具配置中的串口与网页默认值独立。占用时先释放其他串口助手。

## 工作台布局

桌面采用左侧连接与导航、中央终端、右侧任务操作；参数页占满侧栏右侧工作区并只留两行结果栏，地图页使用专用地图与操作区布局。默认打开“系统与标定”；七个工作页见下表。操作区单独滚动，底部停车区始终保留；窄屏改为上下分区。当前默认蓝色，可切换黑色。本版不展示人物背景，浏览器中已有的背景偏好不删除。

点击发送操作时，终端顶部立即显示原始命令与“待发送”，日志记录请求；串口实际写出后才增加 TX，并显示“已写出 · 待设备确认”。写出不代表动作完成，失败或拒绝发送不会增加 TX。顶部最近操作不受日志筛选影响。共享服务停车单独显示“请求停车”，以底部停车状态和实际 TX/RX 为准。

主界面只保留常用操作：读取位置、夹爪 PWM/释放、单轮调试及旧速度测试等不再单独铺设控件，协议能力仍保留，可在手动终端输入。夹爪“打开”发送 `grip open`（500 µs），“夹取”发送 `grip catch`（700 µs）；页面脉宽标注依赖同步更新的固件，点击只表示命令已发送，不表示已实际抓住物料。回零与零点、四轮状态、准备跑图及高级运动默认折叠，参数页的参数组全部展开。底盘反馈对象固定为四轮，不再提供单轮或协议单位选择菜单。离线地图的播放按钮独立可见，路线表和模拟参数按需展开。

| 二维码 | 支持检查、最新缓存读取、新码跟随、四组三位数字及接收统计 |

表单展示实际命令；一次执行发送一次，不自动重发普通运动命令。`pos` 为电机轴相对角度，网页单次限制 ±360°；固件另有机械行程和脉冲配置检查。历史诊断的 `material auto` 保持 Base 当前位置，执行旧识别、搜索和对准，`ALIGNED` 只表示旧任务对准完成。

### 单件取放与视觉诊断

视觉页默认打开“单件抓取”。测试前准备提供三轴回零、重新建立参考、读取状态和总线恢复；运动参数通过链接进入统一参数页。仅协同对准与视觉抓取可选择 1～6 号物料颜色，原料入仓可指定仓位或自动选择最低编号空仓。直接输入不带颜色命令时，仍默认蓝色对准（3）和红色抓取（1）。

| 显式操作 | 命令与终点 |
|---|---|
| 原料固定夹取入仓 | `grab start fixed [slot color]`，从人工已对准位置夹取，抬升、收回 X、分度并放入车载仓，再返回外侧观察姿态 |
| 仅协同对准 | `grab start align [color]`，识别所选颜色，底盘与 X 协同修正；停稳后 HOLD，不执行下降夹取 |
| 原料视觉夹取入仓 | `grab start pick [color slot]`，沿用协同对准，通过到位判据后完成夹取、入仓与返回 |
| 加工区夹取入仓 | `grab store proc <slot> <color>`，在人工已完成水平对准的位置夹起加工物料并入仓 |
| 从车载仓取出释放 | `grab take <slot> rough\|temp1\|temp2`，取出后向已对准的粗加工区、暂存第一层或第二层竖直释放 |
| 返回外侧观察姿态 | `grab return`，参考仍有效时显式返回，不改变库存 |
| 模拟扫码与首件组合 | `grab route [speed]`（默认200），地图页准备后按扫码5/1→首原料4/2运行首件交接测试 |
| 读取状态 | `grab status`，显示操作、场景、仓位、完成结果及组合路线状态 |
| 停止当前任务 | `grab stop`，取消自动推进并请求停止；保留夹爪输出与 Z 承载，停止反馈独立确认 |

单件完成后释放任务占用，可以显式开始下一件。Base 内部转向以保存的实际外侧参考为基准；仓内动作结束后返回同一参考及观察姿态，连续取放不累加 −180°。人工改变原点或观察姿态仍会使相关参考失效，原因由状态说明。普通停止和 `bus recover` 保留有效配置、参考和库存；涉及占用变化的中断只将对应仓位标记为待核对。

状态快照显示任务阶段、目标颜色、操作/场景/仓位、缺项、X/Z 反馈、视觉坐标状态及停止确认。超过5秒或断线后标为历史；点击刷新才查询，不额外自动轮询。`state=stopping` 表示仍在等停止确认；取消后 `state=idle stop_confirmed=1` 才表示设备报告停止完成。`state=complete` 表示软件单件流程完成，`result=stored/released/returned` 分别表示入仓、释放或返回；真实夹持、释放和碰撞余量由实物验收。`align` 的 HOLD 仅表示对准完成。

“历史视觉诊断”默认收起，按需保留旧 `material auto`、旧 Base/X 独立对准、旧视觉标定与对应状态/停止。旧 ArmVision/MaterialVision 使用各自模型，标定不会更新当前 GrabTask 的响应矩阵；当前抓取参数请使用参数页。相机调试单独检查 B2 识别和坐标，停止识别请求不等于停止当前取放任务。

抓取参数与普通轴配置只在 STM32 RAM 生效；参数页打开、切页和连接不自动读写，也不使用网页预填值代替设备值。调试预设只填草稿，仍须主动应用并读回。普通轴配置通过参数页“运动与标定”调整，手动终端保留 `config <axis>` 兼容命令。关于软件默认值、读回和标定单位，见[当前协议](../../../docs/上位机协议.md)及[ID 8 单件取放记录](../../../docs/开发记录/2026-10-03-参数控制台与ID8单件取放.md)。

二维码页的 `qr read` 读取缓存，不触发扫码器，也不消费主循环任务码；跟随通过显式 `qr stream on/off` 控制，新码通知最多 5 Hz。没有新码不等于扫码器离线。

## 准备跑图与实车路线

在“地图与遥测 → 实车监控”展开实车路线准备与执行，点击“准备跑图”。本车采用已确认的 Emm42 默认配置：3200 控制脉冲/电机轴圈、65536 位置反馈单位/电机轴圈、Receive 应答，仅修改 ID。准备流程直接采用这些协议参数，不再要求选择应答模式或勾选实测位置单位。旧配置文件中的 profile/units 不覆盖本车预设。

“本车配置”只需保存四轮安装方向确认，取消勾选后也可保存以撤销资格。准备时只应用到 MCU RAM，不修改驱动器或 Flash。现场仍须确认小车实际摆放位置与朝向。协议数值已知不代表实车距离已验收。

“准备跑图”依次检查任务空闲、应用位置单位并检查固件默认 Receive、开启四轮反馈并检查静止状态、检查 IMU 资格；已有上电验证资格时直接复用，必要时执行 5 秒静止验证。操作者确认车体中心在右下起点 `(2250,150)`、车头朝上、整车静止后，程序设置 `(2250,150,90°)` 原点并开启新遥测会话，收到有效起点反馈后完成准备。

准备期间共享服务限制其他来源修改状态，查询、取消和停止仍可用。准备完成不启动运动。

| 实车操作 | 命令 |
|---|---|
| 开始第 1 段 | `chassis route start <速度mm/s>` |
| 自动跑完整路线（停稳后等0.1秒） | `chassis route auto <速度mm/s>` |
| 手动下一段 | `chassis route next` |
| 取消路线 | `chassis route cancel` |
| 查询路线 | `chassis route status` |

固件固定15目标依次到 `(2100,1200)`、`(2100,2100)`、`(1200,2100)`、`(1200,350)`、`(1200,1200)`、`(350,1200)`、`(1200,1200)`、`(1200,2100)`、`(1200,350)`、`(1200,1200)`、`(350,1200)`、`(1200,1200)`、`(2100,1200)`、`(2100,300)`、`(2250,150)`。首腿保持90°斜向直达扫码；长段先转向再前进/后退，工位最终恢复90°；暂存在(425,1200)转向后低速侧移75 mm进站，退出顺序相反。每个业务目标只需一次next，内部阶段自动执行。第13目标只经过扫码坐标。到点是编码器反馈估计进入容差，不代表完成扫码、视觉精对准或抓取。完整实车检查按[验收顺序](../../../docs/开发记录/2026-10-03-底盘低速转向路线与验收顺序.md)执行。

`chassis run vx vy 0 hold_ms` 自动保持起步HWT101航向，需要本次验证通过且数据新鲜，不需要地图原点；非零角速度执行给定转向。`chassis heading`使用模块角度；新增`chassis turn <地图航向_deg>`使用地图绝对角度（−180～180），两者均需地图锚点。turn纯转向、500 ms起步、角速度≤0.15 rad/s，进入2°容差并取得三组至少500 ms的新鲜四轮停稳反馈后完成；转后角度偏离在原超时内继续修正，保留原点和锚点。

## 停车与解除锁定

底部常驻两项：“立即停止底盘”与“全部轴 / 关联任务停止”（`stop all`）。前者走本地服务停车流程；后者沿用固件全部轴/关联任务停止逻辑。抓取自身的 `grab stop` 留在任务区域，历史视觉诊断保留对应 `vision stop`、`material stop`，不再把这些任务停止按钮重复铺在底栏。停止命令及反馈语义没有改变。

CMD 按 Ctrl+C 或网页“立即停止底盘”会取消准备、清空待发普通命令、锁定新的运动请求并优先请求底盘停车。CMD 窗口继续运行；`quit` 先执行停车流程、最多等待 6 秒后退出。

停车通信节奏（2026-09-22）：立即发送一次 Ctrl+C 和带编号停车请求，不再附加无编号文本停车。未受理时每2秒重试同一编号，最多3次；受理后每2秒查询停车状态。总等待6秒，超时停止自动发送。连接未断开、未解除锁定且编号匹配的迟到回复仍可更新发送/停止结果，不重新启动查询，不自动解除锁定。

状态依次区分请求已发出、MCU 受理、电机总线停车发送完成、四轮反馈确认停止；没有新鲜有效反馈时不能显示已确认停车。查看结果后明确解除锁定，任务不会自动恢复。

`stop all`、视觉停止、底盘停止各有范围；统一停车属于软件措施，不是硬件急停。关闭网页、强制关窗口或无线失联无法保证停车。本地服务的主动断开有停车流程。

## 地图与遥测

### 离线模拟

“历史16段时间示意／手工编辑”保留原时间路线和100 mm/s、100 RPM模拟限制，可编辑至50段，刷新恢复默认。“当前固件路线预览”通过离线服务编译同一C路线/阶段模块，网页只显示和运动学播放转向、前进/后退及接驳；不发送运动命令。足迹诊断标出坐标、阶段和干涉对象，格路可达与300 mm车体能否转向分别展示。

离线播放只作用于浏览器，**不会上传路线或发送实车运动命令**。1/4/10 倍速只改变观看速度；离开页面、隐藏浏览器或停顿超过 250 ms 会暂停。模型采用半余弦起停、最大 20 ms 中点积分，并可量化整数 RPM。

场地为 2400×2400 mm，原点在左下；车体名义外框 300×300 mm，碰到边界、工作区或转盘时终止模拟。默认几何 L=210、W=240、D=80 mm、G=1，包含估计和假设，只用于模拟；不涵盖展开机械臂、随机障碍、驱动器动态和实车定位误差。

默认理想路线运动 154 秒、含占位停留 170 秒，不包含实际取放和视觉耗时。整数 RPM 模式末段可能触发边界保护，需要末端精定位；路线结束与整车返回原启停区合格分别判断。

### 在线遥测

手动选择指令推算或反馈估计并开启遥测，发送 `chassis stream on <非零会话编号>`；关闭发送 `chassis stream off`。准备跑图也会显式建立遥测会话。

`@CHASSIS` JSON 必须先收到同会话 config，再接受 state。在线几何来自 MCU 配置，不使用离线假设。指令推算不等于测量；反馈估计使用 MCU 位姿、轮位置与航向有效性，不以目标 RPM 代替原始反馈。

当前状态周期 2000 ms，首次等待配置最多 8 秒，配置后超时为周期三倍；旧 config 缺少周期字段时按 200 ms 计算。样本相对 MCU 时间的 600 ms 新鲜度要求保持不变。坏帧或超时清除实时状态，保留标记为过期的最后位置与会话；同会话恢复后自动显示，并断开旧轨迹。串口重连、主控重启或主动关闭后需要手动开启；时间跳变、会话或轨迹序号变化会断开轨迹。

## 日志与排障

- 公共终端支持模块与 TX/RX/系统筛选、跟随、清空和导出，最多保留 500 条；清空日志不清二维码或地图状态。
- 终端默认勾选“精简抓取日志”：重复的 `OK grab state=...` 状态报告隐藏并显示隐藏条数；状态、原因、停止确认等关键字段变化、错误、视觉坐标及手动查询回复仍显示。取消勾选可查看当前保留的完整日志，偏好会记住。此功能仅影响显示，不发送设备命令、不代表任务已停止；导出和本地桥接原始日志不受影响。
- 设备回复中的 `accepted` 只表示请求受理；到位与停止必须读取对应反馈。
- 主题与日志显示偏好保存在浏览器；旧常用指令收藏不再作为现行操作入口。
- 服务原始收发记录在项目 `.embeddedskills/logs/serial/`，用于排查丢字、串口写出及反馈。
- 服务不可用时检查 CMD；串口占用时释放其他程序；准备超时时看回显、ERR、四轮反馈和 IMU 状态，不自动重复运动。
- `bus_locked=1` 是总线隔离；`chassis reset-confirmed` 只能在驱动器已经实际复位后使用，它不会复位驱动器。
- 本车 TTL 多机接线实测（2026-09-27）：四轮驱动器断电但 TX/RX 仍接入公共总线时，出现 UART5 帧错误并锁定；全部驱动器上电后连续四次 `state x` 正常。测试机械臂时保持总线上驱动器上电；若需要单独供电，应在全断电后隔离未供电节点的 TX/RX 支路并保持工作节点正确共地。详见[首次锁定诊断记录](../../../docs/开发记录/2026-09-27-UART5首次锁定诊断.md)。

### 距离任务停车与纠偏（2026-09-22）

距离控制按刹车距离提前限制速度，Kp=2.5，软件加减速度现为300 mm/s²（2026-10-03）。可设置5000 mm/s不表示每段达到此速度；短段受制动距离限制。末端20 mm内期望速度限制50 mm/s且不超过路线设置；停稳后的位置纠偏仍限20 mm/s。

`position_correcting`表示已确认停稳后进行低速位置修正（误差≤100mm且航向合格，最多两次）。`position_not_reached`与`stop_confirmed=1`表示已停稳但未到位，路线不会续跑。`stop_unconfirmed`表示停车反馈未在3秒内确认。以上反馈仍基于编码器，不代表视觉精对准。完整说明见开发记录《2026-09-22距离制动与停稳纠偏》。

上电自动准备：Z碰撞回零 → X碰撞回零 → Base就近回零，逐轴检查回零状态与位置反馈，失败不重试。准备区按钮只用于手动重做。fixed/pick均自动完成取放；z_grab预填−80 mm、z_place预填−60 mm，提起沿用z_lift，松爪等待沿用close_ms。上电Z回零成功后固件自动载入480脉冲/mm、−80 mm抓取和−60 mm放置，其他标定参数仍需配置。自动回零属于固件功能，网页不在连接时发送回零指令。

总线锁定恢复：系统页及单件抓取页顶部“一键恢复电机总线”发送 `bus recover`，会停止任务、逐台检查 ID1～7，结果见终端；“查看恢复结果”发送 `bus status`。成功不自动续跑、不自动归零、不解除网页停止锁。底盘未触发的同步缓存仍不确定时只恢复共享通信，保留底盘运动限制；此时结果为 `chassis_ready=0`。需全部驱动器在线。手动运动/回零/改零点/失能前由固件读取状态检查，忙时拒绝且不排队。

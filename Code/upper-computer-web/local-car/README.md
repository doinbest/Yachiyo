# 八千代·巡航 · 本地小车控制台


## 2026-09-29 控制台与断开更新

- 终端默认“中文摘要”，可切换“原始报文”，选择在浏览器保存。命令仍为 ASCII；解析、导出和桥接日志保持原文。摘要隐藏已发送命令的回显与空提示符，未知回复/字段保留，故障即使以 `OK` 开头也会标红。
- `info` 会解释串口、ID、方向、速度及总线状态；`bus recover complete` 明确区分完整恢复和部分恢复，并提示不自动续跑、检查回零参考。网页“解除停止锁定”不代表电机总线恢复。
- 视觉无效帧显示“当前无有效视觉数据”；这不等于识别程序确认没有物体。有新鲜坐标时继续显示 `Color = red，CX = …，CY = …`。
- 点击“断开”立即显示“正在停车并断开”，禁止普通发送和重复断开。匹配本次 token 的四轮停稳反馈到达后关闭串口；最多等 6 秒，失败显示停止未确认并保留停止锁。
- 各任务停止按钮可在普通发送未结束时使用。待写出的普通命令会取消，停止命令按顺序优先发送，仍保持原作用范围；“停止协同对准”仍是 `grab stop`。已写出的命令不会伪装成未发送，也不会自动重发。
- 准备流程持有专属回复期间，其他页面的查询也会被拒绝，以免同名回复混入。先取消准备后查询。连接/断开不会自动续跑。
- 启动状态按实际报告展示回零、等待验证、验证中、就绪或失败。正常启动不再输出六次 Flash ID；OLED 在控制空闲后初始化。

固件需更新后才能使用停车主动上报和独立反馈采集；新版桥接仍保留旧固件每 2 秒查询的兼容路径。原有本地服务进程须退出并重新启动 `start.cmd`，网页刷新后加载新显示逻辑。实车使用前独立验收无线吞吐和停止耗时；浏览器断开不是全机械臂停稳确认。


适配当前 STM32 USART1 文本控制台。网页、CMD 和调试脚本通过本地 Python 服务共享一个串口连接。本地服务是唯一连接方式。

当前实车16段路线输入范围为10～5000 mm/s（默认5000）；网页与固件使用同一上限。轮速软件上限已设为 Emm F6 速度命令的3000 RPM协议上限，尚未验证该电机在本车负载下能达到此转速。距离任务以1000 mm/s²加减速，末端20 mm内限速50 mm/s，自动模式确认停稳后额外等待0.1秒。地图页左列显示地图、右列显示路线与模拟操作，两个区域分别滚动；窄屏时地图排在操作区之前。切换到其他页面仍可查看、导出原始日志，本地桥接也继续记录串口数据。

## 速度曲线实验（离线教学）

启动控制台后，在「地图与遥测」点击「打开速度曲线实验」，或访问同一服务下的 `speed-lab.html`。实验复用原2400×2400 mm场地、300×300 mm车体外框和默认16段离线路径，每次选择其中一段比较；不读取路线编辑器尚未保存的临时修改，不连接串口、不发送实车指令。

- 蓝色：线性加减速，短段形成三角速度曲线，达到速度上限则加入匀速段形成梯形。
- 橙色：半余弦加减速，两头加速度为零，中间逐渐增大再减小。
- 「相同用时」保持两条曲线的路程、峰值速度、加速/匀速/减速时间相同，半余弦峰值加速度为线性的π/2倍。
- 「相同最大加速度」同时遵守相同速度上限和峰值加速度限制，分别计算可达峰值及运动时间。
- 可播放、暂停、复位，拖动时间滑杆或曲线观察两车位置、速度、加速度。页面隐藏或动画停顿超过250 ms自动暂停。
- 红色表示绝对加速度超过手动设定的假设牵引上限，并显示整段超限时间。它是牵引需求示意，不是实测摩擦系数、打滑率或滑移距离；地图仍按无滑移运动学绘制。

实验不套用原离线模拟100 RPM上限，也不复刻固件的距离反馈、延迟制动、末端慢速和停稳逻辑，不能将演示结果当作实车速度或停车验收。公式、验证条件见[开发记录](../../../docs/开发记录/2026-09-24速度曲线离线地图实验.md)。

## 启动与连接

需要 Python 3 和 pyserial；缺少时执行 `python -m pip install pyserial`。Windows 推荐双击上一级目录的 **启动控制台.lnk**：自动启动服务并打开网页，服务窗口初始最小化；已有默认端口服务时直接打开现有页面。也可双击本目录 `start.cmd`，或运行：

```powershell
python serve.py
```

用桌面 Chrome/Edge 访问 `http://127.0.0.1:8765/`，不要直接双击 HTML。服务仅监听回环地址，无需 npm、云部署或网络字体。更新程序后退出旧服务再启动。

- 启动服务不会自动连接串口，连接、刷新和重连不会启动运动。
- 网页共享模式先在“串口”列表中选择设备，再点击连接；没有默认 COM 号。列表显示端口号及设备名称（如 CH340），默认通信格式仍为 115200 / 8N1。
- CH340 换 USB 接口后点击“刷新串口”，重新选择当前端口。刷新仅枚举设备，不打开串口、不发送指令；只有一个端口时也不自动选中。页面不持久保存端口选择。
- CMD 输入 `ports` 查看列表，输入 `connect COM7` 连接指定端口（COM7 仅为示例）。仅当启动时明确传入 `--serial-port COM7`，才允许省略端口输入 `connect`；网页始终自行选择。
- 工程工具配置中的串口与网页默认值独立。占用时先释放其他串口助手。

## 终端工作台布局（2026-09-21）

桌面采用左侧连接与导航、中央常驻终端、右侧任务操作，六页共用固定分栏比例，切换地图页不会改变连接区或终端宽度。默认打开“系统与标定”；导航依次为系统与标定、底盘、地图与遥测、二维码、视觉任务、机械臂与夹爪。右侧单独滚动，终端输入框和底部停车区始终保留；窄屏改为上下分区。默认深色，可切换浅色。本版不展示人物背景，浏览器中已有的背景偏好不删除。

点击发送操作时，终端顶部立即显示原始命令与“待发送”，日志记录请求；串口实际写出后才增加 TX，并显示“已写出 · 待设备确认”。写出不代表动作完成，失败或拒绝发送不会增加 TX。顶部最近操作不受日志筛选影响。共享服务停车单独显示“请求停车”，以底部停车状态和实际 TX/RX 为准。

主界面只保留常用操作：读取位置、夹爪 PWM/释放、单轮调试及旧速度测试等不再单独铺设控件，协议能力仍保留，可在手动终端输入。夹爪“打开”发送 `grip open`（500 µs），“夹取”发送 `grip catch`（700 µs）；页面脉宽标注依赖同步更新的固件，点击只表示命令已发送，不表示已实际抓住物料。回零与参数、四轮状态、准备跑图及高级运动默认折叠。底盘反馈对象固定为四轮，不再提供单轮或协议单位选择菜单。离线地图的播放按钮独立可见，路线表和模拟参数按需展开。

### 单件抓取（2026-09-27）

任务1的“1.1 · Base 转向与 Z 准备”内提供“Base 转到转盘”，角度可修改，默认发送 `pos base -180`。该命令是电机轴相对转动，每次执行会再次转动，页面打开和抓取启动不会自动执行。抓取hold期间先结束任务、确认停止，再操作Base。

“1 · 固定位置抓取”仅保留完整取放流程说明及“开始固定位置抓取”“停止本次抓取”两个按钮，分别发送`grab start fixed`、`grab stop`。移除本区手动Base转向、Z点动、试夹、重复参数表单及独立反馈框；统一参数入口仍在下方“单件抓取标定与参数”，状态与日志沿用公共显示。

任务2“仅协同对准”旁有“停止协同对准”，任务3旁有“停止本次抓取”，均发送`grab stop`；底部常驻“抓取 / 协同对准停止”执行同一命令。独立Base/X对准的`vision stop`属于另一套任务，不用于停止任务2。`state=stopping`代表正在等待停止确认，正常取消到`state=idle`且`stop_confirmed=1`才代表任务结束且确认停止；若保持`stop_confirmed=0`，应检查反馈，不能把隐藏日志或断开连接当作停止完成。

停止后若 `grab status` 仍显示 `missing=none`，可以直接开始下一次协同对准。若手动回零、计数清零或 Base 转去放置处使参考参数失效，页面“重新建立三轴参考”发送 `grab rehome`：依次执行 Z/X 碰撞回零、Base 就近回零，并验证驱动回零标志、位置和电机状态；每轴验证成功后才恢复该轴默认参考参数。执行前移走夹持物并确认运动范围安全。普通单轴 `home` 的受理回复不等于完成验证，不能靠它自动恢复参数；如需保留自定义参数，重新读回并设置。

2026-10-02 修复：自动取放的 Base 放置转向会清除下一次视觉任务的准心和响应模型，状态现在立即同步报告缺项，不再一直显示 `missing=none`、直到下次启动才报错。普通停止和 `bus recover` 保留有效配置；重启及 `grab rehome` 的三轴验证全部完成后恢复默认参考。详见 [本次检查与修复记录](../../../docs/开发记录/2026-10-02-抓取参考诊断与终端精简.md)。

终端“中文摘要”中的抓取状态现在仅显示模式、状态、原因，以及有新鲜有效坐标时的像素偏差。缺参数、参考失效和停车反馈仅在相关情况下显示；正常参考、轴位置/目标、协议、序号、模型、速度和恢复统计不再逐条展开。参考变化导致启动被拒绝时提示“请重新建立三轴参考”。切换“原始报文”或导出可查看完整收包，视觉任务状态页仍保留详细快照。

当前联调固件将 `travel_mm` 默认设为 0，表示暂时关闭四轮相对起点行程限制；参数面板也预填 0。需要重新限制时，可设置正数毫米值，或用 `grab set travel_mm <毫米>`，并用 `grab get travel_mm` 确认。其他反馈与机械轴边界仍照常检查。

视觉抓取的上位机参数集中放在 `grab-params.mjs`：`GRAB_FORM_DEFAULTS` 控制单项输入框预填值，`GRAB_TEST_PRESET` 列出点击“逐项发送调试预设”时要写出的参数。修改文件并刷新页面后才使用新值；连接串口、打开页面或切换任务不会自动下发。按钮逐条发送 `grab set`，遇到写出失败即停止，停止操作会取消剩余发送。网页只能确认串口写出，设备是否接受请检查每条 RX 或用 `grab get <key>` 读回；固件上电默认值不会被该文件修改。

2026-10-01 新增左侧独立“参数调试”页面，不需要编辑上述文件：抓取/对准参数按分组逐行显示设备读回值与待输入值，单项点击“读取”发 `grab get`，点击“应用”发 `grab set` 后再读回；显示“设备读回与输入一致”才表示当前设备数值匹配。Base、X、Z 的 RPM、加速度档位、脉冲限制同样使用现有 `config <axis>` 读写。路线速度框只保存到本机网页并同步地图页两处路线启动输入框，不发送运动命令；真正启动仍在“地图与遥测”页。连接、打开页面和切换页面均不自动读取或写入，断线、停止或 MCU 重启清除等待中的核对及旧读回值。抓取任务运行中固件仍拒绝 `grab set`，当前运行的路线速度也不会因修改网页输入而改变。

参数保存边界（2026-10-02）：`grab set` 和 `config <axis> ...` 改的是 STM32 RAM 变量，不会改写源码宏或 Flash；STM32 复位/重新上电恢复已烧录固件默认值。“应用并读回一致”表示当前 RAM 数值匹配，不表示掉电保存。路线速度的“保存”只写浏览器本地设置，连接或重启后不会自动发送运动命令。当前没有这些调参结果的 Flash 保存与上电加载流程；W25Q128 驱动和默认关闭的读 ID 诊断仍保留，参数持久化另行规划。

“0 · 测试前准备”精简为Base、X、Z三行，每轴只有一个按钮：Base“就近回零”发送`home base near`，X/Z“碰撞回零”分别发送`home x collision`、`home z collision`。此处移除底盘/IMU、计数清零和状态读取；这些通用功能仍可在原模块使用。任务1的手动调试区已移除。回零后再配置抓取位置参数；打开页面不会发送命令。

视觉页默认打开“单件抓取”，按固定位置抓取、仅协同对准、单件视觉抓取、前四段模拟扫码的顺序验证。Base在对准/夹取时保持，提起后自动转−180°放置，页面任务前可选择 1–6 号物料颜色，点击仅协同对准或单件视觉抓取时发送 `grab start align|pick <color>`；直接输入不带颜色命令时仍默认蓝色对准（3）和红色抓取（1），路线交接仍默认红色。旧 `material auto` 位于独立“旧版对准调试”页，纯16段路线入口不变。

| 显式操作 | 命令与终点 |
|---|---|
| 固定位置抓取 | `grab start fixed`，人工对准后自动完成夹取、提起、Base转−180°、下降放置、松爪及提起，再等待人工验收 |
| 仅协同对准 | `grab start align <color>`，识别所选颜色物料（默认蓝色3），底盘与 X 协同修正，不执行下降抓取 |
| 单件视觉抓取 | `grab start pick <color>`，精定位与停稳判据通过后下降、闭合、提起 |
| 前四段模拟扫码 | `grab route <speed>`，先在地图页准备跑图；第2段停稳等待1000 ms、模拟载入 `156+123+516+231`，屏幕发送完成后继续到第4段抓取，结束不进第5段 |
| 读取状态 | `grab status`，分别显示组合路线和抓取任务状态，保留路线错误，不被空闲机械臂状态覆盖 |
| 停止 | `grab stop`，终止自动推进并请求停止；保留夹持和 Z 承载，反馈确认独立显示 |

标定区按尺度与行程、反馈与抓取条件、准心与像素响应、控制与运动边界分组，每次 `grab set <key> <value>` 只设置一个参数；“读取设备当前值”发送 `grab get <key>`，设备以 `value=unset` 表示尚未设置，读回不会自动覆盖输入。输入初始为空，包括确认类参数；坐标、毫米换算和像素响应必须来自本车测量。`retarget_ok=1` 仅在已经验证 X 运动中接受绝对目标更新后设置，未确认时固定位置抓取仍可独立调试。所有配置只在 MCU RAM 中有效；网页输入与复制不代表固件已接受，检查每条回复。复位后重新配置，运行中不能改参数。

状态快照显示阶段、目标颜色、粗/精视觉阶段、缺项、X/Z 实际与目标位置、DX/DY、视觉数据年龄、底盘速度、耗时、停止请求和确认。超过5秒或断线后标为历史；点击刷新才发送查询，不额外自动轮询。`hold` 仅表示动作终点，抓持结果由人工验收，不自动增加正确抓取数。底部同时保留单件抓取停止与共享底盘停车；共享停车会取消抓取推进，其“四轮停止”反馈不替代 X/Z 停止反馈。连接、重连、导航或解除锁定不恢复抓取。

2026-09-27 Z 安装方向修正：烧录新固件后，`pos z` 正数上升（CW）、负数下降（CCW）；`info` 可查看 `positive_dir ... z=0`。回零独立使用驱动器 `O_Dir`，当前安装向上回零应设 CW。普通运动上电/复位默认等效于 `config z 500 120 0`（500 RPM、加速度档位 120、单次脉冲数无限制）；控制台临时配置仅在 RAM。首次低速点动可先发送 `config z 10 20 0`；回零速度独立由驱动器 `O_Vel` 决定。

## 停车与解除锁定

CMD 按 Ctrl+C 或网页“立即停止底盘”会取消准备、清空待发普通命令、锁定新的运动请求并优先请求底盘停车。CMD 窗口继续运行；`quit` 先执行停车流程、最多等待 6 秒后退出。

停车通信节奏（2026-09-22）：立即发送一次 Ctrl+C 和带编号停车请求，不再附加无编号文本停车。未受理时每2秒重试同一编号，最多3次；受理后每2秒查询停车状态。总等待6秒，超时停止自动发送。连接未断开、未解除锁定且编号匹配的迟到回复仍可更新发送/停止结果，不重新启动查询，不自动解除锁定。

状态依次区分请求已发出、MCU 受理、电机总线停车发送完成、四轮反馈确认停止；没有新鲜有效反馈时不能显示已确认停车。查看结果后明确解除锁定，任务不会自动恢复。

`stop all`、视觉停止、底盘停止各有范围；统一停车属于软件措施，不是硬件急停。关闭网页、强制关窗口或无线失联无法保证停车。本地服务的主动断开有停车流程。

## 地图与遥测

### 离线模拟

默认 16 段展示两批物料路线，可编辑起步、匀速、减速、停留和车体速度，最多 50 段。单段运行从地图当前位姿开始，整条运行从设置的初始位姿开始；路线编辑当前不持久化，刷新恢复默认。

离线播放只作用于浏览器，**不会上传路线或发送实车运动命令**。1/4/10 倍速只改变观看速度；离开页面、隐藏浏览器或停顿超过 250 ms 会暂停。模型采用半余弦起停、最大 20 ms 中点积分，并可量化整数 RPM。

场地为 2400×2400 mm，原点在左下；车体名义外框 300×300 mm，碰到边界、工作区或转盘时终止模拟。默认几何 L=210、W=240、D=80 mm、G=1，包含估计和假设，只用于模拟；不涵盖展开机械臂、随机障碍、驱动器动态和实车定位误差。

默认理想路线运动 154 秒、含占位停留 170 秒，不包含实际取放和视觉耗时。整数 RPM 模式末段可能触发边界保护，需要末端精定位；路线结束与整车返回原启停区合格分别判断。

### 在线遥测

手动选择指令推算或反馈估计并开启遥测，发送 `chassis stream on <非零会话编号>`；关闭发送 `chassis stream off`。准备跑图也会显式建立遥测会话。

`@CHASSIS` JSON 必须先收到同会话 config，再接受 state。在线几何来自 MCU 配置，不使用离线假设。指令推算不等于测量；反馈估计使用 MCU 位姿、轮位置与航向有效性，不以目标 RPM 代替原始反馈。

当前状态周期 2000 ms，首次等待配置最多 8 秒，配置后超时为周期三倍；旧 config 缺少周期字段时按 200 ms 计算。样本相对 MCU 时间的 600 ms 新鲜度要求保持不变。坏帧或超时清除实时状态，保留标记为过期的最后位置与会话；同会话恢复后自动显示，并断开旧轨迹。串口重连、主控重启或主动关闭后需要手动开启；时间跳变、会话或轨迹序号变化会断开轨迹。

## 距离任务停车与纠偏（2026-09-22）

距离控制按刹车距离提前限制速度，Kp=2.5，软件加减速度为1000mm/s²。可设置5000mm/s不表示每段实际达到此速度；短段会受制动距离限制。末端20mm内期望速度限制50mm/s；停稳后的位置纠偏仍限20mm/s。

`position_correcting`表示已确认停稳后进行低速位置修正（误差≤100mm且航向合格，最多两次）。`position_not_reached`与`stop_confirmed=1`表示已停稳但未到位，路线不会续跑。`stop_unconfirmed`表示停车反馈未在3秒内确认。以上反馈仍基于编码器，不代表视觉精对准。完整说明见开发记录《2026-09-22距离制动与停稳纠偏》。

上电自动准备：Z碰撞回零 → X碰撞回零 → Base就近回零，逐轴检查回零状态与位置反馈，失败不重试。准备区按钮只用于手动重做。fixed/pick均自动完成取放；z_grab预填−80 mm、z_place预填−60 mm，提起沿用z_lift，松爪等待沿用close_ms。上电Z回零成功后固件自动载入480脉冲/mm、−80 mm抓取和−60 mm放置，其他标定参数仍需配置。自动回零属于固件功能，网页不在连接时发送回零指令。

仅协同对准/视觉抓取的识别阶段会自动在终端显示`VISION RX`坐标采样日志（最多2 Hz），包含原始cx/cy、dx/dy、rx_seq、age_source=rx、age和valid/fresh。选择“全部模块”或“视觉”即可查看，无需额外打开订阅；`camera status`仍可手动查询。

终端中的VISION RX现在仅展示颜色名称和像素坐标，例如`Color = red，CX = 350，CY = 321`。未识别和坐标过期单独提示，不显示旧坐标。原始串口行仍用于任务解析和日志导出；显示简化不修改通信协议。

总线锁定恢复：系统页及单件抓取页顶部“一键恢复电机总线”发送 `bus recover`，会停止任务、逐台检查 ID1～7，结果见终端；“查看恢复结果”发送 `bus status`。成功不自动续跑、不自动归零、不解除网页停止锁。底盘未触发的同步缓存仍不确定时只恢复共享通信，保留底盘运动限制；此时结果为 `chassis_ready=0`。需全部驱动器在线。手动运动/回零/改零点/失能前由固件读取状态检查，忙时拒绝且不排队。


### B2 兼容与坐标状态（2026-09-29）

现行固件的相机调试、仅协同对准、视觉抓取和路线交接均使用 B2，不要求香橙派 test_connect.py 增加字段。任务按钮与停止命令保持不变；先用“相机识别物料 / 蓝色”（camera material 3）及“读取相机状态”验证通信，再执行仅协同对准；完整视觉取放仍使用红色物料（camera material 1）。

抓取反馈将“视觉阶段”替换为“视觉协议”和“坐标状态”。USB 未枚举、等待首个回复、已收到报文但无有效坐标、有效坐标、坐标过期分别显示。frame 是“收到过匹配报文”的布尔值；序号和时间均来自 MCU 接收端。旧固件缺少 protocol/age_source/rx_seq/vision 时显示“未报告”，不会凭功能码或阶段猜测。重连、重启清除旧抓取快照；停止后以新回复显示无活动请求。

参数键不变：age_ms 标签为“有效坐标接收超时 / ms”（默认 1000）；frames 为“稳定坐标观测次数”（默认 3）。坐标还需持续在容差内至少 200 ms 并满足机构停稳反馈；停车前后分别积累。Valid=0 的显示是“当前无有效视觉数据”，不将零收包解释成未识别到物料。

中文终端仍简洁显示 `Color = red，CX = …，CY = …`；原始报文切换与导出保留完整原文。页面显示不额外发送识别或运动指令。B2 不能识别同色迟到回复或证明远端采集时刻，这一限制不会由本地序号消除。


### 短暂漏检时的界面提示（2026-09-29）

蓝色“仅协同对准”先按下节的250 ms容忍减速；超时、临近目标或视觉抓取阶段漏检时显示“正在停车”，暂停期间不会下降夹取。确认停稳后，在1500 ms内得到3次连续新有效坐标且反馈仍停稳，可自动恢复对准；每任务最多完成2次停车后的恢复。仅协同对准会在停稳后重发一次已有的蓝色B2请求，显示“已重发蓝色识别，等待新坐标”；发送忙不会延长窗口，原有快照不计入恢复。视觉抓取/路线pick保持原识别请求，显示“等待目标恢复”。无需修改香橙派程序或另点恢复按钮。

持续漏检显示“恢复窗口超时”，用完两次后再漏检显示“恢复次数耗尽”。USB 断开、坐标接收超时、机械反馈/总线故障仍结束任务，不自动恢复。人工“停止协同对准 / 抓取”始终取消恢复资格。

恢复后还要重新通过对准和停稳判据；任务 2 仍只对准，不夹取、不转 Base。固定取放、下降后的取放以及完成 hold 不参与恢复。

“视觉恢复”状态行只显示 MCU 快照；停稳前无倒计时，旧固件缺字段为“未报告”。失效时隐藏旧偏差/坐标，原始报文及导出保留。去重不丢弃暂停、停稳、恢复和故障变化；重连/重启会清除旧快照。B2 无视觉阶段信息，页面不会将漏检描述为“切换圆检测”。


### 蓝色协同对准与指令模拟修正（2026-09-30）

烧录后可先执行 `info`，应显示 `GRAB protocol=B2 align_color=3 pick_color=1`，无需先运动即可核对固件的任务颜色。`grab start align` 受理后先回复 `OK grab start align accepted color=3 protocol=B2`，随后报告阶段状态；accepted仅表示任务已受理，不表示已到位。周期精简状态同样保留color字段，网页显示“蓝色 · 3”。

重复 `grab stop` 不再清空已经积累的停稳证据。首次停止仍请求底盘及机械臂停止，最终以 `state=idle stop_confirmed=1` 为正常取消确认；停止指令传输失败或反馈不足仍不能确认停稳。

主机模拟覆盖蓝色收敛、控制台发送暂不可用、重复停止、漏检恢复和延迟启动/停止批次；模拟采用虚拟机械/相机反馈，不代表无线链路、实车尺度或方向验收。详见 `docs/开发记录/2026-09-30-蓝色协同对准模拟与停止修正.md`。
## 2026-09-30 视觉参数提速

当前源码默认及网页预填：底盘速度上限20 mm/s、视觉收敛增益0.6 s⁻¹、平移加速度20 mm/s²。网页不自动写入；需点击设置且看到设备受理，再用读取参数确认。`grab set`是RAM设置，复位后以已烧录固件默认值为准。这三项由align/pick共用；X/Z速度上限和固定取放流程未调整。

初始模型预填也与固件同步为 `[2,0,0] / [0,2,2]`，避免发送旧方向假设；这是2 px/mm试验初值，不是完成实测标定。提速比较中10.10秒到5.25秒仅为连续识别、理想机械模型的计算结果，仍需新参数实车验证。详见[参数对比记录](../../../docs/开发记录/2026-09-30-蓝色协同对准参数提速与对比.md)。


### 蓝色协同对准短暂漏检（2026-09-30）

“反馈与抓取条件”新增“蓝色对准漏检容忍”，预填250 ms（可设0～300整数，0关闭）。固件在短暂漏检时按原运动趋势减速，连续3次新有效观测才恢复；临近目标或达到容忍时间时请求停车，确认停稳后等待1500 ms恢复。网页只显示设备状态，不自行发送恢复命令。短暂恢复不占用两次停车恢复次数。`grab get loss_grace_ms` 可核对设备当前值；预填不表示已写入旧固件。

日志显示“本次或最近中断(ms)”“本任务最长中断(ms)”及“减速期间恢复观测(/3)”。中断时间包含连续观测确认、可能的停车及等待；从最后有效坐标到恢复或任务终止，不等于纯漏检时长。减速容忍期间抓取状态的dx/dy显示为空，独立VISION RX仍显示收到的新有效坐标。需烧录对应STM32固件并刷新本地网页；香橙派和B2协议保持现状。


2026-09-30：抓取参数“Z速度上限”预填更新为27.777778 mm/s，按现有Z尺度对应250 RPM；新固件上电默认采用此值。上升、下降、放置共用。临时修改可在任务空闲时直接设置并读取，不必烧录；修改上电默认值才需要烧录对应固件。界面单位为mm/s，不能将250 RPM直接填为250。读回约27.7778是显示舍入，网页预填不等于设备实际参数。

# 视觉、取放与赛事操作

共享串口连接方式见[控制台入口](../README.md)。切换页面和标签不发送命令；“仅识别”不运动，点击对准/追踪/取放才进入对应任务。完整字段与错误原因见[机械臂协议](../../../../docs/协议/机械臂与取放.md)及[B2/追踪协议](../../../../docs/协议/视觉B2与动态追踪.md)。

## 参数与准备

参数页先读回设备值，再显式应用改动；浏览器预填和本机保存不等于MCU值。抓取默认值/范围统一见[grab_parameters.def](../../../template/App/grab_parameters.def)，轴config的acc为Emm档位，grab/track accel为MCU mm/s²。参数只存RAM，复位恢复源码默认，普通停止保留。未知加工/暂存高度留空并显示具体缺项，不自动代填。

Base物理回零朝后；姿态准备先核验Z抬起和X收回再转Base。任务到位容差2°，2～5°残差低速重发原绝对目标，不进行FD模式2相对补偿。上电三轴回零完成后ID8自动就近回零建立第一仓参考；仓2/3角度需标定，库存按实物核对。

## 静态颜色与编号环

颜色用 `grab align color <1..6> [z_mm] [stay]`，编号环用 `grab align ring <1..3> [z_mm] [stay]`。旧grab ring align/start align保留兼容，旧vision入口退役。颜色准心(334,338)，编号环(378,333)，不覆盖彼此；动态追踪使用独立参数。

编号环页选择环号与对准高度，启动后从朝后姿态收X、转Base，到位才识别，不预伸50 mm。识别后先横向接近，随新坐标逐步下降；靠画面边缘暂缓下降，重新进入中央区域继续。达到目标高度、像素窗口并停稳后，“对准后抬高”只抬Z至最高等待装料；“保持低位”用stay保持高度并显示偏差，不继续运动纠偏。

对准后可人工装料、闭爪，再使用独立放置高度执行 `grab ring place <z_mm>`，只下降/松爪/提起，不取仓或改库存。手动环放置默认−150 mm来自用户实物验证；固件仍按当前Z配置核验。用顶部停止并退出结束识别和任务，等待停车确认。

## 手动码垛

1. 选择下层颜色，点击静态对准并补偿：`grab stack align <颜色>`。先对准绿色准心、停稳，再执行固定图像CX+39/CY+1补偿、再次停稳等待装料；日志最终DX=39、DY=-1是预期，不是39/1 mm。
2. 人工装入上层物料，`grip catch`闭爪。
3. 用 `grab stack lower <z_mm>`调整绝对高度，可以向上移动或覆盖未完成目标，下降不松爪。
4. 用 `grab stack release`独立松爪，保持高度；`grab stack lift`另行提起。

高度尺滚轮每格1 mm，停滚1秒才发送最后高度；停止/断线/切页/故障/重启取消待发，不重放。补偿不改准心/参考，不按以后红点更新；普通对准、追踪和正式任务不启用该补偿。本测试不取仓、驱动ID8或改库存。

## 动态追踪与夹取

1. 香橙派B2程序运行，点击“准备抓取姿态”（grab pose work），等待work_ready。
2. 选择颜色，“一键持续追踪”（grab track begin）先等待本轮停稳反馈及新鲜视觉，缺少参考才建立；首次预算允许0～50 mm，已有参考/已耗预算不充值。
3. “追踪并夹取”（grab track pick）在目标停留、±5 px窗口、停车确认及停车后新鲜坐标满足时下降闭爪提起。高度/下降速度读取共享z_grab/z_pick_speed；完成picked保持物料，不自动入仓或改库存。
4. 短漏检按现行250 ms宽限减速/预测，持续缺失停车等待。行程窗口不足时停稳后继续观察，新有效目标回到可追范围可在原预算内自动续追。人工停止结束本轮，不自动重启。

仅观察与reference/start仍保留独立串口入口。X行程/50 mm预算是当前几何与机械条件，不是自动测距。实际发送节奏由Receive应答与反馈轮转决定，20 ms预测或300 ms摘要不能当每台电机的发包周期；状态页查看触发反馈年龄和真实计时。

日志先开启实时记录，再观察/追踪；记录开关不启动运动，关闭记录也不停车。停止确认后关闭记录，原始数据在 `.embeddedskills/logs/serial/`。冻结128条导出含数量/索引/CRC校验，仅补缺条。分析用 `python Code/tools/tracking_report.py <日志> --source live --kind physical`，实际转速/方向人工记录，不能把模拟标为实车。

## 单件与两批任务

- 单件物料入仓/车载取出/加工取回分别使用页面对应步骤；align只对准，普通pick按同一静态控制流程夹取。`grab place car`转车载口、X默认100 mm、到位松爪并停留，不自动驱动ID8或改库存。
- 蓝色首件路线用 `grab route [speed]`（默认200）：右下出发、二维码直接通过、蓝色3入第一仓、后向收回结束，不续加工或返回起点。只要求第一仓已配置且确认空，不要求仓2/3为空；不覆盖二维码任务码。`radar task start`仍是旧红色首件流程。
- 两批用 `grab mission [speed]`：二维码先通过，原料前90°左移、最后75 mm车头转0°并Base顺时针90°作业；加工车头180°、暂存90°，每站后向收回。每批粗加工全部放完再取回，第二批按第一批同色位置码垛，最终返回右下。
- 高度缺项进入config_wait保留当前件，补齐参数后 `grab mission continue`；不代填仓2/3角度。反馈到位后直接推进，不加固定停留。自动Z上下搜二维码仍未实现，完整带料赛事待验收。

兼容 `material ref` 人工确认当前安全观察姿态，`material auto <1..6>` 保持 Base/Z/夹爪不动，后退搜索，新坐标确认目标后停车并进入共用静态对准。对准完成后释放任务占用；`material stop`/`grab stop` 使用统一停车流程。开始时需要有效的机械轴尺度、范围与视觉模型，可从 `grab status` 查看具体缺项。

`material calib <1..6>` 由同一 GrabTask 调度，采样服务测量底盘前后及 X 响应。分母使用实际轮位置反馈和 X 电机角度，成功后前后响应写 j00/j10，X 响应换算像素/mm 后写 j02/j12；侧向 j01/j11 保留，因此不是完整三方向标定。失败或停止保留上一次有效模型。人工物料姿态确认标志仍保留原策略；手动Base参考问题[P001](../../../../docs/待解决问题.md)暂缓。只读grab route/mission status可在运行或停止锁定时查询。历史实测及部署证据见[开发记录](../../../../docs/开发记录/README.md)。

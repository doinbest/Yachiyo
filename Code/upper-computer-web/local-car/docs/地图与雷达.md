# 地图、雷达与路线操作

离线C路线新增“linear · 起步平滑 · 固定路线/C绕行路线”预览，键为task_fixed_smooth/task_planned_smooth；与实车共用连续开局几何及linear限速分配，基准转向段200、出弯扫码800。旧linear/cosine预览键保持，预览单独选取且不改实车草稿、不发送命令；本机理想轨迹/300×300 mm包络检查不代替延迟控制或实车验收。

第二批进入物料台的C预览沿用连续路线，长直线与弯道分开限速：正式linear基准长直线上限min(路线速度,800)，弯道上限min(长直线上限,60)，在入弯前按原制动包络减速。阶段显示的800是可用上限，实际峰值受距离、向量加减速和跟随误差约束。固件及预览共用修正后的路径头文件，CLI按阶段速度生成节点；源码已同步但本轮未重新构建CLI/固件或运行测试，旧缓存二进制不可当作新版已生效。

当前使用方案为linear；用户当前不采用余弦模式，P010（余弦+雷达标准开局丢失连续曲线）不再安排修复或验收。页面余弦选项和以下余弦说明保留兼容参考，本次未删除或修改功能；重新启用该组合时再核对开局路线。其他linear雷达路线问题仍按原范围处理。

linear单段测试支持独立起步加速度与停车减速度，各10～5000 mm/s²；网页初值500/300，参数受理后锁定，只覆盖本次独立动作。旧指令只给一个加速度时仍同时用于加、减速；固件省略参数与普通MoveTo保留300/300；正式linear比赛按路段分配起步500/800/1000，停车减速度300。制动包络用停车减速度，速度矢量减少当前平移动量时用减速度、增加时用起步加速度；前进与后退一致。普通linear直线到点进入位置/航向窗口后，先让平移参考按减速度降至零，再请求同步零速及真实停车确认；人工停止、取消和故障仍立即请求停车，原地转向和连续路径主体沿用独立控制。cosine保持K200，航向默认P0.1/D0。

底盘控制计算目标周期为1 ms；直线平移曲线更新周期默认1 ms，独立单段测试可在上位机填写1～100 ms整数。曲线周期只决定平移速度参考（含位置收敛、制动包络及加减速限制）的更新时间，中间复用最近参考；坐标系转换、按新鲜IMU更新的航向纠偏、四轮分配和到点/停车检查仍按控制循环执行。1 ms与1 ms时同频；例如曲线5 ms时，中间控制循环复用平移参考。参数受理后锁定，仅覆盖本次独立测试，后续普通任务恢复默认1 ms；原地转向、连续路径仍用各自控制。控制周期是主循环调度目标，不保证硬实时1 ms、IMU每1 ms出新样本或串口四轮批次每1 ms生效；同值去重、最新待发目标替换、同步批次及反馈组调度保留，不补发历史积压。

直线平移航向保持默认单P：P=0.1（rad/s每度误差）、I=0、D=0，输出限幅保留±0.50 rad/s。普通直线平移及定时heading/hold航向保持采用±0.1°纠偏死区（比较含0.0001°浮点容差）：误差绝对值≤0.1°时P、D输出均为0，并重置测量角速度历史；超出后按原误差恢复控制。该死区不作用于原地转向、视觉精确转向或视觉坐标对准；视觉校正保留原有精度、观测有效性和新鲜停稳判定。新鲜IMU样本更新航向纠偏，重复样本保持上次输出；测量转速滤波代码保留，但D=0时不参与输出。原地转向采用独立P=0.1、D=0，角速度上限仍100°/s，保留500 ms起步过渡及到角/停稳检查，连续弯道控制不变；正式linear比赛按路段分配，普通MoveTo保留300/300，cosine保持K200；独立单段测试可按次填写线性加速度或余弦K及航向P、D，受理时锁定，不覆盖其他任务。本版采用P0.1/D0，软件通过不代替各方向、载料及整场实车验收。 本轮为固件参数变更，需下载该版后生效，刷新网页不能替代烧录；IMU验证与四轮反馈准备、人工停车流程保留。

线性模式的正式右下标准开局恢复分段路线：(2250,150,180°)保持朝向斜移到(2100,300)，新鲜反馈确认停稳后顺时针原地转到90°，再直行至本轮二维码纵坐标；各平移段同时受本轮路线速度上限与分段参数限制：起步短斜移500/停车300、速度300，右下扫码直线起步800/停车300、速度上限800，不套连续弯道200 mm/s上限。转向停稳后才准备Base扫码姿态，并可与后续直行并行。余弦模式保留右通道连续开局；右上起点、右上角至物料台、第二批进站、非标准绕障和独立二维码测试保持各自现行路线。
实车监控的current与雷达建图的f1_host均由当前正式F407固件提供，通过同一个共享串口连接主车。两套接口分别维护配置与结果；f1_host沿用前期F1验证时的协议名称，不代表另有F1单片机运行，参考源码保存在reference中。扫描/读图/规划不启动底盘，网页预演只播放F407同C核心的动作；实车执行须明确点击对应运动入口。协议字段见[雷达协议](../../../../docs/协议/雷达.md)和[底盘协议](../../../../docs/协议/系统与底盘.md)。

## 正式实车监控

离线任务预演的路线选择提供线性与余弦两组固定/规划路线；选择仅控制预演。比赛执行模式仍在比赛卡片提交，预演不会写入设备。

### 单独测试当前路线加速度

比赛和普通路线余弦默认K200/400 ms；独立测试可填写10～2000整数K，过渡时间K×2 ms，K越大过渡越慢。余弦控制保留余弦速度参考，通过按延迟降低的位置P增益和矢量变化约束连续收敛到点；同一段不因新帧刷新突然放宽制动预算，末端上限不超过50 mm/s并按延迟进一步降低。不会把计划减速结束当作到位。验收同时观察末端是否反复起停、实际位置误差及新鲜停车确认，不能只看受理或峰速。

打开“底盘 → 底盘单段运动测试”，无需扫码、抓取或整场比赛：

1. 选择方向、距离、速度和linear/cosine；linear分别填写起步加速度和停车减速度（网页初值500/300，各10～5000 mm/s²），cosine填写K（默认200，10～2000整数，过渡K×2 ms）。两者均可填写航向P/D（各0～1，默认0.02/0）及曲线更新周期（1～100 ms，默认1）。点击“开始测试”只发送一次本次运动，不先查询或准备；固件仍核验IMU、定位、四轮反馈及任务占用。连续测试直接提交，不重复准备。
2. 状态区展示最近收到的总线、IMU、定位和任务状态、回报年龄及最近拒绝；页面打开、连接和重连不自动查询，未知或历史状态不冒充实时就绪。“查询状态”只读底盘与IMU。缺反馈或测试参考时按需点“准备/恢复测试状态”：读取任务/路线/比赛/IMU，开启四轮反馈并等待新鲜静止数据，仅缺参考时建立本地(0,0,0°)并读回；已有参考保留、不清零IMU，准备完成不自动发车。比赛运行或待续接时不接管。总线停止锁定使用底部恢复入口，IMU未验证到系统页处理；报错不会自动修复或重发运动。
3. 运行中每秒主动查询 `chassis task`，显示实际耗时、实测峰速、终点误差和停车耗时。只绑定本次受理的动作编号；提交新测试时旧结果标为历史，运行中不把当前误差标为终点结果。linear分别按本次起步加速度和停车减速度规划，网页初值500/300 mm/s²，正式linear比赛按路段分配，普通MoveTo仍为300/300；cosine按本次K计算提速、短段峰值和制动参考。结果卡显示设备读回的实际加速度或K/过渡时间及P、D，旧固件未回报时不推定；受理后修改表单只影响下一次测试；距离1～3000 mm、速度10～5000 mm/s，短距离自动降低峰值。
4. 卡片内“停止测试”与底部停止共用现有停止链路，准备阶段也可立即取消，迟到回复不会继续启动。请求发出与真实停稳分别显示，解除停止锁定不会自动续跑。断线和MCU重启取消本次准备/自动查询，重连后需重新点击开始。

运动参数需要配套固件；本次直接启动/状态展示仅改网页，刷新即可，未改固件和Python服务，无需因此烧录或重启服务。软件验证、模拟串口浏览器检查不代表实车验收。

例如前进1000 mm、目标1000 mm/s、线性加速度800 mm/s²，发送`chassis test 1000 0 1000 linear 800`；旧单值格式下加、减速度共用800。理想情况下加到目标需1.25秒、加速和减速合计1250 mm，因此这段1000 mm仍会降低峰值；实际还包含反馈延迟制动余量。余弦示例`chassis test 1000 0 1000 cosine 400 0.1 0.01`使用K400（800 ms）及P0.1/D0.01；线性示例加上P/D为`chassis test 1000 0 1000 linear 800 0.1 0.01`。D仍对新鲜航向测量变化率阻尼、40 ms滤波，输出限幅±0.50 rad/s，不改原地转向控制器。填写允许上限不代表该车实测适用参数。

单段测试使用所选普通直线规划及反馈到点判定，持续保持起步朝向；方向始终相对本次开始时的车头。下方“定时运动”仍是起停各0.5秒的旧接口，不用于验证路线余弦曲线。原地转向可在“高级运动”里测试，它使用独立转向控制器。

页面加载、修改输入和切页不发送运动指令。重新运行比赛时按所选起点摆车，由比赛开始流程重新建立定位；不要把测试坐标当作场地定位。

### 雷达盘转出与收回

“机械臂与夹爪 → 雷达盘舵机”保留两个实测按钮：**转出扫描 · 2450 μs**、**收回车内 · 1450 μs**。舵机型号TD-8125MG，PD12 / TIM4_CH1、50 Hz。出发前转出，确认雷达盘稳定后扫描地图；扫描完成后收回车内，再启动底盘。两点由用户2026-10-12实车确认，后续调度可复用；本次按钮只操作舵机，不自动扫描或出发。

原500/1000/1500/2000/2500五档快捷按钮以及“失能 · 停止PWM”已删除，包括固件off命令及服务端特殊发送规则。用户反馈停PWM没有实际失能效果；软件没有舵机电源开关。查询状态仍显示MCU已设置的脉宽，不表示机构已到位。

手动设置保留500～5000 μs整数输入，预填1450；已实测超过2800不响应，5000仅为保留的调试输入上限。编辑表单不发送，点击应用才动作。上电零脉宽，进入页面、刷新、切页、重连不自动转出/收回，也不重放旧命令。

取放、路线/底盘运动、IMU标定、雷达采集进行中拒绝转出/收回及手动脉宽；结束相应任务后显式重试，查询仍可用。停止锁定下仅可查询，转出/收回需要解除锁定；收回属于机构运动，不作为停车指令处理。

需要烧录新STM32固件、重启更新后的本地服务并刷新网页，实际串口由用户选择；无需重开香橙派程序。源码与网页已同步，整套“展开—扫描—收回—出发”自动衔接未在本轮实现或验收。

支持“先扫描、后准备跑图”和“先准备、后扫描”。保持车体在所选扫描起点静止，完成15圈地图与规划后，可再点击“准备跑图”：检查四轮反馈与IMU，已有原点和新鲜位置符合右下起点则直接复用；首次或不匹配时，人工确认车体中心 `(2250,150)`、车头朝左（−180°，朝物料加工区域方向），再设置定位原点。设置底盘原点、短暂反馈中断、开关遥测与重连不作废完整雷达地图；恢复后重新准备行车即可。地图仍使用采集时冻结的场地投影，修改雷达标定或筛选参数按对应范围重新采集或重算。实际执行仍核验新鲜定位、四轮速度、起点与总线状态；上起点保持只规划。此行为需要更新STM32固件并刷新网页，准备完成不会自动启动路线。

正式地图左下原点，X向右、Y向上。选择起点同时确定唯一安装方向：右下0°朝左180°，右上0°朝下270°；实车监控不再提供安装情况、方向和Q16草稿选择。雷达X、Y按起点分别填写、保存本机和显式应用读回。下方默认(2280,314)，保留新版F1情况2的Q16矩阵 `[65809,680,-407,66623]`、精确原点 `[149407997,20569846]`；改XY只调整平移，原点已含平移，不重复叠加。2026-10-12用户确认上方雷达采用(2050,2250)，单位矩阵保持；该安装位置与右上车辆名义起点(2250,2250)分开，几何精度仍须实测，可显式更新实测XY。右下车体起点为(2250,150,−180°)，+180°与其同向，工位与接驳坐标保留。

物理场地0～2400 mm，现行5×5判障边界为[150,550,1000,1400,1850,2250]，新地图 `g:4` 的X、Y均为半开区间 `[150,2250)`，恰好2250不计入。历史 `g:2` 全场网格、`g:3` 内缩网格按原语义显示。默认筛选0～360°、100～40000 mm、能量0～255、每格阈值1；正常建图采用15个有效完整圈、10mm箱、30mm邻域、至少3个不同圈支持和256候选槽，由F407共用C核心生成稳定XY、格内计数和路线。

1. 人工连接实际串口，读回设备RAM参数。顶部选择本次右下或右上起点，下方“雷达坐标”显示对应X、Y和固定方向。编辑或切换起点不发送命令；“保存本机坐标”保存两个起点的填写值，“应用坐标并读回”只写当前起点的设备RAM坐标，随后重新采集地图。新的读回不会覆盖尚未应用的填写值。历史地图仍使用采集时冻结坐标；右上坐标读写需要包含新增参数接口的固件。
2. 点击“采集15圈并规划”（`radar scan lower|upper 15`），保持静止；采集进度与结果下载进度分别显示。下起点单次及持续采集在首次连接、重连后或设备零角不是180°时，先应用180°并读回确认，再开始采集；确认失败保留当前结果，可重试。已读回确认180°时直接采集。此操作只确认方向，不重置XY、标定矩阵或过滤。无效圈不增加窗口，不把累计恢复次数当结束条件。旧普通1/3圈入口归一为15圈；原始诊断仍为1圈。
3. “持续最近15圈建图”发送 `radar live map start lower|upper`，首次满15圈后逐圈使用最近15圈更新。配置改变位置、方向、矩阵、原点或过滤时重建15圈窗口，雷达保持旋转，历史图保留；阈值、人工障碍与路线可从冻结稳定结果重算。
4. 地图、路径和稳定XY使用同一冻结结果读取，CRC坏页仅补缺页，稳定点完整后才ACK释放。默认点层直接绘制稳定XY；最后圈原始云、最后圈本地筛选和独立preview120都明确标注，不能替代15圈证据。原始点云保存同圈地图的冻结标定，不论地图和点云谁先下载；换起点或新扫描期间，历史云使用自己的标定显示，不借用新地图坐标。旧快照缺少标定时沿用其自身冻结pose，缺少位姿则等待对应地图。导出/导入保留冻结安装、仿射、网格、窗口、算法与稳定点。
5. “停止采集”停止雷达采集并保留最后完整图；“取消读取”只取消当前下载；“取消路线”只请求终止导航。断线保留历史，不自动续采。持续建图时点击实车执行会先停止采集，等设备停止状态和最后完整地图/路径/稳定点收齐，再走原 `radar nav start` 入口。只收到15圈进度不能证明结果可执行。
6. 本机检查/播放绕障预演不运动。固定路线按钮执行固定路线；实车雷达执行须使用完整同窗的下起点结果，上起点只规划。净空和实车到位仍由实测验收。

“场地感知与规划”中的“清除历史结果”一次清除本机缓存与显示的雷达点云、扫描障碍、地图计数、规划路线和对应绕障预演；刷新后也不会恢复这些结果。固定场地、起点、雷达坐标与设备参数、独立离线副本及磁盘日志保留。操作不向设备发送命令，不清设备RAM结果；再次主动读取或采集后可显示新结果。采集或读取进行中按钮暂不可用，完成或取消读取后再清除。起点下拉只显示“右下起点／右上起点”，上起点的执行限制仍在执行处提示。

历史情况1的建图参考为(230,230)、0°朝+Y、单位矩阵和原点 `[15073280,15073280]`；参考文件仍按`(x,y)→(2400−y,x)`逆时针90°转换为实车坐标。实车安装界面取消这个预设入口。旧本机安装草稿只迁移XY到对应起点，方向由起点确定；已确认的旧情况1参考坐标迁移时转换一次。情况2和右上安装本来就在current实车坐标。

导入地图文件默认自动识别`coordinate_frame`；可显式选择实车坐标或建图参考坐标。参考文件的路径、pose、障碍掩码、计数、稳定XY和Q16几何一起转换一次，原始极坐标及投票等采集证据保留。零角增加90°时，矩阵按`M'=R M R^-1`转换，平移按`(2400Q−ty,tx)`转换，保留Q16精度；current文件再次导入不重复旋转。F1导出带冻结坐标来源；沿用备用安装时同步复制方向、精确矩阵和原点，保持原始角度/距离筛选。旧本机草稿保留，只有完整匹配旧情况1预设的草稿自动转换，自定义草稿按原值保留。

## 雷达建图页（F407主机接口）

页面#map/radar是当前F407的“雷达建图与诊断”页面，共享USART1/DL-20的115200链路；雷达USART2为921600。新版设备默认情况2，起点格R1C5；情况1参考预设保留(230,230)、固定mask0x00050140、保护mask0x00404405和任务1-5-4-2-3-4-2-3-1。两种安装分别保存，情况2保护启停格随其起点变化，设备默认值与保护mask以HostConfig读回为准。正式行车入口在实车监控；进入页面、刷新、重连、导入与本机保存不发送雷达或运动指令。协议与旧快照的f1_host标识继续兼容，历史安装坐标保持原含义。

单次扫描采15个有效完整圈；持续扫描首次满15圈后逐圈更新最近15圈。紧凑结果layout2保留32位统计、冻结安装/矩阵/网格与窗口；旧layout1历史仍可读。设备冻结配置、稳定XY收齐后才ACK。页CRC、稳定点整流CRC及身份分别核对，迟到页不混入新结果；下载期间显示上一份完整历史。

默认图层为稳定XY；原始点读取按钮仅下载最后一圈，preview120单独选择。几何/过滤改变需要新的15圈窗口，阈值/人工障碍/路线从冻结稳定证据重算。单个原始圈无法重建15圈稳定窗口，离线入口会明确拒绝这种重建；仍可复用冻结地图mask规划。MCU配置只在RAM，草稿只有显式保存才写本机；未读回显示待同步/—。

## 实时点云与诊断

正式radar live start upper|lower用独立120分区预览，不改完成地图/规划/完整云；stop停止采集但保留旧图。只用最新完整圈整体刷新，不发送半圈。它与15圈正式建图/单圈原始诊断互斥，与正式和F1持续建图分别操作。

radar debug scan按需记录解析前USART2原始字节及冻结参数；raw分页CRC、下载完整性和设备有效完整圈证明分别校验，失败可导出部分证据，不套历史云。radar fetch evidence按需取缺包/逐格来源证据，不加入正常结果下载。radar probe用LUUIDH查询身份，不转雷达、不改参数或地图；必须新鲜PRODUCT SN与MCU发送完成共同证明往返，回显/报警不独立证明。

第一阶段USB-UART直连模块保留独立诊断，当前#map/radar不使用它。雷达供电、USART2交叉连接与共地按实物资料核对，不根据无身份应答直接断言供电故障。

## 路线与遥测

实车监控桌面布局按地图现有显示高度与完整视野的纵横比分配左栏，余下宽度交给右侧控制区，减少白色边带。右栏达到650 px时，六个建图常用按钮排成三列；较窄时保留两列，窄屏继续上下排列。完整场地坐标、比例和图层不变；短窗口仍可滚动查看。更新网页后刷新即可生效。

实车监控顶部只选择本次右下或右上起点，地图突出所选位置；选择只改变本页标记，采集按钮使用该起点，不发送命令、不修改反馈位置或设备安装。右上仍仅建图与规划。实车页优先展示设备当前任务、目标、停车确认、启动速度、阶段限速及当前指令速度；取消重复的“跑图前检查”，完整本机计算、阶段表和模拟停靠统一在离线对照中操作。

离线对照按“地图来源 → 路线与预演速度 → 计算路线 → 检查与播放”使用。预演速度独立保存在浏览器，不再绑定实车启动速度；“复制实车启动速度”仅按需复制到预演设置。修改速度、过滤或障碍后保留上次结果并标为待重算，暂停旧方案，重新计算后才能播放。仅提供一个可见计算入口。地图与方案JSON保存离线速度和路线选择，不包含实车停靠日志；旧坐标导入兼容保留在文件操作中。高级过滤仅显示已接入本机计算的字段，完整点云重判障与冻结稳定窗口的边界沿用现有协议。

“检查绕障路线”及离线计算后的外框报告仍按300×300 mm与整格障碍范围检查。障碍格只表示格内有障碍证据，不表示整格均为实体；播放时遇到此类外框风险会提示目标、阶段和格号并继续，不再在中心原地转向时直接卡住。明确的场地边界、固定非行车区和原料转盘仍会停止播放。此区分只影响网页预演，实车C路线与执行条件保持原有语义。

车框内橙色圆点和箭头表示机械臂安装与阶段朝向：默认在车体中部偏左、朝车尾，随车体位置与yaw旋转。带机械臂阶段的C方案按`arm_pose`显示朝后或顺时针90°作业方向；普通监控默认显示朝后安装示意，不当作机械臂实时反馈。位置按车体尺寸比例绘制，未新增实际毫米安装参数。

地图提供目标编号和方向箭头开关。C阶段使用固件segment编号，中间动作不新占编号；重复到访同坐标合并显示，例如3/8，连续点击依次选择。点击编号或阶段表高亮对应路段，其他路径淡化。实车以设备路径和遥测显示当前目标，可切换“显示全部路段/跟随当前目标”。只有几何路点而缺少C阶段时用W路点编号，避免假定绕行后的路点序号等于业务目标。所有标注仅改变显示，不偏移真实路线坐标。

历史16段时间模型、手工路线表和速度曲线移到折叠的“运动实验”入口；常规C方案拥有独立的播放、暂停、继续与从头播放操作。

车辆状态卡仅保留一个“开始监控／暂停更新”按钮。未连接或尚无状态时只显示一条提示，隐藏空的实时数据和停靠记录；收到有效状态后用四项显示车辆状态、当前目标、计划速度（阶段限速）及指令速度。指令平移速度显示合速度，非零转向显示°/s，分量和启动速度可悬停查看。转向阶段不把0 mm/s当作转向速度。“最近停车”有确认记录才显示，并标注为记录；历史停靠、完整路线、遥测和服务详情统一收在默认关闭的“历史与详情”。暂停更新只停止状态订阅，不停车；断流隐藏实时值，恢复后继续显示。停车记录仅采纳同帧停车确认及新鲜有效编码器＋IMU位置，列出计划坐标、反馈停车坐标、MCU时间及原点版本；不使用指令推算或过期位置补齐。断流、关闭遥测、普通停车与网页重连保留本页记录，刷新网页清空。当前约2秒遥测周期可能漏过短暂停靠，记录不是完整设备停靠日志；已确认的历史坐标也不证明车辆现在静止。实车软件停车确认不依赖网页坐标是否有效。

底盘直线平移提供linear与cosine两种模式：linear为默认，普通MoveTo加减速度300 mm/s²，正式比赛按路段起步500/800/1000、停车300 mm/s²；cosine为K=200、名义400 ms半余弦速度过渡，短段降低峰值。两者都计入反馈年龄和驱动响应的制动余量，共用1000 mm/s路线默认速度、工位局部限速、位置/航向及新鲜停稳判定。除线性模式恢复分段开局外，其他连续转弯和原地转向保持现行独立控制。比赛卡片按轮选择，省略为linear，不需额外写入K；原速度输入、工位限速和反馈到点语义保留。连续转弯仍受原300 mm/s²向量变化率及角速度/跟随限制，转向上限100°/s。右下首腿(2250,150)→(2100,300)→(2100,1200)，中间通行点不触发工位；路线交接按station/visit，不能按绕行后变化的路点序号。

正式比赛加工进站先在(1200,380)停稳转至180°，再保持朝向以不超过50 mm/s平移至(1200,350)；到点停稳且作业姿态就绪后，才启动视觉核验和对准。中心到暂存区先停车转为纵向行驶朝向（0°倒车或180°前进，取较小转角；从90°到两者等角时取0°），直行至(425,1200)，停车转至90°后保留最后75 mm、最高50 mm/s接近。中心连续转弯暂不实现。工位内按首次成功视觉对准的实际底盘位置和环号差换环，不强制回到名义进站纵深，每件仍视觉微调。加工末件取回入仓后保持180°直接到(1200,425)，不先回380停车；425处确认停稳及完整行驶姿态后转90°去中心。转向接驳点380保留，视觉观察目标为350，首次成功对准的实际工位锚点继续保留，固定/雷达续接不再回走同列旧Y350接驳，有效绕障点继续执行。固定/雷达目标与网页共用C核心预览同步，绕障途经点保留；历史16段时间示意不作为现行比赛路线。实际包络及视野仍待实车验收。auto到位停稳后直接推进，附加停留0 ms；独立start按原业务边界推进。

正式比赛正常路线平移/转向到点在停车发送完成后取两组新鲜四轮速度/位置；先补读一次驱动状态，再优先轮转速度/位置。普通独立MoveTo及独立停车监控仍三组，均不附加500 ms持续稳定等待。保留各轮速度≤±1 RPM、相邻位置变化≤2 mm；旧缓存或单轮未更新不能凑组，移动/失效反馈重置证据。路线到位仍核验位置与航向，人工停止/取消/故障保持原处理；视觉夹取和机械臂自身稳定时间不变。实际确认耗时由新反馈到达决定。

正式linear右下标准扫码离站，现有航向容差内的90°续行不生成独立微小转向；到右上接驳点(2100,2100)的10 mm窗口后连续左移至(1200,2100)，保留速度、车头90°及Y方向修正，中间点不请求停车。到物料台仍停车后转0°。只按实际标准三点几何启用；加工区到暂存区等后续路线先记录为候选，本轮不连续化。路线几何预览仍为原途经点折线，不代替真实速度过渡及动态车体投影验收。

网页角速度为°/s，run/遥测为rad/s；底盘平移测试合速度≤300 mm/s。网页定时转向与持续偏航输入上限为±500°/s，比赛转向为5～500°/s、默认100；当前固件对应上限仍为100/360/100°/s，网页放宽不代表设备已支持500°/s。紫色轨迹为反馈估计，橙色为指令推算，不等于实测精确定位；车身外框/动画不能证明真实净空。遥测开启由用户显式操作，重连/重启后不自动开启，旧位置保留过期标记。

历史16段离线时间示意与实车15业务目标路线独立；雷达建图与离线对照共用F407 radar_map/radar_start/radar_plan，不再实现另一套规划算法。SLAM/运行中雷达定位闭环未实现；详细历史与现场证据见[开发记录](../../../../docs/开发记录/README.md)。

余弦模式正式比赛右下标准开局保持180°平滑斜移到(2125,350)，沿右通道在600 mm行程内转至(2100,950,90°)，竖直连接二维码终点；接近/转向段上限200 mm/s，仍按角速度与反馈跟随减速，出弯继续加速。第一批从(2100,2100)保持90°向左平移到物料台中间(1200,2100)，停稳后原地顺时针转90°至0°，预览显示work_approach/work_turn两个停车阶段；第二批从中央进入物料台仍连续转向。C核心同时提供位置和朝向，网页共用几何，连续曲线只在整段终点记录停车；预演动画不代表实车速度响应。暂停继续保留阶段或路径进度。非标准雷达接驳保留原路线，不删除障碍绕行点。普通固定路线及独立二维码测试保留原分段动作。

曲线更新周期可在“底盘单段运动测试”填写，默认1 ms；例如选择5 ms，网页在现有P/D参数之后追加5并随本次运动一起提交。设备结果显示“控制1 ms，曲线5 ms”；运行中修改表单只影响下一次测试。控制与曲线都为1 ms时同频；线性加速度和余弦K仍分别保留。需要配套固件和刷新网页；页面刷新、输入和保存不会自动驱动小车。
